# T1_F017 — Scope-Fences
**Tier 1 · Abh.: F014 · Blockiert: F141-Basis, sichere Langläufer**

## Ziel & Done
Geschützte Pfade / verbotene Aktionen / Muss-Pfade pro Job; Verstoß = harter Task-Fail
(Fehlerklasse fence). Done: Fence-Verstoß-Test schlägt korrekt fehl.

## Design
- `packages/orchestration/scope_fences.py`: `FenceSpec{protected:[glob], forbidden_actions:
  [dependency_change|delete_file|network|schema_migration], must_touch:[glob]}`;
  Quellen: `.remedy/config.toml [fences]` (Projekt-Default) + Flight-Plan-Override.
- Durchsetzung: (a) Prompt-Injektion (Fences im Task-Header), (b) Diff-Prüfung nach
  Builder-Run (protected berührt → Fail, must_touch unberührt am Jobende → Warnung),
  (c) forbidden dependency_change: Lock-/Manifestdateien (package.json, pyproject) in
  protected implizit, außer explizit erlaubt.
- UI: Fence-Chips im Flight Plan, editierbar vor Start (F015-Commands).

## Task-Schnitt
- T001: fences.py + Diff-Prüfer + Tests (jede Verstoßart).
- T002: Prompt-Injektion + Flight-Plan/UI-Anbindung.

## Akzeptanz & Tests
- Builder-Fixture ändert protected Datei → Task FAIL(fence), Repair-Hinweis präzise.

## Risiken / Anti-Ziele
- Fences ersetzen kein Sandboxing (F085); network-Fence v1 = nur Prompt+Review, ehrlich
  dokumentiert als „soft".

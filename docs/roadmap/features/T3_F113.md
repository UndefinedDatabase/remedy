# T3_F113 — Local models for side roles
**Tier 3 · Depends on: F110 · Blocks/used by: marginal cost zero for chores**

## Goal & Done
Chores stop costing API tokens: an OpenAI-compatible local endpoint
(ollama-style) becomes a routable provider for SIDE ROLES ONLY —
summaries, humanize drafts, idea raw drafts — behind a quality gate
that benchmarks each role against the cheap cloud model and falls the
role back when it loses. DONE when a local endpoint serves the summary
role on a fixture with correct evidence and zero cost basis, core
build/review/orchestrator classes are provably unroutable to local,
and a failing quality spot-check flips the role back automatically
with the evidence recorded.

## Design (suggested shape)
- Adapter: base-url + model-name config per endpoint; capability flags
  honest (no resume unless proven); health probe at first use per run
  with a clean unavailable classification (the failover/fallback then
  applies within policy).
- Routing: side-role classes may map to local endpoints; the hard rule
  list gains local_never_core; per-role fallback chain local → cheap
  cloud is configuration, triggered by unavailability OR the quality
  gate.
- Quality gate: per side role, a small frozen spot-check set (inputs +
  acceptance checks — e.g. summary must mention seeded facts) run on
  demand and after endpoint/model changes; a losing role is flipped to
  fallback in config-state with the bench evidence referenced; flips
  are surfaced in status (no silent degradation in either direction).
- Evidence: routed_model shows the local endpoint; actuals record
  token counts as reported (or unmeasured) with basis local_zero.

## Task slicing
- **T001** adapter (or extension) + health probe + classification +
  fake-endpoint tests.
- **T002** routing integration + the local_never_core hard rule +
  fallback chain + tests (a config routing builder to local is refused
  with the rule named).
- **T003** the quality gate + spot-check sets for the summary role +
  the flip/flip-back mechanics + an end-to-end fixture.

## Acceptance
- Summary role served locally on the fixture with correct evidence and
  basis. Core-class-to-local config refused. Endpoint down → clean
  fallback with classification. Failing spot-check flips the role,
  status shows it, passing again flips back only via explicit re-check
  (no flapping — a documented dwell rule).

## Edge cases & assumption defaults (A9)
- Wildly slow local models: the standard timeout profiles apply; a
  chronically timing-out role fails its spot-check by wall-time
  criterion (quality includes latency for chores). Multiple endpoints:
  v1 supports several named endpoints but no load balancing.

## Orchestrator brief
Gate on routing's hard-rule mechanism. T003's spot-check sets are the
quality substance — require seeded-fact acceptance checks, not
LLM-judged vibes, in v1.

## Do not touch

# T4_F117 — Card format & store
**Tier 4 · Depends on: F146 · Blocks/used by: all memory features**

## Goal & Done
Remedy's memory gets its atomic unit: a CARD — markdown with typed
frontmatter, human-readable, git-versionable — stored per project in
the repo, with a store API (create/read/update/archive/list) and a
CLI that makes curation pleasant. DONE when the format is
schema-validated with helpful errors, the store round-trips cards
through edits with history preserved, archiving never deletes, and
default fences keep jobs from writing cards outside the gated path.

## How it fits (a deliberate placement decision — read this first)
Cards live IN THE REPO at `.remedy/memory/cards/<id>.md` — unlike
generated mirrors (data root), cards are curated knowledge that
should travel with the repo, appear in PRs and survive machine
changes; global cards (a later feature) live under the DATA ROOT's
global area, not a home-directory dotfile. Consequences handled
here: the ignore rules must NOT ignore `.remedy/memory/` (verify the
hygiene helper), and the default fence set denies job writes into
`.remedy/` so builders cannot self-serve memory — card writes go
through the store API/CLI and approved harvest flows only.

## Design (suggested shape)
- Format: markdown body + YAML frontmatter, versioned card_v: 1 —
  id (slug+shorthash, immutable), type (architecture | convention |
  lesson | decision | risk | component), title, scope {paths: [],
  job_kinds: []}, status (active|archived), origin (manual | study |
  harvest | adr), value (float, managed by the value feature —
  default neutral), evidence_refs (typed, the provenance
  vocabulary; REQUIRED for non-manual origins, optional for manual),
  created/updated timestamps. Body: free markdown ≤ a token cap
  (config, default matching the dossier discipline ~800) enforced by
  the validator with the count in the error.
- `card_store.py`: load-all with per-file error honesty (a broken
  card is reported and skipped, never crashes listings — the
  established pattern), CRUD with atomic writes, archive =
  status flip + move to `.remedy/memory/archive/` preserving the
  file, id uniqueness enforcement, and a validate-all entry the CI
  guard tests call.
- CLI `remedy memory new|show|edit|archive|list [--type --status]`
  — new opens a templated file path (no interactive editor
  spawning; print the path and template — respect the
  no-interaction discipline), list renders a compact table.
- The store API is the ONLY sanctioned write path (import-linter
  style guard comes with the module feature; the fence deny lands
  here).

## Task slicing
- **T001** schema + validation (each field's failure message tested)
  + the token cap + fixtures of every type.
- **T002** store CRUD + archive + broken-card honesty + atomicity +
  id rules + tests.
- **T003** CLI + templates + the fence deny for `.remedy/` + ignore-
  rule verification + docs (the placement rationale, verbatim from
  this file's fit section).

## Acceptance
- Every card type round-trips; a card over the token cap is refused
  with the count; a corrupted card file degrades listings honestly.
  Archive preserves bytes and history; ids never collide (collision
  fixture). A builder-driven write into `.remedy/memory/` is fence-
  denied; the CLI path succeeds.

## Edge cases & assumption defaults (A9)
- Hand-edited cards with unknown frontmatter keys: warn, preserve
  the keys on rewrite (humans own these files; the store must not
  eat their annotations). Merge conflicts in git are the user's
  normal git life — the format is line-diff-friendly by design
  (frontmatter key order stable, one field per line).

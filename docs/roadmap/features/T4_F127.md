# T4_F127 — Optional retrieval above threshold
**Tier 4 · Depends on: F118 · Blocks/used by: scale**

## Goal & Done
Selection stays fast and deterministic-at-heart even when collections
grow: ONLY above a card-count threshold (config, default 200 active)
an embedding index pre-filters candidates to a top-K set BEFORE the
deterministic funnel runs; below the threshold the path is
bit-identical to today. DONE when the threshold switch is provably
inert below the line, the pre-filter never excludes pinned or
path-scope-matched cards (recall guarantees over recall hopes), the
index rebuilds incrementally on card changes, and embeddings degrade
honestly (index unavailable → full deterministic path with a logged
notice, never a failure).

## How it fits (a dependency-honesty correction versus an earlier
draft)
An earlier sketch named a heavyweight local embedding library as the
default; that drags a large dependency into every install for a
scale most projects never reach. Corrected: embeddings are an
OPTIONAL capability — provider embeddings (an embeddings-capable
endpoint from config, including local OpenAI-compatible ones via the
local-models feature) are the default mechanism; a local library is
at most an extras-install (documented pip extra), never a base
dependency. The selector's determinism contract is preserved by
construction: the pre-filter only SHRINKS the candidate set; the
funnel's ordering rules are untouched, and the funnel evidence
records prefilter: {active, k, index_version} so equal-state
comparisons remain meaningful.

## Design (suggested shape)
- `card_index.py`: per scope (project/global), embedding per active
  card (body+title), stored under the data root with the card's
  content hash — incremental: only changed/new cards re-embed;
  archive removes. Index version ties to the embedding model id
  (model change → full rebuild flagged, old index unusable —
  honesty about comparability).
- Pre-filter: query = the task's goal + files_hint terms → top-K
  (config, default 50) by similarity, UNIONED with all
  path-scope-matching cards and the pinned card (the guarantee set
  bypasses similarity — scope matches are contractual, not
  statistical); the union feeds the unchanged funnel.
- Threshold check per selection: active count ≤ threshold → the
  index code path is never entered (bit-identity test).
- CLI `remedy memory index [--rebuild|--status]`; unavailable
  embeddings at selection time → notice + full path.

## Task slicing
- **T001** index build/incremental/versioning + storage + tests
  (hash-driven re-embed only; model change forces rebuild).
- **T002** pre-filter + guarantee-set union + threshold inertness
  (bit-identity below; evidence field above) + degradation path.
- **T003** CLI + docs (the optional-dependency stance verbatim) +
  a scale fixture (300 synthetic cards: funnel outputs equal with
  and without the pre-filter for tasks whose true matches are
  scope-based — the guarantee test).

## Acceptance
- Below threshold: byte-identical selections and evidence to a
  no-index build. Above: prefilter evidence present, guarantee set
  always survives (property test with adversarial similarity),
  degradation honest. Incremental rebuild touches only changed
  cards (embed-call counter).

## Edge cases & assumption defaults (A9)
- Similarity ties: stable by id (determinism discipline). Embedding
  costs: side-role routed and visible in the ledger like everything
  else; the index command shows the last build's cost.

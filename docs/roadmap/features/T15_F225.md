## Design
`remedy study --infer-spec <module>`: a pipeline (1) collect behavior sources (signatures, tests as behavioral proof, docstrings, caller patterns via the F107 import graph), (2) an LLM SKETCH of a spec draft (the F072 format) where EVERY sentence is marked: proven(anchor) | inferred, (3) invariant candidates additionally become property-test proposals (the F187 bridge!) - inferred invariants become testable instead of believed. Output: a spec draft + card candidates (F117 proposed) + property proposals; everything stays proposal-status.

## Task slicing
T001 the source collector + the sketch prompt + the proven/inferred schema + tests. T002 the property bridge + card coupling + a golden on the legacy fixture (a real invariant recognized AND confirmed by a generated property).

## Acceptance & tests
The golden: the sketch names real invariants with correct markings (proven ones have resolving anchors); one inferred invariant is CONFIRMED by a generated property on the fixture - the loop closes measurably.

## Risks / anti-goals
The sketch is never attached as truth (proposed enforced); IO-heavy modules are honestly marked 'weakly inferable'.

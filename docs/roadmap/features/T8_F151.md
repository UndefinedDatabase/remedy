# T8_F151 — Worker adapter contract v2
**Tier 8 · Depends on: Tier 0 stable · Blocks/used by: F153-F162; the neutrality promise**

## Goal & Done
The neutrality promise gets its load-bearing interface: adapter
contract v2 defines what ANY builder/reviewer backend must provide
— capabilities declaration, a uniform call surface, stream/usage
mapping, isolation declaration — so vendor adapters plug in without
touching orchestration. DONE when the contract is a typed module
with conformance tests any adapter must pass (the reusable
conformance kit is the deliverable), the EXISTING main builder path
is wrapped as the reference adapter passing that kit unchanged in
behavior (golden equality), the v1 worker registry's declarative
specs reconcile with v2's executable adapters under one documented
relationship, and orchestration code imports only the contract —
never a concrete adapter (import guard).

## How it fits (reconciliation with existing code — inspect first)
Real modules exist: worker_registry.py (declarative WorkerSpec
with kind/cost/risk tiers, RoutePolicy, builtin specs, placeholder
detection), worker_adapters.py (WorkerProviderSpec listings),
main_builder_adapter.py (the current builder's wrapping), plus the
ping-pong loop owning transport/timeouts/retries/evidence. The
findings order settles the v1↔v2 relationship: v1 registry entries
DESCRIBE workers (metadata, routing policy inputs); v2 adds the
EXECUTABLE face — an adapter id links a registry spec to an
implementation; placeholder specs (is_placeholder) are exactly the
entries awaiting v2 implementations. Transport ownership stays
where it is: adapters BUILD commands/requests and MAP outputs; the
loop keeps timeouts, retries, per-call evidence (adapters that
re-implement retry are the reject condition — F001's single home).

## Design (suggested shape)
- `packages/workers/adapter_api.py`:
  - capabilities() → typed record {vision, json_schema,
    session_resume, streaming, tool_use, max_context_tokens} —
    the honest-flags discipline (declare only what conformance
    verifies; the certification feature audits declared-vs-real).
  - build_invocation(role, prompt_parts, options) → the
    command/request the loop executes (CLI argv or HTTP shape —
    a small sum type; the loop gains the HTTP execution arm only
    if no adapter needs it yet, deferred honestly to the local
    adapter's order).
  - map_stream(raw) → the F004 event vocabulary; map_usage(raw)
    → the actuals record (raw counters preserved for the pricing
    feature).
  - isolation() → the declaration the isolation feature (F152)
    specifies — reserved here, shaped there.
- The conformance kit: a pytest-importable suite parameterized by
  adapter — capability declaration shape, invocation building on
  canonical prompt fixtures, stream mapping against recorded raw
  samples, usage mapping, error taxonomy mapping (unavailable/
  timeout distinguishable — the failover taxonomy feeds from
  here).
- Reference adapter: today's builder path behind the contract;
  golden equality on the existing integration fixtures (the
  no-behavior-change bar).
- Registry linkage: WorkerSpec gains adapter_ref (additive);
  the resolver (routing) resolves model+adapter pairs.

## Task slicing
- **T001** the findings order: v1 registry/adapters/main-builder
  relationship mapped; the ownership table (who keeps transport,
  retries, evidence) written.
- **T002** the contract module + conformance kit + fixtures
  (recorded raw samples per mapping) — the kit tested against a
  deliberately broken toy adapter (the kit must FAIL things).
- **T003** the reference adapter wrap + golden equality + the
  import guard (orchestration imports the contract only) +
  registry linkage.

## Acceptance
- Conformance kit fails the broken toy on each dimension; the
  reference adapter passes it AND the existing integration suite
  unmodified (equality goldens). Import guard green with a
  violation fixture red. The v1↔v2 relationship documented in
  both modules' docstrings (grep). No retry/timeout logic in any
  adapter (grep + review).

## Edge cases & assumption defaults (A9)
- Capabilities that vary by model within one vendor: capabilities
  take the resolved model as input (per-pair honesty). Streaming
  absence: map_stream may declare non-streaming (the loop's
  existing non-stream path — verify it exists; if not, the
  buffered fallback is a small contract-side shim, noted).

## Orchestrator brief
T001 findings first, reviewed. T002's broken-toy discipline is
the kit's proof — verbatim. T003's equality bar protects
everything downstream; its goldens are the safety net every
vendor adapter later leans on.

## Do not touch
Loop transport/retry/evidence, routing policy semantics, registry
storage. Suggested tests: the conformance kit itself +
tests/workers/test_adapter_contract.py.

# T8_F155 — Local full builder
**Tier 8 · Depends on: F151, F152, F113 · Blocks/used by: F173 air-gap, F174 confidential routing**

## Goal & Done
Local models graduate from side roles toward real building — gated
by proof, class by class: a local adapter speaks OpenAI-compatible
endpoints (Ollama/vLLM, base_url from config) with capabilities
declared honestly reduced (schema via grammar/format params where
the server supports them, resume false, vision model-dependent,
context limit from model metadata), and CORE-role release happens
ONLY per task class after certification — worker_certificate.
classes_passed gates the router hard. DONE when the adapter passes
conformance against a recorded local server's shapes, the F113
side-role hard rule relaxes into the certificate gate (one rule
evolution, documented — side roles remain free, core classes
require the certificate), an uncertified local core-route is
unconstructable (the gate test), and the recommended-start path
(S-class builder + summaries) is the documented default config.

## How it fits (reconciliation — two features, one adapter story)
F113 built the side-role local provider with its never-core hard
rule; this feature EVOLVES that rule rather than contradicting it:
the routing hard rule becomes "local serves core classes only with
a valid class certificate" (the F156 handshake — this feature
lands the gate's shape, certification lands the certificate; the
STATUS order runs F155 before F156, so the gate ships
closed-by-default: no certificate mechanism yet → no core classes,
exactly v1's behavior, opening automatically when F156 delivers —
the sequencing stated so nobody panics). Inspect F113's adapter:
this is the same module grown to the full contract (one local
adapter — the v2 conformance face over the existing endpoint
plumbing + REMEDY_OLLAMA_* config keys already present).

## Design (suggested shape)
- The adapter under the contract: capabilities from server/model
  introspection where available (metadata endpoints), else
  conservative declarations per configured model (config declares,
  certification verifies); json_schema via the server's
  grammar/format parameters (researched per server flavor —
  Ollama format vs vLLM guided — the ADR duty applies to server
  flavors like it does to CLIs); invocation as the HTTP shape
  (the contract's deferred HTTP arm lands HERE — the loop gains
  its HTTP execution path with the same timeout/evidence
  discipline, a named prerequisite order).
- The router gate: classes_passed from the certificate store
  (empty until F156) → core-class local routes require membership;
  side roles unchanged; violating configs refused naming the gate.
- Recommended start: documented config snippet (S-builder +
  summaries) shipped as commented defaults.

## Task slicing
- **T001** the HTTP execution arm in the loop (timeouts, evidence,
  stream handling for SSE-style responses) — the prerequisite,
  with the transport-discipline parity tests.
- **T002** the adapter (introspection, capabilities, grammar
  paths per flavor ADRs, mappings from recorded local-server
  samples) + kit + isolation (trivial for HTTP — the declaration
  says so honestly) + goldens.
- **T003** the gate evolution (rule rewrite + refusals + the
  closed-by-default sequencing) + F113 regression green + docs +
  the live smoke (marker real_ollama — the existing marker).

## Acceptance
- Kit green on recorded shapes; the HTTP arm matches CLI-arm
  discipline (parity tests: timeout classes, evidence fields).
  Core-route without certificate refused naming the gate; side
  roles unaffected (F113 suite green). Flavor ADRs pinned.
  The real_ollama smoke runs where the env provides it.

## Edge cases & assumption defaults (A9)
- Wrong context-limit metadata: the compiler's caps still bound
  input; overruns map to the honest error class with the
  metadata-mismatch note. Multi-GPU/host serving: out of scope —
  base_url is the boundary (the user's infrastructure, stated).

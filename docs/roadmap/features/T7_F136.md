## Goal & Done
Iteration loses its fear: checkpoints become timeline markers, the
human picks "return here + hint" — the worktree resets to the
marker and a steering message seeds the fresh attempt — and the
abandoned future stays in the graph as a grayed fossil branch,
auditable forever, never rewritten. DONE when a return mid-fixture
restores the marker's exact state (the subtree-rerun proof
mechanics), the hint provably lands in the resumed work's first
round (the steering trace proof), fossils render grayed with their
full history intact and inspectable, and cost accounting keeps the
fossil's spend visible (money spent is money spent).

## How it fits (pure composition — inspect the three parts first)
Everything exists: checkpoints carry per-cycle state with worktree
heads; the subtree-rerun feature built addressable reset mechanics
with drift refusal and attempt fans; steering delivers bound
operator notes at round starts. Time travel COMPOSES them:
return(marker, hint) = verify + reset to the checkpoint's head
(the rerun machinery generalized from task-refs to checkpoint
refs — one reset implementation, verify which generalizes) →
tasks after the marker fan into a fossil lineage (the attempt-fan
concept lifted to a branch-of-attempts: lineage id per return,
additive on tasks/evidence) → the hint enqueues as a steering
note consumed by the first resumed round. The graph's reducer
gains the lineage dimension: fossil nodes render per the
reference's grayed treatment, collapsed by default behind a
lineage chip.

## Design (suggested shape)
- Markers: checkpoints render on the timeline (the scrubber's
  track — a marker glyph per checkpoint with its cycle summary
  hover); `return` targets a marker via UI (timeline context
  action) or CLI (`remedy job return <id> --to <checkpoint>
  --hint "text"`), through the write channel with the evidence
  triple (outcome: the reset scope; downside: the fossilized
  work's cost).
- Reset: the shared mechanics (drift refusal verbatim); the
  active lineage increments; post-marker tasks copy into the
  fossil record (states frozen), live tasks reset to planned in
  the new lineage.
- Fossils: never deleted, never re-executed; the reducer renders
  them grayed/collapsed with the lineage chip ("attempt 2 of 3
  from checkpoint 4"); reports list lineages with their costs;
  the ledger's rows keep their lineage tag (spend truth).
- The hint: a steering note flagged origin time_travel — the
  trace proof inherited.

## Acceptance
- Marker-state restoration hash-proven; drift refuses with the
  established message. The hint in the first resumed round's
  trace. Fossils immutable (write attempts fail), rendered
  grayed, expandable to full history. Lineage costs sum to the
  ledger total (accounting identity test).

## Edge cases & assumption defaults (A9)
- Returning twice to the same marker: lineages 2 and 3 both
  fossilize their predecessors — the chip counts honestly.
  Returns across a mission's jobs: v1 scopes to one job; the
  dossier notes the return (mission memory), cross-job travel is
  later. Checkpoint retention vs markers: retained checkpoints
  are returnable; pruned ones render as unreturnable markers with
  the retention note (honesty about the window).

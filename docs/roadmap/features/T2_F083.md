# T2_F083 — CI self-check
**Tier 2 · Depends on: F012, F082 · Blocks/used by: repo health**

## Goal & Done
Remedy's own repository gets an honest CI: one local command (`remedy
ci`) and matching hosted workflows run the unit and integration suites
on the fake provider, the determinism suite, the UI build plus its
smoke, and budget checks — with live-provider tests excluded by marker
and said so. DONE when `remedy ci` reproduces the hosted result locally
on a clean checkout, a seeded failure in each stage fails the right
stage with a readable summary, and total runtime stays within a
documented budget.

## How it fits (inspect current shape before building)
The test tree already auto-assigns markers (integration, subprocess,
ui-contract, live-provider, smoke) — CI stages are marker selections,
not new test organization. The run-manifest feature provides the
determinism checks; the benchmark stays OUT of CI (cost) and is linked
as an on-demand step. Inventory the current test runtime by marker
first; the stage split follows the data.

## Design (suggested shape)
- `remedy ci [--stage NAME] [--json]`: stages fast (pure unit),
  standard (integration + subprocess on the fake provider), determinism
  (manifest suite), ui (frontend build + the HTTP smoke against the
  built assets), budgets (a small script asserting documented ceilings:
  wheel size later, test wall-time per stage, no forbidden patterns —
  the existing guard tests run here too). Each stage prints a one-line
  verdict; the summary table is the artifact.
- Hosted workflow files mirror the same stages by calling the same
  entrypoint (one source of truth for what CI means); caching for deps
  only, never for test results.
- Live-provider and bench are explicitly listed as excluded with the
  commands to run them manually — honesty about coverage (P6).
- Flaky policy: a test failing intermittently gets quarantined only via
  an explicit marker change in a reviewed diff — CI never auto-retries
  suites (retries hide rot).

## Task slicing
- **T001** the stage runner + marker selections + summary + tests (each
  stage runs the right subset — asserted via collected-test counts on
  fixtures).
- **T002** determinism + budget stages + the guard-test wiring + seeded
  failure tests per stage.
- **T003** hosted workflow files calling the entrypoint + docs (badge
  optional) + the runtime-budget documentation from measured data.

## Acceptance
- Clean checkout: `remedy ci` green locally and hosted with the same
  stage results. Seeded failures fail their stage only, with the
  summary naming it. No auto-retries anywhere (grep the workflow).
- Excluded suites are listed in the output with their manual commands.

## Edge cases & assumption defaults (A9)
- UI toolchain absent locally: the ui stage reports skipped with the
  install hint locally but is REQUIRED hosted — local convenience,
  hosted rigor, both honest. Wall-time budget breaches warn first for
  one grace period (config), then fail — documented.

## Orchestrator brief
T001 needs the marker inventory as its first deliverable. Keep hosted
workflows thin wrappers — reject workflow logic that isn't in the
entrypoint.

## Do not touch
Test contents, marker semantics, the bench's cost profile, release
packaging (next features). Suggested tests: tests/cli/test_ci_cmd.py.

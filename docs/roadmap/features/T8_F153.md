# T8_F153 — Codex CLI adapter
**Tier 8 · Depends on: F151, F152 · Blocks/used by: F156/F159 comparability**

## Goal & Done
The first foreign builder joins under the contract: a Codex-CLI
adapter builds non-interactive invocations with JSON output, maps
capabilities honestly (schema support via native response-format
where present, else schema-in-prompt with the validation retry;
vision per the CLI's actual state), parses usage into actuals
with raw counters preserved, and maps its stream onto the F004
event vocabulary — with the FIRST task being documented CLI
research (version pinned, ADR) — no guessed flags. DONE when the
adapter passes the full conformance kit including the isolation
A/B, recorded-sample mappings golden (streams, usage, errors),
a real smoke behind a live marker runs one canonical task end to
end, capability declarations match verified reality (the
certification suite will re-audit — declare conservatively), and
the research ADR pins version + flags + isolation mechanism.

## How it fits (the blueprint role — inspect the contract first)
This adapter is the TEMPLATE every vendor adapter copies: research
ADR → capabilities from verified probes → invocation builder →
mappings from recorded samples → conformance + isolation → live
smoke. Recorded samples are the test substrate (capture once
against the pinned version, commit as fixtures — live calls only
in the marked smoke); the error taxonomy mapping matters most for
downstream honesty: which CLI exit/output shapes mean
provider_unavailable vs timeout vs a tool error (the failover and
postmortem features consume exactly this — the mapping table is a
reviewed artifact). Registry: the codex WorkerSpec links via
adapter_ref; routing/certification gate actual use.

## Design (suggested shape)
- `packages/workers/codex_adapter.py`: invocation builder
  (non-interactive mode, JSON/structured output flags per the
  ADR, prompt parts per the contract's canonical shapes, the
  isolation method applied), capabilities() from the ADR's
  verified probes, map_stream (recorded raw → events; buffered
  fallback if the pinned version lacks streaming — declared),
  map_usage (raw counters → actuals; absent usage → the
  unmeasured honesty), the error mapping table.
- Research ADR contents (the template for F154+): tool version
  pinned, install/update guidance, non-interactive + output
  flags verified, schema-response support verdict, vision
  verdict, usage-output shape, isolation mechanism, known
  quirks.
- Config: the adapter's binary path/model selection through the
  standard config keys (registered specs).

## Task slicing
- **T001** the research order (findings + the ADR + recorded
  samples captured against the pinned version) — reviewed before
  code.
- **T002** builder + capabilities + mappings from the samples +
  the error table + conformance-kit pass + isolation A/B.
- **T003** the live smoke (marker-gated: one canonical S-task,
  evidence complete) + registry linkage + docs (install +
  troubleshooting from the research).

## Acceptance
- Conformance + isolation green; mapping goldens exact against
  the committed samples; the error table covers the researched
  shapes with unknowns mapping to the honest unknown class.
  Capabilities conservative (nothing declared unverified). The
  live smoke produces standard evidence (per-call dirs, actuals,
  postmortems on induced failure). ADR complete per the template.

## Edge cases & assumption defaults (A9)
- CLI version drift post-ADR: doctor compares installed vs
  pinned and warns (the certification suite hard-checks); the
  adapter refuses versions below the pinned floor with the
  update hint. Auth/login state: the research documents the
  non-interactive auth expectation; missing auth maps to
  provider_unavailable with the actionable message.

## Orchestrator brief
T001 alone first — no code before the ADR review. The recorded-
sample discipline (live only in the smoke) and the conservative-
declaration rule go verbatim. This file is the blueprint; keep
its structure clean for F154 to mirror.

## Do not touch
Loop transport, retry policy, routing gates (certification
rules use). Suggested tests: tests/workers/test_codex_adapter.py.

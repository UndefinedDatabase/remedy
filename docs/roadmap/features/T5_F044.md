## Goal & Done
Power and discipline in one feature: Cmd+K opens a palette over the
command catalog plus fuzzy node jump (the omni-bar in ux_design.png
— "Ask your agent or jump to anything" — is this palette fused with
the chat entry), j/k/Enter/Esc navigate the graph, and CI enforces
the performance budgets: first paint < 1.5 s, 60 fps at 200 nodes
(trace-metric measured), and a bundle size cap. DONE when the
palette executes exposed commands and jumps with correct scoping,
keyboard navigation covers the documented map, all three budgets
run red/green in CI with recorded numbers, and budget breaches name
their regression source (the bundle report, the trace).

## How it fits (inspect current shape before building)
The palette is a THIN composition: command entries come from the
channel's exposed catalog (schemas drive argument prompts — a
command needing a task id asks via the same fuzzy node search),
node jump reads the reducer's model (fuzzy over id/title/kind),
project switch and '?'/chat entries register too (the omni-bar
routes: text starting like a question → chat; otherwise palette
semantics — the routing rule documented and tested). Keyboard: a
single keymap module (the zoom machine's Esc chain already exists
— extend, don't fork), scoped so inputs never lose their keys.
Budgets: the tooling per frontend conventions (trace-based fps
metric on the 200-node fixture, size-limit-style bundle cap, a
first-paint measurement on the built shell) wired as CI stages
(the ci feature's ui stage grows them).

## Design (suggested shape)
- Palette per the reference (the omni-bar's visual is the spec):
  sections (Commands | Jump | Projects | Help), fuzzy with
  highlighted matches, argument flow from schemas, recent items;
  execution through the channel (audited like any client).
- The question-vs-command routing rule: leading verbs from the
  catalog → command; otherwise → chat with the text prefilled
  (one bar, two brains, honest split — the rule's tests include
  ambiguous fixtures with the documented tie-break).
- Keymap: j/k sibling walk, Enter = zoom-in/select, Esc = the
  zoom walkback, g then p = projects, ? = catalog panel, / or
  Cmd+K = the bar; a keymap cheat overlay on '?' hold (per
  reference).
- Budgets in CI: numbers recorded per run (trend visible), breach
  output names the biggest deltas (bundle: the size report diff;
  fps: the slowest trace spans).

**T001 — the command palette.** The palette's logic is a set of pure
TypeScript modules under `apps/ui/src/api/`: `fuzzyMatch.ts` (a
contiguous-substring hit outscores a word-start hit outscores a
scattered subsequence hit), `paletteCommands.ts` (`PALETTE_COMMANDS`,
one entry per command of `UI_EXPOSED_COMMANDS` in
`apps/cli/command_catalog.py`, held equal to it by
`tests/ui_contracts/test_palette_contract.py`), `paletteCommandState.ts`
(the first-reason-wins refusal rule: no write token, then a form entry,
then the job's own ended state, then the command's own state),
`paletteArgs.ts` (one argument at a time, a `"task"` kind answered by a
Jump row and a `"text"` kind answered by Enter), `paletteJump.ts`
(fuzzy-ranked node jump, capped at eight results), `paletteRouting.ts`
(`routeBarText`, mirroring `parse_chat_intent` in
`packages/orchestration/chat_intent.py`: a question routes to chat, a
leading verb from `BAR_LEADING_VERBS` routes to its command, a note
opener routes to `job.steer` or `chat.send`, everything else opens the
palette), `paletteSend.ts` (execution through the same `sendChatCard`
the chat's own cards use) and `paletteSheet.ts` (the Recent/Jump/
Projects/Help sections, up to five remembered refs under
`remedy:palette-recent`). `apps/ui/src/components/command/CommandBar.tsx`
mounts the combobox in `RemedyShell.tsx`; `PaletteSheet.tsx` is the
portalled listbox; `ChatSheet.tsx` (D4) wraps the existing
`EvidenceChatTab` for a routed question, asked about the focused task or,
with none focused, the whole project. The shell's old substring-match
`handleJump` is deleted (D2). Seven form-entry commands (six plan edits
plus hunk approval) are listed but stay disabled — no write token — until
F292, registered at D5, lands their server-side routes.

**T002 — the one keymap and its cheat overlay.** `apps/ui/src/api/keymap.ts`
is the single shared, DOM-free keymap: `KEYMAP_BINDINGS` (seven rows,
`/`or `Ctrl+K`, `?`, `g` then `p`, `j`, `k`, `Enter`, `Esc`) and the pure
`keymapAction(press, target, pendingG, dialogOpen)`, which never takes a
key from a text field — `isTypingTarget` excuses every binding except
the `Ctrl`/`Cmd`+`K` chord (D5). The graph's own keys are unified into it:
`apps/ui/src/components/graph/zoomKeys.ts` turns a `KeymapAction` into a
zoom step (the sibling walk, the same click a pointer would make),
`useZoomKeys.ts` is the graph's one keydown listener, and
`useSemanticZoom.ts` now owns no listener of its own — the old
`escapeWalksBack` is deleted (D6). `RemedyShell.tsx` carries the one
shell-level listener, routing `open-terms`/`open-bar`/`go-projects`.
The held-key overlay: `useHeldHelpKey.ts` starts a `KEYMAP_HOLD_MS`
(400 ms) timer on a `?` press; released early it still opens the Terms
panel (F043), held past the timer it opens `KeymapOverlay.tsx`, listing
`KEYMAP_BINDINGS` verbatim in a `role="dialog"` (D6).

**T003 — the three CI budgets.** `packages/orchestration/ci_budgets.py`
gained, over three rounds, `check_bundle_size` (a built `apps/ui`'s total

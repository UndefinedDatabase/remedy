# T1_F062 — Product smoke as the closing gate
**Tier 1 · Depends on: F061, F007 · Blocks/used by: M2 credibility**

## Goal & Done
Green tests can still mean a broken product — the smoke closes that gap:
for jobs touching a runnable app, a standard DoD block proves the app
STARTS, its core paths RESPOND, and the console/log stream is free of
errors, before the job may end green. DONE when a fixture app with green
unit tests but a broken startup keeps its job open, and the smoke's
findings read concretely ("start failed: <probe reason>"), not vaguely.

## How it fits (inspect current shape before building)
The runtime harness already knows how to start a project's dev server,
probe it, capture its logs, and stop it cleanly — the smoke is a DoD
block ORCHESTRATING those existing verbs. The DoD compiler registers
standard blocks; this feature contributes one. Which projects get the
block: those with a configured/detected runtime — no runtime, no smoke,
reported as "smoke: not applicable (no runtime configured)" — honest, not
silently green (P6).

## Design (suggested shape)
- The smoke block compiles into three ordered checks (all blocking by
  default, config can relax):
  1. app_starts — harness start + readiness probe within the configured
     window; teardown always runs.
  2. core_paths_respond — probe a small set of paths: the configured
     health path plus paths the DoD compiler extracted from intent/plan
     (e.g. "/", the feature's route); expectation = status ok and,
     where declared, a content marker. v1 is HTTP-level, deliberately —
     clickable-browser flows stay in the DoD's runtime_flow kind and
     deepen later; do not pull a browser dependency in here.
  3. clean_console — the harness's captured process output scanned for
     error markers (a small documented pattern list: tracebacks,
     "ERROR", framework-specific fatals); any hit fails with the matched
     lines quoted.
- Evidence per check under the job area: probe results, matched log
  lines, timings. The report matrix shows the three rows like any DoD
  check.
- Config: smoke table — enabled (default true where a runtime exists),
  path list override, error-pattern additions, readiness window.

## Task slicing
- **T001** the block registration + app_starts + not-applicable path +
  fixture app (starts) and broken-start fixture (job held open, concrete
  reason).
- **T002** core_paths_respond + path extraction hand-off from the DoD
  compiler + fixtures (ok, wrong status, missing marker).
- **T003** clean_console + the pattern list + a fixture logging an error
  → red with quoted lines; teardown-always test (no zombie processes even
  on red).

## Acceptance
- Broken-startup fixture: unit tests green, job blocked, report says
  which check failed and why. All-green fixture passes all three rows.
- Teardown runs on every outcome (process table asserted). Non-runtime
  project: block reports not-applicable and does not gate.

## Edge cases & assumption defaults (A9)
- Flaky startup: one retry of app_starts after a short backoff, recorded
  as "passed on retry" (visible risk). Ports in use: the harness's
  existing conflict behavior is reused, and the smoke reports it as a
  start failure with that reason. Error patterns are case-sensitive and
  documented — extending them is config, not code.

## Orchestrator brief
Gate on the DoD compiler's schema (T001 there). Three small sequential
orders; require fixtures as real mini-apps in the test tree, not mocks of
the harness. Reject any diff introducing a browser dependency.

## Do not touch
Browser automation, visual comparison, the harness's process semantics.
Suggested tests: tests/orchestration/test_product_smoke.py.

## Built State (accepted 2026-08-01, R1–R3)

Built and reviewed on branch feature/f062-product-smoke:

- **The product-smoke standard block**
  (packages/orchestration/product_smoke.py): registers explicitly
  (never an import side effect) into the F061 standard-check seam;
  contributes three ORDERED blocking checks where a runtime resolves
  — app_starts, core_paths_respond, clean_console. No runtime → ONE
  non-blocking row "smoke: not applicable (no runtime configured):
  <harness reason>". smoke.enabled=false → ONE non-blocking
  "disabled by config" row, and the runner refuses at run time
  BEFORE any process starts (R-0167).
- **app_starts**: harness start + readiness probe via the shared
  _run_app_once cycle (choose_port, own session, _wait_ready,
  stop_process_tree in a finally — teardown on every outcome); one
  retry after 1.0s backoff, a retried pass is labeled "passed on
  retry"; port conflicts and early exits carry the harness's own
  reason ("start failed: …").
- **core_paths_respond**: probes the configured health path first,
  plus up to 5 routes the compiler extracts from intent/plan text
  (conservative: filesystem- and file-shaped tokens are not routes);
  an undeclared expectation means the OK-status rule; declared
  expect_status/expect_text are validated per entry at compile time
  (closed key set, index-named refusals). Path failures never retry.
- **clean_console**: the captured app output scanned against a small
  documented CASE-SENSITIVE base list (traceback header, ERROR,
  CRITICAL, FATAL, Unhandled exception, panic:, Segmentation fault);
  config smoke.error_patterns only ADDS; a red quotes the matched
  lines (bounded at 20). Judged before any pass; never retried.
- **Config table**: smoke.enabled / smoke.paths (REPLACES extracted
  routes, health path stays first) / smoke.error_patterns (adds
  only) / smoke.ready_timeout_s — in config.py with env vars.
- **Schema**: product_smoke kind in dod_v1 (closed spec keys
  smoke/retry/paths; SMOKE_CHECK_NAMES closed vocabulary); runner in
  RUNNER_REGISTRY; the kind-set pin covers six kinds.
- **Proof**: tests/orchestration/test_product_smoke.py (76) with
  four REAL mini-app fixtures (good, broken-start, paths, noisy);
  the broken-start fixture's unit tests are green while its job is
  HELD OPEN — the feature's acceptance criterion. R2 integration
  gate: branch 14969/19 vs base 14900/19, both exit 0, comm empty.

Honest boundary: the smoke gates jobs through the F061 DoD seam;
compile_dod still has NO production caller (F069/F070 wire it). The
block, runners, gate rows and config are proven by the suite, not
yet driven by a production job.

# T14_F216 — Docs site generator
**Tier 14 · Depends on: the cleaned docs/ structure, F086 · Blocks/used by: support relief; M14; marketing**

## Goal & Done
See ROADMAP.md F216; the Done criterion there is binding.

## Context (existing code & prior features)
docs/ is index-led (docs/README.md) with link-checker discipline; no site exists.

## Design
Generator choice by ADR (candidates: mkdocs-material, mdbook - criteria: offline search, versioning, no node requirement). `remedy docs build` (also CI): docs/ -> a static site; the navigation source is the docs/README.md structure (a parser, not double upkeep); roadmap/ pages get an automatic 'FUTURE - not implemented' banner; versioning per release (mike or equivalent). The cleanup's dead-link checker becomes a build gate.

## Task slicing
T001 the ADR + the skeleton + the README parser as the nav source + the build gate. T002 versioning + the roadmap banner + a CI publish artifact (the deploy target stays the operator's choice).

## Acceptance & tests
The site builds deterministically from the repo; nav == the README structure (reconciliation test); a dead link fails the build; roadmap pages are bannered.

## Risks / anti-goals
No second docs source (the site is a pure derivation); no CMS.

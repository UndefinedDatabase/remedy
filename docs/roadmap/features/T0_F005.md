# T0_F005 — Strukturierte Outputs erzwingen (JSON-Schema)
**Tier 0 · Abhängigkeiten: keine · Blockiert: F014 (Plan-Format), F022? nein — F069, F089**

## Ziel & Done
Planner-/Reviewer-Antworten werden per `--json-schema` erzwungen; Format-Parse-Fehler
und deren Repair-Runden verschwinden. Done: 0 Parse-Fehler in 10 Runs.

## IST-Bezug
- `reviewer.py`, `llm_planner.py` parsen heute Freitext mit Fallbacks; Formatfehler
  erzeugen Repair-Runden (Token-Verschwendung, Fehlerklasse `parse` in F010).

## Design
Neues Paket `packages/orchestration/schemas/`:
- `review_verdict.py`, `plan_output.py`, `design_spec.py` (für F089 vorbereitet) als
  Pydantic-Modelle; `to_json_schema()`-Export; Versionsfeld `schema_v`.
- Provider-Aufruf: `claude -p … --json-schema <(schema)`; Antwort → Pydantic-Validate.
- Validierungsfehler = Fehlerklasse `parse` (F010), max 1 Retry mit Fehlerhinweis.

## Task-Schnitt
- T001: schemas/-Paket + Golden-Schemata + Tests.
- T002: reviewer.py auf Schema-Pfad; Alt-Parser als Fallback hinter Flag.
- T003: llm_planner.py auf Schema-Pfad; Fallback-Entfernung nach 5 grünen Runs.

## Akzeptanz & Tests
- Property-Test: jedes valide Modell round-trippt; invalide Antwort → 1 Retry → Fehlerklasse.
- Prompt-Trace zeigt schema_v je Call.

## Risiken / Anti-Ziele
- Schemata klein halten (Token!); keine „Mega-Schemas". Keine neuen Taxonomien (A6).

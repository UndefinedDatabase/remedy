# T17_F247 — Community import with provenance
**Tier 17 · Depends on: F165, F184, F117/F145 · Blocks/used by: network effects without losing trust**

## Goal & Done
See ROADMAP.md F247; the Done criterion there is binding.

## Context (existing code & prior features)
Cards/playbooks/templates are project/org-local (F211); foreign bundles do not exist. F184 curation and the proposed status are the intake lock.

## Design
A bundle format remedy-bundle.tar {manifest (publisher, contents: cards[]/playbooks[]/templates[], hashes), a signature (F165)}. `remedy import <bundle>`: signature + hash verify -> contents land WITHOUT EXCEPTION as proposed with origin={kind:community, publisher, bundle_hash} in the curation queue (F184); a sandbox review view previews every item BEFORE approve (card bodies, playbook text, template file trees). An optional trusted-publisher list ([import] trusted_publishers) shortens NOTHING about the approval - it only shows a badge. `remedy bundle create` is the sharing counterpart (with an F249 redaction pass).

## Task slicing
T001 the format + verify + the proposed import + tests (valid/tampered/unsigned). T002 the review view + origin badges + bundle create.

## Acceptance & tests
A tampered bundle fails signature checks before any write; an imported card is provably never active/attached without approve (a property over the F118 selector); bundle create passes the redaction corpus.

## Risks / anti-goals
No central marketplace server in v1 (bundles are files; distribution belongs to the community); templates from bundles are fully displayed before any init use (no blind scaffolding).

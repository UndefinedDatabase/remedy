# T0_F010 — Automatic failure post-mortems
**Tier 0 · Depends on: none · Blocks/used by: F052, F073, F144, honest stats**

## Goal & Done
Every failed provider call, task, or run leaves a machine-readable
`postmortem.json` with a deterministic failure class, and `remedy stats
failures` aggregates them. DONE when all failure paths emit exactly one
postmortem per final failure, the classifier is a pure function (same input
→ same class), aggregation works on a fixture corpus, and the default path
makes zero LLM calls.

## How it fits (inspect current shape before building)
The raw failure signals already exist inside the provider ping-pong loop:
an error-class field for parse/config failures, retry-reason evidence from
the adaptive-timeout feature, terminal loop outcomes (provider unavailable,
tests failed, review failed), and one evidence directory per provider call.
The worktree layer raises typed conflict/lock errors; the runtime harness
reports probe failures. The event ledger is file/JSON based — do NOT
introduce a database here (a SQLite ledger arrives much later as its own
feature). Postmortems are written into the per-call evidence directories
that already exist; find the exact field names and the retry/timeout
predicate in the current code and reuse them instead of re-deriving.

## Design (suggested shape — follow existing conventions where they differ)
A new orchestration module `failure_postmortem.py`:
- `FailureClass` str-enum: provider_timeout, provider_unavailable,
  provider_nonzero_exit, parse, config, test_failed, review_failed,
  worktree_conflict, worktree_lock, runtime_probe_failed, stopped (reserved
  for the kill switch), budget_exhausted (reserved for budgets), unknown.
  The enum is extensible; later features add members instead of new enums.
- `PostmortemV1` record: postmortem_v=1, failure_class, job/task ids,
  which signal produced the class (signal_source), a truncated raw reason,
  retry evidence carried over, UTC timestamp, and relative evidence_refs
  into the call directory. Written atomically.
- `classify(...)` pure, with a documented precedence: typed exception >
  terminal loop signal > error-class field > retry reasons > unknown. The
  timeout predicate must be THE one the retry policy already uses — import
  or extract it, never copy the string match.
- Wiring: wherever a call/round is abandoned as failed, classify + write
  into that call's directory. Where a task fails terminally, write a
  task-level rollup under the job's evidence export area referencing the
  call-level files. Retried-then-recovered calls get NO postmortem.
- CLI `remedy stats failures [--since] [--job] [--json]`: histogram by
  class + top reasons; registered like the existing stats-style commands.
- Config key `postmortem.llm_summary`, default false — v1 stays fully
  deterministic (P6: no generated prose posing as analysis).

## Task slicing
- **T001** classifier + record + writer + shared timeout predicate;
  table-driven tests covering every class; unknown is returned, never
  raised.
- **T002** wiring at the failure exits + task rollup; integration test
  forcing timeout exhaustion asserts exactly one postmortem with correct
  class and evidence refs; recovered-retry negative test.
- **T003** CLI + fixture corpus + stable `--json`; empty corpus prints an
  honest "no failures recorded", not an error.

## Acceptance
- One forced failure per source (timeout, missing provider binary, invalid
  JSON against a schema, worktree lock, dead runtime probe) → correct class.
- Aggregation over the fixture corpus yields exact expected counts.
- No new dependencies, no database, no LLM call under default config.
- Runs predating this feature: stats prints a coverage line
  ("N scanned, M without postmortems") instead of failing silently.

## Edge cases & assumption defaults (A9)
- Contradictory inputs to classify → precedence order wins; signal_source
  records which. Multiple failures in one round → one postmortem per failed
  call plus one rollup. Read-only evidence dir → raise clearly, never drop.

## Orchestrator brief
Before dispatching T002, have the worker report back the actual names of
the loop's error/outcome fields and the retry predicate location; adjust
prompts to those names. Slice as listed; T001 is pure-unit and safe to run
first and in parallel with nothing.

## Do not touch
Retry POLICY (owned by the timeout feature), evidence layout, run states,
ledger schema. Suggested tests: tests/orchestration/test_failure_postmortem.py,
tests/cli/test_failure_cmd.py.

# T0_F010 — Automatisches Fehlerklassen-Postmortem
**Tier 0 · Abhängigkeiten: keine · Blockiert: F008? nein — F052, F073, F081-Smoke, F144**

## Ziel & Done
Jeder gescheiterte Run schreibt failure_postmortem.json (Klassen: timeout | parse |
review_reject | infra | budget | fence | unknown) und `remedy stats failures` aggregiert.
Done: Retry-Kaskaden als Klassen zählbar.

## IST-Bezug
- Fehlschläge landen heute verstreut in Logs/Reports; keine Klassifikation.

## Design
- `packages/orchestration/failure_postmortem.py`: Klassifikator regelbasiert
  (Exitcodes, Marker aus F001/F005/F104/F017-Fences); LLM wird NICHT gefragt (deterministisch).
  Datei je Fehlfall: `task_runs/Txxx/failure_postmortem.json`
  `{class, signal, retryable:bool, advice_key}` + advice-Katalog (ui_copy).
- Aggregation in `~/.remedy/projects/<pid>/ledger.sqlite` Tabelle `failures`
  (Grundlage F103-Ledger-Design mitnutzen). CLI: `remedy stats failures --since 30d`.

## Task-Schnitt
- T001: Klassifikator + Schreiben + Tests (jede Klasse ein Fixture).
- T002: sqlite-Aggregation + CLI + Tests.

## Akzeptanz & Tests
- Simulierte Fälle je Klasse → korrekte Klasse; unknown < 10 % im Benchmark (F082 später).

## Risiken / Anti-Ziele
- Keine neue Evidence-Pflicht (A6): postmortem ist Zusatzartefakt, kein Gate.

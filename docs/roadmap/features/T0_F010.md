# T0_F010 — Automatic failure post-mortems
**Tier 0 · Depends on: none · Blocks/used by: F052, F073, F144, honest stats**

## Goal & Done
See ROADMAP.md F010; the Done criterion there is binding.

## Context (existing code & prior features)
Failures land scattered across logs/reports without classification.

## Design
`failure_postmortem.py`: rule-based classifier (exit codes, markers from F001/F005/fences) - deterministic, no LLM. Per failure: task_runs/Txxx/failure_postmortem.json {class, signal, retryable, advice_key} + an advice catalog. Aggregation into ledger.sqlite table failures; CLI `remedy stats failures --since`.

## Task slicing
T001 classifier + writer + one fixture per class. T002 sqlite aggregation + CLI + tests.

## Acceptance & tests
Each simulated class classifies correctly; unknown stays <10% on the benchmark.

## Risks / anti-goals
Post-mortems are extra artifacts, never a new gate (A6).

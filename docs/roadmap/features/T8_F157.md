# T8_F157 — Capability matrix & honest degradation
**Tier 8 · Depends on: F151 · Blocks/used by: every worker-dependent feature; law P5**

## Goal & Done
See ROADMAP.md F157; the Done criterion there is binding.

## Context (existing code & prior features)
Implicit assumptions are scattered (F005 expects json_schema, F088 vision, F106 resume, F004 streaming) - nowhere central.

## Design
packages/workers/capability_matrix.py: a declarative register FEATURE_REQUIREMENTS = {F005:[json_schema], F088:[vision], F106:[session_resume], F004:[streaming], ...} + one registered degradation handler per entry (e.g. F005 without json_schema -> schema-in-prompt + validation retry; F088 without vision -> style block only, noted). One central check require_or_degrade(feature, adapter) at each usage site; the evidence field degraded:[...] per run; a UI badge on the job while degradation is active.

## Task slicing
T001 register + require_or_degrade + handlers for the four core capabilities + per-path tests (LARGE, A3: touches the F004/F005/F088/F106 sites). T002 UI badge + report line.

## Acceptance & tests
A completeness test: every register entry has handler+test; a run with a fully-castrated fake adapter ends green-degraded with complete notes instead of crashing.

## Risks / anti-goals
Degradation is visible or it does not exist (P6); no capability checks outside the central point (lint rule).

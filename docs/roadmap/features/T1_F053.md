# T1_F053 — Final & interim report
**Tier 1 · Depends on: F046, F003 · Blocks/used by: F040, F060, human oversight of self-build**

## Goal & Done
Every run produces ONE human-readable account: what was attempted, what
succeeded, what is blocked and why, what it cost, what needs answering,
and the single recommended next action. DONE when the final report renders
automatically at job end, `remedy job report <id> --interim` renders a
clearly labeled snapshot of a still-running job, and every number in the
report names its basis (P6).

## How it fits (inspect current shape before building)
All inputs exist as structured data: job/task states, cycle summaries,
postmortems, open decisions, token actuals, the assumption log, the plan
rendering, and the run manifest. The report is a pure RENDERER over those
sources — it computes nothing new and never guesses; a missing source
renders as "not recorded", not as a made-up value.

## Design (suggested shape)
Module `run_report.py`:
- `render_report(job, mode=final|interim) -> str` (markdown, deterministic
  ordering): header (job, project, mission, state, duration); per-task
  results with one-line outcomes and links (relative paths) into evidence;
  blocked items with their postmortem class and, for decisions, the exact
  answer command; costs from actuals with the unmeasured notation carried
  over verbatim; healed-cycles and normalization notes surfaced (risk
  visibility); open assumptions; and exactly one "Recommended next action"
  line chosen by a small documented rule table (open decisions → answer;
  blocked-failed → inspect postmortem; all green → review/merge branch).
- Final mode writes automatically to the job's evidence area at every
  terminal state (green, stopped, blocked, budget) — one writer, called
  from the terminal-state persistence path.
- Interim mode renders the same structure from live state, headed by a
  loud "INTERIM SNAPSHOT — run still in progress (rendered at <ts>)".
- CLI on the job command group; `--json` emits the underlying structure
  for future UI use.
- Milestone distance: "N features remain to <next milestone>" computed
  from the STATUS mirror — never hand-maintained.
- Momentum flag, mechanically defined: forward = each round closes items
  and nothing previously fixed recurs; circling = the same finding class
  recurs across ≥2 rounds OR open findings do not decrease over a round.
  Circling renders as an explicit warning with a proposed escalation
  (smaller slices, re-plan, or human decision) — never silently absorbed.
- Capability lines ("can now / can next"): "can now" may cite ONLY
  accepted ([x]) state; in-progress work always renders as "in progress".
  (P1 applied to progress reporting.)

## Task slicing
- **T001** renderer + the next-action rule table + golden final reports
  for three fixture terminals (green, blocked-with-decision, budget).
- **T002** terminal-state hook (every terminal path writes exactly one
  report) + interim mode against a running fake job + CLI + tests.

## Acceptance
- Three golden reports match; every cost line carries a basis; a job with
  missing actuals renders "not recorded" (negative test against invented
  numbers).
- Exactly one report file per terminal job, regenerated (not appended) on
  resume-then-finish.
- Interim label test; interim never mutates state.

## Edge cases & assumption defaults (A9)
- Enormous jobs: per-task lines cap at a readable count with a "and N
  more (see evidence)" line — the report is a summary, evidence is the
  archive. Reports are English (repo language) regardless of mission
  language; mission text is quoted as-is.

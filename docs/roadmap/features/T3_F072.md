# T3_F072 — Spec-first (living specification)
**Tier 3 · Depends on: F014, F061 · Blocks/used by: drift protection**

## Goal & Done
Scope creep announces itself: every job/mission maintains a generated
SPEC document (from intake, plan and DoD), and after each task a
three-way drift check — spec vs tests vs code — raises FINDINGS when
they disagree: DoD red, touched paths outside the declared scope, new
public exports without a spec paragraph. Drift is reported, never
auto-fixed. DONE when each drift class fires on its fixture, the spec
regenerates deterministically from its sources, and a clean run stays
finding-free end to end.

## How it fits (inspect current shape before building)
The spec is a RENDERING, not a new source of truth: goal and
constraints come from the order, scope and tasks from the job plan,
verifiable behavior from the contract (DECISION amend0905-vocab D9,
2026-09-05; F269 builds it — the contract is the source this spec
renders and F072 is NOT absorbed into F269; the DoD is the contract's
compiled form) — regenerated whenever those change
(the plan.md/report renderer discipline: pure, deterministic,
golden-tested). The drift checks reuse existing signals: the DoD
matrix, the fence/files_hint closure versus the applicator's actual
touched paths (already in evidence), and the context compiler's
export-signature extraction for the new-exports check (reuse the
extractor — one parser home).

## Design (suggested shape)
- `spec_sync.py`: render_spec(job) → SPEC.md in the job's evidence
  area with fixed sections (Intent, Scope: in/out paths, Behavior:
  the DoD checks in prose-plus-id form, Assumptions: from the
  assumption log) — every section traceable to its source artifact by
  reference.
- Drift check, run at task finalization and at terminals:
  1. behavior drift — blocking DoD rows red after a task claiming
     completion of their acceptance source;
  2. scope drift — applicator-touched paths outside the declared
     closure (fences already BLOCK hard violations; this catches the
     soft case: allowed by fences but undeclared by the plan —
     finding, not violation);
  3. surface drift — new exported symbols (extractor diff against
     the task-start snapshot) with no matching Behavior/Intent
     reference in the spec.
- Findings are report items with the evidence (paths, symbols, check
  ids) and a suggested next action (extend the spec via replan, or
  revert the surprise) — suggestions only (P2).
- Missions: the milestone spec aggregates its jobs' specs; the
  orchestrator's evaluation reads drift findings as first-class
  signals (a drifting job is not "done" even if green — note for the
  loop's evaluator, wired here).

## Task slicing
- **T001** the renderer + traceability references + goldens +
  regeneration determinism.
- **T002** the three drift checks as pure functions over evidence +
  table tests per class (fires/clean).
- **T003** wiring at finalization/terminals + report items + the
  loop-evaluator signal + a clean-run end-to-end (zero findings) and
  a seeded-drift end-to-end per class.

## Acceptance
- Each drift class fixture raises exactly its finding with correct
  evidence; the clean fixture raises none. Spec regenerates
  byte-identically from unchanged sources. Nothing is ever modified
  by the checker (state diff). The loop treats a drift finding as
  not-done (evaluator test).

## Edge cases & assumption defaults (A9)
- Generated/vendored paths: the shared ignore notion applies to
  surface drift. Legitimate emergent work (the builder had to touch
  an extra file): the finding is the FEATURE — the human or
  orchestrator decides replan vs revert; the checker never judges
  intent.

## Orchestrator brief
T001/T002 parallel (both pure), T003 wires. The reuse map (DoD
matrix, touched-paths evidence, export extractor) is the first
deliverable — reject re-implementations of any of the three.

## Do not touch
Auto-fixing, plan mutation, fence semantics, the extractor's parsing.
Suggested tests: tests/orchestration/test_spec_sync.py.

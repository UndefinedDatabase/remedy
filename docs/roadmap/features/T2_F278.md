## Goal & Done
One durable write in this repository, used everywhere, and no artifact that is
silently incomplete.

DONE when the Acceptance list holds.

## Why this exists
Measured at `a5bf8949` over `packages/` and `apps/`:

- 26 definitions of a private atomic-write helper across 24 modules, in seven
  signatures: 21 `_atomic_write`, 2 `_atomic_private_write`, and one each of
  `_atomic_write_job`, `atomic_write_bytes`, `atomic_write_text`,
  `write_file_atomically`, `publish_atomically` and `publish_dir_atomically`.
- 31 `os.replace(tmp…)` sites, against 14 `fsync` lines in total. Most writes never
  fsync the file, and NONE fsyncs the parent directory — so the rename can be lost on
  power loss while the data itself was safe.
- 30 modules derive the temporary path as a FIXED sibling of the destination — 4 via
  `with_suffix(".tmp")`, the rest by string concatenation — so two writers of one
  record race on one temporary path and can publish a torn file. Only five modules
  use `tempfile.mkstemp`, and only `storage.py`, `proposed_tasks.py` and
  `project_registry.py` place it in the destination directory.

The 2026-09-08 orchestrator counted 16 of the 26 helper copies inside the prototype
cluster F275 deletes; that split is re-derived against the deletion set as it stands
when this feature is claimed, never carried forward from this paragraph. The
survivors it named include `storage.py`, `token_economy.py`, `real_test_execution.py`,
`repair_request_builder.py`, `proposed_tasks.py`, `provider_patch_material.py` and
`packages/runtimes/dev_server.py`.

Separately: 312 `except …: pass` handlers under `packages/` and `apps/`, 9 of them in
`packages/orchestration/stream_evidence.py`, the F004 raw-stream evidence writer. An
artifact that is silently incomplete is indistinguishable from a complete one, which
is against P1 (evidence over claims) and P6 (honest labels).

## Design
One helper, one import per call site, one lint rule holding the line. The helper lands
first and completely, because every later slice is a migration onto it.

## T001 — `packages/common/secure_fs.py`
`durable_write(path, data, *, mode=0o600, fsync_dir=True)` and `durable_write_json`:
`mkstemp` in the DESTINATION directory, write, fsync the file descriptor,
`os.replace`, fsync the parent directory descriptor, and unlink the temporary file on
every failure path.

Tests: `os.fsync` patched and asserted for the file AND the directory; 8 threads
writing one path leave exactly one of the 8 payloads and no `.tmp` residue — which
reddens against the fixed-sibling form, and is the red proof for the race;
`durable_write(Path("a.b.json"))` keeps the temporary file a sibling rather than
colliding with the multi-suffix name.

## T002 — The migration, which is a deletion
Every surviving private helper is replaced by an import and DELETED — AGENTS.md,
"Replacing is deleting" — one module per commit, with each call site's return-type
contract kept. An AST guard test then forbids a function named
`_?atomic_(private_)?write` anywhere outside `packages/common/`.

## T003 — Loud failures
`ruff` rule BLE001 is enabled with its initial ignore list frozen at the measured
sites, so the count can only fall. The nine handlers in `stream_evidence.py` go
first, and the stream artifact gains a `degradations` field naming the step that
failed. Every remaining ignored site carries a `# noqa: BLE001 — <reason>` in the
`run_report.py` style, asserted by a test. The ignore list only ever shrinks.

## Acceptance
- `durable_write` fsyncs the file and the parent directory; a test asserts both by
  patching `os.fsync` (red proof: removing either fsync reddens it).
- 8 concurrent writers of one path leave exactly one intact payload and no residue.
- No function matching `_?atomic_(private_)?write` is defined outside
  `packages/common/`; adding one reddens the guard (red proof).
- Every surviving call site imports the shared helper; no private copy remains in the
  tree, and each deletion is in its own commit.
- BLE001 is enabled; the ignore list is frozen at its measured size, every entry
  carries a reason, and a test asserts both.
- A `stream_evidence` write that fails records the failing step in `degradations`;
  the artifact never claims completeness it does not have.

## Do not touch
`storage.py`'s existing `mkstemp` placement, which is already correct and is the
pattern the helper generalises. The stream artifact's existing fields. The BLE001
ignore list's size upward — it is a ratchet in one direction only.

## Orchestrator brief
T001 alone in its round, with both red proofs, because everything after it is a
migration onto a helper that has to be right first. T002 only AFTER F275's deletion
has landed, or the migration touches modules that are about to disappear; re-derive
the survivor list at that point rather than trusting the count above. T003 is
independent of both and may be taken in parallel by a later round.

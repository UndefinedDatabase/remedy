# T1_F052 — Self-healing test rounds
**Tier 1 · Depends on: F046, F003 session ids · Blocks/used by: cycle robustness**

## Goal & Done
Trivial test breakage no longer kills unattended cycles: when a cycle's
verify step fails, up to two bounded auto-repair rounds run REUSING the
existing repair loop, and only then does the cycle fail with a classified
postmortem. DONE when a fixture with a trivially broken test heals in one
round, a stubborn break stops after exactly two rounds with an honest
trail, and repair costs are attributed to the job's budget.

## How it fits (inspect current shape before building)
A repair loop already exists in the ping-pong machinery (bounded repair
rounds with their own evidence); this feature TRIGGERS it from the cycle
verify step with the test-output digest as findings — it must not build a
second repair mechanism (A6). Budgets already count repair calls; the
postmortem classifier already has a test-failure class. Inspect how the
repair loop receives findings today and feed it the same way.

## Design (suggested shape)
- After a cycle's verify fails: build a findings payload from the test
  output (failing test ids, tail of the failure text, changed files of
  this cycle as hint), invoke the existing repair path capped at a config
  key (cycles.repair_rounds, default 2), re-run verify after each round.
- Healed → the cycle completes normally, cycle evidence records
  "healed after N repair rounds" (visible in reports — silent healing
  hides risk).
- Not healed → cycle fails with the existing test-failure classification;
  the postmortem references the repair-round evidence.
- Safety: repair rounds respect fences, budgets, and stop requests exactly
  like any other provider work (they flow through the same safe points —
  assert, don't assume).

## Task slicing
- **T001** the verify→findings→repair trigger + round cap + healed path;
  fixture: a one-line assertion break heals in round one.
- **T002** the stubborn path (fixture whose break the fake provider never
  fixes) → exactly two rounds, then classified failure; budget attribution
  asserted via actuals; stop request during repair honored.

## Acceptance
- Healed fixture: cycle green, evidence line present, one repair round
  counted in actuals.
- Stubborn fixture: exactly two rounds (not one, not three), classified
  postmortem, repair evidence linked.
- A stop request between repair rounds stops cleanly (safe-point test).

## Edge cases & assumption defaults (A9)
- Verify failing for non-test reasons (command missing, config) →
  classified config/unknown, NO repair rounds (repairing a broken harness
  wastes money). Flaky tests: a heal that changed no files is suspicious —
  record "healed without changes (flaky?)" so humans see it; detection
  beyond that is a later quality feature.

## Orchestrator brief
Small feature, one worker. Before T001, have the worker report how the
existing repair loop accepts findings and cap configuration; reject any
diff that adds a new repair entry point.

## Do not touch
The repair loop's internals, flaky-test quarantine, review policies.
Suggested tests: tests/orchestration/test_self_healing_cycles.py.

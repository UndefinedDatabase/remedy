# T15_F229 — Adaptive task-size recommendation
**Tier 15 · Depends on: F144, F074, F016 · Blocks/used by: planner quality from own experience**

## Goal & Done
See ROADMAP.md F229; the Done criterion there is binding.

## Context (existing code & prior features)
The F144 ladder knows success per size; F016 slices by static rules with a ladder-bias stub.

## Design
packages/intel/ladder_adaptive.py: per (module prefix x class) from history: success/repair statistics -> a recommendation {finer | keep | coarser} with its data basis (n, quotas). The job plan shows the recommendation as a note per affected task ('history: L tasks in packages/orchestration fail 3x more often - proposal: 2xM'); the planner prompt receives it as a hint segment. Adoption stays planner/operator business (F015 edits are trivial); ADOPTION is logged -> effectiveness itself becomes measurable ('recommendation followed vs. outcome' in the F115 report).

## Task slicing
T001 statistics + recommendation logic + minimum n + tests (a synthetic history flips the recommendation). T002 the job-plan note + the prompt segment + effectiveness tracking.

## Acceptance & tests
The history fixture provably changes the recommendation; the plan_rationale cites the data basis; tracking numbers are queryable in the report.

## Risks / anti-goals
A recommendation, never coercion (A3 courage toward large tasks stays wanted - the recommendation can say 'coarser' and does in a fixture); module granularity stays coarse (prefixes, no per-file micromanagement).

# T9_F167 — SIEM / audit event export
**Tier 9 · Depends on: F009 audit, F059, F163 · Blocks/used by: enterprise integration; F172**

## Goal & Done
Enterprise security teams get Remedy's audit story in their own
tools: a consolidated stream — commands audit, decisions, job
lifecycle, failover events, lineage commits, policy violations —
exports as schema-versioned JSONL and CEF lines through
configurable sinks: rotating file, webhook (retry + spool on
outage, NEVER blocking a run), and syslog; the field schema ships
as customer-facing documentation. DONE when each source's fixture
events map to both formats per goldens, the webhook sink provably
never blocks (an unreachable-endpoint fixture: runs proceed, events
spool, delivery resumes), the schema document is generated from the
same field definitions the code uses (one source), sinks respect
the redaction corpus (audit events carry no secrets/content —
digests and refs only), and a local schema-version registry
anticipates the later cross-product schema work with a forward
note.

## How it fits (a forward-reference note + composition)
The old draft referenced a later schema feature (F245) for
versioning — that feature isn't built yet, so THIS feature owns a
local, explicit schema registry (audit_export_schema_v1 with the
field definitions as data), documented as the seed the later work
will absorb (forward compatibility by doing the simple right thing
now). Sources are all files/events that exist: commands_audit
lines, decision lifecycle (requested/resolved with actors), job
lifecycle events (the ledger's terminal/start kinds), failover
disclosure records, lineage commit notes (refs, not content),
policy findings (MCP violations, matrix denials, secret-scanner
blocks as they land). The notify machinery (F059) contributes the
webhook mechanics pattern — retry+spool generalizes it (verify
whether one delivery core can serve both — the consolidation
finding).

## Design (suggested shape)
- `packages/enterprise/audit_export.py`: source taps (each a
  small reader/subscriber on its file/event source, normalized
  into the schema's envelope {ts, source, kind, actor?, project,
  job?, fields{}}) → the sink fan-out.
- Formats: JSONL (the envelope verbatim) and CEF (a documented
  field mapping table, golden-tested per source kind).
- Sinks per [audit_export]: file (rotation by size/age), webhook
  (bounded retry, disk spool on failure, resumed delivery in
  order, delivery state visible in doctor/status — never
  blocking: emission is fire-and-spool from the run's
  perspective), syslog (stdlib handler, transport per config).
- Redaction: the envelope's fields are refs/digests by
  construction (schema review) + the corpus test over emitted
  streams.
- The schema doc: generated from the definitions (fields, types,
  meanings, per-kind examples) — the customer artifact.

## Task slicing
- **T001** the envelope + local schema registry + source taps +
  normalization goldens per source.
- **T002** formats (JSONL/CEF mapping table) + goldens + the
  redaction corpus pass.
- **T003** sinks (rotation, webhook retry+spool+resume with the
  unreachable fixture, syslog) + the never-block proof + the
  consolidation finding with F059 + the generated schema doc +
  the end-to-end.

## Acceptance
- Per-source goldens both formats. The unreachable-webhook
  fixture: run timing unaffected (measured), events spooled and
  later delivered in order. Corpus green over real emitted
  samples. The schema doc regenerates from definitions (drift
  test). Doctor shows sink health.

## Edge cases & assumption defaults (A9)
- Event floods (a busy multi-job day): sinks are sequential
  per-sink with bounded memory (spool to disk beyond the buffer
  — the spool IS the pressure valve); ordering guaranteed
  per-source, best-effort global (documented — SIEMs sort by
  ts). Historical backfill: `remedy audit export --since` replays
  from the source files through the same taps (one mapping).

# T1_F071 — Mission dossier
**Tier 1 · Depends on: F070 · Blocks/used by: context efficiency, F079**

## Goal & Done
Long missions no longer die of context bloat: a maintained, hard-budgeted
dossier (goal, per-milestone state, open risks, recent decisions, next
step) is the orchestrator's working memory — rewritten by compression, not
by truncation. DONE when a fixture mission's dossier stays under its token
budget across many iterations, survives information-recall checks, and is
the stable PREFIX of the orchestrator prompt.

## How it fits (inspect current shape before building)
The orchestrator loop already assembles its context dossier-first — this
feature owns the dossier's content quality and budget. Token counting for
the budget uses whatever counting basis the actuals feature established;
label the basis, don't invent a counter (P6). The dossier lives with the
mission's records; every rewrite is versioned in evidence so a human can
audit what the compression dropped.

## Design (suggested shape)
Module `mission_dossier.py`:
- A structured document with fixed sections in fixed order (cache
  friendliness): GOAL (immutable, copied once), MILESTONES (one line each:
  state, blocking item), RISKS (open only), DECISIONS (last few, with
  outcomes), NEXT (the single next step). Hard budget from config
  (dossier.max_tokens, conservative default ~3000).
- `update(dossier, iteration_facts)`: append the new facts into their
  sections; if over budget, ONE compression provider call rewrites the
  overweight sections under explicit rules ("merge resolved risks away,
  keep every open item, never drop the goal") — schema-validated output;
  a failed compression falls back to keeping the previous dossier plus
  the raw facts appended and FLAGS over-budget honestly rather than
  silently truncating.
- Each version stored (dossier_v<N>.md) with a diff-friendly layout; the
  live prompt uses the newest.
- Recall discipline: a small eval harness seeds known facts across
  iterations and asserts they remain answerable from the dossier alone —
  quality is measured, not assumed (the handoff feature reuses this
  harness).

## Task slicing
- **T001** structure + update mechanics + budget check + versioning +
  unit tests (section ordering stable; over-budget flag path).
- **T002** the compression call + rules + schema + fake-provider tests
  (open items survive; resolved items merge; goal immutable).
- **T003** loop integration (prefix position asserted) + the recall
  harness with a seeded 10-fact fixture across simulated iterations.

## Acceptance
- After a long fixture mission: dossier within budget, all open items
  present, goal byte-identical to iteration one, versions archived.
- Recall fixture: the seeded facts that were still OPEN are answerable;
  resolved ones may compress away (that asymmetry is the point).
- Compression failure path leaves an honest over-budget flag, never a
  truncated document.

## Edge cases & assumption defaults (A9)
- Facts that are both risk and decision are recorded once, in decisions,
  with the risk closed — one home per fact. Token counting differences
  across models: budget against the orchestrator model's basis, labeled.

## Orchestrator brief
Small but quality-critical: put the compression rules verbatim in the
T002 order and require the fake-provider tests to encode them as
assertions. T003's recall harness is a deliverable other features reuse —
name it as such.

## Do not touch
Cross-session handoffs (next-but-one feature), prompt ordering policy
(cache feature owns it), memory systems beyond the dossier. Suggested
tests: tests/orchestration/test_mission_dossier.py.

## Built State (2026-08-03)

Delivered as designed, with the reviewer findings folded in.

### What was built
- **`packages/orchestration/mission_dossier.py`** — the maintained
  document: five fixed sections in fixed order (GOAL immutable ·
  MILESTONES one line each, merge-by-id · RISKS open-only ·
  DECISIONS recent few rendered, full record kept · NEXT single
  step). `start_dossier` copies the goal ONCE; nothing after can
  change it — the compression contract has no `goal` field, so
  "never drop the goal" is schema shape, not prose.
- **Budget** from config `dossier.max_tokens` (default 3000,
  `REMEDY_DOSSIER_MAX_TOKENS`) counted through the EXISTING seam
  `token_economy.estimate_text_tokens`; every count carries basis +
  confidence (`low`) — no invented counter (P6). The over-budget
  flag is metadata, never counted against its own budget, never a
  truncation.
- **Compression** — ONE schema-validated call
  (`allow_parse_retry=False`), rules verbatim and enforced:
  `_check_rules` judges the REBUILT document and returns that same
  object (R-0172), so a section-crossing id cannot pass the check
  and then be dropped. Every failure route returns the previous
  dossier + raw facts + honest flag.
- **Versioning** — `dossier_v<N>.md` in the mission's evidence
  area; never overwritten (R-0173: identical rewrite no-op,
  differing content refused); live state `dossier_state.json`;
  torn writes self-heal by fast-forwarding past the archive's
  high-water mark (R-0175) — version numbers are a monotonic
  high-water mark, not an update counter.
- **Loop integration** — `update_mission_dossier` drives the
  maintained document every iteration BEFORE context assembly;
  `maintained_dossier_text` feeds the existing
  `assemble_context(dossier=...)` seam; the newest version is the
  asserted byte-prefix of the prompt. The stand-in render remains
  only as the no-stored-version fallback and labels itself.
- **Recall harness** — PUBLIC reusable deliverable
  (`RECALL_FIXTURE_FACTS`, `run_recall_harness`, `recall_report`):
  seeds 10 mixed facts across simulated iterations under a tight
  budget; open facts must be answerable from the newest dossier
  alone, resolved ones may compress away (the measured asymmetry).
  F079 reuses it.

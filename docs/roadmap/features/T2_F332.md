# T2_F332 — A task an earlier task already did ends done
**Tier 2 · Depends on: R-0999 and R-1117 (no-change defenses), amend1014b D3 (a pass on an empty diff is rejected) · Blocks/used by: the improve run's orders over universe-chat**

> Registered 2026-10-29 by the operator order beweis on the orchestrator's order, in Package 3
> because it comes from the runs of 2026-10-29: job 6c4564622e87457e.

## Goal & Done
A job task that stages no change ends done, not blocked, when an earlier task of the same job already changed the files the task names and the reviewer, asked so and reading the job's workspace, finds the task's acceptance met. It keeps the plain record „already done by task N“: the story phrase `already_done` and an evidence line naming the earlier task and the files. Every other no-change task fails as before.

## What it rests on
- Job 6c4564622e87457e (universe-chat, unattended, order „Das (i) in Gedächtnis bekommt denselben Namen und dasselbe Verhalten wie jedes andere (i) der App.“), planned as four tasks. Task 2 („Refactor NetHeader ...“) changed `NetHeader.tsx` and its call site `KnowledgeNet.tsx`, so task 3 („Update KnowledgeNet to pass rendered InfoButton to NetHeader“) had nothing left to do. Its builder staged nothing, the empty-diff gate made the review needs_repair with `EMPTY-change`, and `no_file_changed` (R-1117) blocked the job: `task_001c113a0720484e_gate_failed: no_file_changed`. Task 4 („Run the test command and confirm it exits green“) was skipped.

## Acceptance
- A no-change task whose deliverable file (else every file it names) an earlier applied task of its job changed, and whose review passed with no finding above `low`, ends `applied_to_job_workspace` with `inputs["already_done"]` (task number, task id, files, evidence line), and the job goes on.
- The reviewer of such a round is told which files the earlier tasks changed and asked whether the task's acceptance already holds in the workspace; the code decides from its verdict.
- A no-change task that names a file no earlier task changed, the first task of a job, and one whose review did not pass still fail with `no_file_changed` (R-0999, R-1117, amend1014b D3 unchanged).
- A task that only runs the tests (title begins with run, rerun, execute, führe or starte and says test) is read the same way over every file the earlier tasks changed.
- The story's task row carries `phrase` `already_done` with `task` and `n`; contract 1.34 names it.

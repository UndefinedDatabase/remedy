# T9_F168 — Technical dossier generator
**Tier 9 · Depends on: F163, F166, F169, F035 · Blocks/used by: M10 sales artifact**

## Goal & Done
The compliance conversation gets its binder: `remedy export dossier
[--since --until]` renders chapters — (1) a process description of
the agentic development (a reviewed static core plus project
values), (2) the logging proof (the audit-export schema extract
with real examples), (3) the model/worker inventory for the period
(from the ledger), (4) the human-oversight proof (F169 embedded),
(5) change/lineage statistics, (6) open points, honestly — with
EVERY chapter header carrying "Technical input — not a legal
document, no conformity claim", and a --brief SME variant. DONE
when fixture periods render all six chapters from their real
sources (goldens), the static core is a reviewed committed
document that generation NEVER edits (values interpolate into
placeholders only), every number/claim in chapters 2–5 resolves to
its source artifact (the trust-dashboard discipline applied to
prose), the disclaimer appears on every chapter (grep), and the
brief variant compresses without dropping the honesty chapter.

## How it fits (inspect current shape before building)
Pure composition over four finished features plus the ledger:
chapter 1 interpolates project facts (config, autonomy level,
policy pack provenance, conventions refs) into the reviewed core
text (the core is customer-facing prose — written once, reviewed
like the certificate wording, versioned; generation fills the
named placeholders and refuses unknown ones); chapter 2 extracts
the audit-export schema doc (one source — the generated
definitions) plus N real sanitized example lines from the period;
chapter 3 aggregates ledger rows (adapters/models used, call
counts, cost with bases, certification states from the worker
certificates); chapter 4 embeds F169's period artifact verbatim;
chapter 5 renders lineage statistics (commits with full trailers,
lineage coverage percentage, churn summary — each figure linked);
chapter 6 lists KNOWN gaps mechanically where detectable (missing
capability proofs, uncertified adapters in use, unenforced sandbox
dimensions on this platform, stale price catalogs) plus the
static core's standing-limitations text.

## Design (suggested shape)
- `remedy export dossier`: period selection → chapter builders
  (each pure over its source, each returning {md, source_refs})
  → assembly (toc, disclaimers, the period/versions header) →
  dossier/ tree (chapters + an evidence/ subdir of referenced
  extracts) — archive-compatible (F166's tree discipline).
- The static core: docs/enterprise/dossier_core.md with named
  placeholders ({{project}}, {{autonomy_level}}, ...); a
  placeholder audit (unknown/unfilled → hard error).
- --brief: chapter summaries (bounded) + chapters 4 and 6 intact
  (oversight and honesty never compress away — the rule).
- Resolvability: a dossier-wide check that every source_ref
  resolves (the provenance machinery) — a dossier with dangling
  claims refuses to render final (draft mode shows the gaps).

## Task slicing
- **T001** the chapter-builder framework + the static core (the
  reviewed writing deliverable) + placeholder audit + tests.
- **T002** chapters 2/3/5 builders (schema extract + examples,
  ledger inventory, lineage stats) + per-figure source refs +
  goldens.
- **T003** chapter 4 embedding + chapter 6 mechanical gap
  detection + --brief rules + the resolvability check + the
  end-to-end (a fixture period → the full tree; a gap fixture →
  chapter 6 lists it; a dangling ref → draft-only).

## Acceptance
- Fixture dossiers golden per chapter; disclaimers on every
  chapter (grep). The core is never modified by generation (hash
  test); unfilled placeholders refuse. Every figure resolves
  (the walk); dangling refs block final mode. Brief keeps 4+6.
  Mechanical gaps detected per fixture (an uncertified adapter
  in the period appears in chapter 6).

## Edge cases & assumption defaults (A9)
- Periods with no activity: chapters render honestly minimal
  ("no runs in period") — an empty dossier is a valid answer.
  Multi-project dossiers: per-project v1; an org rollup is later
  (noted). Sanitized examples in chapter 2: the redaction corpus
  applies to the extracts (tested).

## Goal & Done
Remedy's structure has a measure, a ledger and a ratchet. The measure is a product command that
works on any repository, because F301 uses it for every project Remedy builds; Remedy's own
repository is its first user. Every function and module above a size limit is written down with
its measured size; a test lets each of those sizes fall and never rise and refuses a new function
or module above the limit; a rule pays the debts down on a fixed cadence; and the first step has
landed without changing behaviour. DONE when the command, the ledger page, the ratchet test and
the rule exist, the test is proven by mutation, and the first paydown step is in.

## Task slicing
- T001 — The measure, as a product command. One module and one command measure any repository:
  for Python every function and module by its syntax tree, for every other tracked text file its
  lines; the limits are parameters with defaults decided at the claim from the measurement. It
  reads only, prints text and `--json`, and has tests on fixture repositories.
- T002 — Remedy's ledger and ratchet. A page under `docs/system/`, linked from the docs index,
  lists each of Remedy's debts with its measure, the boundary it should be cut along and its
  steps in order. A test in the pattern of `tests/test_ble001_ratchet.py` holds the recorded size
  of every listed function and module: a size may fall, and the commit that lowers it lowers the
  record; a size that rises, and a new function or module above the limit, fail the test.
- T003 — The rule, written into the self-drive protocol. The rolling findings paydown comes after
  every fifth accepted feature and closes with one structural step from the ledger. Each paydown
  begins by running the measure and asking whether the structure still fits what Remedy has
  become; a new debtor enters the ledger with its boundary and steps. A feature that touches a
  listed function draws the boundary the ledger names first, in its own commit. A feature that
  replaces a structure deletes what it replaces before it closes; when a deletion must wait, its
  closure registers it as the next paydown's first step. A structural step changes no behaviour,
  keeps every import path working, and its proof is the unchanged tests staying green.
- T004 — The first step. `run_job`'s safe points become one function that every safe point calls,
  with the stop, the pause and the budget handled in one place; the recorded size of `run_job`
  falls by what moved.

## Acceptance
- The command measures a fixture repository with one oversized Python function and one oversized
  text file and names both; it changes nothing on disk.
- The ratchet test fails when a listed function grows by one line and when a new function above
  the limit is added, shown by the reviewer's mutation.
- After T004 `run_job` is shorter than its first record, no test changed its expectation, and a
  pause that arrives at any safe point parks the job.
- The protocol names the rule in one place, with the cadence of five.

## Do not touch
Behaviour. Any public import path. The limits never rise to let a change through.

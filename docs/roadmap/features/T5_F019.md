## Goal & Done
The brain graph comes alive: SSE events materialize nodes and links
in real time — plan approval births the task ring, runs bud from
their tasks, verdicts recolor — on the committed stage-1 stack, at
the design reference's visual bar. DONE when a replayed fixture
event stream builds the exact expected graph (ontology golden),
live streaming and the demo recording both drive it, out-of-order/
gap situations resolve via the snapshot path without ghosts, and
the stage decision stays honored (no renderer swap smuggled in).

## How it fits (binding stage decision, restated)
Stage 1 = react-force-graph-2d (the existing dependency:
nodeCanvasObject glyphs, linkDirectionalParticles, zoom API).
Stage 2 (PixiJS v8) ONLY if the F044 perf budget measurably fails
→ F233. The ontology is the contract between events and pixels:
```ts
type NodeKind='job_core'|'task'|'builder_run'|'review_run'|'repair_run'|'test_run'|'synapse'|'artifact'|'cluster';
type NodeState='open'|'planned'|'in_progress'|'pass'|'fail'|'blocked'|'vetoed';
interface BrainNode{id:string;kind:NodeKind;state:NodeState;parentId?:string;seq:number;meta:Record<string,unknown>}
```
Events arrive via the SSE hook (with its gap→snapshot contract);
materialization is a PURE REDUCER events→graph model (brainOntology
+ a reducer module), with rendering a separate concern — the
reducer is testable headless and is where the goldens live.

## Design (binding specifics)
- Reducer: per Part E event kind → node/link creation and state
  transitions (the lifecycle feature owns the visual language; the
  reducer owns existence and state); idempotent per seq (replays
  can't double-create); unknown event kinds → ignored with a
  counted debug note (forward compatibility).
- Layout: job_core centered, task ring by plan order, run buds
  radially from their task, synapse/artifact satellites — initial
  positions deterministic from the model (stable screenshots),
  force simulation refines with pinned core.
- Materialization motion: new nodes enter per the design
  reference's motion tokens (scale-in, the reference's timing);
  link particles indicate active flows only for in_progress.
- Snapshot path: the state endpoint's full graph → reducer state
  replacement, then live resumption (the hook's contract) — tested
  with induced gaps.
- Perf: stage-1 scope is the F044 budget (60 fps at 500 nodes) —
  a perf fixture measures; failing it triggers the stage-2
  conversation, not silent degradation.

## Task slicing
- **T001** ontology + the reducer + idempotence + goldens (fixture
  streams → exact models; replay/double-delivery safe).
- **T002** rendering on react-force-graph-2d (canvas glyph slots
  wired for the lifecycle feature, layout, motion tokens) against
  reduced fixtures; the demo recording renders.
- **T003** live wiring (hook → reducer → render) + gap/snapshot
  recovery + the perf fixture measurement + an end-to-end on a
  live fake job.

## Acceptance
- Stream goldens exact incl. hostile orderings; ghost-node hunts
  clean after induced gaps. The demo recording and a live fake job
  render identically per model. Perf fixture meets budget on
  stage 1 (numbers recorded). Token-only styling guard holds.

## Edge cases & assumption defaults (A9)
- Hundreds of runs on one task: the cluster kind aggregates beyond
  the design threshold (the zoom feature expands) — the reducer
  clusters, the renderer draws. Browser tab sleep/wake: the gap
  path covers it (a wake test).

## Built State (F019, 2026-09-24)

What exists on disk at the close of F019, built in six rounds over two sessions on
`feature/f019-live-node-materialization`, cut from `main` at `92b7f5f1`. Every DECISION named lives
in `.agent/decisions.md`; every round's verdict in `.agent/live_review.md` or, once rotated, its
archive.

**T001 — the ontology and the reducer.** `apps/ui/src/components/graph/brainOntology.ts` holds the
node kinds and states and the two status tables; `brainReducer.ts` folds the stream's frames into a
`BrainModel` as DECISION F019 D1 rules. The input row is `{seq, kind, outcome, taskId}`, which
`feedRowOf` produces, because the server's envelope carries no Part E type names and no run id. A
run node is keyed `run:<task>:<seq>` by the frame that birthed it; the task ring is seeded from the
dashboard's task list by `seedBrainModel`, since no plan-approval event exists; a row at or behind
`lastSeq` returns the identical model; `rebuildBrainModel` is the snapshot path, the seed and then
the rows in seq order with the first row of a repeated seq kept; and `clusterBrainModel`, for a task
with more than eight runs, keeps every open run and fills the rest of eight with the most recent
finished runs, collapsing the others into one `cluster` node. The
`test_run_*` and `repair_*` frames draw no node, because they carry no outcome or no task.

**T002 — the layout, the motion and the renderer.** `buildBrainLayout` in `buildForceBrainModel.ts`
lays out the clustered model one to one: the core pinned at the origin, the tasks a golden angle
apart on a ring of radius 150, each task's runs fanned 34 away from it, trunk widths 2.2 and 1.4,
and a link `active` while a run under it is in progress (DECISION F019 D2). `brainMotion.ts`
schedules births, at most three at once, 90 ms apart, 420 ms each or a 180 ms fade under reduced
motion, from the tokens `--remedy-dur-birth` and `--remedy-ease-soft`. `ForceBrainGraph.tsx` paints
the layout on react-force-graph-2d through `NODE_PAINTERS`, one slot per node kind for the
lifecycle feature to fill, animates births, shows one particle per active link and none under
reduced motion, keeps a surviving node's simulated position across a new layout, and hides its
canvas from assistive technology. `BrainGraphStage.tsx` mounts it by default and mounts the SVG
picture `BrainGraphCanvas.tsx`, unchanged, as the simple view and whenever no task is visible;
`brainView.ts` maps the dashboard's task words onto the seed, applies the filter chips, and selects
a clicked task's dashboard `nodeId` (DECISION F019 D3). The decorative dashboard builder and its six
types are removed with their source pins, and `brainDemoRecording.ts` is the demo recording, a
captured fake-provider job's task list and eight frames (DECISION F019 D4).

**T003 — the live wiring, the gap path and the budget.** `brainLedger.ts` merges `events-since`
pages and the live stream's ring into one ledger, and the stage folds only its complete prefix
from seq 0; a hole is filled by paging `events-since` from its first missing seq, and until then
the graph holds the state before it. `useBrainLedger.ts` is the thin hook, and `eventsSincePath` in
`apps/ui/src/api/brainStreamDeps.ts` is the one builder of that path, which `RemedyShell.tsx` uses
to hand the stage a page reader beside `stream.recent` (DECISION F019 D5).
`brainPerfFixture.ts` builds models whose layouts hold exactly 200 and 500 nodes through the real
reducer path (DECISION F019 D6).

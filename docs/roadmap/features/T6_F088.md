## Goal & Done
The builder sees what it must match: UI-task prompts attach the
relevant reference image directly where the routed model supports
vision — capability-gated per adapter, honest image_attached flag —
and ALWAYS additionally the written style block (image plus words,
never image alone), with the prompt trace recording exactly what was
sent. DONE when a vision-capable fake receives pixels+words on a
design-ref'd task (trace-proven), a non-vision route receives the
described fallback with its label, the words half is present in
every variant, and per-call image budgets keep costs sane.

## How it fits (inspect current shape before building)
Everything gates through existing machinery: the task's design_refs
select images from the addressing table; the adapter vision
capability flag (the vision feature's surface) decides pixels vs the
labeled description path (that feature's VisionDescription reused —
one description mechanism); the segment registry carries the words
half — the written style block is a SEGMENT (design-context rank
near job-context) composed from the design reference materials
available at this point (the scope note, dimensions, and — once
decomposition lands — the spec's tokens/regions; until then the
block says honestly what it contains). A8's rule is the soul:
image plus words, never image alone — enforced structurally (the
builder prompt assembly refuses an image without the block).

## Design (suggested shape)
- UI-task detection: tasks with design_refs (or the plan's UI
  classification) route through the design-prompt assembly.
- Pixels path: the referenced images as image parts (per-call
  count/size budget config; over-budget → the highest-relevance
  refs by scope-note match, the rest listed as available by
  R-number); evidence image_attached: [R-numbers], hashes.
- Words path (always): the style block segment — reference list
  with scope notes + the written design intent available (grows
  with decomposition; its content source documented per stage).
- Fallback: non-vision route → VisionDescription per reference
  (generated once per job, cached by hash) in place of pixels,
  labeled per the vision feature's rule; image_attached: false with
  fallback: described.
- Trace truth: the prompt trace records parts (images by hash,
  segments by manifest) — "what was really sent" is greppable.

## Task slicing
- **T001** design-prompt assembly + the structural image-plus-words
  guard + budget selection + unit tests.
- **T002** pixels/description/none matrix on fake adapters +
  evidence flags + trace proofs per variant.
- **T003** the style-block segment (stage-1 content) + docs + the
  end-to-end (design-ref'd fixture task on both route types;
  traces golden).

## Acceptance
- Matrix exact (vision: pixels+words; non-vision: description+
  words; the guard makes image-alone unconstructable — a unit test
  proves the refusal). Budget selection deterministic by scope
  relevance. Traces record hashes/manifests. Description caching
  by hash (one generation per reference per job).

## Edge cases & assumption defaults (A9)
- Tasks citing many references: the budget rule + the by-number
  availability line keep prompts honest about what wasn't shown.
  Animated/exotic formats: registration already constrained types;
  here only registered refs flow.

# T7_F141 — Permission matrix per autonomy level
**Tier 7 · Depends on: F078, F017 · Blocks/used by: F175 role dimension later**

## Goal & Done
What Remedy MAY DO (not just start) becomes one enforced table:
actions — read, write_worktree, commit, push, dependency_change,
destructive, expensive, external_call — cross autonomy levels
L2–L5 in ONE module's require(action), the matrix renders in docs
and UI, and no bypass flags exist. DONE when every action class
routes through the single gate at its enforcement seams (the seam
inventory is the deliverable), the matrix is a reviewable table
constant with per-cell tests, denials produce decisions/refusals
with the cell cited, docs/UI render FROM the constant (no prose
drift), and a grep guard proves no bypass parameter anywhere.

## How it fits (inspect current shape before building)
This completes what levels started: F078 gated who may INITIATE;
this gates what running work may DO. Enforcement seams exist and
are countable: reads (context compiler — L2+ allows, trivially),
worktree writes (applicator — fences stay orthogonal: fences say
WHERE, the matrix says WHETHER), commit (the applicator's commit
path), push (currently no machinery pushes — the matrix encodes
push=never-below-L5-and-even-then-config, verify and encode the
reality), dependency_change (manifest-touching diffs — the ADR
detector's parser reused for DETECTION at apply time),
destructive (deletions above a threshold / migrations — a
documented predicate), expensive (the cost-preview threshold —
that feature's gate becomes a matrix consumer), external_call
(network-touching DoD/custom commands — the sandbox policy's
knowledge reused). Denial UX: below-level actions raise the
standard decision ("requires L4: dependency_change — approve this
instance or change the level via ADR") — per-instance human
override is the escape valve, audited; a bypass FLAG is not.

## Design (suggested shape)
- `permission_matrix.py`: the table constant (action × level →
  allow | ask | deny) + require(action, context) → allow | the
  decision path | typed refusal; ONE module, imported by every
  seam; the context carries the instance evidence for the
  decision's triple.
- Matrix defaults (reviewed as the feature's policy core): L2
  ask-heavy (commit ask, dependency ask, destructive deny), L5
  allow-heavy but destructive still ask, push config-gated at
  every level — the exact table is the T001 review artifact.
- Rendering: docs table + a UI matrix view generated from the
  constant (the terminology audit pattern — no hand-written
  copies).
- The no-bypass rule: require() has no override parameter;
  per-instance approvals go through decisions (audited); the grep
  guard hunts bypass-shaped kwargs.

## Task slicing
- **T001** the seam inventory (findings order: every action
  class's enforcement point named with its current behavior) +
  the reviewed matrix constant.
- **T002** the gate module + per-cell tests + seam integrations
  (one small order per seam, each with allow/ask/deny fixtures at
  boundary levels).
- **T003** decision UX (the cited cell, the triple) + docs/UI
  generation + the no-bypass grep + the end-to-end per level
  fixture.

## Acceptance
- Every cell tested; every seam routes through the one module
  (import guard). Denials/asks cite their cell; instance
  approvals audited. Docs/UI render from the constant (delete a
  row → both lose it). No bypass parameter exists (grep). Fences
  remain orthogonal (a fence-denied path stays denied at L5 —
  the layering test).

## Edge cases & assumption defaults (A9)
- Actions spanning classes (a dependency change that is also
  expensive): ALL applicable cells must pass (conjunction,
  documented). Mid-run level changes: F078's rule inherits —
  running work keeps its start-time level; the matrix reads the
  job's pinned level (additive field at start).

## Orchestrator brief
T001's inventory + matrix review is the policy moment — human
review before any code. Seam orders are parallel after. The
conjunction rule and the pinned-level rule go verbatim.

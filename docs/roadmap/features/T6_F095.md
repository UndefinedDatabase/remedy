## Goal & Done
Mobile stops being a hope: where a mobile reference exists, the
fidelity machinery runs per viewport (capture+compare per pair);
where it does NOT, only honest heuristics run — no horizontal
scroll, tap targets ≥ 44px, minimum font 12px — reported SEPARATELY
from fidelity comparisons so nobody mistakes a lint pass for design
fidelity. DONE when a two-reference fixture (desktop+mobile) runs
paired fidelity per viewport, a desktop-only fixture runs mobile
heuristics with the separate-report labeling, each heuristic fires
on its seeded violation with element evidence, and the DoD gains
the distinct check kinds (visual_fidelity per viewport vs
responsive_heuristics).

## How it fits (inspect current shape before building)
References carry dimensions (the addressing table) — viewport
pairing is mechanical: a reference within a documented tolerance of
a configured viewport class (mobile/desktop sets from the capture
feature) pairs with it; ambiguous dimensions ask via the scope note
or a compile-time clarification (the bundled rules — plan-time,
once). The fidelity loop already accounts per reference-and-
viewport pair — this feature ensures mobile pairs enter it.
Heuristics are DOM/layout measurements through the same browser
session (no LLM): scroll width vs viewport, computed target sizes
on interactive elements, computed font sizes — each violation with
the element's selector/screenshot crop.

## Design (suggested shape)
- Pairing: reference dims → viewport class (tolerance config);
  the pairing table lands in evidence (which R matched which
  viewport — reviewable); unpaired viewports with UI tasks →
  heuristics mode for that viewport.
- Heuristics (each a pure measurement over the loaded page):
  h_scroll (document width ≤ viewport width), tap_targets
  (interactive elements' boxes ≥ 44px min side; the interactive
  set: buttons/links/inputs/testid-marked), min_font (computed
  size ≥ 12px on text nodes above a length threshold — icon
  glyphs excluded, documented); violations: {rule, selector,
  measured, crop_path}.
- Reporting separation: DoD kinds visual_fidelity (per pair) and
  responsive_heuristics (per unpaired viewport) render in
  DISTINCT report sections with the explanatory line ("heuristics
  verify usability floors, not design fidelity — provide a mobile
  reference for fidelity"); blocking defaults: fidelity per the
  loop's config, heuristics blocking on h_scroll only (usability
  floor), the rest warn (config).
- Thresholds config (44/12 defaults per platform guidance,
  documented sources).

## Task slicing
- **T001** pairing + the table + ambiguity clarification + unit
  tests (clear pair, tolerance edge, ambiguous → question).
- **T002** the three heuristics + element evidence + crops +
  seeded-violation fixtures each + the exclusion rules.
- **T003** DoD kinds + report separation + blocking defaults +
  the end-to-end (paired fixture runs dual fidelity; desktop-only
  fixture runs heuristics with the labeling; seeded h_scroll
  blocks).

## Acceptance
- Pairing table golden; ambiguity asks once at plan time. Each
  heuristic fires exactly on its fixture with selector+crop;
  exclusions hold (icon font fixture). Report sections distinct
  with the explanatory line (grep). h_scroll blocks; others warn
  by default.

## Edge cases & assumption defaults (A9)
- Responsive references beyond two classes (tablet): the viewport
  set is config — classes extend without code (pairing is
  data-driven). Hidden-on-mobile elements: heuristics measure the
  RENDERED state per viewport (display:none excluded by
  construction).

## Orchestrator brief
Gate on the loop + capture. The separation labeling is the
honesty core — verbatim into T003. Heuristics are pure
measurements; reject LLM judgment sneaking in.

## Do not touch
Fidelity thresholds, capture determinism, DoD gate semantics.

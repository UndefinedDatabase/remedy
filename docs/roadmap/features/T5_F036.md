## Goal & Done
"What did I get?" answered in a guided minute: tour.py generates up
to eight stops from report, diff and DoD — what was built, where it
lives, why it's shaped this way, how to run it — rendered as a UI
overlay with next/prev and printed identically by the CLI's --tour.
DONE when fixture jobs yield coherent stop sequences (goldens), every
stop anchors to a real artifact (deep link into graph/diff/evidence —
no free-floating prose), generation is a labeled side-role call with
a deterministic fallback, and the tour never exceeds eight stops or
invents claims beyond its sources.

## How it fits (inspect current shape before building)
Inputs are the terminal artifacts: the report's structure, the diff's
file map, the DoD matrix, plan rationale — the stop GENERATOR is a
side-role call (cheap routing) with a schema (stops[{title, body ≤
bound, anchor {kind: node|diff|evidence|command, ref}}]) validated
per the standard discipline; the deterministic fallback derives
stops mechanically (one per changed area + the run command + the DoD
summary) labeled as such. Anchors reuse the deep-link contracts
already established (graph focus params, diff endpoint, evidence
panel tabs) — a stop is prose ATTACHED to a place, enforced by the
schema's required anchor.

## Design (suggested shape)
- Generation at terminal (with the report, same funnel, same
  never-block rule) or on demand; stored as tour.json in evidence;
  regeneration versioned like plan renders.
- Anchor-truth validation: every anchor resolves at creation
  (node exists, diff path exists, command is the DoD's real run
  command) — unresolvable anchors drop the stop with a log (the
  idea engine's ref discipline, same pattern).
- UI overlay per the design reference's tour treatment: dimmed
  backdrop, the anchored element spotlighted, next/prev/skip,
  progress dots; opening a stop navigates the shell to its anchor
  (zoom focus, diff tab, etc.). CLI --tour prints numbered stops
  with their commands/paths.
- Content honesty: bodies may only restate source content
  (report/diff/DoD/rationale) — the generation prompt mandates it
  and goldens check no-new-claims on fixtures (the P6 line).

## Task slicing

- **T003** the overlay (spotlight, navigation, progress) + anchor

## Acceptance
- Fixture tours golden (≤8 stops, every anchor resolving,
  navigation lands correctly). Fallback tours labeled and useful.
  No-new-claims holds (denylist/entailment-style golden checks).
  CLI and overlay render the same stops (parity test). Demo tour
  golden.

## Edge cases & assumption defaults (A9)
- Tiny jobs (one file): a two-stop tour is fine — the cap is a
  ceiling, not a quota. Failed/blocked terminals: the tour exists
  and says so (stop one is the honest state; comprehension
  includes bad news).

## Orchestrator brief

no-new-claims rules go verbatim into orders — they are what keeps
the tour from becoming marketing.

## Do not touch
Report content, deep-link formats (consumed), preview mechanics
(F041 enhances stops later). Suggested tests:
tests/orchestration/test_result_tour.py.

## Built State (F036, 2026-09-28)

What exists on disk at the close of F036, built in seven rounds over two sessions on
`feature/f036-guided-result-tour`, cut from `main` at `9dc2f2a7`. This file was written before
most of the tour's inputs were built. The tour reads the report's sources, the diff's file list,
the job's evidence folder and the Definition of Done's recorded commands, and changes none of them
(DECISION F036 D1). Every DECISION named lives in `.agent/decisions.md`; every round's verdict in
`.agent/live_review.md` or, once rotated, its archive.

**T001 — the stops and the mechanical tour.** `packages/orchestration/result_tour.py` holds the
whole Python half. A tour is `{"schema": "remedy.tour.v1", "job_id", "generator", "stops",
"dropped"}`; a stop is `{"title", "body", "anchor": {"kind", "ref"}}` with a title of at most 80
characters and a body of at most 400; a tour holds at most eight stops (`MAX_TOUR_STOPS`), a
ceiling and not a quota. `anchor_problem` checks each anchor against `collect_tour_context` of the
job when the tour is built: a `node` ref is the full id of one of the job's tasks, a `diff` ref a
path in the job's diff file list, an `evidence` ref a file directly in its evidence folder, and a
`command` ref, byte for byte, the command of a Definition-of-Done check the gate recorded.
`resolve_tour_stops` drops a stop whose shape is wrong or whose anchor does not resolve, and every
sound stop after the eighth, logs it and lists it under `dropped` with its reason.
`build_fallback_tour` builds the mechanical tour, labelled `fallback`, in this order: how the run
ended, anchored to `report.md` when it exists and else to the first task; one stop per changed
area, an area being a changed file's first path segment, with a last stop gathering the rest when
the areas outnumber the room; how to run it, the first recorded Definition-of-Done command; and
the Definition of Done's outcome, anchored to `dod_result.json`. A text too long for its bound is
cut with an ellipsis, never rewritten.

**T002 — the model-written tour, its storage and the command line.** `generate_result_tour` asks
the summary role, through `tour_call_fn()`, for a tour bound to its own schema. The model sees
`tour_source_text`, one fact of the job's records per line, and `tour_claim_problems` drops a
model-written stop that states a number, a quoted span or a file path that text does not hold, or
a word of `TOUR_CLAIM_DENYLIST`. The first stop is always the mechanical "How the run ended", so a
failed or held run is never toured as a success; the label reads `summary-role` when a model stop
survives and `fallback:<reason>` otherwise. Provider failures are caught by the named tuple
`PROVIDER_CALL_ERRORS`, so no new `# noqa: BLE001` exists, and `result_tour.py` is one more entry
of `ROLE_CONFIG_CALL_SITES`, with the literal role `summary` (DECISION F036 D3). The summary model
writes a tour only when the operator switches on `tour.model_written`, environment variable
`REMEDY_TOUR_MODEL_WRITTEN`, which is off by default and listed in `docs/guides/environment.md`;
with it off, every job still gets its mechanical tour (DECISION F036 D7). `write_result_tour`
writes `tour.json` beside `report.md` in the job's evidence folder and every later version as
`tour_v<N>.json`, through `durable_write_json`; it never raises for an `OSError`, a `ValueError`
or a `ResultTourError`, records such a failure on the job under `tour_error`, and clears that key
on success. `long_run_executor._apply_terminal` calls it directly after `write_final_report`, so
every reported terminal writes one new version, and `load_result_tour` reads the latest (DECISION
F036 D4). `job show --full` ends with a `tour` section and `job show --tour` shows it alone: the
stored tour, or the mechanical tour marked not stored with version 0; an unreadable stored tour is
the section error `tour_unreadable` and the command still exits 0. `render_tour_lines` prints the
numbered stops.

**T003 — the browser.** `tour_view` answers `{"stored", "version", "tour", "error"}`; the route
`GET /api/jobs/<job_id>/tour` serves it verbatim, answering 200 for every known job, and the
command line's section is built from the same function (DECISION F036 D5).
`apps/ui/src/api/resultTour.ts` decodes the view whole or not at all and answers the overlay's
stepping, progress, step label and anchor labels; `loadTourView` in `remedyApi.ts` is its one
read and never throws. A "Tour" button beside "Lessons" in `RightLivePanel.tsx` opens
`apps/ui/src/components/tour/TourOverlay.tsx`, which `RemedyShell.tsx` mounts after `</main>` and
which is portaled to `document.body`: a backdrop dimmed with `--remedy-ink-strong`, and one glass
card with the step label, one progress dot per stop, the title, the body, the anchor's label, a
line naming who wrote the tour, and Previous, Next, "Show me" and "Close tour". Escape closes it
and the arrow keys step. "Show me" opens a task stop's task detail, or the job's whole diff
scrolled to a diff stop's file, lifts the backdrop and docks the card over the lower left of the
left rail; stepping dims again and re-centres the card. A record stop names its file and a command
stop shows its command as code, in the card (DECISIONS F036 D6 and D7). The design reference's
assumption log records the backdrop and the card.

a reported terminal, never on demand from the browser. Preview links from a stop are F041's.

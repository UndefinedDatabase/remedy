# T11_F194 — i18n checks
**Tier 11 · Depends on: F094 · Blocks/used by: internationally selling customers**

## Goal & Done
See ROADMAP.md F194; the Done criterion there is binding.

## Context (existing code & prior features)
Nothing exists; the F107 AST infrastructure is reusable.

## Design
A hardcoded UI-string detector: ts/tsx - JSX text nodes + string props outside i18n calls (t(), Trans) via a ts-morph scan; py templates analogous per framework config. A pseudo-locale test: wrap the i18n layer (accented + 30% longer), playwright screenshots checked for overflow (element bounding vs. container) + an RTL smoke (dir=rtl, layout-flip heuristic). An optional DoD kind i18n; findings in the review schema.

## Task slicing
T001 the string detector for both stacks + an allowed-exceptions file + tests. T002 the pseudo-locale harness + the overflow detector + a fixture.

## Acceptance & tests
The hard string yields a finding with file:line; the pseudo-locale overflow is caught with a screenshot; the exceptions file works and is documented.

## Risks / anti-goals
No translation feature (verifiability only); per-framework heuristics stay small and config-extensible.

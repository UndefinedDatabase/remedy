## Ziel & Done
`remedy` erkennt das Projekt aus dem Arbeitsverzeichnis und bindet Jobs/Evidence/Memory
an eine stabile project_id. Done: zwei Repos → sauber getrennte Jobs, Memory, Ledger;
Evidence trägt project_id.

## IST-Bezug
- `project_registry.py` existiert als Stub. Daten liegen heute repo-lokal unter .data/
  bzw. evidence/ ohne Projekt-Dimension.

## Design
`packages/core/project_identity.py`:
```python
@dataclass(frozen=True)
class ProjectIdentity: pid:str; root:Path; name:str
def detect(cwd:Path) -> ProjectIdentity | None
# Aufwärtssuche: .remedy/ zuerst, sonst .git; pid = sha256(realpath)[:12] beim ersten
# Kontakt in ~/.remedy/projects.json registriert {pid,{root,name,created}}; Umzug eines
# Repos: `remedy init --relink` aktualisiert root, pid bleibt stabil (gespeichert auch
# in .remedy/config.toml [project] id=..., das gewinnt bei Konflikt).
```
- Datenmodell (CONVENTIONS): Repo-nah in `.remedy/` (config.toml, memory/cards/,
  ledger.md, STOP); maschinennah in `~/.remedy/projects/<pid>/` (jobs/, cache/,
  ledger.sqlite, locks/, runtime.log).
- Evidence: jedes job_report/manifest erhält `project_id`; Migrations-Shim: fehlt es,
  gilt legacy-pid `local-default` (kein Bruch alter Evidence).
- Außerhalb eines Projekts: klare Meldung + `remedy init`-Hinweis, Exitcode 2.

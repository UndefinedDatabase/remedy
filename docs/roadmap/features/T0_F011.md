# T0_F011 — Kill switch
**Tier 0 · Depends on: none · Future UI integration: the cockpit stop button maps to the stop_job command once F009 (Tier 5) exists · Blocks/used by: F046, F018, F200**

## Goal & Done
See ROADMAP.md F011; the Done criterion there is binding.

## Context (existing code & prior features)
No emergency stop exists; long runs would be unstoppable without kill -9.

## Design
`kill_switch.py`: should_stop() checks .remedy/STOP (global) and STOP.<job> (targeted) at three safe points: before every provider call, after every task, per cycle. On stop: write a checkpoint (job_state.json suffices in v1) and status stopped_by_operator. CLI `remedy jobs stop|resume <id>`; the UI button later maps to the stop_job command whose consumer creates the STOP file.

## Task slicing
T001 module + checkpoints wired + tests (stop between tasks). T002 CLI stop/resume + command consumer.

## Acceptance & tests
Stop during task n finishes or breaks at the provider-call checkpoint; resume continues at n/n+1 with a consistent result (comparison test).

## Risks / anti-goals
SIGKILL on provider processes only behind an explicit --force.

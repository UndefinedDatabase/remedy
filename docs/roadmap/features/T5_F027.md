## Goal & Done
The human red line is one click and one reason: veto_task (reason
mandatory) marks a node vetoed — struck glyph per the design
language — computes and shows the unreachable downstream, and files
a replan proposal into the decision inbox, never auto-executing
anything. DONE when a vetoed diamond-branch fixture renders the
strike and its unreachable set, the run continues on independent
branches (established branch semantics), the replan proposal carries
the veto's context, and the reason lands in ownership evidence
verbatim.

## How it fits (inspect current shape before building)
Veto composes existing pieces: the vetoed state exists in the
ontology and glyph language (strike treatment); unreachable
downstream is the DAG module's blocked_downstream with a vetoed
cause (reuse, don't re-derive); continuation-despite-blockage is the
escalation feature's behavior; the proposal is a decision entry
(type replan_proposal) whose payload seeds the planner if the human
approves it — approval routes into a replan flow (the job plan's
replan exists pre-execution; mid-run replanning arrives with its own
rules — v1's proposal offers the honest menu: replan remaining work
as a follow-up job, or accept the reduced scope; both explicit).

## Design (suggested shape)
- Command veto_task {task_id, reason: minLength enforced} — schema
  rejects empty/whitespace reasons (the mandatory-reason rule is
  the feature); effect: task → vetoed (terminal for the task),
  downstream computed and marked unreachable-by-veto in cycle
  evidence, one decision entry {veto context, the two-option menu}.
- Vetoing in-progress tasks: the current call finishes (pause
  discipline), then vetoed — no mid-call kills.
- UI: strike glyph + reason on hover; the unreachable set dims with
  a linking affordance ("unreachable due to veto of T004"); the
  inbox card renders the menu.
- Ownership: the audit line ("You vetoed T004 — reason: ...") is
  the ownership ledger's showcase entry — coordinate the phrasing
  there (one vocabulary).

## Task slicing
- **T001** command + reason enforcement + state transition + the
  in-progress finish rule + unit tests.
- **T002** unreachable computation reuse + evidence marking + the
  decision entry with the two-option payload + tests.
- **T003** UI strike/hover/dim/link + inbox card + the diamond
  end-to-end (veto one branch mid-run: strike renders, other branch
  completes, decision open, terminal blocked lists the veto).

## Acceptance
- Empty reason refused at schema. Diamond fixture exact (strike,
  unreachable set, sibling completion, terminal accounting).
  Nothing replans without the decision answer; both menu options
  produce their documented effects on fixtures. The reason string
  survives verbatim into audit, report and hover.

## Edge cases & assumption defaults (A9)
- Vetoing an already-terminal task: refused with state. Vetoing
  every remaining task: terminal blocked with an honest "all
  remaining work vetoed" story. Un-veto does not exist in v1 —
  the replan path is the recovery (stated; reversibility here
  would blur the red line).

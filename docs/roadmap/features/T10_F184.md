## Context (existing code & prior features)
Card approval is single-person today; the proposed status exists.

## Design
Curation rules: approve_card/archive_card require the reviewer role or higher (an F175 matrix row); the proposal queue gains lightweight voting (+1/-1 per user, purely informative - a human still approves); card frontmatter gains approved_by and votes{}. A disagreement (documented via -1 plus an F179 comment) escalates as a decision to an operator.

## Task slicing
T001 role enforcement + voting fields + tests. T002 the UI (vote buttons; approve only with the role) + the conflict decision path.

## Acceptance & tests
Approve without the role is 403; votes NEVER change status automatically (property test); approved_by roundtrips stably (F117 loader).

## Risks / anti-goals
No voting automatism (the P2 line); the frontmatter extension is versioned via the schema registry (F245).

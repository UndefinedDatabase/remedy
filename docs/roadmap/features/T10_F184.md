# T10_F184 — Shared card curation
**Tier 10 · Depends on: F120/F149, F175, F177 · Blocks/used by: F211 federation; F247 imports**

## Goal & Done
Team memory gets team governance: approve_card and archive_card
require the reviewer role or higher (a permission-matrix row),
the proposal queue gains lightweight voting (+1/-1 per user,
purely informative — a human still approves), card frontmatter
gains approved_by and votes{}, and a documented disagreement
(a -1 plus a comment) escalates as a decision to an operator.
DONE when the curation commands enforce the matrix cells
person-precise (viewer refused citing the cell; reviewer
approves with their id in frontmatter), votes record per user
with revotes replacing (one voice each), voting NEVER auto-
approves or auto-rejects (the informative-only rule grep-proven:
no vote-count reads in the approval path), the dissent escalation
fires exactly on the documented trigger (-1 with a linked
comment) creating the operator decision with both sides'
material, and single-user curation flows unchanged.

## How it fits (inspect current shape before building)
Card curation exists (the proposal queue, approve/archive through
the gated write path, frontmatter conventions) — this feature
adds the WHO: matrix cells for the commands (reviewer+ — the
F175 role semantics said so; the cells make it enforced),
person-precise frontmatter (approved_by: user id; the write path
threads the actor), and the voting layer as queue-entry metadata
(votes {user: +1|-1, ts} on the proposal — additive, schema-
versioned). Dissent: a -1 whose author also attached an F179
comment (the linkage: the vote command accepts comment_ref?) —
that combination raises the escalation decision (the queue's
decision machinery; payload: the card proposal, the vote tally,
the dissenting comment, the triple framed as "team memory
disputed"). The informative-only rule is architectural: approval
remains the human command; tallies render as context in the
inbox's proposal view (the reference's list treatments).

## Design (suggested shape)
- Matrix rows: approve_card/archive_card → reviewer+; vote_card
  → any authenticated member (viewers may vote — voice without
  power, documented).
- vote_card {proposal id, value +1|-1, comment_ref?}: revote
  replaces; the tally renders in the proposal view; frontmatter
  on approval snapshots votes{} + approved_by (provenance of the
  moment, immutable after).
- Escalation: on a -1 with comment_ref (validated: the comment
  targets the proposal) → the operator decision (dedup: one
  escalation per proposal per dissenter; resolution outcomes:
  approve anyway | reject | send back with guidance — each
  audited).
- Single-user: implicit operator curates as today (the
  regression sweep); votes are inert without other users.

## Task slicing
- **T001** matrix rows + person-precise frontmatter + refusal

- **T002** voting (command, revote replacement, tally rendering,

- **T003** dissent escalation (trigger exactness, the decision

## Acceptance
- Cell enforcement person-precise (fixtures per role). Revotes
  replace; tallies render; approval path reads no counts (grep
  + a behavior fixture: a -5 tally still approvable). The
  escalation trigger exact (a bare -1 does not escalate; -1 +
  comment does, once). Frontmatter snapshots golden.
  Single-user unchanged.

## Edge cases & assumption defaults (A9)
- Votes after approval: refused (the proposal left the queue —
  honest message). Dissenter later revoting +1: the open
  escalation resolves as withdrawn (audited — minds may change).
  Archive disputes: the same escalation path applies to
  archive_card (symmetry, stated).

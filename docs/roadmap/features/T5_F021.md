## Goal & Done
The stream of raw events becomes a story a human can follow: a
humanization catalog maps event kinds to plain lines ("reads file
X", "runs pytest (attempt 2)", "reviewer: 3 findings"), a NowCard
shows the newest action with an activity dot, and feed rows carry
their seq and click-jump to their node in the graph. DONE when the
catalog covers every Part E event kind (unknown kinds render an
honest generic line, never vanish), the feed renders fixture
streams per the binding CSS, jump-to-node focuses correctly, and
the steering input renders DISABLED with the honest tooltip until
its backing feature exists.

## How it fits (inspect current shape before building)
The same SSE hook feeds graph and feed — one subscription,
fan-out in the client store (no second connection); humanization
is a pure catalog module (event → line + optional detail), so it
is golden-testable headless and reusable by the CLI's future
verbose views. Jump-to-node needs a node id the stream does not
carry today: measured at 4a7b5cbf, `_safe_event_summary` in
`packages/orchestration/ui_server.py` emits exactly seq, event,
timestamp and outcome and drops the task linkage, so DECISION
F021 D2 adds ONE additive field at that single-writer seam rather
than inventing a second client-side mapping. The steering input
is a design
element of this surface but its command lands with F030: render
it disabled with the tooltip pattern the design reference
prescribes for not-yet features — visible honesty over hidden
UI.

## Design (binding specifics)
- `humanize.ts`: kind → template with typed slot filling from
  the envelope (paths shortened per the reference's truncation
  rule, counts pluralized); severity accents (findings, failures)
  via tokens; unknown kind → "<kind> event" generic (counted in
  a dev console note).
- Feed + rows, binding CSS core:
```css
.feed{width:340px;max-height:52vh;overflow:auto;border-radius:var(--remedy-radius-lg);
  background:var(--remedy-card);backdrop-filter:blur(14px);box-shadow:var(--remedy-shadow-soft)}
.feed-row{display:flex;gap:10px;padding:9px 14px;font:500 13px/1.45 var(--remedy-font-ui);color:var(--remedy-ink)}
```
  Rows: time (mono, relative), the humanized line, a kind glyph
  dot; hover reveals seq; click emits focus(nodeId) to the graph
  store; auto-scroll pinned to newest with a "jump to live"
  affordance when the user scrolled up (never yank the scroll).
- NowCard: the newest ACTION-class event (a documented subset —
  heartbeats and bookkeeping excluded) with the activity dot
  pulsing on recency (motion tokens), fading to idle after a
  config quiet window.
- Steering input: rendered, disabled, tooltip "steering lands
  with F030" — one flag flip when it does.

## Task slicing
- **T001** the humanize catalog + coverage test against the kind
  set DECISION F021 D1 rules, because no "Part E kind list"
  exists: measured at 4a7b5cbf, `RunEvent.event` is an
  unvalidated free string and the four defined kind sets are
  pairwise disjoint. A kind in that set without a template fails
  the coverage test (drift protection), and the emission sites
  that compute their kind at runtime are covered by the
  unknown-kind generic line instead + goldens.
- **T002** feed + NowCard components on fixture streams + the
  scroll/jump behaviors + CSS conformance.
- **T003** graph-focus wiring + the disabled steering + a live
  fake-job end-to-end (story reads correctly start to finish).

## Acceptance
- Catalog coverage complete (the failing-on-new-kind test);
  goldens for the canonical kinds; unknown-kind generic renders.
  Scroll never yanks; jump focuses the right node (fixture ids).
  NowCard tracks action events only; the dot's recency behavior
  per tokens. Steering disabled + tooltip asserted.

## Edge cases & assumption defaults (A9)
- Event bursts: row virtualization beyond a threshold (measure
  first per the perf discipline); the feed keeps a bounded window
  with "earlier events in the timeline" (the scrubber feature owns
  deep history). Localization: English now like all product
  surfaces; the catalog's template structure keeps future locales
  possible without promising them.

# T1_F051 — Escalate instead of block (unattended)
**Tier 1 · Depends on: F050, F046 (the backend decision queue already exists in the codebase) · Future UI integration: F031 inbox UI · Blocks/used by: long-run throughput**

## Goal & Done
See ROADMAP.md F051; the Done criterion there is binding.

## Context (existing code & prior features)
An unattended run must not stall on the first human question.

## Design
In multi-cycle runs decision.requested pauses only its branch; the executor pulls the next ready task (path/fence disjoint from the waiting branch). The final/interim report lists open decisions prominently; the notification hook (F059, Tier 3) attaches later. CLI-first answering (Part B): `remedy decisions list` and `remedy decisions answer <id> approve|reject [--note]` write directly into the decision queue with full audit - the same queue F009 later feeds from the UI.

## Task slicing
T001 executor integration + fixture (1 blocked / 2 free) + tests. T002 the decisions CLI (list/answer with audit entries) + tests.

## Acceptance & tests
The unattended run delivers 2 results + 1 waiting decision; the disjointness assertion holds.

## Risks / anti-goals
NEVER auto-decide (P2), no matter how obvious the answer looks.

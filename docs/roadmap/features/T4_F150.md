# T4_F150 — Card value & exploration chance
**Tier 4 · Depends on: F118, F103, F123 · Blocks/used by: self-measuring memory**

## Goal & Done
Card value stops being an opinion: value changes ONLY through
defined signals — attach + task pass without repair: +w1 (default
.10); pass after repair: +w2 (.03); task fail with the card in
scope of the failure class: −w3 (.05); plus a bounded periodic
correction from the KPI aggregates — smoothed exponentially into
[0,1] with rank thresholds bronze <.25 ≤ silver <.5 ≤ gold <.75 ≤
platinum, and the exploration slot from the selector gains its
meaning: low-value cards earn occasional chances instead of
starving. DONE when the update rule reproduces golden trajectories
on fixture histories, every value change is journaled with its
signal, ranks render everywhere values show, and no other code path
can move a value.

## How it fits (inspect current shape before building)
The selector already reads value and reserves the exploration slot
(seeded deterministic rotation) — this feature makes the number
mean something; attached_cards per task outcome is in evidence and
on ledger rows (the KPI plumbing) — the updater consumes THOSE at
task finalization (the same seam the KPI writer used; one walker).
Values live in card frontmatter (the store owns writes — the
updater goes through the store API, which permits the value field
programmatically while body edits stay human/gated; a narrow,
documented exception).

## Design (suggested shape)
- `card_value.py`: on_task_finalized(task, outcome) → per attached
  card compute the signal (pass_clean | pass_after_repair |
  fail_in_scope | neutral — fail_in_scope requires the failure's
  class/paths to intersect the card's scope; an attached card
  scoped elsewhere at a failure is neutral, documented), apply
  Δ = w·direction into an exponential smoothing toward [0,1]
  (formula in the docstring, golden-tested), journal {card, task,
  signal, before, after} to a per-project value journal (append-
  only, the audit trail).
- Periodic correction: the KPI aggregates (per class contrast)
  produce a BOUNDED adjustment (cap per period, config) toward
  cards whose classes show contrast — applied via the same journal
  with signal kpi_correction; observational honesty carries into
  the journal note.
- Ranks: pure thresholds; rendered in the collection tiles, graph
  popovers, funnel evidence (the neutral placeholders flip live).
- Exploration meaning: unchanged mechanics, now consequential —
  the docs explain the loop (low value → occasional attach →
  chance to earn signals) and the journal proves it happens.

## Task slicing
- **T001** the updater + signal derivation (fail_in_scope
  intersection rules) + smoothing + journal + golden trajectories
  (a card through mixed outcomes reaches the exact expected value).
- **T002** the finalization-seam wiring (shared walker) + the
  store's narrow value-write exception + no-other-path guard (grep
  + API test).
- **T003** kpi_correction bounded pass + rank rendering flips + the
  end-to-end (fixture history → values, ranks, journal complete).

## Acceptance
- Golden trajectories exact; journal reconstructs every value
  bit-for-bit (replay test). fail_in_scope intersection fixtures
  (in/out of scope) correct. The correction never exceeds its
  bound; its journal notes carry the observational label. Value
  writes outside the updater are impossible (guard).

## Edge cases & assumption defaults (A9)
- The pinned dossier card: exempt from value (always attached —
  signals would be meaningless); rendered as pinned, not ranked.
  Weight tuning: config with the defaults above; changes are
  config diffs, journaled forward (no retroactive rewrites —
  history is history).

# T4_F150 — Card value & exploration chance
**Tier 4 · Depends on: F118, F103, F123 · Blocks/used by: self-measuring memory**

## Goal & Done
See ROADMAP.md F150; the Done criterion there is binding.

## Context (existing code & prior features)
Card value must be earned by measurable outcomes only.

## Design
card_value.py - value changes ONLY through signals:
attach + task PASS without repair: +w1 (default .10) | PASS after repair: +w2 (.03)
task FAIL with the card in scope of the failure class: -w3 (.05)
periodic A/B correction from F123 aggregates (bounded adjustment).
Exponential smoothing toward [0,1]; ranks bronze<.25<=silver<.5<=gold<.75<=platinum.
Selector exploration: a reserved share (default 20%) of the card budget goes to proposed/low-value cards, drawn DETERMINISTICALLY from a job-seed PRNG (seed=job_id) - reproducible 'luck'. uses increments on attach; a property test proves no other code path writes value.

## Task slicing
T001 value updater + signal wiring + property test. T002 exploration draw + distribution test + rank rendering (F119 dots).

## Acceptance & tests
Selection distribution over 100 fixture tasks ~ 80/20 (tolerance); value changes trace to signals 1:1; job-seed reproducibility.

## Risks / anti-goals
NEVER an LLM judgment on value; weights live in config with documented defaults.

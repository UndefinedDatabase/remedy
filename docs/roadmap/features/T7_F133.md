# T7_F133 — Provider trust score
**Tier 7 · Depends on: F103, F010 · Blocks/used by: routing wisdom, F226**

## Goal & Done
Which model earns which work becomes rolling, queryable fact: per
model+role, trust aggregates PASS quota, repair need, format-error
rate and cost per PASS from the ledger and postmortems; `remedy
stats trust` renders it; routing consumes it as a RECOMMENDATION —
changes remain config + ADR. DONE when the aggregation matches
goldens on a fixture history, every metric names its window and
sample size, the existing provider-trust module is EXTENDED (not
shadowed) after inspection, and the recommendation path is the
documented human one.

## How it fits (reconciliation with existing code — inspect first)
provider_trust.py and provider_trust_verification.py ALREADY exist
in the codebase — the first order is a findings pass: what do they
compute today, over which sources, consumed where? This feature
grows THAT module to the full metric set on ledger/postmortem
sources (A6: one trust home; a second trust notion is the reject
condition), reconciling any older ad-hoc metrics into the
documented four (plus derived cost-per-PASS from normalized costs
once the pricing feature lands — until then token-basis with the
label). Windows and floors follow the calibration feature's
discipline (rolling window config, small-n honesty).

## Design (suggested shape)
- Metrics per (model, role, window): pass_quota (task terminals
  where this model served the role), repair_need (repair rounds
  per task), format_error_rate (parse-class postmortems per call),
  cost_per_pass (basis-labeled); each with n.
- Sources: ledger rows (model/role per call — recorded since the
  routing feature), task outcomes joined via job records,
  postmortem classes; pure aggregation, snapshot-cached like
  calibration.
- `remedy stats trust [--role] [--json]`: the matrix with n and
  window; deltas vs the prior window; the recommendation line per
  role where a clear leader exists ("consider routing review to X
  — adopt via config + ADR") with the promotion-discipline
  reference.
- Routing consumption: trust renders IN routing's context (the
  resolver may log "trust suggests otherwise" as an informational
  evidence note when config contradicts a strong signal — inform,
  never override; the wording tested).
- F226 kinship (later auto-routing experiments) reads this store —
  the schema versions accordingly.

## Built State — what F133 delivered (2026-10-23)

`main` at `11fda065b`; DECISIONs F133 D1 to D4 in `.agent/decisions.md` rule each slice, and

- T001: the findings pass, `.agent/f133_inventory.md`. The provider-trust pair this file names was
  deleted at `0242c0a3b` and gated patch candidates, never a model's record, so the one trust home
  is a new module (D1). The reviewer added one source the inventory missed: a ledger row's model is

- T002: `packages/orchestration/model_trust_score.py` measures, read-only, per model and role inside
  a window of `model_routing.trust_window_days` (90), the pass quota and the repair need over
  settled tasks, the format-error rate over calls and the cost per pass with its basis
  (`provider_reported`, `price_table`, `mixed`, `tokens` or `unknown`), each with its `n`. The role's
  last call names the model that served a task; a row below `model_routing.trust_sample_floor` (20)
  settled tasks is thin. The table is saved as `model_trust_snapshot.json` beside the ledger and
  measured again after `model_routing.trust_snapshot_max_age_seconds` (3600). Unattributed calls and
  unsettled tasks are counted, never guessed.
- T003: `remedy stats trust [--role] [--project] [--json]` shows the matrix with `n` and the window
  on every figure, the change against the prior window, and one recommendation line per role: a
  clear leader leads the next eligible model by at least ten points, and the line says the change is
  made through config and an ADR (D3). `remedy job plan-show` prints "Trust suggests otherwise" for
  a role whose configured model a clear leader outranks, and never changes the job record (D4). The
  per-tier record stays F296's own; this module computes nothing per tier (D3).
- `tests/regression/test_f133_acceptance.py` holds the Done line through the command line; the

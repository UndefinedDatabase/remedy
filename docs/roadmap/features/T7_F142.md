## Goal & Done
The numbers that sell live on one route: /trust tiles autonomy
share, PASS trend, cost per feature class, card effectiveness,
model trust and churn — and EVERY tile deep-links its raw-data
query (the ledger view or stats call that produced it). DONE when
each tile renders its owning feature's numbers verbatim (no
re-aggregation in the UI — the one-arithmetic-home rule), every
deep link lands on the reproducing query/evidence, small-n and
basis labels survive onto the tiles uncompressed, the route
renders per the design reference at fixture scale, and a
consumers-loop test proves each tile against its stats source.

## How it fits (inspect current shape before building)
Pure read composition — every number already has a home with
honesty labels: autonomy stats (share + trend), the ladder/bench
(PASS trend), the ledger + calibration (cost per class), the
memory KPI (card effectiveness with its correlation header),
provider trust (model matrix), churn (ratios + measurable-from).
The dashboard endpoint FANS OUT to those computations (or their
snapshots) and returns tile payloads {value(s), n, window, basis/
caveat, deeplink} — the UI renders payloads, computes nothing
(the cost ticker's display-only discipline, dashboard-wide).
Deep links: each stats surface already has a CLI/json form —
tiles link the cockpit's corresponding views where they exist
(trust matrix view, churn view) or the evidence/json route
(honesty over polish; views deepen later).

## Design (suggested shape)
- Endpoint: /api/projects/<id>/trust → the six tile payloads;
  per-tile failure isolation (one source erroring renders that
  tile's honest error state, the rest live — the status view's
  degraded-value pattern).
- Tiles per the reference's tile treatment: headline value,
  trend spark (data points from the owning feature's snapshots),
  the caveat line (small-n, basis, correlation header — REQUIRED
  rendering, not tooltip-buried; the honesty is the product),
  the deep-link affordance.
- The consumers-loop test: for each tile, compute via the owning
  stats API on the fixture data and assert payload equality —
  the anti-drift contract; new tiles must join the loop.
- Caveat fidelity: a grep-style test that the owning features'
  exact caveat strings appear (the correlation header verbatim
  on the card tile, measurable-from on churn).
- Refresh: on-load + manual; no polling (calm by default).

## Task slicing
- **T001** the endpoint + fan-out + failure isolation + payload
  contracts + the consumers-loop test.
- **T002** tiles + sparks + caveat rendering + deep links +
  component tests per tile state (healthy, thin-data, error).
- **T003** the route composition per reference + the end-to-end
  on seeded fixture stores (all six live, one source broken →
  five live + one honest error).

## Acceptance
- Consumers loop green (payloads equal owning-API outputs).
  Caveats verbatim (grep). Every deep link resolves (walk test).
  UI computes nothing (code audit + no arithmetic on payload
  values beyond formatting). Failure isolation per fixture.

## Edge cases & assumption defaults (A9)
- Young projects (everything thin): the dashboard renders
  honestly sparse with the invitation lines (run more, the
  numbers will come) — designed empty states per reference, not
  apologetic blanks. Cross-project trust: the project switcher
  scopes; an all-projects rollup is later (noted).

# T0_F017 — Scope fences
**Tier 0 · Depends on: none · Later integrates: F014 renders/edits fences in the Flight Plan · Blocks/used by: F141 basis, safe unattended runs**

## Goal & Done
See ROADMAP.md F017; the Done criterion there is binding.

## Context (existing code & prior features)
Nothing prevents a builder from touching arbitrary paths or bumping dependencies silently.

## Design
`scope_fences.py`: FenceSpec{protected globs, forbidden_actions (dependency_change|delete_file|network|schema_migration), must_touch}; sources: project defaults in config + per-job overrides. Enforcement: (a) prompt injection of fences into the task header, (b) post-run diff checks (protected touched -> hard fail class fence; must_touch untouched at job end -> warning), (c) manifest/lock files implicitly protected unless explicitly allowed.

## Task slicing
T001 module + diff checker + one test per violation type. T002 prompt injection + flight-plan/UI chips (editable pre-start).

## Acceptance & tests
A builder fixture touching a protected file fails with a precise repair hint.

## Risks / anti-goals
Fences are not sandboxing (that is F085/F162); the network fence is honestly documented as soft in v1.

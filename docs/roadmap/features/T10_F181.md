# T10_F181 — Team ownership & contribution view
**Tier 10 · Depends on: F177, F035 · Blocks/used by: retros; F210**

## Goal & Done
Who carried what becomes visible — as contribution, never blame:
ownership_agg.py aggregates per person and period — decisions
(approve/reject by type), steering hints, vetoes, reviews, card
curation — rendering as a cockpit 'Team' tab and `remedy stats
team --since`, with csv/md export for retros; the tone rule is
part of acceptance (a CONTRIBUTION record, wording reviewed).
DONE when aggregation matches goldens on multi-user fixture
histories (each source counted per its person-precise records),
periods and filters behave exactly, exports round-trip, the tab
renders per the reference's team treatments with empty states for
thin data, the wording review is a named acceptance step (no
ranking language, no productivity framings — the documented
vocabulary), and everything is a pure read (state diff proves
no writes).

## How it fits (inspect current shape before building)
Pure aggregation over person-precise stores that F177 unlocked:
the ownership ledger (F035 — its actor field now real users),
decision records (resolved_by + decision types), steering notes
(origin+author), veto commands (audit), human-review verdicts
(F180), card curation actions (F184's approve/archive — the
forward dependency is soft: the source registers when it lands,
the aggregator's source registry pattern makes that additive).
The snapshot-cache discipline applies (aggregation over long
histories is not free); the source registry mirrors the
consumers-loop idea in reverse: each source declares its
extractor, and the completeness test enumerates registered
sources against the person-precise surfaces (new surfaces
should join — the guard).

## Design (suggested shape)
- `packages/org/ownership_agg.py`: aggregate(period, project) →
  per user {decisions {approved, rejected, by_type}, steering,
  vetoes, reviews {approved, changes_requested}, curation} with
  n and the period; the source registry {source → extractor}.
- Renderings: the Team tab (per-person cards with contribution
  counts, the period selector, deep links to the underlying
  records — the trust dashboard's deep-link discipline);
  `remedy stats team --since [--json|--csv|--md]`.
- The tone rule as code+review: no ordering by totals in the
  default rendering (alphabetical — ranking is a retro's human
  choice, not the tool's), no rate/velocity derivations, the
  vocabulary constant ("contributed", "carried", never
  "performance") — the wording review checks renderings against
  the documented list.
- Legacy: operator(legacy) aggregates as its own row (honest
  history).

## Task slicing
- **T001** the registry + extractors per source + aggregation +
  goldens on multi-user fixtures + the completeness guard.
- **T002** stats CLI + exports + snapshot caching + period/
  filter exactness tests.
- **T003** the Team tab (cards, selector, deep links, empty
  states) + the tone/wording review artifacts + the end-to-end
  (a two-user fixture history → tab and CLI agree — the
  consumers-loop test).

## Acceptance
- Goldens exact per source and person; legacy rows honest.
  CLI/tab agree (loop test). Exports round-trip. Default
  ordering alphabetical (the no-ranking test); the vocabulary
  scan passes renderings. Pure read (state diff). Deep links
  resolve.

## Edge cases & assumption defaults (A9)
- Users deactivated mid-period: their contributions render with
  the inactive marker (history is history). Cross-project
  periods: per-project v1; the org rollup is F210 territory
  (noted). Tiny teams (n=1): the tab renders without
  comparative framing (it's a mirror, not a contest —
  the empty-state spirit).

## Orchestrator brief
Gate on the person-precise surfaces. The no-ranking/vocabulary
rules go verbatim — the wording review is a scheduled human
step, not a suggestion. T001's registry guard keeps future
surfaces honest.

## Do not touch
Source record formats, retro processes (the tool serves them),
comparative analytics (deliberately absent). Suggested tests:
tests/org/test_ownership_agg.py.

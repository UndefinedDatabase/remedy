## Goal & Done
Nothing in the cockpit is jargon without a hand to hold: a tooltip
catalog — ONE source — covers every metric, status and term; an
audit test proves no term lacks an entry and no entry is a dead key;
a six-step first-run tour introduces the shell with a prominent
skip; '?' opens the catalog as a searchable panel. DONE when the
audit passes on the real shell (and fails when a term is added
without an entry — the drift guard), tooltips render per the
reference from the catalog alone, the tour runs once with skip/
never-show honored, and catalog content follows the honesty
vocabulary (bases, estimates, scrubbed/live) already established.

## How it fits (inspect current shape before building)
The catalog is the humanize catalog's sibling for STATIC vocabulary:
a keyed module (term → {title, body ≤ bound, learn_more anchor?})
consumed by a Tooltip component every surface uses (the audit walks
rendered surfaces' data-term attributes against the catalog — the
mechanism: terms are declared via the component, so coverage is
greppable both directions). Content sources: the definitions already
written into features (autonomy metrics' --explain, basis labels,
the ladder's criteria, scrubbed/live) — the catalog QUOTES those
single sources or anchors to them rather than re-authoring (one
truth per definition, the recurring rule).

## Design (suggested shape)
- `terminology.ts` (or equivalent per frontend conventions): the
  catalog; entries reference their backend definition source in a
  comment (review traceability); learn_more anchors deep-link
  (evidence panel, docs).
- Tooltip component per the reference (delay, placement, focus/
  keyboard triggering — a11y basics here even before the full
  a11y feature); every metric/status/term renders through it with
  data-term.
- The audit test: collect data-term across rendered fixture
  surfaces (shell, inbox, ticker, ladder view, memory) → every
  term in catalog; every catalog key used somewhere → no dead
  keys. New-term drift fails visibly.
- First-run tour: six steps (graph, timeline, feed/NowCard, inbox,
  chat, palette), spotlight mechanics shared with the result tour
  (one overlay engine — reuse), skip prominent, never-show
  persisted; re-launchable from '?'.
- The '?' panel: searchable catalog list, keyboard-openable
  (palette integration noted).

## Task slicing

## Acceptance
- Audit green on the real shell, red on both drift fixtures.
  Tooltip content matches sourced definitions (spot goldens: basis,
  scrubbed, urgency formula). Tour runs once, skip/never-show
  honored, re-launchable. Overlay engine shared (import proof).

## Edge cases & assumption defaults (A9)
- Terms with context-dependent meaning (e.g. "blocked" task vs
  job): keyed variants (blocked.task/blocked.job) — the audit
  enforces the specific key. Localization: English, structure
  locale-ready, no promises (the feed's stance).

## Orchestrator brief
T001's content sourcing rule (quote/anchor single sources) is the
anti-drift architecture — verbatim into the order with the source
map. The audit is the feature; ship it before content polish.

## Do not touch
Definition sources' wording (quoted, not edited), the result
tour's stops, docs site content. Suggested tests: the audit suite
+ tooltip component tests.

**T001 — the catalog, the term and its tooltip.** `apps/ui/src/api/terminology.ts` holds
`TERM_CATALOG`, the one home of every explanation: each entry a title, a plain-language body of at
most 240 characters, the file that defines the term and a phrase that file states.
`terminology.test.ts` reads every such file back and fails when its phrase is gone, which is how the
catalog quotes a single source without copying it (DECISION F043 D1).
`apps/ui/src/components/term/Term.tsx` wraps a word, writes its key into `data-term`, and opens a
glass tooltip portalled into the page body, at once on keyboard focus and after 120 ms on hover; a
term inside a button opens on hover only (D2), and a tile's live breakdown shows under the
explanation (D3). The terms cover the live-status pill, the timeline's phases, the metrics bar's
tiles, the right panel's cards, the task list's states, the NowCard's Live badge and the graph's
SCRUBBED badge. The timeline's hint map and the metrics bar's own tooltip are deleted, since the
term replaced them.

**T002 — the audit.** `apps/ui/src/api/terminologyAudit.ts` reads the `data-term` values of rendered
markup and answers the terms the catalog lacks and the keys nothing renders.
`components/term/termAudit.test.ts` renders the real right panel, the metrics bar, the pill in each
state and the timeline, requires both directions empty, and holds two drift fixtures red; the graph

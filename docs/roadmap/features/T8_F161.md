# T8_F161 — MCP passthrough with policy
**Tier 8 · Depends on: F009 audit, F004, F152 · Blocks/used by: F172 packs; enterprise readiness**

## Goal & Done
See ROADMAP.md F161; the Done criterion there is binding.

## Context (existing code & prior features)
Workers like Claude Code can use MCP servers; F152 isolation currently blocks ALL host MCP config. Controlled passthrough is missing.

## Design
.remedy/policy/mcp_allowlist.toml: [[server]] name/url/tools=[{name, class: read|write|external}]. The call builder generates a worker-specific MCP config inside the isolated temp HOME (F152) - the worker sees ONLY what is allowed. Tool calls surface as run.tool_call events (F004) with server+tool; a post-hoc checker flags calls outside the list (where adapter-side prevention is impossible) as high review findings + an optional task-fail policy; write/external classes require an F141 matrix row.

## Task slicing
T001 allowlist format + per-adapter config generator + tests. T002 event enrichment + the post-hoc checker + F141 coupling + a fixture (an unlisted tool -> finding/block).

## Acceptance & tests
A worker with a poisoned host MCP config reaches only allowlisted servers (A/B like F152); the audit shows every MCP call; an external-class call without a matrix permission fails cleanly.

## Risks / anti-goals
The default is an EMPTY allowlist (opt-in per project); no wildcards for write/external.

# T7_F132 — Review tournament
**Tier 7 · Depends on: F082 · Blocks/used by: reviewer calibration, F159 kinship**

## Goal & Done
Reviewer choice becomes measured, not assumed: the SAME curated
diff set goes to two or three reviewer models against ground-truth
findings, precision and recall land per model per finding class,
and the output is a reviewer-routing RECOMMENDATION — benchmark-
only machinery that never touches production runs by itself. DONE
when the tournament runs the curated set across configured models
with per-class precision/recall matching goldens on scripted
fakes, ground-truth matching is deterministic (finding identity
rules documented), the recommendation renders with sample sizes
and the config+ADR path stated, and tournament costs are visible
and bounded.

## How it fits (inspect current shape before building)
This is the bench harness's reviewer sibling: a frozen DIFF SET
(fixture diffs with curated ground-truth findings — seeded bugs
with known classes: logic, edge case, security, style) run through
the review call per candidate model; matching uses the finding-
identity notion the harvesting feature established (rule/normalized
message + location tolerance — import, extend for ground-truth
matching with a documented location window). Results append to a
tournament history (the bench history pattern); the recommendation
feeds routing the way trust scores do — as INPUT to a human config
change with an ADR, never an automatic flip (the promotion
discipline verbatim).

## Design (suggested shape)
- The set: diffs/<case>/ {diff, context files, ground_truth.json
  [{class, location, description}]} — versioned, frozen like bench
  orders (changes start a new series); rationale comments per case.
- Runner: per model × case → findings → match against truth
  (matched/missed/extra) → per-class precision/recall + per-case
  detail; history JSONL under the data root; the same call budgets
  and evidence as any review.
- Matching determinism: identity = class + location within the
  window + description similarity above a threshold (documented,
  table-tested — the matcher is the science here; ambiguous
  matches resolve by the documented tie-break and are FLAGGED for
  human curation of the truth set).
- Output: `remedy stats tournament` — the matrix, sample sizes,
  the recommendation line ("model X leads on security recall
  (n=12) — to adopt: config + ADR"), cost of the tournament run.
- Kinship note: the scoreboard feature (F159) reuses this runner
  shape across vendors — factor accordingly (shared runner core,
  two front-ends), stated for that feature.

## Task slicing
- **T001** the curated set (initial cases per class with
  rationale) + the matcher + table tests (match/miss/extra,
  window edges, ambiguity flags).
- **T002** the runner + history + per-class aggregation + goldens
  on scripted fakes (a model missing all security findings scores
  zero recall there).
- **T003** the stats view + recommendation phrasing + cost line +
  docs (the config+ADR adoption path) + the end-to-end.

## Acceptance
- Matcher table exact; ambiguity flagged not guessed. Scripted
  goldens exact per class. History append-only, series-versioned.
  The recommendation never edits config (state diff); its
  phrasing carries n and the adoption path. Costs visible.

## Edge cases & assumption defaults (A9)
- Models refusing the schema (format failures): recorded as
  format_error per case, excluded from precision math but SHOWN
  (a reviewer that can't answer is a result, not a gap). Truth-set
  maintenance: curation is human, via normal PRs — the runner
  validates truth-set shape and refuses malformed cases.

## Orchestrator brief
Gate on the bench harness + the finding-identity helper. T001's
matcher tests are the science — enumerate the window/tie-break
cases in the order. The never-auto-adopt rule verbatim.

## Do not touch
Production review routing (recommendation only), the bench order
set, trust-score mechanics. Suggested tests:
tests/orchestration/test_review_tournament.py.

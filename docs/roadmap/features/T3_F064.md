# T3_F064 — Idea queue UI/CLI
**Tier 3 · Depends on: F063 · Blocks/used by: idea flow**

## Goal & Done
Proposals get a human gate with memory: ideas can be approved (creating
a DRAFT job plan with the idea reference, never autostarting),
denied (with the denial remembered so the same idea is never
re-proposed), and reprioritized — all from the CLI now, UI later. DONE
when approve produces a planned-but-unapproved job traceable to the
idea, deny writes the dedup hash into a permanent denial memory the
engine consults, and every transition is audited in the idea record.

## How it fits (inspect current shape before building)
Ideas live in the per-project store with a dedup hash (previous
feature); approval reuses the ENTIRE golden-path planning machinery —
an approved idea becomes a normal job whose mission text is composed
from the idea (title + rationale + areas as context refs), flowing
through intake, job plan and the standard human plan-approval gate;
there is no second execution path (A6). The idea engine consults the
denial memory before appending — that check lands here and is wired
back into the engine's append path.

## Design (suggested shape)
- Transitions on the idea record (status + audit trail entries {ts,
  actor, action, note}): proposed → approved | denied; priority is an
  orderable field (small int) with reprioritize as an audited edit;
  denied is terminal for that hash.
- `remedy ideas approve <id> [--yes]`: compose the mission text
  (deterministic template from the idea fields, golden-tested), create
  the job with idea_ref, run intake+plan; WITHOUT --yes the plan
  approval stays open as usual — approve means "plan it", not "run it"
  (the wording in the CLI output says exactly that). `deny <id>
  [--note]` sets status, appends the hash to denied_hashes;
  `reprioritize <id> --prio N`.
- Denial memory: a small per-project denied-hashes file; the engine's
  append path drops matching new ideas with a counted log line
  ("suppressed: previously denied") — visible suppression, not silent.
- `remedy ideas list [--status]` gains priority ordering and shows the
  idea→job link once approved.

## Task slicing
- **T001** transitions + audit trail + denial memory + engine
  consultation + unit tests (deny → engine suppresses the same hash;
  suppression counted).
- **T002** approve → mission-text composition (golden) → job with
  idea_ref → plan-approval-still-open assertion + tests.
- **T003** CLI surface + list ordering + docs; end-to-end fixture:
  propose → deny one (never returns) → approve one → answer the plan
  approval → run completes with idea_ref in report.

## Acceptance
- Approve creates exactly one job, planned, approval open, idea_ref in
  evidence and report. Deny is permanent across engine runs (fixture
  re-proposes → suppressed). All transitions audited; illegal
  transitions (approve a denied idea) refused with the state named.

## Edge cases & assumption defaults (A9)
- Editing an idea before approval is out of scope v1 — approve/deny/
  reprioritize only; a human wanting changes writes their own mission
  (cheaper than an edit UI). Approving with a stale evidence ref
  (source vanished): allowed with a warning — the provenance feature
  formalizes staleness next.

# T3_F063 — Idea engine v1
**Tier 3 · Depends on: F053, F005 · Blocks/used by: F064-F066**

## Goal & Done
Remedy starts proposing follow-up work — with receipts: after a job
finishes, an idea pass reads the report, diff summary and DoD gaps and
emits structured ideas (title, rationale, effort band, benefit, areas,
MANDATORY evidence references) into a per-project idea store with
status proposed. DONE when a fixture job yields schema-valid ideas
whose every claim carries a resolvable evidence reference, idea
generation is a labeled side-role call that never blocks or fails the
job, and nothing is ever executed from an idea without the human gate
(next feature).

## How it fits (inspect current shape before building)
This is a post-terminal hook beside report writing — same funnel, same
never-block discipline as notifications (cite the pattern). The idea
call is a side-role provider call (cheap/local routing applies) with a
versioned schema through the standard validation; the store follows
the data-root project-area convention (append-friendly jsonl file is
fine here — small, human-greppable, per-project; the ledger precedent
does not force sqlite where queries are trivial).

## Design (suggested shape)
- Schema `Idea` (versioned "idea_v1"): title, rationale, effort_band
  (S|M|L|XL), benefit (one sentence, outcome-phrased), areas (paths/
  modules), evidence_refs (min one; typed later by the provenance
  feature — v1 requires at least existing evidence paths), status
  (proposed), created_from (job id), created_at, dedup_hash
  (title+areas normalized — the queue feature uses it).
- `idea_engine.py`: on_terminal(job) → build the prompt from report +
  diff stat + unmet/non-blocking DoD rows + open assumptions → one
  side-role call → validate → append valid ideas (cap per job, config,
  default ~5) to `<project area>/ideas.jsonl`; invalid output → one
  parse retry then a logged miss, job unaffected.
- Honesty rules in the prompt AND validated where mechanical: benefits
  must not promise metrics the evidence doesn't show; every idea's
  evidence_refs must resolve at creation (checked against the
  filesystem/store — unresolvable refs drop the idea with a log).
- Config: ideas.enabled (default on for terminals of real runs, off
  for rehearsals), cap, role routing inherited.
- CLI (thin, read-only here): `remedy ideas list` (status, title,
  band, refs count) — management commands are the next feature.

## Task slicing
- **T001** schema + store append/read + dedup hash + unit tests.
- **T002** the engine hook + prompt + validation + ref resolution +
  never-block tests (provider down → job unaffected, miss logged).
- **T003** list CLI + caps/config + fixture end-to-end goldens (a
  DoD-gap fixture yields the expected idea shape).

## Acceptance
- Fixture terminal yields ≤cap schema-valid ideas, every ref resolving;
  an idea with a dead ref never lands. Provider failure leaves the job
  terminal untouched. Rehearsals produce zero ideas. Store is valid
  jsonl after crashes mid-append (atomic line writes — reuse the
  pattern).

## Edge cases & assumption defaults (A9)
- Duplicate ideas across jobs are allowed at v1 (the queue's denied-
  hash memory handles re-proposals after human denial — that's the
  meaningful dedup). Idea language: English, like all repo artifacts.

## Orchestrator brief
Gate on report + routing. The mandatory-evidence rule is the feature's
character — make ref-resolution-at-creation an explicit acceptance
line and reject prompt-only enforcement.

## Do not touch
Approval/deny flows (next feature), continuous mining (v2), provenance
typing (later). Suggested tests:
tests/orchestration/test_idea_engine.py.

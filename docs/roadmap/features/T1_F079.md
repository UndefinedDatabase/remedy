# T1_F079 — Context handoffs
**Tier 1 · Depends on: F071, F047 · Blocks/used by: long missions across sessions**

## Goal & Done
Session and context-window boundaries stop losing knowledge: at a
boundary, Remedy packages the dossier, the latest checkpoint reference,
open decisions and the next intent into a handoff artifact plus a
rendered prompt block, and the successor context resumes from it with
MEASURED recall. DONE when the recall eval (facts seeded before the
boundary, queried after) passes its threshold on a fixture mission, and
the handoff is a pure artifact — producing it changes no state.

## How it fits (inspect current shape before building)
The dossier is the compact memory; checkpoints anchor execution state;
open decisions live in the queue; the orchestrator loop assembles
context. A handoff is a SNAPSHOT COMPOSITION of those sources into one
versioned artifact — no new state, no new truth. The recall harness
built for the dossier is reused with a simulated boundary.

## Design (suggested shape)
Module `handoff.py`:
- `build_handoff(mission_id) -> path`: compose handoff.json (schema-
  versioned: dossier text, checkpoint reference + worktree head, open
  decisions with ids, next intent, provenance timestamps) and a rendered
  handoff.md prompt block (fixed section order, dossier first) into the
  mission's evidence area; idempotent per state (same inputs → same
  content hash).
- Boundary triggers v1: explicit (`remedy mission handoff <id>`) and
  loop-integrated (the loop builds one whenever it terminates for limits
  or stop — so every pause is resumable by a fresh context). Automatic
  in-flight context-pressure detection is NOT v1; document that.
- Consumption: the loop's context assembly accepts a handoff as the
  seed for iteration one of a resumed mission; consuming verifies the
  checkpoint/worktree references still hold (the checkpoint feature's
  rules) before trusting the narrative.
- Measurement: the recall eval runs a fixture mission, seeds ten facts
  (decisions, risks, constraints), forces a boundary, resumes from the
  handoff alone in a fresh context, and asserts a documented recall
  threshold on OPEN items (resolved items may compress — same asymmetry
  as the dossier).

## Task slicing
- **T001** schema + composer + idempotence + unit tests (missing sources
  render as explicit gaps, never invented).
- **T002** triggers + loop consumption + reference verification + tests
  (stale worktree head → refuse with the checkpoint feature's message).
- **T003** the boundary recall eval on a fake-provider mission + the
  threshold assertion.

## Acceptance
- Same mission state → byte-identical handoff (hash test). Resume from
  handoff alone completes the fixture mission. Recall threshold met for
  open items; the eval report archived as evidence. Building a handoff
  mutates nothing (state snapshot before/after equal).

## Edge cases & assumption defaults (A9)
- Handoff of a mission with zero progress is valid (goal + empty
  sections). Multiple handoffs accumulate; consumption uses the newest
  valid one and logs which. Secrets never enter handoffs — the manifest
  redaction denylist applies to any config values included.

## Orchestrator brief
Reuse is the theme: dossier renderer, checkpoint verification, recall
harness — have workers name each reused piece; new implementations of
existing pieces are rejects. T003 is the acceptance heart.

## Do not touch
Automatic context-pressure detection, cross-machine transport, memory
features beyond composition. Suggested tests:
tests/orchestration/test_handoff.py.

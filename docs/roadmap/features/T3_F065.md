# T3_F065 — Idea engine v2 (continuous, opt-in)
**Tier 3 · Depends on: F063, F045 · Later integrates: F067 routine-library packaging · Blocks/used by: steady stream**

## Goal & Done
Beyond post-job sparks, Remedy can MINE standing signals — TODO/FIXME
markers, coverage gaps, failure-class clusters — into ideas on a
schedule the human chose: v2 runs as a declared LOOP (opt-in by
definition), each miner contributes candidates with the same mandatory
evidence discipline, and the run reports what it scanned and what it
suppressed. DONE when each miner yields correct candidates on fixtures,
the loop run produces deduplicated, denial-filtered ideas, and an
unconfigured project never mines anything.

## How it fits (inspect current shape before building)
The loop-definitions feature provides the trigger/scope/budget frame —
v2 is an ACTION KIND for it (action idea_mining with a miners list),
not a daemon. Miners are deterministic scanners plus at most one
side-role call to phrase candidates into the idea schema; the v1
engine's validation, caps, denial memory and store are reused
unchanged — v2 only adds SOURCES.

## Design (suggested shape)
- Miner interface: scan(project, scope) → raw findings {kind, location,
  metric, excerpt}; miners v1: todo_scanner (marker regex set,
  configurable), coverage_gaps (parse an existing coverage report file
  if present — never run coverage itself here; absent report → miner
  skips with an honest note), failure_clusters (postmortem store
  grouped by class+top reason over a window, threshold count from
  config).
- Pipeline per loop run: run configured miners → merge findings →
  ONE phrasing call (side role) turning findings into idea candidates
  with evidence_refs pointing at the findings' locations → v1
  validation + ref resolution + denial/dedup filter → append; a
  mining-run summary artifact records counts per miner
  (found/phrased/suppressed/appended).
- Opt-in shape: nothing mines without a [[loop]] with action
  idea_mining; the routine library (later) ships a ready-made one.
- Caps: per-run idea cap and per-miner finding caps (noise discipline);
  oversupply is truncated by a documented priority (failure clusters
  first, TODOs last) and the summary says so.

## Task slicing
- **T001** miner interface + todo_scanner + failure_clusters (both
  deterministic, table-tested) + the skip-honesty for coverage.
- **T002** the phrasing pipeline + reuse of v1 validation/filters +
  the summary artifact + fake-provider tests.
- **T003** loop action wiring + caps/priorities + the end-to-end
  fixture (a repo with seeded TODOs and a postmortem cluster → the
  expected ideas, the denial fixture suppressed, summary golden).

## Acceptance
- Each miner's fixture yields exactly the expected findings; the
  pipeline appends only validated, resolvable, non-denied ideas; the
  summary accounts for every finding (found = phrased + dropped, with
  reasons). No loop configured → zero mining code paths run.

## Edge cases & assumption defaults (A9)
- Huge repos: miners respect the loop's scope paths; unscoped mining
  warns about breadth in the summary rather than silently taking
  forever. TODO markers in vendored/generated dirs: the standard
  ignore conventions apply (reuse whatever the context compiler
  ignores — one ignore notion).

## Orchestrator brief
Gate on loops + idea v1. Miners are ideal parallel small orders (one
per miner, table tests each); the pipeline order follows. Keep the
one-phrasing-call rule (not one call per finding) explicit — cost
discipline.

## Do not touch
Coverage EXECUTION, ownership-signal mining (arrives with its
feature), scheduling internals. Suggested tests:
tests/orchestration/test_idea_miners.py.

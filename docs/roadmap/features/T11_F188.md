# T11_F188 — API compatibility guard
**Tier 11 · Depends on: F061, F005 · Blocks/used by: semver discipline; F221 gate**

## Goal & Done
See ROADMAP.md F188; the Done criterion there is binding.

## Context (existing code & prior features)
No API diff tool exists; F072 spec drift is related but heuristic.

## Design
packages/verification/api_compat.py: py - the public surface via a griffe-style extractor (signatures, defaults, exports) snapshotted before/after; ts - exported declarations via a tsc declaration diff. Classification breaking|additive|patch by a fixed documented rule table. breaking -> a decision with the triple (proof=the diff line, expectation=semver major or a deprecation path proposal, downside=consumer breakage). DoD kind api_compat; baselines in .remedy/api_baselines/ (update command, the F098 pattern).

## Task slicing
T001 the py extractor + the rule table + per-class tests. T002 the ts path + decision integration + baseline mechanics.

## Acceptance & tests
A removed parameter -> breaking + decision; a new optional function -> additive, frictionless; baseline updates only explicit.

## Risks / anti-goals
No runtime behavior analysis promised (surface only - stated honestly); the rule table freezes per version.

# T2_F077 — Autonomy watchdog
**Tier 2 · Depends on: F070, F010, F018 · Blocks/used by: safety in continuous operation**

## Goal & Done
Continuous operation gets a tripwire that is independent of the thing it
watches: a watchdog observes the orchestrator loop for no-progress
repetition, burn-rate anomalies and goal drift, and on a trip it PAUSES
the mission and raises a decision with the evidence — it stops, it never
repairs. DONE when each tripwire class fires on its fixture, a tripped
mission is paused with a decision carrying the evidence triple (what,
since when, the numbers), and false-positive rates are tunable via
config, not code.

## How it fits (inspect current shape before building)
The orchestrator loop writes a ledger entry per iteration (move, outcome,
cost) — the watchdog READS that ledger plus postmortems and actuals; it
needs no hooks inside the loop beyond the pause mechanism that already
exists (missions pause via their status; the loop checks it each
iteration like a stop request — verify that check exists from the
mission feature and add it there if missing, as a tiny prerequisite
order). Independence rule: the watchdog runs as its own evaluation pass
(per iteration or per invocation), with no shared mutable state with the
loop.

## Design (suggested shape)
Module `watchdog.py`, pure evaluation + one action:
- Tripwires v1 (each with config thresholds and an evidence extractor):
  1. no_progress — the same task/milestone dispatched N times (default
     3) without a state change in the mission plan;
  2. burn_anomaly — sliding-window cost rate versus the mission's own
     trailing baseline (a self-relative check; the later cost-anomaly
     feature adds class-expectation checks — note the deliberate overlap
     and that unification happens there);
  3. goal_drift — dispatched jobs whose plan references no current
     milestone (every loop-dispatched job carries its milestone link —
     assert that link exists from the loop feature).
- `evaluate(mission) -> list[Trip]`; on any trip: set mission paused,
  enqueue ONE decision per trip class (dedup within a mission until
  resolved) with options resume|abort and the evidence; ledger entry
  watchdog_tripped.
- Invocation: called by the loop between iterations (cheap, read-only
  except the pause) AND available as `remedy mission watchdog <id>` for
  manual audits.

## Task slicing
- **T001** the three evaluators as pure functions over fixture
  ledgers/plans + threshold config + unit tests per tripwire (fires /
  just-under-threshold doesn't).
- **T002** pause + decision + dedup + ledger entry + loop-integration
  test (trip on iteration k pauses before iteration k+1 dispatches).
- **T003** the manual CLI + report surfacing (a paused-by-watchdog
  mission's report leads with the trip) + tests.

## Acceptance
- Each tripwire fixture fires with correct evidence; the near-miss
  fixtures don't. A tripped mission dispatches nothing further until the
  decision is answered; resume clears exactly that trip's dedup. The
  watchdog never modifies plans, jobs, or dossiers (state diff test).

## Edge cases & assumption defaults (A9)
- Legitimate expensive iterations (a big milestone) versus anomaly: the
  self-relative baseline plus a config multiplier keeps this tunable;
  the decision text shows the numbers so the human judges. Missions too
  young for a baseline: burn tripwire inert until a minimum sample
  (documented), the other two active from iteration one.

## Orchestrator brief
Gate on the loop's ledger format. T001 pure-first with the fixture
ledgers spelled out. The independence rule (read-only + pause only) is
an acceptance criterion — reject diffs where the watchdog "helpfully"
fixes anything.

## Do not touch
Repair logic, class-expectation anomaly detection (later feature owns
it), loop policy. Suggested tests:
tests/orchestration/test_watchdog.py.

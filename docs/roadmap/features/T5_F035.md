## Goal & Done
Who decided what stays answerable forever: ownership.py aggregates
the command audit, clarification answers and reference-sourced
assumptions into ownership.json per job, rendered humanly in report
and UI — "You vetoed T004 — reason: ..." — so responsibility is a
record, not a memory. DONE when every human-attributable action
class appears in the ledger with actor, time and consequence link,
the report's ownership section reads as plain sentences (golden),
the UI surfaces entries at their nodes, and machine actions are
explicitly attributed to Remedy-with-config (nothing renders
authorless).

## How it fits (inspect current shape before building)
All sources exist as files: commands_audit.jsonl (every channel
action with fingerprints), clarification answers with answered_by
human|default, the assumption log's sources, --yes auto-approvals
(audited by design), CLI-originated actions (verify CLI verbs audit
comparably — a gap here is a small prerequisite order: CLI mutating
verbs append to the same audit shape). Aggregation is a pure pass
over those, joined with consequences (the veto's unreachable set,
the answer's branch resumption) from evidence — rendered by ONE
phrase catalog (the vocabulary coordinated with the veto feature;
one dialect for "you did X").

## Design (suggested shape)
- ownership.json (versioned): entries {ts, actor (human fingerprint
  | remedy+config-ref | default-policy), action kind, target,
  reason/answer verbatim, consequence_ref}; built at terminals and
  on demand (pure over sources — regenerable, never a second
  truth).
- Actor honesty: --yes approvals attribute "you (auto-approved via
  --yes)"; defaults attribute "default policy (you accepted at plan
  approval)" — the chain of consent is the point.
- Rendering: the report's Ownership section as sentences from the
  phrase catalog (goldens); the UI shows entry chips at affected
  nodes (L2 popover section) and a job-level ownership tab in the
  evidence panel.
- `remedy job ownership <id> [--json]` CLI parity.

## Task slicing
- **T001** the source inventory + any CLI-audit prerequisite + the
  aggregation pass + entry schema + unit tests per action class
  (veto, hunk decisions, steering, injections, answers, --yes,
  defaults).
- **T002** the phrase catalog + report section + goldens (every
  class one sentence; verbatim reasons embedded).
- **T003** UI chips + panel tab + CLI + the end-to-end (a run with
  one of each action class → the ledger complete, sentences
  golden, chips at the right nodes).

## Acceptance
- Every action class present with correct actor honesty (the --yes
  and default attributions exact). Regeneration determinism (pure
  pass). Verbatim reasons survive to every surface. No entry
  without an actor (schema); no surface invents authorship.

## Edge cases & assumption defaults (A9)
- Token rotation mid-job: fingerprints stay per token id (the
  channel's rule) — the ledger shows "operator (token #2)" without
  claiming identity beyond what's known. Multi-operator teams are
  future auth's problem; the schema's actor field is ready,
  honesty about current granularity documented.

## Orchestrator brief

orders.

## Do not touch

auth/identity. Suggested tests:
tests/orchestration/test_ownership_ledger.py.

## Built State (F035, 2026-09-28)

What exists on disk at the close of F035, built in eight rounds of one session on
`feature/f035-ownership-ledger`, cut from `main` at `a0b287a5`. Most of the records this feature
reads were written by features built after this file: the veto, the injection, the rerun, the
runtime edit, the pause, the steering note. F035 reads them and changes none of them (DECISION
F035 D1). Every DECISION named lives in `.agent/decisions.md`; every round's verdict in
`.agent/live_review.md` or, once rotated, its archive.

**T001 — the ledger.** `build_ownership_ledger` in `packages/orchestration/ownership.py` is a pure
pass over one job's records that answers `{"schema": "remedy.ownership.v1", "job_id",
"entries"}`: vetoes and their control files, answers to a veto's replan proposal, confirmed
injections with their fold, subtree reruns, plan and runtime task edits from the plan's edit log
(an injection's own edit entry left to the injection), steering messages and task notes with
their consumption markers, the `job_paused`, `task_paused`, `job_resumed`, `task_resumed`,
`job_stopped` and `plan_approved` events of the run log, decided hunk rows, answered task
decisions, resolved clarifications, and a rejected plan or an approved one with no event. Every
entry carries `record_ref`, `ts`, `actor`, `action`, `task_id`, the record's `text` verbatim, a
`consequence` of `kind`, `task_ids` and `ref`, and a `detail`; `ownership_entry_problems` refuses
any other shape, and a reader's own error or a duplicate reference raises `OwnershipError`. The
actor names the door its record holds and no more: `browser` for a token fingerprint, `cockpit`
or `ui`, `cli` for the command line, none otherwise; a fingerprint is numbered by the order it
first acts; `auto_approved` marks an unattended `--yes`; a default is the `default_policy`'s and
the planner's own resolution is `remedy`'s. A resume is attributed to no door, because its event
carries the pause's source. Clarification answers carry no time, because their record keeps
none. A decorator on `run_job` in `packages/orchestration/pingpong_job.py` saves the ledger as
`ownership.json` in the job's evidence export after every return, for a job whose directory
exists, and logs, never raises, a failure to build or save it (DECISION F035 D2).

**T002 — the sentences.** `packages/orchestration/ownership_phrases.py` is the one catalog that
words an entry: the actor as `You (browser, token #<n>)`, `You (browser)`, `You (command line)`,
`You`, `You (recorded as <value>)`, `You (auto-approved via --yes)`, `The default policy (you
accepted at plan approval)` or `Remedy's <role> (under this job's configuration)`; every reason,
answer and note quoted verbatim; a task named with its title; plan edits in plain verbs ending
`the plan is now at version <n>`. The job report's `Ownership:` section lists the sentences in
ledger order and replaced the per-task `Vetoed by` line; the `Paused by` line stays because it
states the job's present state. The digest's `ownership` key, empty since F040, carries the same
sentences at the same version (DECISION F035 D3).

**T003 — the surfaces.** `ownership_view` answers each entry with its sentence, or none with one
sentence naming why the ledger could not be read. `remedy job ownership <job_id> [--json]` in
`apps/cli/commands/job_ownership_cmd.py` prints it, exiting 3 for a job whose record cannot be
read and 1 for an unreadable ledger; the browser's read route `/api/jobs/<id>/ownership` answers
it (DECISIONS F035 D4 and D5). `apps/ui/src/api/ownership.ts` decodes it whole or not at all;
`RemedyShell.tsx` loads it once per job and token, again on a stream frame of an event the ledger
reads and again for a newly selected task; the task detail shows a "Who did what" section of
chips and verbatim sentences for the task's entries and the ones that name it as a consequence;
and the evidence panel's fourth tab, "Ownership", shows the whole job's (DECISION F035 D6). A view
that cannot be read shows "Who did what could not be read for this job." and never the server's
error. The design reference's assumption log records the section and the tab.

**Guards widened on purpose.** `tests/orchestration/import_reachability_allowlist.txt` gained
the feature's three new modules, `apps.cli.commands.job_ownership_cmd`,
`packages.orchestration.ownership` and `packages.orchestration.ownership_phrases`, the measured
closure of the entry points now reaching all three (closure precondition 7).

**Deliberate absences.** The command audit is not joined and the command line does not write it:
every class whose record names an actor already names its door, and a join by time would be a
guess (DECISION F035 D1). An assumption sourced from a reference has no producer, so the ledger
has no such class. The ledger never names a person, only a door and a token number; a team of
several operators is future authentication's. The browser's steering message carries no token
number, because the steering record keeps its channel and not the fingerprint.

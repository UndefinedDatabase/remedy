## Goal & Done
Deviation gets language a builder can act on: a multimodal review
call receives reference, shot, heatmap and spec, and returns
findings in EXACTLY four criteria — layout, colors, typography,
component completeness — each finding {region, expected, actual,
severity, fix_hint}; the schema forbids verdicts without criteria.
DONE when seeded-deviation fixtures yield findings in the right
criterion and region (fake-multimodal goldens), the schema rejects
free-form verdicts, severity vocabulary is shared with the code
reviewer's (one scale), and non-multimodal configurations degrade
to metrics-only with the honest label (numbers without language).

## How it fits (inspect current shape before building)
This is the review role's visual sibling: same schema discipline
(a versioned VisualReviewVerdict beside the existing review
models), same severity scale as code review findings (import the
enum — one vocabulary for "high"), routed to a multimodal-capable
model (the routing table gains the class; the vision capability
gate applies). Inputs are the comparison record's artifacts — the
reviewer sees the heatmap the human sees (localization guides
language); the spec provides region names so findings speak in
the design's own terms ("header-nav", not "top area").

## Design (suggested shape)
- Schema visual_review_v1: {findings: [{criterion: layout |
  colors | typography | component_completeness, region (a spec
  region name or "global"), expected, actual, severity (the
  shared enum), fix_hint}], summary?: bounded} — validators: only
  the four criteria; region names from the provided spec or
  global; a verdict with zero findings is valid (clean) but a
  textual verdict WITHOUT structured findings is rejected (the
  forbids-vibes rule).
- The call: images (ref, shot, heatmap) + the spec JSON + the
  schema; parse-retry standard; per-call image budget from the
  builder-attachment rules (same config).
- fix_hint discipline: actionable phrasing referencing tokens/
  regions ("use the reference's #2563eb for the primary button"),
  prompted AND spot-golden-checked — hints feed the repair loop
  next.
- Degradation: no multimodal route → the loop gets metrics-only
  (documented there); this module returns capability_unavailable
  honestly.
- Evidence: verdict JSON beside the comparison record; the
  evidence panel renders findings over the heatmap (boxes +
  criterion chips — UI wiring minimal here, deepened by the loop's
  round view).

## Task slicing
- **T001** schema + validators (four-criteria enforcement, region
  vocabulary, the forbids-vibes rule) + unit tests.
- **T002** the call assembly + budgets + degradation +
  fake-multimodal goldens per seeded deviation (wrong color →
  colors finding in the right region; missing button →
  component_completeness).
- **T003** evidence + the findings-over-heatmap rendering + the
  end-to-end on the doctored fixture pair.

## Acceptance
- Seeded matrix exact (criterion × region). Free-verdict fixture
  rejected by schema. Severity imports the shared enum (grep).
  Degradation label correct. Findings render anchored on the
  heatmap.

## Edge cases & assumption defaults (A9)
- Findings outside any region: "global" is legal but the prompt
  discourages it (localization is the value) — a global-heavy
  verdict is reviewable in goldens. Conflicts between reviewer
  language and metrics: both are evidence; the LOOP's thresholds
  arbitrate action (measurement/judgment separation upheld).

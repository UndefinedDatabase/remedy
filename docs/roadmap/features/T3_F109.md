# T3_F109 — Semantic dedupe
**Tier 3 · Depends on: F105, F106 · Blocks/used by: repeat contexts**

## Goal & Done
Within a RESUMED session, identical context blocks stop being resent:
segments whose hash already went to this exact session are replaced by
short reference markers — and ONLY there, because only a resumed
session guarantees the model still has the prior content; everywhere
else full content wins (correctness before savings). DONE when a
fixture resumed repair chain shows deduped segments with measured
savings, any non-resume path is provably untouched, and a dedupe
never fires across sessions.

## How it fits (inspect current shape before building)
The segment registry already hashes every composed segment into a
per-call manifest — dedupe is bookkeeping over those hashes keyed by
provider session id (from the resume feature). The scope rule is the
whole feature: sent-hash memory lives per session id, is populated
only from calls that actually reached that session, and is consulted
only when composing a call that RESUMES that session.

## Design (suggested shape)
- `session_sent_index`: per session id, the set of segment hashes
  successfully sent (recorded at call finalization, from the same
  manifest evidence — one seam). Persisted in the job's evidence so a
  process restart cannot hallucinate prior sends it can't prove.
- Composition hook: when building a resuming call, segments whose hash
  is in the session's index are replaced by a one-line marker
  ("[unchanged: <segment name>, previously provided]") — names stay so
  the model can still refer to them; ranks/order unchanged (cache
  discipline).
- Safety valves: any resume fallback (session expired) invalidates the
  index for that chain; a config flag disables dedupe entirely; the
  manifest records deduped segments so evidence shows exactly what the
  model did NOT receive again.
- Measurement: actuals comparison on the fixture chain, recorded.

## Task slicing
- **T001** the sent-index (record at finalization, persist, invalidate
  on fallback) + unit tests (restart honesty: unproven sends absent).
- **T002** composition hook + markers + scope guards (non-resume calls
  bypass entirely — asserted) + fake-provider chain tests.
- **T003** measurement fixture + the disable flag + docs.

## Acceptance
- Resumed chain: second call's manifest shows deduped segments,
  markers in the prompt, savings recorded. Fresh calls and non-resume
  providers: byte-identical prompts (golden equality). Expiry mid-chain
  → full content resumes, index reset. Dedupe never crosses session
  ids (negative test with two parallel sessions).

## Edge cases & assumption defaults (A9)
- A segment whose content changed hashes differently and is sent full
  — no staleness risk by construction. Tiny segments: marker overhead
  can exceed savings — a minimum-size threshold (config) skips them.

## Orchestrator brief
Small feature, strict scope. Put the scope rule ("resumed session
only, proven sends only") verbatim in every order and make the
non-resume golden-equality test the first acceptance item.

## Do not touch
Cross-session caching, provider-side cache mechanics, prompt content.
Suggested tests: tests/orchestration/test_semantic_dedupe.py.

## Built State — what F109 delivered

T001-T003 built semantic dedupe inside a RESUMED provider session only.
The prose description of the built state, for a reader rather than for
this ledger, is `docs/system/semantic-dedupe-v1.md`.

- `packages/orchestration/session_sent_index.py` — `SessionSentIndex`
  keyed by provider session id, holding the segment SHA-256 digests
  `ComposedPrompt.manifest_as_dicts()` produced. `record_call` records
  nothing for a call that carried an error and nothing for an empty
  session id, so an unproven send and a sessionless call can never enter
  the index; a malformed manifest row raises rather than shrinking it
  silently. The module is pure and imports nothing from the rest of
  `packages.orchestration`. `record_finalized_call` and
  `invalidate_on_resume_fallback` are the adapter seams, and
  `session_sent_index_from_evidence` is the restart-honesty seam (T001a,
  T001b-i).
- `packages/orchestration/pingpong_loop.py` — the loop calls both seams
  on the Builder path and again on the Reviewer path and writes
  `as_evidence_dicts()` onto `PingPongResult.session_sent_evidence`
  (T001b-ii, `7451e9c7`). `_dedupe_resumed_segments` replaces an
  already-sent segment's text with
  `[unchanged: <name>, previously provided]`, rewriting text only, so
  names and ranks survive; both `compose_*` functions reach it behind a
  `dedupe_sent_hashes` parameter that bypasses dedupe by default
  (`24352750`, `60343048`). `run_pingpong` carries
  `semantic_dedupe_enabled` and forwards it as `dedupe_enabled`, and
  `enabled` is consulted first and alone, so the kill switch is total
  (T002a-T002c, `b245e1c9`).
- `packages/orchestration/prompt_trace.py` — every `PromptTraceEntry`
  carries `deduped_segment_names`, derived from the composed prompt
  alone (T003c, `78d2b7b5`); and `measure_dedupe_savings_from_traces`
  reports what a run did not resend, reading only that record. Its
  `unmeasured_segment_names` field NAMES a deduped segment whose
  full-content size was never observed and excludes it from every total,
  so an absent measurement can never be read as a zero saving (T003d).
- Measured on the two-round resumed fixture chain at commit `d52a5371`:
  556 characters avoided against 97 spent on markers, 459 net over 2
  withheld segments, nothing unmeasurable; the same chain with the flag
  off reports zero on every field and names nothing unmeasured.
- SCOPE LIMIT, stated because it is the first thing a reader should
  know: no concrete adapter resumes in production — `ClaudeProvider`,
  `ClaudeCliProvider` and `OllamaPingPongProvider` all return
  `supports_resume = False` — so dedupe is exercised by the suite and is
  inert on every real run today. The measurement function is a library
  with no production caller.

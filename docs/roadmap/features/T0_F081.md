# T0_F081 — remedy init
**Tier 0 · Depends on: F146, F007 · Blocks/used by: onboarding**

## Goal & Done
One interaction-free command turns a git repo into a Remedy project:
register it, write a minimal project config, protect repo hygiene, detect
the runtime, print exactly what happened plus the one next command. DONE
when init on a fresh fixture repo is idempotent, asks ZERO questions (A9),
and `remedy project current` plus a runtime probe work immediately after.

## How it fits (inspect current shape before building)
Registration primitives come from the project registry (this feature runs
after the identity feature in STATUS order — build on resolve/require).
The project config file lives at the repo root and its valid keys are
defined centrally, so init writes ONLY registered keys and `remedy config`
can immediately explain every line. Runtime detection logic exists in the
runtimes package — reuse its confidence rules, add no new framework
sniffing (A6). The worktree layer already maintains ignore-file hygiene —
call it. There is no init command yet; add one following the existing
command registration pattern.

## Design (suggested shape)
`remedy init [--project-name NAME] [--print-only] [--json]` — ordered
steps, each reported as `[created|exists|skipped] <what>`:
1. Preflight: not a git repo → exit 4 with "remedy init requires a git
   repository — run `git init` first." Never git-init for the user.
2. Registry: already resolvable → report exists (idempotent). Otherwise
   create (name = flag or directory name), attach the resolved repo root,
   save. No prompts, ever.
3. Project config: if absent, write a minimal commented template — an
   empty core table pointing at `remedy config list`, plus a runtime table
   filled ONLY when detection is confident, otherwise a commented example
   and the honest line `skipped runtime autodetect (no known framework
   marker)` (P6). An existing config file is NEVER rewritten.
4. Hygiene: ensure ignore entries (data dir, workspaces); report added
   lines.
5. Summary: slug, uuid, config path, data root, then exactly one
   suggestion: `Next: remedy do "<your first mission>"`.
`--print-only` renders everything including the exact config content
without touching disk; `--json` emits the step list machine-readably.
Write order: config file → ignore file → registry, so a failed write never
leaves a registered-but-unconfigured project.

## Task slicing
- **T001** command skeleton + preflight + registry step + idempotency (run
  twice → all exists; zero writes proven by mtime snapshot).
- **T002** config template (one module constant, single source of truth) +
  runtime detection wiring + honest-skip path; fixtures: a Vite-marker
  repo, a Python-server-marker repo, a no-marker repo.
- **T003** hygiene + summary + print-only/json; print-only leaves the repo
  byte-identical (recursive hash compare).

## Acceptance
- Fresh repo: exit 0; project resolves; config parses through the config
  loader; ignore file covers the data dir. Second run fully idempotent.
- Non-git dir: exit 4, exact message, nothing created. Handwritten config:
  untouched (hash-equal), project still registered.
- No stdin reads under any circumstances (test runs with stdin closed).

## Edge cases & assumption defaults (A9)
- Run from a subdirectory: everything targets the repo root and the
  summary says so. A repo already registered under a different name:
  exists wins; renaming is project-command territory. Read-only target:
  fail atomically with a clear message.

## Orchestrator brief
Single-worker feature; dispatch T001→T003 sequentially (each builds on the
previous). Have the worker echo the runtime-detection confidence rule it
found before wiring step 3.

## Built State
- **T001 — Command skeleton, preflight, registry, idempotency:**
  `apps/cli/commands/init_cmd.py` with `_handle_init` handler registered
  as `init.run` in `command_catalog.py`. Preflight: non-git → exit 4
  with exact message. Registry: reuses `resolve_project` /
  `register_project_repo` from F146. Idempotency: second run →
  all `[exists]` lines, zero mtime changes on project files.
  `_ALWAYS_INJECT = {"init"}` / `_DEFAULT_COMMAND["init"] = "run"` in
  `grouped.py` so bare `remedy init` auto-maps to `init.run`.
  Group-help contract tests exempt `_ALWAYS_INJECT` groups.
- **T002 — Split config: [remedy] → remedy.toml, [runtime] → .remedy/config.toml:**
  `_CORE_TEMPLATE` writes `[remedy]` table to `remedy.toml` (read by
  `config.py::load_config`). `_build_runtime_config` calls
  `detect_runtimes(root)`: exactly 1 result → `_RUNTIME_ACTIVE` fills
  `[runtime]` in `.remedy/config.toml` (read by
  `runtime_config.py::load_config_spec`); 0 or >1 → `_RUNTIME_SKIP`
  commented example + honest `[skipped]` message. Existing files NEVER
  overwritten. `resolve_spec(root).source == "config"` after confident
  detection (probe uses written config, not live re-detection).
- **T003 — Hygiene, summary, --print-only, --json:**
  `_ensure_ignore_entry` writes `.remedy-wt/` + in-repo data-dir +
  workspaces to `.git/info/exclude` (not `.gitignore` — working tree
  stays clean). Summary block: slug, uuid, config path, runtime config
  path, data root + exactly one `Next: remedy do "<your first mission>"`
  line. `--print-only` renders all steps + exact config content without
  touching disk (repo byte-identical, no project registered).
  `--json` emits machine-readable step list + summary as valid JSON.
  Combinable.
- **Tests:** `tests/cli/test_init_cmd.py` — 23 tests
  (5 T001 + 9 T002 + 9 T003). All subprocess-based with

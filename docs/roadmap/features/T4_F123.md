# T4_F123 — Effectiveness KPI
**Tier 4 · Depends on: F118, F103 · Blocks/used by: proof that memory pays**

## Goal & Done
"Does memory actually help?" gets numbers instead of faith: every
call's ledger row knows its attached cards, statistics compare
pass/repair outcomes with versus without cards MATCHED BY TASK
CLASS, an A/B mode in the benchmark alternates the selector on and
off — and every output labels correlation versus causation honestly.
DONE when the stats render from fixture data with the matching
methodology documented next to the numbers, the benchmark A/B runs
both arms and reports per-arm metrics, and no surface ever claims
causal lift from observational rows.

## How it fits (inspect current shape before building)
attached_cards already lands in run evidence (the selector's
contract); the ledger writer extends additively (the same pattern
the segment-manifest column used — cite it) so rows carry the card
ids/count. Outcome signals exist: task terminal states, repair
rounds, postmortem classes per task. The benchmark harness already
runs frozen orders with recorded metrics — the A/B is a harness
parameter (selector on/off via the memory-module switch that lands
two features later; until it exists, the A/B uses the selector's
config flag — verify which switch is available in STATUS order and
use the earliest honest one).

## Design (suggested shape)
- Ledger: additive attached_card_ids (compact) + count; backfill
  tolerant (old rows = unattributed, reported).
- `memory_kpi.py`: observational view — per task class with enough
  samples on BOTH sides (floor, config): pass rate, mean repair
  rounds, cost — with-cards vs without; classes lacking either side
  render "insufficient contrast data" (no cherry-picking). Header
  paragraph (rendered, not optional): "observational comparison —
  selection is not random; treat differences as correlation."
- Benchmark A/B: `--memory-ab` runs each frozen order twice
  (arms interleaved), records the arm on each row, reports per-arm
  metrics + the delta with sample sizes; THIS is the causal-ish
  instrument and its output says "randomized within the frozen set".
- CLI `remedy stats memory [--json]` (observational) and the A/B
  summary in the bench report.

## Task slicing

## Acceptance
- Fixture goldens exact; the no-contrast class renders the honest
  line; headers present in every output path (grep test). A/B runs
  both arms per order, arms recorded on rows, deltas with n. No
  output contains causal vocabulary for observational data
  (denylist grep: "proves", "causes" outside the A/B section).

## Edge cases & assumption defaults (A9)
- The pinned dossier card attaches everywhere → observational
  "without cards" barely exists once it lands: the view therefore
  compares card COUNT strata too (0 / 1 / 2+), documented. Cost
  bases mix: compare within basis, as established.

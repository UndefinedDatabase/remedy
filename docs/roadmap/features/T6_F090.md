## Goal & Done
Remedy can look at what it built: screenshot.py captures (url,
viewport, ready_strategy: selector | networkidle+quiet) to PNG via
browser automation — default set desktop 1440×900 and mobile
390×844 — deterministic within an anti-aliasing tolerance, with
fonts pinned in the runtime image where possible. DONE when
captures of the fixture app are stable across repeated runs within
the documented tolerance, ready strategies provably wait correctly
(a late-rendering fixture), the capability is an OPTIONAL install
that degrades honestly when absent, and every capture lands as
evidence with its parameters.

## How it fits (a dependency-stance decision, stated)
Browser automation (Playwright) enters here — deliberately at
Tier 6, and as an OPTIONAL EXTRA (pip extra `remedy[design]` /
documented install step), never a base dependency: the whole
product works without it; design-tier features detect availability
and report "screenshot capability not installed — pip install
remedy[design]" (the honest-degradation pattern throughout).
The runtime harness provides the running app (start/probe/stop);
capture composes it: start via harness → wait ready → capture →
teardown always. The sandbox's exec-guard policies apply to the
browser process class (its own policy row — it needs network to
localhost only).

## Design (suggested shape)
- capture(url, viewport, ready) -> path: ready strategies —
  selector (waitFor) or networkidle+quiet (network idle plus a
  quiet window for animations); a hard timeout with the honest
  failure classification (screenshot_timeout, additive postmortem
  class for the tier).
- Determinism levers documented and applied: fixed viewport +
  device scale, animations disabled via injected reduced-motion,
  fonts pinned where the runtime image allows (the finding per
  stack — record what IS pinned in the capture evidence; unpinned
  fonts widen tolerance honestly), timestamps/dynamic content are
  the app's business (the comparison feature's tolerance handles
  minor noise; heavy dynamism is a fixture-design concern,
  documented).
- Evidence: captures under the job's captures/ area {png, params
  json (url, viewport, ready, browser version, pinned-fonts
  note)} — the preview feature's screenshot grid reads this
  convention (coordinate the dir name there).
- The default viewport SET is config; features request specific
  viewports explicitly.

## Task slicing
- **T001** the optional-extra packaging + availability detection +
  degradation messages + install docs.
- **T002** capture + ready strategies + timeout classification +
  evidence + tests on fixture apps (instant, late-render,
  never-ready).
- **T003** determinism: repeated-capture stability within
  tolerance on the pinned fixture (numbers recorded), the
  reduced-motion injection, the pinned-fonts finding per fixture
  stack + docs.

## Acceptance
- Availability matrix honest (absent → the message, present →
  works). Ready fixtures behave (late-render captured complete;
  never-ready → classified timeout, teardown clean). Stability:
  N repeated captures within tolerance (recorded); the unpinned-
  font case documents its wider tolerance. Evidence params
  complete.

## Edge cases & assumption defaults (A9)
- Headless vs headed: headless always (CI reality); rendering
  differences are inside the tolerance budget or a fixture
  problem. Multiple pages/routes: capture takes a url — routing
  is the caller's concern (flows come with F094).

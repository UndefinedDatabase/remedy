# T14_F219 — Telemetry strictly opt-in
**Tier 14 · Depends on: F199 · Later integrates: F249 reuses and extends the anonymization suite · Blocks/used by: the product's trust anchor**

## Goal & Done
See ROADMAP.md F219; the Done criterion there is binding.

## Context (existing code & prior features)
F199 crash reports are local-only; this governs product usage metrics.

## Design
Default: NO telemetry, zero bytes (a capture test is a permanent CI fixture). Opt-in via `remedy telemetry enable` (an interactive display of the FULL field catalog BEFORE confirmation). The catalog is public in docs, every field justified: version, os_family, editions, feature counters (F-number usage) - NEVER paths/prompts/project names. A local buffer ~/.remedy/telemetry/outbox/ (inspectable: `remedy telemetry show`), batched sending, `remedy telemetry disable|purge` one-liners.

## Task slicing
T001 the catalog + collector + outbox + show/purge + tests. T002 the enable flow + sending + the CI capture gates (default silent / enabled sends exactly the catalog).

## Acceptance & tests
The default capture shows zero bytes, permanently; the enabled payload equals the catalog (schema test); purge provably empties; a catalog change invalidates the opt-in (fresh consent required - tested).

## Risks / anti-goals
No coupling nudges (no features behind telemetry); catalog growth only via ADR + docs update.

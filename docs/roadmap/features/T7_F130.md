# T7_F130 — Mutation sampling
**Tier 7 · Depends on: F061 · Blocks/used by: test quality truth**

## Goal & Done
"Tests pass" meets "tests catch": a BUDGETED mutation sample (n
mutants, hard time cap) runs on the modules a job touched,
survivors are listed plainly as "tests that catch nothing" with
their mutants, and an optional test-task proposal flows through the
idea queue. DONE when seeded weak-test fixtures produce the
expected survivors, the budget caps hold (count and wall clock —
the run never explodes), the tooling ships as an optional quality
extra with honest degradation, and survivors never block by
default (truth first, policy later — a config can promote to
blocking per project).

## How it fits (a dependency-stance note, consistent with the tier)
Mutation tooling (mutmut-style) joins an optional `remedy[quality]`
extra — never base (the design-extra precedent); absent → the DoD
row reports tool_unavailable per the established rule. Scope
derives from the job's touched files (applicator evidence) mapped
to modules; the sample budget makes it a spot check, said so in
every rendering ("sampled n mutants — a survey, not a proof").
Survivor→proposal reuses the idea machinery (kind test_gap, the
provenance-typed refs pointing at mutant descriptions + module).

## Design (suggested shape)
- `mutation_sample.py`: select touched modules → generate/run up to
  n mutants (config default modest) under a wall cap; per mutant
  {module, description/diff, killed|survived|timeout}; timeouts
  counted separately (a hung mutant is infra noise, not test
  blindness — the honesty split).
- Output: a DoD check kind mutation_sample (default non-blocking
  warn) with the survivor list + the survey label; evidence stores
  mutant records; the report renders survivors grouped by module.
- Proposals (config opt-in): one idea per surviving module (not per
  mutant — bounded) "tests for <module> miss injected faults" with
  the mutant refs; the queue's gate applies as ever.
- Determinism: the sample selection is seeded (job id) — reruns
  sample the same mutants at equal state (comparable), stated.
- Runs post-verify at terminals or on demand (`remedy job mutate
  <id>`) — never inside repair rounds (cost discipline).

## Task slicing
- **T001** extra packaging + availability + module scoping from
  touched files + seeded selection + unit tests.
- **T002** the budgeted run + outcome classification (killed/
  survived/timeout) + caps enforcement (a runaway fixture stops at
  the wall cap, partial results honest) + fixtures (weak tests →
  survivors; strong tests → kills).
- **T003** DoD kind + report rendering + optional proposals + the
  end-to-end.

## Acceptance
- Weak-fixture survivors exact; strong fixture kills all sampled.
  Caps hold on the runaway (partial output labeled "cap reached
  after k/n"). Seeded determinism (two runs, same mutants).
  Non-blocking default; the promote-to-blocking config works.
  Proposals bounded per module with resolvable refs.

## Edge cases & assumption defaults (A9)
- Ecosystems without a mutation tool (frontend TS in v1): the
  check reports ecosystem-unsupported honestly; Python first, the
  record notes the gap. Mutants in generated/vendored code: the
  shared ignore notion excludes them.

## Orchestrator brief
Gate on the DoD runners + idea provenance. The survey-not-proof
label and the timeout/survivor split go verbatim. T002's runaway
cap test is the safety line.

## Do not touch
Test execution machinery, TDD pairing, blocking defaults (config
territory). Suggested tests:
tests/orchestration/test_mutation_sample.py.

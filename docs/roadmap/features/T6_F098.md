## Goal & Done
Once it looks right, it stays right: golden screenshots per route/
component live under the repo's design-system baselines area, CI
compares captures against them within the documented tolerance,
breaks fail with heatmap artifacts, and updates happen ONLY through
`remedy baselines update`, which shows the diff before accepting.
DONE when a seeded visual regression fails CI with the localizing
heatmap, an intended change updates cleanly through the command with
the shown-diff step proven, the baselines path is fence-protected
against casual job writes, and baseline runs reuse the capture
determinism levers (no flaky goldens).

## How it fits (inspect current shape before building)
Pure composition of the tier's parts: capture (viewports, ready
strategies, determinism levers), comparison (metrics + heatmap —
thresholds live HERE as the guard's policy, respecting the
measurement/judgment split), the design-system placement rule
(baselines are curated repo capital at
`.remedy/design_system/baselines/<route-or-component>/<viewport>.png`
with a params sidecar), and fences (the baselines path joins the
protected set — writes only via the update command's gated path,
the card-store pattern). The CI wiring is a stage/DoD check like
the others; availability follows the design extra's honest
degradation.

## Design (suggested shape)
- Baseline entries: png + params.json (url/route, viewport, ready,
  capture env notes, tolerance override?) — the params pin HOW the
  golden was made so re-captures compare like with like; mismatched
  params fail with the difference named (comparing across
  viewports is a config bug, not a regression).
- The check: for each baseline, capture with its params → compare →
  pass within tolerance (global config, per-baseline override for
  known-noisy routes with the override reason required in params);
  fail → heatmap + numbers as artifacts, the DoD/CI row red.
- `remedy baselines update [--route X]`: re-capture → render the
  diff (numbers + heatmap, and in the cockpit the side-by-side per
  reference patterns) → explicit accept per baseline (tty y/N; --yes
  audited) → write through the gated path with the acceptance in
  the audit trail. `remedy baselines add` seeds new entries the
  same way.
- Fossilization honesty: baselines record their source job in
  params (provenance — which run blessed this look).

## Task slicing
- **T001** entry format + params pinning + the fence protection +
  the gated write path + unit tests (param mismatch named; direct
  write denied).
- **T002** the check (capture-compare per entry, tolerance/override
  rules, artifacts) + CI/DoD wiring + the seeded-regression fixture.
- **T003** update/add commands with the shown-diff acceptance +
  audit + the end-to-end (regress → red with heatmap → intended
  change → update accepts → green).

## Acceptance
- Seeded regression red with the heatmap localizing it; the
  intended-change flow green only after explicit acceptance
  (state diff proves no write before accept). Direct writes into
  baselines/ fence-denied. Repeated checks on unchanged code stay
  green N times (stability run, numbers recorded). Overrides carry
  reasons (validator).

## Edge cases & assumption defaults (A9)
- New routes without baselines: the check reports "no baseline"
  as a warn-level row inviting `baselines add` (never silently
  green, never blocking new work). Baseline drift from toolchain
  updates (browser version): params record the version; a version
  jump failing many baselines suggests a batch review via update
  (the command supports it) — honesty about the cause in the
  output.

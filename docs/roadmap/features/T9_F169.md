# T9_F169 — Human-oversight proof
**Tier 9 · Depends on: F009 audit, F032, F078, F141 · Blocks/used by: F168 chapter 4; M10**

## Goal & Done
"A human was in charge" becomes a checkable artifact: oversight.py
renders oversight.md + json per job or period — a table of ALL
applied changes, each resolving to either its approval chain (who,
what, when, with which evidence triple) or its autonomous
application (under which level and which policy rule allowed it) —
with a machine-checked invariant that NO application lacks a chain
or a rule; part two proves intervention CAPABILITY per release:
kill switch, pause and veto each carry one linked test-run proof
from CI artifacts. DONE when fixture jobs of both shapes render
complete tables (mixed approved/autonomous), the invariant checker
fails loudly on a doctored gap (an applied change with neither
source), all references resolve through the provenance machinery,
the capability proofs link real CI artifacts with their assertions
named, and the whole artifact embeds cleanly into the dossier.

## How it fits (inspect current shape before building)
Every row's evidence exists: applied changes enumerate from the
applicator's records (hunks/patches per task — the lineage seam's
sibling view), approval chains from decisions (the evidence-triple
schema made them complete) + hunk-approval ledgers + plan-approval
records, autonomous applications from the job's pinned level + the
permission-matrix cell that allowed the action (require() evidence
— verify calls are recorded; if not, the additive evidence write
at the gate is the prerequisite). The invariant is a pure checker
over the join: every application maps to exactly one source
(approval | level+rule) — gaps are structurally possible only via
bugs, which is why the checker exists. Capability proofs: the CI
suites for kill/pause/veto already assert behavior — the proof
LINKS a named test run's artifact per release (release tooling
records the run refs; the renderer verifies the links resolve).

## Design (suggested shape)
- `packages/enterprise/oversight.py`: build(scope: job | period)
  → the table rows {change (task/hunk ref, files), applied_at,
  source: {approval {actor, at, decision ref, triple}} |
  {autonomous {level, matrix cell, rule text}}} + the invariant
  verdict; render md (the auditor's one-pager per job) + json.
- The invariant checker: standalone (`remedy oversight check`)
  and embedded in build — failure names the orphaned application
  precisely; a CI fixture keeps the checker itself honest (the
  doctored gap).
- Capability proofs: a release manifest section {capability:
  kill|pause|veto → {ci run ref, test id, artifact link}};
  the renderer resolves and embeds; missing proofs render as
  missing (the dossier's honesty chapter picks it up).
- Person precision arrives with Tier 10 (actors are operator-
  scoped until then — the legacy vocabulary stated, upgraded by
  F177's rule).

## Task slicing
- **T001** the applied-changes enumeration + source join + the
  require()-evidence prerequisite where needed + unit tests.
- **T002** the invariant checker + the doctored-gap fixture +
  renderings (md/json goldens both scopes).
- **T003** capability-proof manifest + link resolution + dossier
  embedding contract + the end-to-end (a mixed fixture job:
  table complete, invariant green; the gap fixture: red naming
  the row).

## Acceptance
- Mixed-fixture tables complete with resolvable refs; triples
  render verbatim. The doctored gap fails naming the change.
  Autonomous rows cite real matrix cells + the pinned level.
  Proof links resolve to CI artifacts with test ids. The md
  reads as the auditor one-pager (review golden).

## Edge cases & assumption defaults (A9)
- Changes applied then reverted by later rounds: rows per
  application event (history, not net state — the table says
  what happened, stated). Period scope spanning level changes:
  rows carry their job's pinned level (F141's rule keeps this
  coherent).

## Orchestrator brief
Gate on triples + the matrix + applicator records. T001's
require()-evidence prerequisite is a small gate-side order if
the finding demands it. The invariant's doctored-gap fixture
goes verbatim — it is the feature's credibility.

## Do not touch
Approval semantics, matrix cells, CI suites (linked, not
changed). Suggested tests:
tests/enterprise/test_oversight.py.

# T9_F173 — Air-gap mode
**Tier 9 · Depends on: F155, F162, F165 Ed25519, F158 · Blocks/used by: regulated segments; F213 compatibility**

## Goal & Done
Remedy can run where the internet doesn't: [network] mode=
"airgapped" makes the router accept only adapters with net=deny
sandbox profiles, switches signing to the local Ed25519 backend,
disables update checks and notify webhooks with honest UI/CLI
notes, and reads the price catalog locally; `remedy doctor
--airgap` proves it — a static config-coherence check plus a
dynamic proof: one full fake job and one local real job under
packet capture with ZERO egress beyond loopback. DONE when the
mode's config validation refuses incoherent setups at load
(naming each violation: a net-allowlist adapter, cosign selected,
webhook sinks configured), every disabled surface shows its
honest note instead of failing silently, the dynamic doctor proof
runs the two jobs under capture and asserts loopback-only, and
airgapped operation exercises the full local stack (local
builder, local signing, catalog-computed costs) end to end.

## How it fits (composition — the parts were built for this)
Every ingredient landed with its air-gap stance stated: the local
adapter (F155) serves models on loopback endpoints; sandbox
profiles (F162) express net=deny and localhost allowlists; the
signing interface (F165) has the local backend explicitly for
this mode; pricing (F158) reads in-repo catalogs with staleness
warnings that never block. This feature is the MODE that binds
them plus the negative space: enumerating every network touchpoint
in the product (the findings order: update checks, webhook/notify
sinks, audit-export webhook sinks, MCP servers beyond loopback,
telemetry later) and gating each behind the mode with its note
("disabled: airgapped mode") — the honest-degradation register
(F157) hosts the entries where they're capability-shaped; UI
notes follow the established disabled-with-tooltip pattern.

## Design (suggested shape)
- Config: [network] mode = open | airgapped (default open);
  airgapped validation at load: adapters' resolved profiles must
  be net=deny or loopback-only allowlists; signing backend must
  be local; sink configs with external targets refused (each
  violation named with its fix).
- The touchpoint registry: a declarative list {feature, touchpoint,
  behavior_under_airgap: disabled_note | loopback_only | local
  source} — the completeness guard pattern (new network code must
  register; a grep guard hunts socket/http usage outside
  registered sites — the enforcement teeth).
- `remedy doctor --airgap`: static (the validation + registry
  coverage) + dynamic (run the recorded fake job AND one real
  local-adapter job inside a packet-capture harness — a netns/
  capture utility with a documented fallback where the platform
  lacks it: the static check stands, the dynamic marked
  unavailable honestly); assert zero non-loopback egress.
- MCP under airgap: allowlists restricted to loopback URLs
  (validation), consistent with the closed-by-default posture.

## Task slicing
- **T001** the touchpoint findings + registry + the grep guard +
  config validation with named violations + tests.
- **T002** per-touchpoint gating + honest notes (UI/CLI) +
  fixtures per touchpoint (webhook configured → refused at load;
  update check → the note).
- **T003** the doctor proof (capture harness + platform fallback
  honesty + the two-job dynamic run) + the full local end-to-end
  (local builder + local signing + catalog costs → a certified,
  locally-signed fixture job) + docs.

## Acceptance
- Validation names every seeded violation. Each touchpoint's
  note renders (loop over the registry). The dynamic proof:
  loopback-only asserted on both jobs (or the honest platform-
  unavailable state). The full local end-to-end produces a
  verifiable locally-signed certificate with catalog-basis
  costs. The grep guard catches a seeded unregistered socket
  use.

## Edge cases & assumption defaults (A9)
- Package installation is OUTSIDE the mode's scope (air-gapped
  installs are ops reality — docs describe offline install
  paths honestly, the mode governs RUNTIME egress; stated
  loudly). Loopback definition: 127.0.0.0/8 + ::1 + unix
  sockets (documented); LAN-local model servers require the
  explicit allowlist variant mode=restricted (a documented
  middle mode, config, same machinery — small addition, big
  practicality).

## Orchestrator brief
Gate on F155/F162/F165/F158 + F157's register. T001's touchpoint
findings is the map — review before gating orders dispatch. The
runtime-not-install scope line and the restricted middle mode go
verbatim. The capture harness is the proof instrument — its
platform honesty matters as much as its assertions.

## Do not touch
Adapter internals, signing backends, catalog mechanics, install
tooling. Suggested tests: tests/enterprise/test_airgap.py.

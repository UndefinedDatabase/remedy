# T10_F180 — Human reviews as a gate
**Tier 10 · Depends on: F177, F033, F061 · Blocks/used by: the M11 core; F169 chains**

## Goal & Done
Human sign-off becomes a first-class DoD check: kind human_review
{assignee: role|user, scope: full|paths[], blocking} creates a
review assignment — a decision variant with diff context — whose
verdict command human_review_verdict {approve | request_changes,
findings: [{anchor, severity, text}]} feeds request_changes
findings into THE SAME repair flow as LLM findings (the repair
request builder unchanged, A6); blocking=true holds the task/job
open until approve; a four-eyes option min_reviewers=2 exists;
and self-review by the change author is forbidden. DONE when the
DoD kind compiles into the assignment on task completion with the
diff context attached (the hunk-approval viewer's rails), verdicts
round-trip person-precise with findings entering a real repair
round (trace-proven — the finding text reaches the builder),
blocking semantics hold across resume/restart, min_reviewers
counts distinct qualified approvals, and the self-review rule is
enforced structurally (the author's identity from lineage/
ownership vs the reviewer's — refused with the honest message).

## How it fits (inspect current shape before building)
Composition over four rails: the DoD compiler (F061) registers
the kind (its check row renders pending/approved/changes-
requested); the assignment is a decision-queue entry (F178's
fields power routing/escalation for free) with a payload carrying
the diff context refs (the F033/F037 viewer opens it — reviewers
review IN the cockpit's diff UI, the design reference's review
treatments); the verdict command is catalog+schema work
(findings reuse the ReviewFinding shape — the shared severity
enum, anchors as hunk/file refs); the repair injection point is
the round builder's findings input (LLM findings and human
findings are the same type by construction — origin human_review
tagged, the red-review precedent). Self-review: the change
author set derives from the task's commits (trailer/ownership
data); the verdict command refuses author ∈ reviewers.

## Design (suggested shape)
- DoD kind: {assignee, scope, blocking (default true),
  min_reviewers (default 1)}; compile → on task verify-complete,
  create the assignment decision {diff refs scoped per paths[],
  the summary context (F053's short form)}; the DoD row tracks
  states.
- The verdict: approve (records reviewer, counts toward
  min_reviewers) | request_changes (findings required, anchored)
  — findings → the task's repair round via the standard path;
  after repair, the review REOPENS with the delta highlighted
  (the diff-since-last-review — the viewer's range mechanics;
  the honest re-review, not a rubber stamp).
- Blocking: the task terminal gates on the row (the DoD's
  blocking mechanics); non-blocking records verdicts without
  gating (advisory reviews, rendered).
- Four-eyes: distinct qualified reviewers (role-eligible per the
  assignment); approvals below the count keep pending with the
  progress shown (1/2).
- Oversight: approval chains cite the review verdicts (F169's
  rows gain the richest human evidence — the interlock tested).

## Task slicing

## Acceptance
- Assignment carries scoped diff context (viewer opens it).
  Findings reach the builder verbatim (trace). Self-review
  refused structurally (the author fixture). Blocking holds
  across a restart fixture; min_reviewers counts distinct
  qualified users. The reopen shows the delta range. Oversight
  chains cite verdicts.

## Edge cases & assumption defaults (A9)
- Reviewer pool exhausted (everyone authored): the honest
  blocked state naming the conflict — the operator reassigns or
  waives via a decision (audited waiver, never silent).
  Scope paths[] drifting (repair touches new files): scope
  widens to the touched set with the reviewer seeing the
  addition flagged (honesty over surprise).

## Orchestrator brief

The same-repair-flow rule (A6) and the structural self-review

assertion.

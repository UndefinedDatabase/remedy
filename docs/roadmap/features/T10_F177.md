# T10_F177 — Multi-user write channel
**Tier 10 · Depends on: F175/F176, F009 · Blocks/used by: F178-F181; F169 person precision**

## Goal & Done
See ROADMAP.md F177; the Done criterion there is binding.

## Context (existing code & prior features)
The F009 gateway has client_nonce + audit; identity is missing from the envelope.

## Design
The command gateway requires user_id from session/token; audit lines + decision-queue entries + the ownership ledger (F035) + lineage approval_ref (F163) become person-precise. Nonce idempotency scopes per (user, nonce). SSE gains an actor field on decision.resolved/command events (the UI shows who). Migration rule: legacy data reads actor='operator(legacy)'.

## Task slicing
T001 envelope + gateway + audit extension + tests (2 users, separate nonce spaces). T002 the downstream fields (F035/F163/SSE) + the UI actor display + the migration shim.

## Acceptance & tests
The two-user fixture attributes every effect unambiguously; replaying another user's nonce is not deduplicated against them; the F169 report shows persons.

## Risks / anti-goals
No permission logic duplicated in the gateway (it stays in require(), F175); actor fields are append-only.

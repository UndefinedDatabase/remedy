# T10_F177 — Multi-user write channel
**Tier 10 · Depends on: F175/F176, F009 · Blocks/used by: F178-F181; F169 person precision**

## Goal & Done
Every mutation knows its human: the command gateway requires a
user_id from session or token, audit lines, decision-queue
entries, the ownership ledger and lineage approval refs all become
person-precise, nonce idempotency scopes per (user, nonce), SSE
gains an actor field on decision.resolved/command events so the
UI can show WHO, and legacy data reads as actor='operator(legacy)'.
DONE when unauthenticated mutations are refused at the gateway in
multi-user mode (single-user keeps the implicit operator — the
F175 rule), every person-precise surface records the real user id
on fixture flows (the surface sweep), two users sharing a nonce
value do NOT collide (the scoping test), actor fields render in
the feed with the established presence treatment, the oversight
artifact's approval chains carry persons (its legacy vocabulary
upgraded per the migration rule), and no historical data migrates
destructively (read-time mapping only).

## How it fits (inspect current shape before building)
The write channel (F009) is the single mutation seam — user
resolution happens exactly there (session cookie via F176 or
bearer token via F175 → user; downstream code receives the
resolved actor in the command context, never re-authenticates).
Person-precision is a context-threading exercise over known
writers: commands audit (actor field exists — upgraded from
fingerprint to user id), decision entries (requested_by/
resolved_by), the ownership ledger's actor, lineage's
approval_ref (gains the user), notification events. The
migration rule is read-time: absent actor fields render
operator(legacy) — no rewriting of historical files (append-only
stores stay append-only; the rule lives in the readers, one
shared helper). Nonce scoping: the idempotency store keys
(user, nonce) — two-user fixtures prove isolation.

## Design (suggested shape)
- Gateway: resolve-or-refuse in multi-user mode (401-class with
  the honest message; viewer-role GETs pass per the matrix);
  the command context carries {user_id, roles} to every handler.
- The surface sweep (the deliverable list): audit, decisions,
  ownership, lineage approval_ref, SSE actor, notify events —
  each an additive field with its reader's legacy fallback via
  the shared helper.
- SSE: decision.resolved/command events gain actor {user_id,
  name} — the UI renders initials/name per the reference's
  presence treatment (small, non-intrusive).
- Tests as the contract: a two-user fixture exercising a
  decision flow end to end (A requests nothing; B resolves —
  every surface shows B; A's parallel nonce reuse isolated).

## Task slicing
- **T001** gateway resolution + refusals + context threading +
  the (user, nonce) scoping + unit tests.
- **T002** the surface sweep (per-surface additive fields +
  the shared legacy-fallback reader helper + per-surface tests).
- **T003** SSE actor + UI rendering + the oversight person
  upgrade + the two-user end-to-end + docs (the migration rule

## Acceptance
- Multi-user refusals exact; single-user fixtures byte-identical
  (the F175 sweep extended). Every surface shows the resolving
  user on the two-user fixture; legacy fixtures render
  operator(legacy) without file modification (hash test on the
  stores). Nonce isolation proven. Oversight chains person-
  precise on new data.

## Edge cases & assumption defaults (A9)
- Commands from CLI in multi-user mode: tokens identify the CLI
  user (the CLI reads a per-user token from env/config — the
  documented setup); an unconfigured CLI in multi-user mode gets
  the honest refusal with the setup hint. Concurrent resolution
  races (two reviewers answering one decision): the queue's
  atomic claim already arbitrates — the loser's honest "already
  resolved by <user>" message (the actor named — small UX,
  tested).

## Orchestrator brief

every order. The read-time-only migration rule goes verbatim.

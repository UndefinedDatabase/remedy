# T8_F160 — Cross-vendor failover v2
**Tier 8 · Depends on: F058, F156 · Blocks/used by: durability in continuous operation**

## Goal & Done
Failover crosses vendor lines without crossing trust lines: chains
become adapter.model tuples spanning vendors, every link carries
preconditions — a valid class certificate plus capability coverage
(else the link is SKIPPED with a note, never blindly tried) — a
ten-second health mini-probe runs before takeover, and the report
gains a mandatory block: the chain walked, the reason, the cost
delta (pricing-normalized). DONE when cross-vendor chains validate
their links at config time (certificate + capability per link,
per class), a down-primary fixture walks to the first ELIGIBLE
link with skips noted, the probe gate provably prevents a takeover
by a dead fallback (probe fail → next link), degradation state
recomputes on takeover (the capability matrix's mid-job rule), and
the cost delta renders with bases.

## How it fits (an evolution of F058 — inspect its shape first)
F058 built the discipline: trigger only on provider_unavailable,
per-role chains, hard-rule validation, disclosure evidence, sticky
cooldowns, the resume guard — ALL of it stands; v2 grows the link
type (adapter.model tuples) and the precondition set (certificate
validity for the task's class + capability coverage via the
matrix for the features the task uses — a link that would degrade
a REQUIRED capability skips with capability_gap noted; a link
that merely degrades optionals is eligible with the degradation
recorded on takeover). The probe: a cheap canonical mini-call
(the certification probe pattern, budgeted ten seconds) before
committing the round to the fallback — probe cost is real and
ledgered (honesty). Config validation extends F058's: every link
checked against certificates + the class + hard routing rules
(a chain is as safe as each link, per class).

## Design (suggested shape)
- Chain config: per role, ordered [adapter.model]; validation per
  task class at load (invalid links named with the failing
  precondition — config that can never fire is a lie caught
  early).
- Runtime walk: on the trigger, per link — certificate valid? →
  capability coverage for the run's active feature set? → probe
  (10 s budget, one canonical prompt, success = well-formed
  response) → take over; any gate failing → skip with the typed
  note (no_certificate | capability_gap | probe_failed) → next;
  chain exhausted → the classified failure stands (F058's rule).
- Takeover effects: degradation recompute + evidence, session
  resume never crosses the pair (F058's guard restated for
  tuples), sticky cooldown per failed link.
- The report block (mandatory when any walk happened): the chain
  with per-link outcomes, the trigger reason, the cost delta
  (normalized, bases labeled — pricing's currency rules).

## Task slicing
- **T001** link tuples + precondition validation at load + typed
  skip notes + unit tests (each precondition's fixture).
- **T002** the runtime walk + the probe (budget, ledgered cost,
  a dead-fallback fixture skipped via probe) + takeover effects
  (degradation recompute, resume guard, cooldown) + fixtures.
- **T003** the report block + cost delta + the end-to-end
  (primary down → skip an uncertified link → probe-fail a dead
  link → land on the eligible third → job completes; the block
  golden).

## Acceptance
- Load validation names failing links per class. The walk fixture
  lands correctly with all skips typed; the dead-fallback probe
  prevents the bad takeover. Degradation state and the resume
  guard proven on takeover. The report block mandatory-when-
  walked (a walk without the block fails the test) with
  normalized deltas.

## Edge cases & assumption defaults (A9)
- Probes hitting rate limits: the governor's signals apply — a
  rate-limited fallback WAITS per policy rather than failing the
  probe (limit ≠ unavailable, the F058 taxonomy verbatim).
  Certificates expiring mid-chain-life: load-time validation +
  runtime re-check at the walk (both, cheap) — stale at walk
  time skips with no_certificate.

## Orchestrator brief
Gate on F058 + certification + the matrix + pricing. The
taxonomy discipline (limit waits, unavailable fails over) and
the mandatory report block go verbatim. T002's dead-fallback
fixture is the safety demo.

## Do not touch
F058's trigger taxonomy, routing hard rules, probe budgets
beyond config. Suggested tests:
tests/workers/test_failover_v2.py.

## Goal & Done
Blocked work stops blocking independent work: the executor draws its next
tasks from a topological READY SET computed from the Flight Plan's
dependency edges, and a blocked branch (failed or awaiting a decision)
locks only its own downstream. DONE when a diamond-shaped fixture plan
executes both independent branches while one is blocked, the ready set
recomputes after every task end, and linear plans behave exactly as
before.

## How it fits (inspect current shape before building)
Dependency edges already exist on planned tasks (the Flight Plan schema
validates them as a DAG at plan time — cycles cannot reach this feature).
The multi-cycle executor currently picks tasks in linear order; this
feature replaces its "next batch" selection only. Task state lives on the
core model; check which states exist and treat failed-terminally and
awaiting-decision as blocking states.

## Design (suggested shape)
Pure module `dag_schedule.py`:
- `ready_set(tasks) -> list`: tasks whose dependencies are all completed,
  ordered by plan order (stable, deterministic — no timestamps).
- `blocked_downstream(tasks, blocked_id) -> set`: transitive dependents of
  a blocked task; the executor marks them skipped-blocked in cycle
  evidence so reports can say WHY nothing happened on that branch.
- Executor integration: at each batch boundary compute ready_set minus
  blocked downstreams; empty ready set with unfinished tasks → the
  terminal blocked status the executor already has.
- Tasks without dependency metadata (legacy plans, heuristic fallback
  plans) behave linearly: each task implicitly depends on its predecessor
  — one rule, stated in the docstring, tested.

## Task slicing
- **T001** pure functions + table tests (diamond, chain, independent
  islands, legacy-linear rule, deterministic ordering).
- **T002** executor integration + the diamond fixture run (one branch
  blocked by a forced failure, the other completes; evidence marks the
  skipped downstream) + linear-regression test (existing fixtures
  unchanged).

## Acceptance
- Diamond fixture: independent branch completes while the failed branch's
  downstream is skipped-blocked; final status blocked lists exactly the
  right tasks.
- Ready-set recomputation happens after every task end (asserted via a
  counting stub). Two runs of the same fixture produce identical
  schedules.

## Edge cases & assumption defaults (A9)
- A task depending on a skipped-blocked task is itself skipped-blocked
  (transitivity test). Plans with one task degenerate correctly. Parallel
  EXECUTION is out of scope — the ready set feeds a sequential batch;
  concurrency is a later feature's risk to take.

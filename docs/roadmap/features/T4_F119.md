## Goal & Done
The memory becomes something you WANT to browse: a /memory route
renders the card collection as a grid of tiles — type-colored,
value-ranked, filterable — with a detail sheet for reading and the
curation actions (archive, edit-link, promote later) wired through
the single write channel. DONE when the grid renders fixture
collections at the design reference's quality bar, every tile datum
comes from the store API (no parallel reader), curation actions are
commands (never direct writes from the UI), and the route degrades
gracefully when the shell/backend pieces it needs are not yet
merged (CLI-first remains fully sufficient until Tier 5).

## How it fits (inspect current shape before building)
The data layer is the card store; the UI consumes a read endpoint
(list + detail JSON from the store's honest listing — broken cards
appear as degraded tiles, consistent with everywhere else) and
issues curation through the command channel once it exists; until
then this feature ships the components, the route behind the
existing UI serving path, and read-only rendering — action buttons
render disabled with the honest "lands with the Tier 5 shell"
tooltip pattern the design reference prescribes. Frontend stack,
tokens, fonts, icons: the design reference block above is binding.

## Design (binding specifics)
- Tile: 210×290, radius 16, card background token, soft+inset
  shadows, hover lift:
```css
.card-tile{width:210px;height:290px;border-radius:16px;background:var(--remedy-card);
  box-shadow:var(--remedy-shadow-soft),var(--remedy-shadow-inset);display:flex;flex-direction:column;
  overflow:hidden;transition:transform .18s ease}
.card-tile:hover{transform:translateY(-4px)}
```
- Tile anatomy: type band (token color per card type — the six types
  get six stable token-derived hues), title (Manrope, two-line
  clamp), scope chips (paths count / job kinds), value rank dot
  (bronze/silver/gold/platinum tokens once the value feature feeds
  it; neutral dot until then), status corner (archived tiles render
  desaturated in the archive filter view).
- Grid: responsive columns, type + status + text filters, sort by
  value | updated | type; empty states designed (a new project's
  empty collection invites `remedy study` — copy from the design
  reference's empty-state pattern).
- Detail sheet: the card body rendered as markdown, frontmatter
  facts as a definition list, evidence refs with their live
  resolution badges (the provenance resolver — reuse), and the
  action row (archive/edit-path/promote) as command-channel buttons.
- Data endpoint: read-only JSON alongside the existing UI serving;
  list is paged and filter-aware server-side (collections grow).

## Task slicing
- **T001** the read endpoint on the store (paging, filters, degraded
  entries) + contract tests.
- **T002** tile + grid + filters + empty states against fixture
  collections (component tests; visual conformance per the design
  reference checklist).
- **T003** detail sheet + resolution badges + disabled-action
  honesty + route wiring + an end-to-end against a seeded store.

## Acceptance
- Fixture collection renders per design (tile CSS token-only —
  the guard test greps for raw color literals); filters/sort
  correct; broken card → degraded tile, not a blank grid. Detail
  sheet resolves refs live with badges. All actions disabled with
  the tooltip until the command channel exists (asserted), then
  enabled by feature flag when it does.

## Edge cases & assumption defaults (A9)
- Hundreds of cards: server paging + grid virtualization only if the
  design reference's perf bar demands it at fixture scale — measure
  first. Long titles/bodies: clamp per the tile spec; the sheet
  scrolls.

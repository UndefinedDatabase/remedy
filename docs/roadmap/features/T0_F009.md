# T0_F009 — Der eine Schreibkanal (POST /commands)
**Tier 0 · Abhängigkeiten: keine · Blockiert: F025–F035, F064, F119**

## Ziel & Done
Genau EIN POST `/api/jobs/{jid}/commands`, der ausschließlich in approval_/decision_queue
schreibt. Done: UI-Entscheidung wird vom Backend ausgeführt; jede andere POST-Route bleibt 405.

## IST-Bezug
- ui_server: do_POST → 405 (read-only-Philosophie). approval_queue.py, decision_queue.py,
  command_catalog.py existieren.

## Design
- `packages/orchestration/command_gateway.py`: validiert `{command,args,client_nonce}`
  gegen command_catalog (Whitelist, s. CONVENTIONS), prüft Bearer-Token + `X-Remedy-CSRF`
  (Token beim UI-Start ausgegeben, an EventSource-Handshake gebunden), Rate-Limit
  10 req/10 s/Client, Idempotenz via client_nonce (Replays → 200 mit `duplicate:true`).
- Wirkung: Gateway ENQUEUED nur (decision_queue-Eintrag mit command payload);
  Ausführung bleibt bei den bestehenden Konsumenten. Audit: `commands_audit.jsonl`.
- Antwort: `{accepted:true, queue_id, seq}` — UI wartet auf SSE `decision.resolved`.

## Task-Schnitt
- T001: command_gateway + Katalog-Validierung + Tests (Whitelist, Nonce, Rate-Limit).
- T002: ui_server-Route + Security-Header + Audit + Tests.
- T003: Erster End-to-End-Command `pause_job` inkl. SSE-Bestätigung.

## Akzeptanz & Tests
- Nicht-Katalog-Command → 400; fehlender CSRF → 403; Replay-Nonce → duplicate.
- Sicherheit: Kein Command kann Dateien/Shell direkt erreichen (nur Queue-Write).

## Risiken / Anti-Ziele
- KEINE zweite POST-Route, je. Kein Freitext-Shell-Kanal (F065 mappt auf Katalog).

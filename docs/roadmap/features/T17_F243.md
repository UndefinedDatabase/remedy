# T17_F243 — Public benchmark participation
**Tier 17 · Depends on: F151 adapters, F012, F082 harness · Blocks/used by: external credibility; M16**

## Goal & Done
See ROADMAP.md F243; the Done criterion there is binding.

## Context (existing code & prior features)
F082/F159 measure internally; public comparability is missing. F012 determinism and evidence make results provable.

## Design
An ADR-led benchmark choice (criteria: publicly reproducible, pinned instances, no network surprises - a SWE-bench-verified-style suite). packages/ecosystem/public_bench.py: a harness adapter (load an instance -> shape it as a Remedy job -> extract the patch -> run the official evaluator), a run matrix {worker, instances}, a result report with ALL cases (resolved/unresolved/errored) + per-instance cost (F158) + a methodology section (version, pins, deviations). The publication variant passes the F249 anonymizer (no internal paths).

## Task slicing
T001 the ADR + adapter + a 3-instance smoke (fake + one small real). T002 full-run orchestration (the queue F048, checkpoints F047) + the report + the publication variant + the redaction corpus.

## Acceptance & tests
The smoke reproduces; the report counts EVERY case (the sum invariant resolved+unresolved+errored == n); the methodology is complete enough for third parties to restage the run (a review checklist).

## Risks / anti-goals
No selecting 'convenient' instance subsets without a declared filter; no benchmark-specific prompt hacks in the core (the adapter may map; it must never teach the planner to game the benchmark - the boundary lives in the ADR).

visible-pass/hidden-fail amplification under injected faults, gated
loop vs naive loop — using the F075 injection apparatus as the

## Goal & Done
A job started unattended stays unattended through run, resume, retry and continue: the choice is stored on the job. Every order over HTTP runs unattended unless it sends `unattended: false`; only a question without a safe default waits, with a one-sentence reason. `remedy job run` and the HTTP run and retry routes take `unattended` and `repair_rounds`, an order over HTTP `unattended`; interface 1.33.

## Acceptance
- A job planned by an unattended walk records `unattended`; resuming it answers a budget trip within its caps by its default instead of asking.
- POST /api/v1/jobs/{job}/run with `repair_rounds` 6 answers 400 `api_body_invalid`; with 1 the job runs with one repair round.

## Built state (2026-10-29)
Built on branch welt2/remedycore. New `packages/orchestration/job_unattended.py` keeps the choice on the job (`metadata.unattended`): `do_targets.name_do_job` records it for an unattended walk's jobs, `remedy job run --unattended`/`--no-unattended` switch it (a tri-state pair in `apps/cli/grouped.py`'s `_TRI_STATE_FLAGS`, beside `--stream-evidence`), and `job_run_refusals.refuse_job_run_before_it_starts` calls `prepare_unattended_run`, which approves a plan that still waits (`approve_unattended_plan`, audit reason names F324) before any refusal reads it. `job_burn.job_approved_unattended` reads the stored choice first, and `record_burn_trip` keeps a trip of an unattended job with its own caps as an assumption (`unattended_assumptions`) instead of pausing it. HTTP: `POST /api/v1/orders`, `/run` and `/retry` take `unattended` (flag), and `/run` and `/retry` `repair_rounds` (body kind `rounds`, 0 to 5, else 400 `api_body_invalid`; `public_api_writes._body_refusal`, moved there verbatim from `public_api.py`); an order's `unattended: false` makes `OrderLauncher.start` leave out `--run-unattended`. Public API and machine client interface 1.33; `docs/system/api-release-matrix-v1.json` has its entry.

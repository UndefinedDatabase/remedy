## Goal & Done
See ROADMAP.md F048; the Done criterion there is binding.

## Context (existing code & prior features)
worker_queue exists in name only; unattended processing needs a real queue.

## Design
SQLite table queue in the project ledger DB {id, goal_ref, prio, claimed_by, claimed_at, status}; atomic claim via UPDATE ... WHERE claimed_by IS NULL ... RETURNING. CLI `remedy queue add <goal.md|text> [--prio] | list | rm`. The executor consumes the queue when scope.queue is set.

## Task slicing
T001 queue + claim atomicity + a two-process no-double-claim test. T002 CLI + executor binding.

## Acceptance & tests
3 entries, one run, 3 results; parallel claiming clean.

## Risks / anti-goals

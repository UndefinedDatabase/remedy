## Context (existing code & prior features)
useSemanticZoom knows L0-L3; the F042 grid is a card view - the GRAPH view over jobs is missing.

## Design
A zoom level L-1 in useSemanticZoom (the state machine extended; transition-matrix tests as in F023): each active/recent job renders as a mini-organism (an aggregated state ring: pass/fail/progress shares as ring segments; a core glyph by job kind); mission threads (F056) connect organisms as edges; the layout uses force with mission clusters. Clicking an organism dives into that job's L0 (backfill via /graph). Data: a light endpoint GET /api/projects/{pid}/organisms (per-job aggregates: state distribution, cost, last activity - NO node details). An org variant (?scope=org) filters via F185.

## Task slicing
T001 the organisms endpoint + aggregation + tests. T002 the L-1 state + ring rendering (a glyphPaths extension) + threads + navigation + playwright (a 10-job fixture; smooth drill-down).

## Acceptance & tests
10 jobs stay readable; ring shares reconcile with job states; L-1 -> L0 -> back keeps state (zoom-machine tests); ACL filtering holds (the F185 property).

## Risks / anti-goals
L-1 shows aggregates, never individual nodes (detail belongs to L0 - resist the temptation); refresh rides SSE aggregate events, no polling storm.

## Context (existing code & prior features)

## Design
`remedy release check` (a mandatory CI gate before tagging): (1) the benchmark shows no regression vs. the last stable (F082; F159 where adapters are configured), (2) the determinism suite passes (F012), (3) the migration path last-stable -> HEAD is tested (F202 up/down), (4) the edition matrix passes (F214), (5) open P0 findings = 0 (source: an issue-label convention, configurable), (6) the docs build passes (F216). The beta channel: criteria 2/3/4 mandatory, 1 informative. The result report ships as a release artifact (a maturity proof, linkable).

## Task slicing
T001 the check orchestration + criteria 2-4 + the report. T002 criteria 1/5/6 + channel differentiation + CI wiring (tagging without a green check impossible - branch protection docs).

## Acceptance & tests
A deliberate benchmark regression blocks stable (test); beta lets it pass with a note; the report lists every criterion with a proof link.

## Risks / anti-goals
The criteria list freezes per major (changes = ADR); no emergency-skip flag exists (emergencies = the beta channel).

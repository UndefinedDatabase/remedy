## Design
packages/verification/property_gen.py: candidates = pure functions in the diff (AST: no IO calls; type-annotated preferred). Strategy derivation from types (st.from_type) + docstring examples; the generated test ships as a PROPOSAL task (the F064 path, or direct under --tdd) into tests/property/. Shrinking results are formatted as readable findings (minimal example + property name). An optional DoD kind property.

## Task slicing
T001 candidate detection + strategy derivation + tests. T002 the generator + the finding formatter + a fixture (an edge-case bug in date logic is found).

## Acceptance & tests
The fixture bug is caught by a generated property with the minimal example in the finding; IO functions yield no proposals (negative test); generated tests run deterministically (hypothesis seed pinned, F012).

## Risks / anti-goals
No property flood (max n proposals per job, ranked by function centrality via the F107 import graph); generated tests are proposals under normal review.

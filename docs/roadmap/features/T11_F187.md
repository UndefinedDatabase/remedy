# T11_F187 — Property-based test generator
**Tier 11 · Depends on: F061, F129 · Blocks/used by: depth beyond example tests**

## Goal & Done
Tests learn to hunt instead of spot-check: property_gen.py finds
candidates — pure functions in the diff (AST: no IO calls, type-
annotated preferred) — derives strategies from types plus
docstring examples, and ships each generated test as a PROPOSAL
task (the F064 path, or directly under --tdd) into
tests/property/; shrinking results format as readable findings
(the minimal example plus the property name); an optional DoD
kind property exists. DONE when candidate selection matches its
table on fixture diffs (pure/typed found, IO-touching excluded),
generated tests are valid, runnable and MEANINGFUL on fixtures
(round-trip/invariant templates instantiated from signatures —
not tautologies; the meaningfulness review is an acceptance
step), proposals flow the idea gate (human-approved into the
tree), shrunk counterexamples render as findings with the
minimal input verbatim, the property runner ships as the
quality extra with honest degradation, and generated tests are
marked as such (provenance headers — curators know origin).

## How it fits (a dependency note + composition)
The property engine (hypothesis-style) joins the `remedy[quality]`
extra (the mutation feature's home — one extra, the testing-depth
toolbox; absent → the DoD kind reports tool_unavailable, the
generator refuses politely). Candidate analysis is pure AST work
over the job's diff (the churn/security scope pattern: touched
files → new/changed functions → purity heuristic (no IO-class
calls, no filesystem/network imports in the call graph's first
ring — documented, conservative), annotations preferred (from_type
needs them; unannotated candidates rank lower with docstring-
example fallback). Generation is TEMPLATED, not free-form: a
small library of property shapes (round-trip encode/decode,
idempotency f(f(x))==f(x), invariant preservation, oracle-
against-reference where the diff replaced an implementation) —
the generator instantiates shapes whose preconditions the
signature/docstring satisfies; no shape fits → no proposal
(silence over tautology, the rule).

## Design (suggested shape)
- `packages/verification/property_gen.py`: candidates(diff) →
  ranked list {function, purity evidence, annotations, examples};
  generate(candidate) → {test source (provenance header, the
  shape named, strategies from types/examples), rationale};
  proposals via the idea kind property_test (refs: the function,
  the shape, the rationale) → approval materializes under
  tests/property/ (the gated tree-write path).
- --tdd interplay: under the TDD gate, generated tests may join
  the test task's selector directly (still human-visible in the
  plan — the pairing rules apply).
- Findings: a failing property run's shrunk case renders {property,
  function, minimal input (repr), the assertion} — into the
  normal repair flow when the DoD kind is active.
- The DoD kind property (optional, default off): runs
  tests/property/ scoped to touched modules under a budget
  (examples count config — bounded time, the sampling honesty).

## Task slicing
- **T001** candidate analysis (purity table, ranking, exclusions)
  + fixtures (pure found, IO excluded, unannotated ranked low).
- **T002** the shape library + instantiation + meaningfulness
  fixtures (each shape on a matching function; the no-shape-fits
  silence) + provenance headers + proposal flow.
- **T003** the DoD kind + budget + shrunk-finding rendering +
  the repair-flow injection + the extra packaging + the
  end-to-end (a diff with an encode/decode pair → proposal →
  approved → a seeded bug → the property fails → the shrunk
  finding drives repair).

## Acceptance
- Candidate table exact. Generated tests run green on correct
  fixtures, red with shrunk minimal inputs on seeded bugs; no
  tautological instantiations (the review + the shape
  preconditions). Proposals gate through humans; direct writes
  only via approval (state diff). Budgets hold. Absent extra →
  honest degradation everywhere the kind/generator surfaces.

## Edge cases & assumption defaults (A9)
- Strategies for project-specific types: from_type fails →
  docstring examples seed a sampled strategy; neither → the
  candidate drops with the reason (no guessing generators —
  stated). Flaky properties (time/randomness leaks past the
  purity check): the flaky detector's machinery applies to
  property tests like any test (the interlock noted).

## Orchestrator brief
Gate on the idea gate + the DoD compiler + the quality extra.
The silence-over-tautology rule and the shape-precondition
discipline go verbatim. T002's meaningfulness fixtures are the
feature's credibility — enumerate the shapes in the order.

## Do not touch

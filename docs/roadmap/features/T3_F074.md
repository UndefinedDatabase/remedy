# T3_F074 — Estimate calibration
**Tier 3 · Depends on: F003, F103 · Blocks/used by: F014 bands, F104, F144, F222**

## Goal & Done
Estimates stop being folklore: rolling per-class distributions built
from ledger actuals (tokens and cost per task class × role) replace
the configured class defaults everywhere estimates surface — bands
become the class's P20–P80, and every consumer's basis label flips
from class_default to calibrated(n) once a class has enough samples.
DONE when a fixture ledger produces correct distributions, all three
consumers (flight-plan bands, predictive budget, cost preview) read
the SAME calibration source, and thin classes stay honestly on
defaults.

## How it fits (inspect current shape before building)
The estimator was deliberately shared when predictive budgets and cost
preview were built — calibration slots in UNDER that shared estimator
as its data source; consumers must not change (one seam test per
consumer proving the label flip is the whole integration). Task
classes are the shared vocabulary routing established; per-task
actuals need task_id+class on ledger rows — verify both are recorded
(the ledger writer captured task ids; class may need a tiny additive
backfill from job records).

## Design (suggested shape)
- `calibration.py`: build(project, window) → per (class, role):
  {n, p20, p50, p80, updated_at} for tokens and cost; computed on
  demand from ledger queries with a small cached snapshot under the
  data root (refreshed when stale by config age — no background
  jobs); sample floor n≥20 (config) per class before "calibrated"
  applies; outlier damping documented (trim the top/bottom
  percentile before fitting — protect against one runaway poisoning
  a class).
- Estimator integration: resolve(class) → {band, basis:
  calibrated(n)|class_default, source_window}; mixed states are per
  class (one class calibrated, its neighbor default — labels say so
  individually).
- Flight-plan bands: the S/M/L/XL band VOCABULARY stays (plans stay
  human-readable); calibration maps each band to its class's
  measured token range for arithmetic, and the plan renderer can
  annotate bands with the current calibrated midpoints.
- `remedy stats calibration` renders the table with n, percentiles
  and staleness — the trust view.

## Task slicing

## Acceptance
- Fixture percentiles exact; the outlier fixture's P80 is not dragged
  by the runaway (damping test). Each consumer's output flips labels
  correctly with zero other behavioral change below the floor.
  Snapshot staleness honored; computation is read-only on the ledger.

## Edge cases & assumption defaults (A9)
- Model changes shift cost curves: distributions are per (class,
  role) and windowed — old-model rows age out; a model-dimension
  split is a later refinement, noted, not built. Empty ledgers:
  everything stays default-labeled; the stats view says why.

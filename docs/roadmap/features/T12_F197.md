# T12_F197 — OpenTelemetry export (GenAI conventions)
**Tier 12 · Depends on: F004, F103, F171/F174 · Blocks/used by: customer stacks; M12**

## Goal & Done
See ROADMAP.md F197; the Done criterion there is binding.

## Context (existing code & prior features)
F004 run events and the F103 ledger hold all raw data; a standards export does not exist.

## Design
packages/telemetry/otel.py (opentelemetry-sdk, OTLP exporter): mapping job -> trace, task -> span, run -> a GenAI client span (gen_ai.* semantic-convention attributes: system=worker_id, request.model, usage input/output tokens; cost as remedy.cost_eur + pricing_version), tool_calls -> tool execution spans, decisions -> span events. The semconv version is pinned PER EXPORT (attribute remedy.semconv_v) - the conventions are partly experimental; pinning tames drift. Prompt/completion CONTENT only under a double opt-in ([telemetry] content=true AND the data class allows it; the F174 gate first, F171 redaction on top). Config: endpoint, headers, resource attributes (project_id).

## Task slicing
T001 mapping + exporter + semconv pinning + tests (in-memory exporter, attribute goldens). T002 the content opt-in chain (F174/F171 gates) + a jaeger integration test (container, subprocess marker) + a 'Remedy in your Grafana in 10 minutes' doc.

## Acceptance & tests
The fixture job produces a valid trace (attribute golden per pinned semconv version); span cost sums equal the ledger; without opt-in no span contains prompt text (corpus test).

## Risks / anti-goals
No own trace viewer (the cockpit stays evidence-based; OTel is the INTEGRATION); semconv updates only via a deliberate version bump + golden update.

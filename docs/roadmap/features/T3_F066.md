# T3_F066 — Idea provenance
**Tier 3 · Depends on: F063 · Blocks/used by: trust in ideas**

## Goal & Done
Idea references become checkable forever: evidence refs get TYPES —
file location, failure class+count, coverage metric, decision id — a
resolver verifies them at creation AND at display, and a reference
whose source vanished marks the idea STALE (visible, explained) but
never deletes it. DONE when each ref type round-trips through
creation/display resolution on fixtures, a removed source flips the
idea to stale with the missing ref named, and the list/show surfaces
render staleness prominently.

## How it fits (inspect current shape before building)
V1 required refs to resolve as paths at creation; this feature
formalizes the vocabulary the engine and miners already implicitly
produce (a failure cluster IS a class+count claim; a TODO IS a
file+line claim) — migrate the producers to emit typed refs and keep
accepting v1 plain-path refs as type file with a legacy note (additive
schema evolution, no store migration).

## Design (suggested shape)
- Typed ref schema: {type: file|failure|coverage|decision, plus
  type-specific fields — file: path + optional line + content_hint
  (a short expected substring making line drift detectable); failure:
  class + window + count; coverage: module + metric + value; decision:
  queue id} — extensible enum, unknown types render as unverifiable
  (honest) rather than erroring.
- Resolver `resolve_ref(ref) -> Resolution{status: ok|drifted|missing,
  detail}`: file checks existence and, with a content_hint, that the
  hint still matches near the line (drift ≠ missing — a moved line is
  drifted with the new location if found); failure re-queries the
  postmortem store for the window (counts may legitimately change —
  report current vs claimed); coverage re-reads the report file;
  decision checks the queue.
- Display integration: ideas list/show resolve on render (cheap,
  bounded) and badge each idea ok|drifted|stale (stale = any missing
  ref); a stale idea keeps its record and gains a staleness entry in
  its audit trail the first time detected.
- Approval of a stale idea: allowed with an explicit warning
  acknowledging which claims no longer verify (human's call, informed).

## Task slicing
- **T001** typed schema + resolver per type + table tests (ok/drifted/
  missing per type; legacy plain-path acceptance).
- **T002** producer migration (engine v1 + each miner emits typed
  refs) + fixtures re-run green with typed output.
- **T003** display badging + staleness audit entry + approve-with-
  warning + the end-to-end (delete a source file → idea stale, named
  ref, approvable with warning).

## Acceptance
- Per-type fixtures resolve correctly in all three states; content-
  hint drift finds the moved line. Legacy refs render as file-type
  with the legacy note. Staleness is detected at display without a
  background job, recorded once, and never deletes.

## Edge cases & assumption defaults (A9)
- Resolution cost on big lists: resolve lazily per rendered page/N
  items (config), with a --verify-all flag for full audits. Refs into
  evidence of pruned/archived jobs: missing with a "job archived"
  detail if the job record proves it existed — accuracy in the
  epitaph.

## Orchestrator brief
T001's per-type table tests are the substance. T002 touches several
producers — one small order per producer with its fixture. Keep the
never-delete rule verbatim in T003.

## Do not touch
Idea content, approval semantics, archival policies. Suggested tests:
tests/orchestration/test_idea_provenance.py.

# T11_F190 — Test environment provisioning
**Tier 11 · Depends on: F007 · Blocks/used by: F189/F191/F192 environments**

## Goal & Done
Multi-service targets get real test beds: [runtime.compose] in
config names the compose file, per-service readiness probes and an
optional seed command; compose_env.py drives up → ready probes →
optional seed → a handle for checks → down — ALWAYS down,
trap-secured — with per-service logs as artifacts; without
docker/podman the block degrades honestly (a capability-register
entry: compose → skip with a note; affected DoD checks report
'not verified', NEVER green). DONE when the lifecycle runs a
fixture compose project end to end (up, probes gate, seed runs
once, checks receive the handle, down happens on success AND on
every failure/interrupt path — the trap matrix), readiness
probes support the documented kinds (http, tcp, cmd) with
per-service timeouts and honest timeout findings naming the
service, logs land per service as run artifacts, degradation
without a container runtime marks every dependent check
not-verified (the never-green rule proven), and secrets in
compose/seed configs flow through the secret:// provider.

## How it fits (inspect current shape before building)
F007 owns single-service runtime (start, ready, stop) — compose
is its multi-service sibling behind the SAME handle abstraction
(checks consume {base_urls per service, env, workdir} — verify
F007's handle shape and match it; consumers like the contract
kind take the handle, not the provisioning). Container runtimes
are detected external tools (podman preferred where both — the
documented order), NEVER Python dependencies (the extras/tools
stance); the capability register (F157) hosts the compose
capability with its degradation entry (skip + not-verified —
the never-green rule is the honesty core: a DoD check whose
environment didn't exist must not pass). The trap discipline:
teardown registered before up returns (context-manager +
signal handling per the runtime layer's existing patterns —
verify and reuse); orphan detection in doctor (labeled
containers from dead runs — a cleanup hint, honest about the
platform's realities).

## Design (suggested shape)
- Config: [runtime.compose] {file, services_ready: [{service,
  probe: {kind: http|tcp|cmd, target, timeout_s}}], seed_cmd?};
  validation (file exists, services in the compose file, probe
  shapes).
- `packages/verification/compose_env.py`: provision() → the
  handle (F007-shaped, per-service addresses from the compose
  runtime's port mapping — queried, not guessed); teardown
  always (the trap matrix: success, check failure, probe
  timeout, signal, Python exception); per-service logs captured
  at teardown into run artifacts (bounded size, the tail rule
  documented).
- Probes: http (status < 500 on target), tcp (connect), cmd
  (exit 0, run in-container via the runtime's exec); per-service
  timeout → the finding {service, probe, waited} and teardown.
- Seed: runs ONCE after all-ready (idempotency is the seed
  author's contract, documented); secret:// resolution +
  redaction registration (F171's interlock).
- Degradation: no runtime detected → the register entry fires;
  dependent DoD rows render not-verified with the install hint.

## Task slicing

- **T002** the lifecycle (up, probes per kind, seed, handle

- **T003** doctor orphan detection + secret interlock + consumer

## Acceptance
- The trap matrix: containers absent after every path (asserted
  via the runtime's listing). Probe kinds each proven incl. the
  timeout finding naming the service. The handle matches F007's
  shape (the consumer test passes unchanged against both
  providers). Logs per service bounded. Not-verified rendering
  on the no-runtime fixture (never green — the rule's test).
  Seed once; secrets never on disk (the walk).

## Edge cases & assumption defaults (A9)
- Port conflicts on busy machines: ephemeral port mapping is
  the default posture (query the runtime for actuals — no fixed
  ports in fixtures, documented for user compose files too).
  Slow images (first pull): pull time counts against a separate
  documented setup timeout, not the probe budget (fairness,
  stated). Rootless runtimes: the detection prefers what works
  rootless; quirks land in the docs honestly.

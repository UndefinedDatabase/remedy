## Goal & Done
The tokens one `claude-cli` call spends before it does any work are measured, attributed to their
sources and cut by the configuration Remedy starts the worker with. DONE when the same small task
is shown before and after with its tokens by kind, and `remedy stats` shows tokens per call and
per landed change.

## Why this exists
The operator's first standing priority is that Remedy is frugal by construction, and he reads
tokens and calls, not money (ruling R1). Measured from the closure self-use runs of F293, F294,
F292, F200, F290, F295 and F287 (`.agent/selfuse_f293/`, `.agent/selfuse_f294/`,
`.agent/selfuse_f292/`, `.agent/selfuse_f200/`, `.agent/selfuse_f290/`, `.agent/selfuse_f295/`,
`.agent/selfuse_f287/`): a change of two lines took 2 to 6 provider calls, and its `total_tokens`
read 5,505 to 25,099 — a figure that leaves out cache creation and cache reads, where a whole
Claude Code session spends most of what it spends. Three of the seven runs landed a change; two
passed review with no file changed; one stopped at its limit after three of five tasks with 12
calls; one passed and was never landed. Read in `build_claude_cli_args` in
`packages/orchestration/pingpong_provider.py`: the worker is started with the prompt, the output
format, the model, the schema, the resumed session and the allowed tools; nothing limits the tool
servers of the operator's account, the settings, skills and hooks of the operator and the project,
or the project's instruction files, so each call is a whole Claude Code session with everything
loaded. In Remedy's own repository that includes `AGENTS.md`, which is the build loop's law and no
business of a builder. Read in the records: the builder may edit and may not run a command, and
the jobs' `test_command` was empty, so no test ran inside these jobs.

## Task slicing
- T001 — Measure from the records. For the `claude-cli` calls already in the token ledgers and
  run records: input, output, cache-creation and cache-read tokens per call and per role, and the
  share of cache creation in a session's first call. Written to an inventory file under `.agent/`.
  No new provider call.
- T002 — Attribute. With one small fixed task, in a scratch repository and in a worktree of
  Remedy, switch each source off in turn (tool servers, settings with skills and hooks, project
  instruction files, the tool set) and read what the first call then spends. Which switches the
  installed `claude` offers is read from its own help output and documentation at the claim, never
  from a model's memory. The whole task makes at most 40 provider calls and says how many it made.
- T003 — Cut. The leanest configuration that still passes the gauntlet becomes the default the
  worker is started with; each source switched off has a configuration key that turns it back on,
  and a run's evidence names the configuration its calls ran under.
- T004 — Show. `remedy stats` gains tokens by kind per call and per landed change, per role and
  provider.

## Acceptance
- The inventory holds the four token figures for at least twenty recorded calls.
- The same task's first call spends measurably fewer tokens after T003 than before, both figures
  by kind in the Built State; or a dated DECISION says with numbers why nothing could be cut.
- A test fails when the worker's command line loses a switch T003 added.
- T002's number of calls stands in the Built State and is at most 40.

# T1_F013 — Job intake
**Tier 1 · Depends on: F146, F005 · Blocks/used by: F014, F056, F069**

## Goal & Done
A free-text mission becomes a structured, validated JobIntake — goal,
context references, constraints, acceptance hints, open clarifications —
persisted on the job before planning. DONE when intake runs through the
structured-output schema gate (never trusts raw LLM text), degrades
honestly to a deterministic fallback without a provider, and the Flight
Plan can consume the result without re-reading the mission.

## How it fits (inspect current shape before building)
The schema infrastructure exists: a strict base model family with a schema
version constant, a validate-response helper that yields a parse error
class and a retry hint, and JSON-schema rendering for prompts. The intake
model is one more subclass — no new validation path. Provider transport,
timeouts, retries and per-call evidence all live in the ping-pong loop:
intake must reuse the same single-shot call helper (extract one if none is
importable) — never a second subprocess/timeout implementation (A6). The
mission text arrives on the job via the golden-path do command.

## Design (suggested shape)
- Schema: `JobIntake` (versioned "intake_v1"): goal (one normalized
  sentence), context_refs (paths/URLs the mission mentioned), constraints,
  acceptance_hints, truncated_input flag, and clarifications — a list of
  `{question, default_answer, impact}`. The bundled-clarification feature
  consumes this contract later; define it here, once.
- Module `intake.py`: `run_intake(job, provider_call)` builds the prompt
  from mission + cheap repo facts (top-level layout, detected runtime,
  project slug) + the rendered JSON schema; validates; uses the existing
  single parse retry. `heuristic_intake(mission)` is the deterministic
  fallback (goal = first sentence, empty lists, zero questions) used when
  the provider is unavailable; the result records source llm|heuristic and
  the CLI prints `intake: heuristic fallback (provider unavailable)` —
  degraded mode is labeled, never silent (P6).
- Persistence: additive optional intake field on the job, saved before
  planning. The intake call goes through a normal per-call evidence
  directory, so postmortems and the run manifest cover it for free.
- CLI: the do path runs intake before planning; `remedy job show` renders
  the intake block; `--no-llm` forces the heuristic path for offline work.

## Task slicing
- **T001** schemas + validation round-trip tests (valid; missing field,
  wrong type, extra field all rejected as parse class) + job field with a
  backward-compat fixture.
- **T002** intake module + prompt builder + shared single-shot call +
  fake-provider tests: valid; invalid-then-valid via the retry;
  invalid-twice → parse-class failure + postmortem; provider missing →
  labeled heuristic path.
- **T003** do-path integration + job-show rendering + golden-path smoke
  update (the deterministic-skeleton plan label STAYS until the Flight
  Plan feature).

## Acceptance
- Fake-provider run: the stored intake carries the schema version and the
  exact goal the fake returned; its evidence directory exists.
- No provider binary: do still reaches a planned job via the heuristic,
  label shown, exit 0. A mission mentioning file paths shows them in
  context_refs (fixture asserts pass-through, not extraction magic).

## Edge cases & assumption defaults (A9)
- Non-English missions pass through untranslated. Oversized missions are
  truncated in the PROMPT at a documented marker, kept whole on the job,
  and flagged truncated_input. More than five clarifications → keep the
  first five, record the drop count (bounded human load).

## Orchestrator brief
T001 alone first (schema is the contract others consume). Before T002,
have the worker identify the loop's reusable single-shot call surface and
report it; if extraction is needed, that extraction is its own small
order with its own tests.

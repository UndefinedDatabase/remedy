## Goal & Done
Costs stop being an opaque total: because every call already records its
segment manifest and its actuals, `remedy stats report` can show WHERE
tokens go — by segment kind, by role, by task class — plus a cost curve
and a prior-period comparison, on demand, as markdown and json. DONE when
the report renders from fixture data with every number traceable to
ledger rows, cache share and priciest classes are visible, and a period
with missing data says so instead of interpolating (P6).

## How it fits (inspect current shape before building)
The prompt-segment registry records a manifest (segment names, ranks,
hashes) into call evidence; the token ledger stores per-call actuals.
This feature JOINS them: persist the manifest reference (or the compact
manifest itself) alongside the ledger row when calls are recorded — check
what the writer already stores and extend additively — then aggregate.
No new capture, no new numbers: aggregation and presentation only.

## Design (suggested shape)
- Ledger extension (additive column/table): per call, the segment
  manifest as compact json or a reference to the evidence file; a
  backfill pass tolerates old rows without manifests (reported as
  "unattributed" — never guessed).
- `remedy stats report [--since] [--until] [--json]` renders: total cost
  and tokens with basis labels; per-role and per-task-class breakdown;
  per-segment-kind input share (system/conventions/dossier/context/task);
  cache-read share; top five priciest jobs with links; a comparison to
  the equal-length prior period where data exists.
- Rendering is a pure function over query results (goldens); markdown for
  humans, json for the later UI section.
- Explicitly on demand — no scheduler, no background jobs here.

## Task slicing
- **T001** manifest-alongside-actuals persistence + backfill tolerance +
  unit tests (old rows render unattributed).
- **T002** aggregation queries + the pure renderer + goldens on a fixture
  ledger (mixed roles, classes, missing manifests, unpriced calls).
- **T003** CLI + period comparison + json schema + tests (empty prior
  period → "no comparison data", not zeros).

## Acceptance
- Golden report matches on the fixture ledger; every cost line carries
  its basis; unattributed and unmeasured shares are shown as such.
- Segment shares sum to the attributed total (internal consistency test).
- Report generation touches nothing (read-only; state snapshot equal).

## Edge cases & assumption defaults (A9)
- Timezone: all periods UTC, stated in the header. Huge ledgers: queries
  are indexed and bounded by the period; no full-table scans in the hot
  path (assert via query plan or row-count discipline in tests).

## Orchestrator brief
Gate on the ledger and segment registry. T002's goldens are the substance
— put the fixture ledger's expected numbers in the order so the worker
computes them independently.

## Do not touch
Pricing tables, calibration, UI rendering, scheduled reporting. Suggested
tests: tests/orchestration/test_cost_report.py, tests/cli/test_stats_report.py.

## Correction — the manifest premise, and DECISION F115 D1 (2026-08-13)

This file's premise is false as written. "How it fits" says the prompt-segment
registry "records a manifest ... into call evidence" and the Goal assumes
"every call already records its segment manifest". The registry does build the
manifest and `PromptTraceEntry` does carry it, but only four of the seven
non-test `build_trace_entry` call sites pass `composed_prompt` —
`intake.py:145`, `flight_plan.py:191`, `orchestrator_loop.py:930` and
`mission_compiler.py:290`. The three that produce the prompts behind every
real ledger row do not: the builder (`pingpong_loop.py:2824`), the reviewer
(`pingpong_loop.py:3010`) and the planner (`apps/cli/commands/job.py:236`).
On live data the manifest is therefore EMPTY for exactly the calls this
feature exists to explain. Evidence: `.agent/f115_inventory.md` (F115 R1),
Q3 and Q4.

DECISION F115 D1 — wire the missing sites through the registry before building
the report, starting with the builder site. Chosen because the alternative
(accept current rows as permanently "unattributed" and build only the
backfill-tolerant path) ships a report whose headline breakdown is 100 %
unattributed on real data — a feature that passes its goldens on fixtures and
explains nothing about an actual run, which is the failure mode P1 and P6
exist to prevent. The cost is low and the risk is bounded: `_build_builder_prompt`
is a thin wrapper that already returns `compose_builder_prompt(...).text`, and
the suite already pins that equivalence
(`tests/orchestration/test_builder_prompt_golden.py:254`), so the sent bytes do
not change. Alternatives considered: (a) accept unattributed — rejected above;
(b) re-split the prompt string after the fact to recover segments — rejected
because it re-derives what the composer already knows and would drift from it
silently. Reverse this decision by deleting this section and dropping the
`composed_prompt=` argument at the wired call sites; the manifest returns to
empty and nothing else changes.

Two limits this correction does NOT remove, both recorded here so the report's
scope stays honest. The ledger's `role` column takes its value from
`token_accounting.json`, which hardcodes `"role": "builder"` for a whole task
run (`pingpong_loop.py:4011`), so the "per-role breakdown" this file asks for
has ONE bucket until that is fixed — the existing CLI already says so in its
own output (`_ROLE_LIMIT_NOTE`, `stats_ledger_cmd.py:334-339`). And the "by
task class" breakdown has no source at all: there is no task-class column on a
ledger row and `task_granularity.py:5` states that Remedy has no per-task-class
cost history yet. Both belong to their own features; F115 reports what exists
and says "no data" for what does not, rather than inventing a bucket.

## T001 persistence shape — DECISION F115 D4 (2026-08-13)

T001's "persist the manifest reference (or the compact manifest itself)
alongside the ledger row" is settled as a SEPARATE TABLE, not a column on
`calls`. A ledger row is one finalized task run; a manifest is one provider
call, so the relation is one-to-many, and `verify_ledger`'s whole-dataclass
equality plus the hook's ordering against the trace-file copy make an
evidence-derived column read as drift on every row. Full reasoning, citations
and the reversal recipe: `.agent/decisions.md`, "DECISION F115 D4".

Consequence for this file's Design section: "Ledger extension (additive
column/table)" resolves to the TABLE reading. The backfill tolerance the same
bullet asks for is structural — a pre-F115 row owns no `call_segments` rows,
and the report renders that absence as unattributed rather than guessing.

## Built State — what F115 shipped (2026-08-13)

This section is an inventory: names, files and literal values. What the
commands print, and why, is in `docs/guides/cost-report-user-guide-v0.md`,
which is written against real output.

Command surface — `apps/cli/command_catalog.py` carries the entry
`command_id="stats.report"`, whose handler is `_cmd_stats_report` in
`apps/cli/commands/stats_ledger_cmd.py`. Its declared args are `--since`,
`--until`, `--job`, `--by`, `--label`, `--project` and `--json`. There is no
`--all-projects` arg in that entry, deliberately: cost folds across projects
but the segment breakdown does not.

Renderers — `packages/orchestration/cost_report.py`.
`render_cost_report_markdown` and `cost_report_json_bytes` are declared
`-> str`; `cost_report_json` is declared `-> dict[str, Any]`. All three take
report objects rather than a connection. `COST_REPORT_VERSION = 3`, carried in
the json under the key `report_version`.

Queries and persistence — `packages/orchestration/token_ledger.py`, with
`SCHEMA_VERSION = 2`. New public names: `query_segment_shares`,
`prior_report_period`, `record_call_segments`, `segment_rows_from_trace_file`,
and the row types `CallSegmentRow`, `SegmentShareRow`, `SegmentShareReport`,
`PriorReportPeriod`.

Literal values — `COST_UNMEASURED_LABEL = "unmeasured"`,
`COST_DEFAULT_LABEL = "(unlabelled)"`,
`COST_UNNAMED_BUCKET_LABEL = "(unnamed)"`. A recursive search of `tests/` finds
`unmeasured` in the cost-report tests and in both goldens; it finds
`unlabelled`, `(unnamed)`, `COST_DEFAULT_LABEL` and
`COST_UNNAMED_BUCKET_LABEL` nowhere. Only the first of the three is pinned
today.

Why a comparison can be absent — `prior_report_period` returns one of four
reasons, and their names are their meanings: `_PRIOR_REASON_OPEN_ENDED` (a
bound is missing), `_PRIOR_REASON_UNPARSEABLE` (a bound does not parse),
`_PRIOR_REASON_MIXED_AWARENESS` (one bound is offset-aware and the other
naive), `_PRIOR_REASON_EMPTY_PERIOD` (the period ends at or before it starts).
All four are properties of the REQUESTED period; the separate case of a prior
window that was read and held no call is `COST_EMPTY_COMPARISON` in
`cost_report.py`, beside `COST_NO_COMPARISON_DEFAULT` for a window that was
never read. An absence and a measured zero are kept apart throughout.

Wiring — `plan_job_with_llm` in `packages/orchestration/llm_planner.py` gained
a keyword-only parameter `on_prompt_composed`, which `apps/cli/commands/job.py`
passes. `packages/orchestration/pingpong_loop.py` carries the builder and
reviewer composed-prompt wiring. The whole branch touches seven files under
`packages/` and `apps/`: `command_catalog.py`, `commands/job.py`,
`commands/stats_ledger_cmd.py`, `cost_report.py`, `llm_planner.py`,
`pingpong_loop.py`, `token_ledger.py`.

Two breakdowns are deliberately absent. `token_ledger.py` contains no
`task_class` anywhere, so a per-task-class breakdown has no source to
aggregate. A per-role breakdown has one bucket, because a task run's `role` is
recorded as `"builder"` for the whole run. The note describing the role limit,
`_ROLE_LIMIT_NOTE`, is read in exactly two places — `_cache_payload` and
`_render_cache_human`, both belonging to `_cmd_stats_cache`. The body of
`_cmd_stats_report` contains neither that constant nor any task-class text.
Both limits belong to their own features.

Goldens are DATA — `tests/orchestration/fixtures/cost_report/golden/`. No test
regenerates them, and the golden `cost_report.md` appears verbatim inside
`docs/guides/cost-report-user-guide-v0.md`. A renderer change that moves those
bytes must move the guide in the same commit.

One lesson outlives the code. F115's cover for the planner call site is a test
in `tests/orchestration/test_structured_planner_cli.py` that reads
`apps/cli/commands/job.py` with `inspect.getsource` and asserts the wiring
string appears in the source. It reads the file instead of executing the call,
so it proved the argument was written and could never prove it worked — and a
test double left with the old two-parameter signature broke six tests that
stayed invisible to every scoped round gate until the integration gate ran
(finding R-0340). A wiring test that does not execute the wiring is not cover.

# T2_F115 — Prompt breakdown & cost report
**Tier 2 · Depends on: F103, F105 · Blocks/used by: transparency, F123 section**

## Goal & Done
Costs stop being an opaque total: because every call already records its
segment manifest and its actuals, `remedy stats report` can show WHERE
tokens go — by segment kind, by role, by task class — plus a cost curve
and a prior-period comparison, on demand, as markdown and json. DONE when
the report renders from fixture data with every number traceable to
ledger rows, cache share and priciest classes are visible, and a period
with missing data says so instead of interpolating (P6).

## How it fits (inspect current shape before building)
The prompt-segment registry records a manifest (segment names, ranks,
hashes) into call evidence; the token ledger stores per-call actuals.
This feature JOINS them: persist the manifest reference (or the compact
manifest itself) alongside the ledger row when calls are recorded — check
what the writer already stores and extend additively — then aggregate.
No new capture, no new numbers: aggregation and presentation only.

## Design (suggested shape)
- Ledger extension (additive column/table): per call, the segment
  manifest as compact json or a reference to the evidence file; a
  backfill pass tolerates old rows without manifests (reported as
  "unattributed" — never guessed).
- `remedy stats report [--since] [--until] [--json]` renders: total cost
  and tokens with basis labels; per-role and per-task-class breakdown;
  per-segment-kind input share (system/conventions/dossier/context/task);
  cache-read share; top five priciest jobs with links; a comparison to
  the equal-length prior period where data exists.
- Rendering is a pure function over query results (goldens); markdown for
  humans, json for the later UI section.
- Explicitly on demand — no scheduler, no background jobs here.

## Task slicing
- **T001** manifest-alongside-actuals persistence + backfill tolerance +
  unit tests (old rows render unattributed).
- **T002** aggregation queries + the pure renderer + goldens on a fixture
  ledger (mixed roles, classes, missing manifests, unpriced calls).
- **T003** CLI + period comparison + json schema + tests (empty prior
  period → "no comparison data", not zeros).

## Acceptance
- Golden report matches on the fixture ledger; every cost line carries
  its basis; unattributed and unmeasured shares are shown as such.
- Segment shares sum to the attributed total (internal consistency test).
- Report generation touches nothing (read-only; state snapshot equal).

## Edge cases & assumption defaults (A9)
- Timezone: all periods UTC, stated in the header. Huge ledgers: queries
  are indexed and bounded by the period; no full-table scans in the hot
  path (assert via query plan or row-count discipline in tests).

## Orchestrator brief
Gate on the ledger and segment registry. T002's goldens are the substance
— put the fixture ledger's expected numbers in the order so the worker
computes them independently.

## Do not touch
Pricing tables, calibration, UI rendering, scheduled reporting. Suggested
tests: tests/orchestration/test_cost_report.py, tests/cli/test_stats_report.py.

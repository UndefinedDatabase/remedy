# T4_F124 — Card hygiene (manual + periodic)
**Tier 4 · Depends on: F117, F113, F045 · Blocks/used by: collection quality**

## Goal & Done
The collection stays trustworthy as it grows: `remedy memory
compact` proposes merges for near-duplicates, archives (never
deletes) what the human confirms, enforces the token budget, and
routes conflicts to decisions; a periodic cheap-model loop checks
active cards against current code — do referenced paths and patterns
still exist? — and files archive/update PROPOSALS. DONE when the
duplicate detector finds seeded near-pairs without false-positive
noise on a healthy fixture, every hygiene outcome is a proposal or
an explicit human command, and the periodic loop runs as a normal
declared loop on the cheap route.

## How it fits (inspect current shape before building)
Everything is composition: the provenance resolver already answers
"does this ref still hold" (staleness per card = its refs' states +
a path-scope existence check); the idea/harvest queue carries
proposals; loops host the periodic run; local/cheap routing serves
the one LLM-assisted step (semantic near-duplicate confirmation —
the DETECTION is deterministic first: title token overlap + scope
overlap + body shingle similarity above thresholds; the cheap call
only CONFIRMS candidate pairs and drafts the merged card, so a dead
LLM degrades to "pairs listed, merge drafts unavailable" — honest).

## Design (suggested shape)
- `memory_hygiene.py`:
  - find_duplicates: the deterministic similarity pipeline
    (thresholds config; table-tested) → candidate pairs → optional
    cheap-model confirmation + merged-card draft (both originals'
    evidence refs union, provenance preserved) → merge PROPOSALS
    (approve = new card active with merged_from, originals archived
    with pointers — history navigable both ways).
  - check_liveness: per active card, resolve refs + scope paths →
    stale cards get archive-or-update proposals with the specific
    dead references named; cards with drifted (not missing) refs get
    update proposals carrying the resolver's new locations.
  - budget sweep: cards over cap (grandfathered hand-edits) →
    trim-proposals, never trims.
  - conflicts (two active cards contradicting on the same scope —
    detected only via the cheap confirmation step when merging is
    wrong because they DISAGREE): a decision with both cards quoted;
    humans arbitrate, always.
- `remedy memory compact [--dry-run]` runs all passes and prints the
  proposal summary; the periodic variant ships as a loop definition
  (the routine library gains it) on the summary/side-role route.

## Task slicing
- **T001** deterministic duplicate detection + thresholds + table
  tests (seeded near-pairs found; the healthy collection silent).
- **T002** liveness/budget passes on the resolver + proposal filing
  + fixtures per outcome (stale, drifted, oversized).
- **T003** cheap-model confirmation + merge drafts + conflict
  decisions + degradation honesty + the loop definition + the
  end-to-end (compact on a messy fixture → the expected proposal
  set, nothing mutated without approval).

## Acceptance
- Seeded pairs found, healthy fixture silent (false-positive
  budget: zero on the fixture). Every pass's output is proposals/
  decisions only (state diff proves no mutation). Merge approval
  produces the bidirectionally-linked history. LLM-down degradation
  is labeled, run completes.

## Edge cases & assumption defaults (A9)
- The pinned dossier is exempt from merge/archive proposals (its
  own checker owns it — cross-reference, don't duplicate). Archived
  cards never re-propose as duplicates of each other (active-only
  scanning).

## Orchestrator brief
Gate on provenance + routing. T001's determinism-first split is the
architecture — the cheap model confirms, never discovers; verbatim
into the order. T003 is one careful order.

## Do not touch
Deletion (does not exist), value mechanics, the dossier checker.

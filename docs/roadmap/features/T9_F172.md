# T9_F172 — Policy packs
**Tier 9 · Depends on: F017, F141, F161, F166 · Blocks/used by: F209 org inheritance; F169 quotes**

## Goal & Done
Governance ships as a named unit: a pack is a directory —
policy_packs/<name>/ with pack.toml (name, version, description)
plus fences.toml, permissions.toml, mcp_allowlist.toml,
licenses.toml, retention.toml — ALL existing formats, nothing new
invented; `remedy policy apply <pack>` copies into .remedy/policy/
with a provenance note (pack@version); `remedy policy check` diffs
live state against the applied pack as a drift detector; projects
may tighten, and loosening below the pack minimum is a check
FINDING. DONE when apply round-trips fixture packs with provenance
recorded, check classifies drift exactly (tightened: ok noted,
loosened: finding naming the file+key+minimum, unrelated
additions: listed neutrally), the tighten/loosen comparison
reuses each policy domain's own semantics (the sandbox partial
order, matrix cell strictness, allowlist subsets — one comparator
per domain, owned by its feature and imported), pack validation
refuses malformed members via their own validators, and the
oversight/dossier artifacts can QUOTE the applied pack@version as
the governing policy.

## How it fits (composition — the formats are the features')
Every member format exists with its own validator and semantics —
the pack layer adds only bundling, provenance and drift: apply
validates members via THEIR validators (imported — a pack cannot
smuggle an invalid fences file past fences' own rules), copies
with the provenance file (.remedy/policy/pack_provenance.json
{pack, version, applied_at, by, member hashes}); check re-hashes
live files against provenance and, where hashes differ, runs the
DOMAIN comparator (each policy feature exports
compare(pack_value, live_value) → tightened | loosened | changed
— the sandbox feature's partial order generalizes into the
pattern; domains without a natural order treat any change as
changed-needs-review, honestly). The "quotes" consumers: F169's
autonomous rows and the dossier's chapter 1 cite pack@version
from provenance (the interlock tested).

## Design (suggested shape)
- Pack layout + pack.toml schema + member validation via domain
  validators; packs live in-repo (policy_packs/ — reviewable,
  versioned with the project) or imported from a shared location
  (a later org feature — the format is the contract).
- apply: validate → show the incoming diff vs live (the shown-
  diff-before-accept pattern) → copy + provenance; re-apply of a
  newer version shows the version diff.
- check: hash comparison → domain comparators → the report
  {member, status: unchanged | tightened | loosened(finding) |
  changed}; wired as a doctor section and an optional CI/DoD row.
- The comparator contract: each domain feature exports its
  compare (small orders per domain adding it where missing) —
  the pack feature imports, never reimplements (the A6 line).

## Task slicing
- **T001** pack schema + member validation via imports + the
  provenance record + apply with the shown diff + tests.
- **T002** the comparator contract + per-domain orders (sandbox
  imports its order; matrix defines cell strictness; allowlists
  subset semantics; licenses/retention documented semantics) +
  table tests per domain.
- **T003** check + classifications + doctor/DoD wiring + the
  oversight/dossier quote interlock + the end-to-end (apply →
  tighten one file (ok) → loosen another (finding names the
  minimum) → check report golden).

## Acceptance
- Apply validates via domain validators (an invalid member
  refused by ITS validator's message). Provenance complete;
  quotes resolve in oversight/dossier fixtures. Check matrix
  exact per domain; loosened findings name file+key+minimum.
  Comparators imported (grep: no comparison logic in the pack
  module beyond dispatch).

## Edge cases & assumption defaults (A9)
- Packs with a subset of members: unlisted domains are
  unmanaged (check ignores them — packs govern what they
  contain, stated). Local edits before any pack: check without
  provenance says "no pack applied" (never inventing a
  baseline). Multiple packs: v1 is one pack per project (the
  org-inheritance feature layers later — noted).

## Orchestrator brief
Gate on the five domain features. T002 is parallel per-domain
orders — each adds compare() to ITS feature with table tests;
the pack module only dispatches (verbatim rule). The shown-diff
apply and the quote interlock are acceptance spine.

## Do not touch
Domain formats/validators (imported), org inheritance (later),
policy semantics. Suggested tests:
tests/enterprise/test_policy_packs.py.

# T9_F172 — Policy packs
**Tier 9 · Depends on: F017, F141, F161, F166 · Blocks/used by: F209 org inheritance; F169 quotes**

## Goal & Done
See ROADMAP.md F172; the Done criterion there is binding.

## Context (existing code & prior features)
Fences, matrix, allowlists, retention exist as separate configs; bundling+versioning+conformance checking are missing.

## Design
A pack = a directory policy_packs/<name>/ (pack.toml: name, version, description; containing fences.toml, permissions.toml, mcp_allowlist.toml, licenses.toml, retention.toml - all EXISTING formats, nothing new invented, A6). `remedy policy apply <pack>` copies into .remedy/policy/ with a provenance note (pack@version); `remedy policy check` diffs the live state against the applied pack (a drift detector). A hardening half-order: projects may tighten; loosening below the pack minimum is a check FINDING.

## Task slicing
T001 pack format + idempotent apply + provenance + tests. T002 the drift detector + half-order rules per policy type + fixture packs (strict/standard).

## Acceptance & tests
apply twice == once (idempotence); a deliberate loosening is found with a diff; F169 can quote rules verbatim (an anchor API).

## Risks / anti-goals
Packs are files in a repo/org store - no policy server; conflict resolution is deterministic and documented (pack < project tightening).

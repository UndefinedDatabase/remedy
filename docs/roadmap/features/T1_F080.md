# T1_F080 — Machine-readable roadmap mirror & STATUS.md
**Tier 1 · Depends on: parser: none (build FIRST in this tier); adapter: F070 · Blocks/used by: the self-build interface itself; F248**

## Goal & Done
The roadmap becomes machine-usable without losing its human form: a
parser mirrors ROADMAP.md + the feature files + STATUS.md into a
generated structured index; `remedy plan status` names the next open
feature and its blockers; and a feature→mission adapter turns a detail
file into a runnable mission. DONE when the parser round-trips THIS
repository, grammar violations fail with file-and-line precision, and
one real feature file compiles end to end into a mission plan. Build the
parser/status half FIRST in this tier — humans get `remedy plan next`
immediately.

## How it fits (inspect current shape before building)
STATUS.md is the ONLY execution-order truth (its grammar: checkbox lines
in order; the first unchecked line is next) and stays human-owned:
updating it remains part of the same PR as the work (A4) — Remedy READS
it and may PROPOSE an update as a diff in a job's changes, but the merge
is the human act. The mirror is a GENERATED artifact under the data root
— never committed, always rebuildable, so it can never drift into a
second truth. The mission compiler and DoD compiler exist for the
adapter half.

## Design (suggested shape)
- Parser `roadmap_index.py` (pure): read ROADMAP.md, features/*.md and
  STATUS.md → index {features: [{id, tier, title, depends_on, blocks,
  status, file}], milestones, order}. Header conventions of the feature
  files (title line, the bold dependency line) are the parse anchors —
  validate them strictly and report violations as `<file>:<line>:
  <what>` so fixing is mechanical. Write the index (yaml or json) under
  the data root.
- CLI `remedy plan status` (next open feature, its blockers' states,
  the milestone it serves) and `remedy plan next` (prints the proposed
  next feature with its file path — proposes, never starts).
- Consistency checks (report, don't fail, except grammar): STATUS
  entries without a feature file, files absent from STATUS, dependency
  references to unknown ids.
- Adapter `feature_mission_adapter.py`: detail file → mission draft —
  the context/fit section becomes context input, task slicing seeds the
  plan structure, acceptance seeds the DoD compiler input, the
  do-not-touch list becomes fences. Output is a PREPARED mission
  (records + plan draft) awaiting the standard human approval — the
  adapter never starts execution.
- Regenerate on every read path (cheap) or on demand — no staleness
  states to manage.

## Task slicing
- **T001** parser + grammar validation + index writer + CLI status/next;
  fixture = this repository itself plus broken-grammar fixtures for each
  violation class.
- **T002** consistency checks + reporting + tests.
- **T003** the adapter + one end-to-end compile of a real small feature
  file into a prepared mission (approval left open) + tests proving
  no execution side effects.

## Acceptance
- On this repo: index complete, `plan next` names the first unchecked
  STATUS feature and its real blockers. Each grammar-violation fixture
  fails with exact file:line. Adapter output carries context, plan seed,
  DoD seed, and fences traceable to the file's sections; zero jobs
  started.

## Edge cases & assumption defaults (A9)
- Features present in files but not in STATUS: reported, treated as
  not-scheduled (STATUS rules). Duplicate ids across files: hard grammar
  error. The index never feeds back into the markdown — one-way mirror,
  stated in the docstring.

## Orchestrator brief
T001 is high-leverage and independent — dispatch it early, even before
neighboring features. The adapter (T003) gates on the mission compiler.
When the orchestrator later drives self-build, `plan next` + the adapter
IS its work-intake path: review T003's output format with that use in
mind.

## Do not touch
STATUS.md semantics and ownership (A4), committing generated artifacts,
auto-checking checkboxes. Suggested tests:
tests/orchestration/test_roadmap_index.py,
tests/orchestration/test_feature_mission_adapter.py.

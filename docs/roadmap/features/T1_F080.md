## Goal & Done
See ROADMAP.md F080; the Done criterion there is binding.

## Context (existing code & prior features)
This unified ROADMAP.md and Part C's STATUS.md are the contract; Remedy must read and maintain both. Build the parser/status parts before everything else in Tier 1 - humans benefit from `remedy plan next` immediately.

## Design
`scripts/masterplan_sync.py` parses ROADMAP.md (this file) + features/*.md -> .remedy/masterplan.yaml {features[{id,tier,title,deps,status}]}; status comes from STATUS.md (Part C grammar - the ONLY execution-order truth). CLI: `remedy plan status` (next open feature + blockers), `remedy plan next` (proposes it). Grammar validation: a malformed STATUS.md line fails with file:line precision. The feature->mission adapter turns a detail file into a mission: the Context section becomes a context segment, Task slicing seeds the plan, Acceptance seeds the DoD. STATUS.md updates are part of A4 (same PR as the work).

## Task slicing
T001 parser + yaml + status/next CLI + grammar validation (this repo as the fixture). T002 the feature->mission adapter + an end-to-end compile of one detail file.

## Acceptance & tests
`remedy plan next` names the correct feature for fixture STATUS states; the adapter output is a runnable mission; malformed lines rejected precisely; the mirror is a read-only derivation (markdown stays the single truth).

## Risks / anti-goals
Never let the yaml mirror become editable truth; never bypass STATUS.md order (A5).

# T10_F185 — Per-project permissions
**Tier 10 · Depends on: F175, F148 · Blocks/used by: F210 visibility; light tenant separation**

## Goal & Done
See ROADMAP.md F185; the Done criterion there is binding.

## Context (existing code & prior features)
F148 scopes data per project; person x project is missing.

## Design
Access config (.remedy/policy/access.toml per project or ~/.remedy/org/access.toml centrally): user -> role per project (default in multi-user mode: no access; single-user unchanged and open). Enforcement server-side BEFORE the F148 filter (the project list itself is filtered); cost visibility is its own flag (viewer_costs). The F148 leak test gains the person dimension (a property over all GET endpoints x roles).

## Task slicing
T001 access resolution + the endpoint gate + tests. T002 the cost flag + the extended leak property + the UI project list per user.

## Acceptance & tests
A user without a role sees the project in NO response (including later aggregates - the F210 coupling is pre-tested); the cost flag governs stats/ticker.

## Risks / anti-goals
No row-level encryption promises (access separation, not crypto separation - docs honest); the single-user path stays configuration-free.

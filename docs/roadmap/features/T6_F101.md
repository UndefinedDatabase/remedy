# T6_F101 — Reference fidelity rule
**Tier 6 · Depends on: F088, F092 · Blocks/used by: A9 enforcement**
> **CANONICAL DESIGN REFERENCE:** This feature MUST follow the canonical Remedy
> UI design reference in `docs/ui/design_reference/`. `ux_design.png` is the
> visual authority; the written specs, tokens, component rules, graph rules and
> motion rules in that folder are binding for this feature. Builders must not
> invent a new visual language; any visual deviation must be documented in the
> assumption_log with a technical reason. All UI work uses the shared design
> tokens (`--remedy-*`) and component rules from the design reference.
> **ASSET REFERENCE:** fonts, icons, graph glyphs, logo and visual assets
> follow `assets_spec.md` in the same folder (the asset authority). No new
> font, icon library, glyph style, logo treatment or asset source may be
> introduced unless `assets_spec.md` is updated and the deviation is
> documented in assumption_log with a technical reason.

## Goal & Done
The tier's law becomes enforceable: one central prompt block — "the
screenshot is law; deviate only on technical impossibility, then
write an assumption_log entry with the reason" — ships in every
design-task prompt, and the visual reviewer treats UNLOGGED
deviations as high findings while logged ones review as documented
trade-offs. DONE when the block provably reaches every design-task
prompt from one source constant, a seeded unlogged deviation
fixture yields the high finding citing the rule, a logged deviation
fixture reviews without the escalation, and the assumption-log
entries carry the technical reason in a validated shape.

## How it fits (inspect current shape before building)
Tiny feature, heavy leverage — pure composition: the block is a
SEGMENT constant (the style block's opening — F088's segment grows
its stage-2 content here; one source, rank inherited); the
assumption log exists (the bundled-clarification artifact) — design
deviations append entries of a typed kind {kind:
design_deviation, region/element, reference value, built value,
technical_reason} via a small builder-facing convention: the
builder DECLARES deviations in its response (the response schema
for design tasks gains an optional deviations[] — validated,
flowing into the log); the reviewer's prompt (F092) gains the
cross-check instruction: findings matching a logged deviation
reference it (downgraded to the documented severity), findings
without a log entry escalate to high with the rule cited.

## Design (suggested shape)
- The rule constant: exact wording versioned in the segment
  module; the reviewer's instruction references the same constant
  (one wording, two consumers — drift-proof by import).
- Builder declaration: deviations[] on the design-task response
  schema (additive) {element/region, expected_per_reference,
  actual, technical_reason: minLength}; validation feeds the
  assumption log with actor=builder + the round ref.
- Reviewer cross-check: the review call receives the current
  deviation log; the schema's finding gains logged_deviation_ref?
  — findings with a matching ref render as trade-offs (severity
  from the log's review, default medium), findings WITHOUT a
  match on a deviating element are high with "undeclared
  deviation from reference" phrasing (golden).
- Human visibility: the assumption log's design section renders
  in plan/report; the fidelity residue report cross-links logged
  deviations (an aborted loop distinguishes "couldn't" from
  "didn't try").

## Task slicing
- **T001** the constant + segment growth + trace proof on design
  tasks + the reviewer-instruction import + tests.
- **T002** the deviations[] schema + log wiring + validation +
  unit tests (reason required; entries typed).
- **T003** the reviewer cross-check (ref matching, severity
  rules) + seeded fixtures both ways + residue cross-links + the
  end-to-end.

## Acceptance
- One-source proof (grep: the wording exists once). Both seeded
  fixtures exact (unlogged → high citing the rule; logged →
  trade-off severity). Log entries validated and rendered.
  Residue links logged deviations.

## Edge cases & assumption defaults (A9)
- Builders over-declaring (logging everything defensively): the
  reviewer still reviews the reasons — a hollow technical_reason
  is itself a finding (the goldens include one). Deviations the
  reviewer can't see (behavioral): out of scope here — the
  interaction tier owns behavior.

## Goal & Done
Design references become first-class job inputs: `remedy do --design
shot.png` (repeatable) registers reference images R1..Rn with
optional scope notes ("R2 = settings page"), hashes them into the
job's input evidence, keeps originals immutable, and threads the
references into the Job Plan so every downstream tier-6 feature
has one addressing scheme. DONE when multi-reference fixtures
register with stable numbering and scope notes, the run manifest
covers the images (input determinism extends to pixels), plan tasks
can cite R-numbers, and mutation of a registered original is
detected and refused.

## How it fits (inspect current shape before building)
The vision-planner feature built attachment intake (CLI surface,
storage, manifest hashing, type/size validation) — this feature is
its DESIGN-SPECIFIC specialization: verify what --attach shipped and
extend it (a --design alias with reference semantics: ordered
numbering, scope notes, the immutability contract) rather than a
parallel path (A6). Storage under the job's inputs/design/ area with
content-hash filenames beside the original names; the R-number ↔
hash mapping is the addressing table every later feature (builder
attachment, decomposition, comparison) reads — one table, defined
here.

## Design (suggested shape)
- CLI: `--design path[:scope note]` repeatable; numbering by
  argument order (R1..Rn, stable forever for the job); re-running
  intake never renumbers.
- Registration record (evidence, versioned): [{r: "R1", original
  name, sha256, scope_note?, dimensions, registered_at}]; originals
  copied byte-exact; the manifest's input hashes include them.
- Immutability: reads verify the hash; a mismatch (someone edited
  the file in evidence) is a hard, named error — references are
  facts, not moods.
- Job-Plan threading: the intake/plan prompts receive the
  reference LIST (numbers, scope notes, dimensions — not yet
  pixels; the next feature attaches images to build tasks); planned
  UI tasks may carry design_refs: ["R2"] (additive field), seeding
  region hints once decomposition lands.
- Mission-level design inputs follow the same table (a mission's
  references pass to its jobs — noted for the compiler, wired
  when needed).

## Task slicing
- **T001** the --design surface on the attachment machinery +
  numbering/scope parsing + registration record + immutability
  verification + tests (multi-ref order, mutation detection,
  duplicate file → distinct R-numbers allowed with a note).
- **T002** manifest coverage + plan threading (list in prompts,
  design_refs on tasks) + fake-provider tests proving R-number
  citations survive into the stored plan.
- **T003** CLI/UX polish (the do output lists references), docs,
  and the addressing-table read helper every later feature
  imports (one accessor, tested).

## Acceptance
- Fixture with three references + scope notes registers exactly;
  manifest includes the hashes; plan tasks cite R-numbers from the
  fake provider round-trip. Edited original → named refusal.
  The accessor helper is the only read path (grep guard seeds the
  tier's discipline).

## Edge cases & assumption defaults (A9)
- Oversized/malformed images: the attachment validation's rules
  apply (caps config). References without scope notes: fine —
  notes are hints, not requirements. Jobs mixing --design and
  plain --attach: both work; only --design gets R-numbers.

# T15_F230 — Mission portfolio optimizer
**Tier 15 · Depends on: F064/F066, F074, F226, F104 · Blocks/used by: F248 self-build steering; budget realism**

## Goal & Done
See ROADMAP.md F230; the Done criterion there is binding.

## Context (existing code & prior features)
The idea queue has manual drag priority; proofs (F066), effort bands (F074) and risk (F226) exist as ingredients.

## Design
`remedy ideas rank [--budget-eur X]`: a per-idea score = f(benefit proof strength from F066 ref types, inverse effort band midpoint, inverse risk, strategic tag weights from config) - the formula is printed OPENLY in the output; the budget constraint runs greedy selection up to X with a justification line per position ('in: strong proof + S band; out: budget'). The result is a PROPOSED ordering: one command adopts it into the queue (a reprioritize_idea batch); the audit notes 'ranked by optimizer vX'.

## Task slicing
T001 the score + formula disclosure + budget greedy + tests (a target-function golden). T002 the adoption command + a UI view (before/after ordering) + the audit.

## Acceptance & tests
The synthetic queue orders exactly per the declared target function (golden); budget edge cases are correct; adoption happens only via the explicit command (nothing reorders itself).

## Risks / anti-goals
The formula stays simple + visible (no blackbox scoring); strategic weights are operator config, never LLM opinion.

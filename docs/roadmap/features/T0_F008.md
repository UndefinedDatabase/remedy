# T0_F008 — SSE-Eventstream
**Tier 0 · Abhängigkeiten: F004 (Event-Quelle) · Blockiert: F019–F024, F040, F066–F068-UI**

## Ziel & Done
`GET /api/jobs/{jid}/events/stream` liefert Server-Sent Events aus dem bestehenden
events-since-Cursor + run_events (F004). Done: Statuswechsel <1 s in der UI, Polling tot.

## IST-Bezug
- ui_server.py: stdlib BaseHTTPRequestHandler, GET-only, events-since-Cursor existiert
  im Backend; Frontend pollt 5 s.

## Design
- `packages/orchestration/event_stream.py`: Aggregiert Job-Events (Status, decisions)
  + run_events zu Envelope (CONVENTIONS), monoton `seq`, Heartbeat alle 15 s
  (`:keepalive`), `Last-Event-ID`-Resume.
- ui_server: Route streamt chunked (`text/event-stream`), Thread pro Verbindung,
  max 8 gleichzeitige Streams (429 darüber), Token-Gate wie bestehend.
- Frontend `apps/ui/src/components/brain/useBrainStream.ts`: EventSource, Reconnect
  mit Backoff, Fallback auf Polling wenn SSE 3× scheitert (Ehrlichkeit: Badge „poll").

## Task-Schnitt
- T001: event_stream.py + Envelope-Tests (seq monoton, resume korrekt).
- T002: ui_server-Route + Limits + Tests (httpx-Client, keepalive).
- T003: useBrainStream + Umstellung State-Refresh; Vitest + Playwright-Latenztest.

## Akzeptanz & Tests
- Event nach Backend-Statuswechsel in <1 s beim Client (Playwright-Messung).
- Reconnect verliert keine Events (Last-Event-ID-Test).

## Risiken / Anti-Ziele
- Kein WebSocket (stdlib-Server behalten, A6-Geist: minimaler Umbau).

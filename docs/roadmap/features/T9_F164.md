# T9_F164 — AI labeling in commits (standard)
**Tier 9 · Depends on: F139, F151 · Blocks/used by: F163 resolvability; audit expectations**

## Goal & Done
Every Remedy commit says plainly what made it: a binding trailer
set — Remedy-Job:, Remedy-Task:, Remedy-Worker: <adapter>@
<version>, Co-Authored-By: <model> via Remedy <version> — enforced
in the ONE commit path (consolidating the worktrees commit helper
is part of the work), where a missing trailer is a programming
error and a hard test failure; `remedy audit commits [--since]`
checks history and lists unlabeled foreign commits informatively.
DONE when the consolidation finding proves one helper (or makes it
so), every machinery commit carries the full set (a commit-path
walk test), the churn feature's minimal trailers upgrade to this
standard with its parser following, the audit command classifies
fixture histories correctly (remedy-labeled, foreign, pre-standard),
and trailer values resolve (job/task ids real, adapter@version
from the run's evidence).

## How it fits (inspect current shape before building)
F139 introduced minimal trailers for churn attribution — this
feature is the STANDARD those seeded: the same commit-helper site
grows the full set, and F139's parser reads the superset (one
format, documented in one place; the churn tests updated, not
duplicated). The consolidation finding inventories commit sites
(the applicator's task commits, checkpoint commits if any,
baseline updates, design-system extraction — every git commit the
machinery makes) and routes them through the one helper; the gate
is structural (the helper REQUIRES the fields — callers without
context can't commit, which is the point). Values come from run
context (job/task ids, the resolved adapter.model pair from
routing evidence, the Remedy version constant).

## Design (suggested shape)
- The helper: commit(worktree, message, context {job, task,
  worker_pair}) → message + trailers; missing context fields
  raise (programming error class — tests per caller prove the
  context flows); trailer formats versioned in one constants
  module (F139's parser imports it).
- Multi-model commits (repair rounds mixing models before one
  commit): Remedy-Worker/Co-Authored-By lines repeat per
  distinct pair (git trailers allow repetition; the parser
  handles lists — documented).
- `remedy audit commits [--since]`: walk history → per commit
  {remedy (trailers valid) | foreign (no trailers) |
  pre-standard (partial trailers, dated before the standard)} —
  informative listing, never failing (foreign commits are the
  human's right); --json for tooling.
- Docs: the trailer standard as a short spec (customer-facing —
  auditors read this).

## Task slicing

## Acceptance
- One helper (grep: no raw commit invocations outside it +
  the violation fixture). Every machinery commit path walk
  yields full trailers with resolvable values. Multi-pair
  fixture repeats lines correctly; the parser reads them.
  Audit classifications golden. Churn suite green.

## Edge cases & assumption defaults (A9)
- User-configured commit templates/hooks in the target repo:
  trailers append AFTER template content; a hook rejecting the
  commit surfaces as the honest task failure (the target's
  rules win — documented). Squash workflows: the audit's
  pre-standard/foreign vocabulary covers the aftermath; lineage
  notes and the archive carry the deep truth (cross-referenced).

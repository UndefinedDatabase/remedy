# T0_F006 — Worktree-Isolation pro Lauf
**Tier 0 · Abhängigkeiten: keine · Blockiert: F049, F056, F136, F137**

## Ziel & Done
Jeder Run arbeitet in eigenem `git worktree`; Ergebnis = Branch + PR-fertiger Diff.
Done: zwei parallele Läufe kollidieren nicht.

## IST-Bezug
- `staging_workspace.py` kopiert heute in Staging-Verzeichnisse; kein echtes worktree,
  Haupt-Checkout wird bei Self-Runs berührt (80 dirty files-Risiko).

## Design
Neues Modul `packages/orchestration/worktrees.py`:
```python
def create(job_id) -> WorktreeHandle  # git worktree add .remedy-wt/<job_id> -b remedy/<job_id>
def snapshot(handle) -> sha; def diff(handle) -> path; def remove(handle, keep_branch=True)
```
- Pfad: `<repo>/.remedy-wt/<job_id>/` (in .gitignore via F081/F146-Init).
- Locking: `~/.remedy/projects/<pid>/locks/<job_id>.lock` (fcntl), Anti-Doppel-Claim.
- Ergebnisübergabe: Branch `remedy/<job_id>`, `result.diff` in Evidence.

## Task-Schnitt
- T001: worktrees.py + Tests (create/diff/remove, Lock-Kollision).
- T002: pingpong_job/loop nutzen Worktree statt Staging; Evidence-Feld `worktree`.
- T003: Parallel-Smoke: 2 Fake-Jobs gleichzeitig, getrennte Branches, kein Konflikt.

## Akzeptanz & Tests
- Haupt-Checkout bleibt clean während eines Laufs (git status-Assertion).
- Abbruch (kill) hinterlässt reparierbaren Zustand: `remedy jobs resume` räumt Lock.

## Risiken / Anti-Ziele
- Kein Auto-Merge in main — Merge bleibt bewusste Aktion (F009-Command später).

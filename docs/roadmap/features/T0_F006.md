# T0_F006 — Worktree isolation per run
**Tier 0 · Depends on: none · Blocks/used by: F029, F049, F056, F136, F137, F200**

## Goal & Done
See ROADMAP.md F006; the Done criterion there is binding.

## Context (existing code & prior features)
staging_workspace.py copies into staging dirs; self-runs can dirty the main checkout (the historic 80-dirty-files risk).

## Design
`worktrees.py`: create(job)->handle (git worktree add .remedy-wt/<job> -b remedy/<job>), snapshot()->sha, diff()->path, remove(keep_branch=True). fcntl lock files under ~/.remedy/projects/<pid>/locks/ prevent double claims. Results are handed over as branch + result.diff in evidence. .remedy-wt/ goes into .gitignore at init.

## Task slicing
T001 module + tests (create/diff/remove, lock collision). T002 job/loop use worktrees instead of staging; evidence field worktree. T003 parallel smoke: 2 fake jobs, separate branches, zero conflict.

## Acceptance & tests
Main checkout stays clean during a run (git status assertion); a killed run leaves a repairable state that `remedy jobs resume` clears.

## Risks / anti-goals
No auto-merge to main - merging stays a deliberate human action.

# T14_F220 — Feedback funnel
**Tier 14 · Depends on: F199, F171, F219 · Blocks/used by: supportability without breaking trust**

## Goal & Done
See ROADMAP.md F220; the Done criterion there is binding.

## Context (existing code & prior features)
F199 produces local crash reports; the F171 redaction corpus exists.

## Design
`remedy feedback [--attach-crash <id>] [--attach-bundle <job>]`: builds a structured report (version, editions, a doctor short status, free text); attachments are REDACTED (the F171 suite + the F249 anonymizer) and shown to the user IN FULL (a pager) - sending only after an explicit yes. The target is configurable: a mailto draft, an HTTPS endpoint, or a file (air-gap: file + manual transfer). Never an auto-attachment.

## Task slicing
T001 the report builder + the redaction chain + the mandatory display + corpus tests over attachments. T002 the three target kinds + the air-gap path + an E2E (declining after the display sends nothing).

## Acceptance & tests
Without confirmation zero bytes leave (capture); canaries appear in no sent attachment; the file target works fully offline.

## Risks / anti-goals
No 'send diagnostics automatically' checkbox (deliberate friction is the feature here); the endpoint is the vendor's concern - the client stays dumb.

**Tier 7 · Depends on: F061 (Definition-of-Done compiler), F062 (product smoke), F269 (the mission contract), F270 (the push a red contract refuses) · Blocks/used by: every order on a project other than Remedy; the first real order of Luna on a universe repository**

## Goal & Done
A mission on a repository that is not Remedy's own gets acceptance checks that can pass there:
they run the project's own test command in the project's own environment, and a project with no
tests is told so instead of being judged red. DONE when three scratch targets — a Python project
with its own virtual environment and a dependency Remedy's environment lacks, a Node project whose
tests run with `npm test`, and a repository with no tests — each end a `remedy do` with the fake
providers in the state the facts support, and the push rule of F270 follows that state.

## Why this exists
Measured by the operator's orchestrator on 2026-10-07 on `main` at `e80b9546`: `remedy do` on a
scratch repository with no `tests` folder, planned without a model, gave the mission one blocking
criterion checked by `pytest` with the selector `tests`; the job ended `completed`, the criterion
`unmet`, and `--push` was refused. Read in `packages/orchestration/dod_runners.py`: a `pytest`
check runs with `sys.executable`, the interpreter Remedy itself runs in, so a project's own
dependencies are not there. Read in `packages/orchestration/dod_compiler.py`: the fallback
selector is `tests`. No configuration key names a project's test command, although
`packages/orchestration/test_runner.py` already holds the closed list of executables Remedy may
start. Remedy builds Remedy, so its own environment has always been the target's. On the universe
repositories — Python services with their own environments and a TypeScript app — the default
check is red by construction, and a red contract refuses the push an accepted result asks for.

## Acceptance
- On the Python target the default check runs the project's command in the project's environment
  and the criterion ends `met`.
- On the Node target the check runs `npm test` and the criterion ends `met`.
- On the target with no tests no criterion ends `unmet` for want of a test folder, and every
  surface that shows the criterion says that no check ran.
- Remedy's checks on Remedy's own repository are unchanged.

## Do not touch
The closed list of executables grows only by its own review. The approval gate. The push rule of
F270 for a criterion that really is unmet.

## Amendment — DECISION F299 D1 (2026-10-09)
T001's measurement is `.agent/f299_inventory.md`. The configured planner writes no check: every
criterion of a mission takes the compiler's fallback whatever planner runs, so T002 is not
shrunk. T002's one place is the `[tests]` table of the project's own `.remedy/config.toml`; when
it has none, the check reads the project as it stands when the check runs, a `test` script in its
`package.json` and then a `tests` folder, rather than what `remedy study` found, which records no
test command. The check is the kind `project_tests`, and the project's environment is the virtual
environment and `node_modules` of its own checkout.

## Goal & Done
ONE binding documentation page, `docs/system/vocabulary.md`, fixes the concept
model: what Project, Job, Task, Run, Plan, Order (the order file), Evidence and
Gate each mean — under the rule **one word, one meaning, everywhere** — together
with a do-not-confuse table that names the pairs this repository has actually
mixed up.

The page also SETTLES the two open naming questions, with the reasoning written
down beside each answer:

1. the final name of the F263 command — candidates `absorb`, `sync`, `refresh`;
2. whether today's `task-file` / `job-file` doubling collapses onto ONE word.

DONE when the page exists, a docs test pins its core terms against the CLI's own
command descriptions, and F260 and F261 cite it as binding.

Explicitly NO code rebuild in this feature. It decides words; F260 and F261
spend them.

## Why this exists
The command tree, the data model and the docs each grew their own dialect. `do
plan`, `do job-plan` and `job plan` are three different things whose names claim
they are one; `task-file` and `job-file` are two words that may or may not be
one thing; "run" means a provider call in one module and a whole execution in
another. Every later feature that renames or merges something needs a decided
vocabulary to rename *to*, or it invents a fourth dialect. Deciding the words
once, in one page, is cheaper than deciding them separately in F260, F261 and
F263 — and it is what makes those three reviewable at all.

## Design
- The page lives at `docs/system/vocabulary.md` — built state, not roadmap,
  because from the moment it is written it describes what the words mean.
- Shape per term: the word, one sentence of meaning, where it is spelled in code
  (module or field), where it is spelled in the CLI, and what it is NOT.
- A do-not-confuse table with one row per collision the repository actually has
  — at minimum Job/Run, Plan (the noun) vs `plan` (the command group), Order
  (the file a human writes) vs Job (what Remedy makes of it), Task vs Slice.
- The naming rulings sit in the page as dated DECISION paragraphs, so a later
  reader sees the reasoning and can reverse it by deleting the paragraph.
- The docs test reads the shipped CLI's own help strings — the catalog, not a
  transcript — and asserts that every term the page marks BINDING appears in the
  command descriptions with the page's meaning and with no competing synonym.

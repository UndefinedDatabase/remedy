## Goal & Done
When a paused or interrupted task is relaunched, Remedy resumes the provider session the task
last used, on the providers the product really runs, so that work already done is not paid for
twice (operator priority 1, token frugality). DONE when a relaunch of a task that a pause or a stop
interrupted, run on the `claude-cli` provider, resumes the parked session and the run's evidence
records `resume_used` true with the parked session's reference, and when every production provider
that cannot resume says so in the run's evidence instead of silently starting fresh.

## Why this exists
Finding R-1055 found that a relaunch after a park never resumed a provider session. F285's
round 2 (DECISION F285 D2) resolved it where the product's own code was missing: every round's
builder and reviewer blocks in a run's `result.json` now carry the session the call reported, and
the relaunch of an interrupted task offers that session to its first calls. That repair was proven
through the test provider only, because every production provider in
`packages/orchestration/pingpong_provider.py` answers `supports_resume` with false. So in real use
a relaunch still starts a new session and pays again for the context the parked session held.
This feature closes that gap. R-1055 itself stays resolved; this feature takes over the practical
half of its goal by name.

## Task slicing
- T001 — the `claude-cli` provider: it reports the session id of each call, accepts a session to
  resume, answers `supports_resume` with true, and falls back once to a fresh session when the
  resume is refused, with the fallback recorded.
- T002 — the relaunch path: a relaunch on `claude-cli` of a task a pause or a stop interrupted
  resumes the parked builder and reviewer sessions, proven by a test that parks and relaunches a
  job through `run_job` with the real provider's command line replaced by a recorded stand-in.
- T003 — the other production providers: each either resumes or records in the run's evidence
  that it cannot, and the operator guide names which providers resume.

## Slice order (written at the claim, 2026-10-07)
DECISION F287 D1 fixes it. T001 first, because the relaunch path can be proven end to end only on
a provider that resumes. T001 makes `claude-cli` resume; T002 proves a relaunch through `run_job`
on `claude-cli` resumes the parked sessions, after first measuring that the relaunch runs the
provider in the working directory the `claude` CLI keeps the session under; T003 makes every other
production provider say in the run's evidence that it did not resume, and names in the operator
guide which providers resume. Then the hardening stage of operator amendment amend0930b-slow-cap,
then the closure sequence.

## Acceptance
- A relaunch on `claude-cli` records round 1's builder `resume_used` true and
  `resume_session_ref` equal to the parked session.
- A refused resume falls back once to a fresh session and records the fallback.
- A provider that cannot resume records that it did not, and never fails the relaunch for it.

## Do not touch
The persisted session fields and the relaunch hand-over F285 built (DECISION F285 D2); the
fallback-once rule; the prompt, which stays at full context on a resumed call.

## Built State (F287, 2026-10-07)

What exists on disk before the closure sequence of F287, built on
`feature/f287-provider-session-continuity`, cut from `main` at `7c91c3b69`. Every DECISION named
lives in `.agent/decisions.md`; every round's verdict in `.agent/live_review.md` or, once rotated,
its archive.

**T001 — `claude-cli` resumes.** `build_claude_cli_args` in
`packages/orchestration/pingpong_provider.py` passes `--resume <ref>` only for a session reference
that fully matches a plain session-id shape, and raises `ValueError` for any other (DECISION F287
D2). `ClaudeCliProvider` threads the offered session through every call path of `build` and
`review`, records `resume_used` and `resume_session_ref` only on a call that succeeded, and
answers a failed resumed call with an error that begins `resume_refused:`, which the loop's
transport retry never sends again, so the existing fallback-once rule runs on the first failure
(D3). `supports_resume` answers true (D4). That also turns on F106's repair-round resume and
F109's resumed-prompt dedupe for this provider, which the operator confirmed on 2026-10-07 (D6).

**T002 — the relaunch.** No production change was needed (D5). A job on a git target runs in its
own worktree, and its relaunch runs in the same worktree, so the `claude` CLI finds the parked
session there. A job in copy mode gets a new staging directory for every run, so its relaunch's
resume is refused and falls back once to a fresh session at full context.
`tests/orchestration/test_relaunch_session_resume.py` proves both through `run_job`, for a pause
and for a stop, with the CLI child replaced by a stand-in that keeps sessions per directory.

**T003 — providers that cannot resume.** `ClaudeProvider` and `OllamaPingPongProvider` keep
`supports_resume` false and say why in `resume_unsupported_reason`. When a relaunch offers a
parked session to a role whose provider cannot resume, the run record `result.json` names the
role and the reason under `resume_declined`, and the run goes on with a fresh session (D7).
`docs/system/session-resume-v1.md` names which providers resume and the copy-mode limit.
Two older texts still said that no production provider resumes, the bullet on production in
`docs/system/semantic-dedupe-v1.md` and the README's entry for semantic dedupe; the closure
corrected both to say that `claude-cli` repair rounds may dedupe and the other two providers never
resume (R-1164).

**The hardening stage.** Because the sessions ran in SLOW MODE, a fresh auditor who saw only this
file and the repository looked for a test behind every statement under Goal & Done and Acceptance
and tried to break each one (operator amendment amend0930b-slow-cap,
`.agent/f287_acceptance_audit.md`). It audited 9 statements, and all 9 had a test that failed
when the auditor broke the code. It found one gap: no test reached the feature through the
command line (R-1163). `tests/cli/test_job_run_session_resume.py` now starts a `claude-cli` job
with `remedy job run`, parks it with `remedy job pause`, relaunches it with `remedy job run` and
reads `remedy run show --json`, once on `claude-cli`, which resumes the parked session, and once
on a provider that cannot, which is named under `resume_declined`. A repeat audit of that
statement found the gap closed, with mutations in the command-line layer itself
(`.agent/f287_acceptance_reaudit1.md`). No gap remains open.

**Reachability (closure precondition 7).** This feature added no module under `packages/`,

# T7_F129 — TDD gate (optional per job)
**Tier 7 · Depends on: F061 · Blocks/used by: test-first credibility**

## Goal & Done
Test-first becomes provable, not proclaimed: `--tdd` enforces
test-task-before-implementation pairs in the plan, the test task
must FAIL first (the red proof archived in evidence), the
implementation task must turn it green, and the DoD requires
completed pairs. DONE when a --tdd fixture plan validates as pairs
(unpaired implementation tasks rejected at plan validation), the
red proof is captured before implementation starts (ordering
enforced by dependencies, not hope), a test that passes immediately
fails the red gate with the honest message, and the pair status
renders in plan, graph and report.

## How it fits (inspect current shape before building)
Plan-shape enforcement lives where plan validation lives: a --tdd
flag on the job makes the flight-plan validator require the pairing
convention (task metadata pair_role: test|impl + pair_id;
implementation depends_on its test task — the DAG carries the
ordering for free); the planner prompt gains the TDD instruction
under the flag (segment conditional). The red proof: the test
task's verify step runs the new tests EXPECTING failure — a
distinct verify mode (expect_red) whose evidence archives the
failing output; green-at-red is a named failure ("test passes
before implementation — not a valid TDD test"), returning the task
for repair. The DoD compiler maps pairs: each pair contributes a
check "pair Txxx red→green proven" from the two archives.

## Design (suggested shape)
- Plan: pair metadata + validator rules (--tdd: every impl task
  paired; test tasks carry the target's acceptance traceability);
  normalization (granularity) preserves pairs (split children keep
  pairing — a rule added there via import, tested).
- expect_red verify mode on test tasks: run the pair's test
  selector; failure = success (archive red_proof), pass = the
  named failure; the impl task's verify runs the same selector
  expecting green (green_proof archived).
- DoD: the pair check kind reads both proofs; missing either →
  red with which half.
- Rendering: pair badges in plan.md and the graph (linked nodes
  per the reference's pairing treatment), the report's TDD section
  (pairs, red→green timestamps).
- Scope: --tdd is per job, default off; missions can set it per
  milestone (config passthrough, noted for the compiler).

## Task slicing
- **T001** pair metadata + validator + planner instruction +
  normalization-preservation + unit tests (unpaired rejected;
  pairs survive splits).
- **T002** expect_red/green verify modes + proofs + the
  green-at-red failure + fixtures (honest test fails first then
  greens; dishonest test caught).
- **T003** DoD pair checks + rendering + the end-to-end (--tdd
  fixture: plan pairs, red proof, impl, green proof, DoD green;
  the dishonest fixture blocks).

## Acceptance
- Validator matrix exact; pairs survive normalization. Red/green
  proofs archived with timestamps ordered (red strictly first —
  the dependency proves it structurally, the test asserts it).
  Green-at-red message golden. DoD holds on a missing half.

## Edge cases & assumption defaults (A9)
- Refactor tasks under --tdd (no new behavior): the plan may mark
  them pair_exempt with a reason the approver sees (escape hatch,
  visible). Flaky red (fails for the wrong reason): the red proof
  archives the failure TEXT; the impl verify failing on an
  unrelated error surfaces normally — TDD doesn't suspend other
  honesty.

## Orchestrator brief
Gate on the DoD compiler + granularity. The structural-ordering
rule (dependency, not timestamps) goes verbatim. T002's dishonest
fixture is the credibility test — name it in the order.

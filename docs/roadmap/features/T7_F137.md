## Goal & Done
"What would happen if..." runs for real, risk-free: --shadow
executes the FULL pipeline in a throwaway worktree; the result
exists only as diff + report under an unmistakable SHADOW banner;
one click adopts it into a real branch; shadow metrics are excluded
from production KPIs via a ledger flag. DONE when a shadow run
completes end to end with zero effect on the project's real
branches (git state proof), the banner marks every surface the
shadow touches (report, status, UI, certificate refused), adoption
transplants the changes onto a real branch through the normal
gated path with provenance, and every KPI/stat consumer proves the
exclusion flag.

## How it fits (inspect current shape before building)
The worktree layer already isolates per job — shadow deepens the
contract: a shadow worktree binds to a throwaway branch namespace
(the branch_for convention gains a shadow variant; verify the
naming helper) that is NEVER pushed/merged by any machinery, and
the job record carries shadow=true flowing to: ledger rows (the
demo feature's exclusion-flag pattern — verify whether one shared
"excluded from stats" mechanism can serve demo AND shadow: one
predicate, two reasons, the consolidation is this feature's tidy-up),
evidence, reports (banner), the cockpit (banner chrome per the
reference), and the certificate builder (refuses shadow jobs with
the honest line — proofs are for real work).
Adoption: the diff transplants via the applicator onto a fresh
real-job branch (a thin job wrapping "apply this reviewed diff" —
plan approval applies; the shadow's report links as provenance).

## Design (suggested shape)
- `--shadow` on do/mission paths: job flagged, worktree/branch in
  the shadow namespace; the full pipeline runs (plans, approvals,
  DoD — everything real EXCEPT permanence).
- Exclusion: the shared excluded-from-stats predicate (reasons
  demo|shadow) adopted by every aggregation (stats, trust,
  calibration, ladder, autonomy, KPI — the loop test enumerates
  consumers; new aggregations must use the predicate — a grep
  guard).
- Adoption: `remedy job adopt-shadow <id>` → the transplant job
  (diff as input, normal gates) + provenance links both ways;
  the shadow job stays archived as-is.
- Cleanup: shadow worktrees/branches are disposable —
  `remedy shadow clean` and a retention window (config); adopted
  shadows keep their evidence per normal retention.
- Banner discipline: one banner component/prefix constant reused
  (the demo banner's cousin — same visual family per the
  reference, distinct label).

## Task slicing
- **T001** the shadow namespace + flag propagation + the shared
  exclusion predicate consolidation (demo migrates onto it, its
  tests green) + unit tests.
- **T002** pipeline pass-through + banner surfaces + certificate
  refusal + the zero-effect git proof (before/after real-branch
  state identical).
- **T003** adoption (the transplant job, gates, provenance) +
  cleanup/retention + the end-to-end (shadow run → adopt →
  real branch carries the change through normal approval;
  stats never counted the shadow — the consumer loop test).

## Acceptance
- Zero-effect proof exact; no machinery path pushes/merges the
  shadow namespace (grep + behavioral fixtures). Banner on every
  surface (audit loop); certificate refusal golden. The exclusion
  predicate is single-home (grep) and every consumer proves it.
  Adoption flows the normal gates with provenance both ways.

## Edge cases & assumption defaults (A9)
- Shadow of a design job: fidelity loops run; baselines are READ
  but never updated from shadows (the guard's gated path already
  ensures it — assert). Shadows outliving retention with pending
  adoption interest: adoption re-runs from the archived diff
  (evidence retention rules the truth).

## Orchestrator brief
Gate on worktrees + the demo exclusion pattern. T001's predicate
consolidation is the tidy-up deliverable. The zero-effect proof
and the certificate refusal go verbatim.

## Do not touch
Branch semantics of real jobs, approval gates (adoption uses
them), retention policy defaults. Suggested tests:
tests/orchestration/test_shadow_mode.py.

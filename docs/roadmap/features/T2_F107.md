# T2_F107 — Context compiler v2
**Tier 2 · Depends on: F105 · Blocks/used by: input costs, F112, F174 later**

## Goal & Done
Tasks stop receiving whole files regardless of relevance: the context
compiler selects fenced-path files, their direct import neighbors, and
only SIGNATURES of distant dependencies — and writes an omissions record
naming everything it left out and why (P6 + debuggability). DONE when a
fixture repo's task context shrinks measurably versus whole-files with
the fixture task still solvable by the fake provider, and the omissions
record explains every exclusion.

## How it fits (inspect current shape before building)
Context assembly for worker tasks currently pulls files at whole-file
granularity — find that assembly point; this feature replaces its
SELECTION, not its formatting (the prompt-segment registry owns
composition; the compiled context enters as a ranked segment). Fences
define the task's declared write scope — the selection seed. Two
languages matter now (Python and TypeScript-ish frontends); parsing
uses the standard library for Python and a deliberately simple
line-level import scanner for TS/JS (regex on import/export lines) —
good enough for neighbor discovery, honestly documented as heuristic;
a real TS parser is a later upgrade, not a hidden dependency now.

## Design (suggested shape)
Module `context_compiler.py`:
- Selection tiers: (1) files matched by the task's files_hint and fence
  allow scope — full content; (2) direct import neighbors of tier 1 —
  full content up to a per-file size cap, else signatures; (3)
  transitive dependencies — signatures only (Python: module/class/def
  lines with docstring first lines; TS: exported symbol lines); (4)
  everything else — omitted.
- Budgets: a total context token budget (config) enforced by demoting
  tier 2 → signatures → omitted, never by silent truncation mid-file;
  every demotion/omission appends to omitted_context.json {path, tier,
  reason: budget|distance|binary|size}.
- The compiled context becomes a registry segment with its manifest
  hash in evidence; the omissions file sits next to it per task.
- CLI: `remedy job context <id> --task <tid>` renders what a task
  received and what was omitted — the debugging view for "why didn't
  the model see X".

## Task slicing
- **T001** import-neighbor graphs: Python via ast, TS via the
  documented line scanner; unit tests on fixture trees (cycles,
  relative imports, index files).
- **T002** signature extractors for both languages + size caps + tests
  (goldens per language).
- **T003** tiered selector + budget demotion + omissions writer +
  integration on a fixture repo (counts per tier asserted; budget
  squeeze demotes tier 2 first).
- **T004** segment integration + the CLI view + an end-to-end fixture
  task solved by the fake provider with compiled context, alongside a
  size comparison recorded in evidence.

## Acceptance
- Fixture task context excludes unrelated modules, includes the fenced
  file and its direct neighbors, signatures beyond; omissions record
  lists every excluded path with a reason (completeness asserted by
  diffing against the repo listing). Budget squeeze behaves as
  specified. The debugging CLI matches the evidence.

## Edge cases & assumption defaults (A9)
- Dynamic imports and string-based requires: invisible to v1 —
  documented limitation; the omissions reason distance covers them, and
  the files_hint escape hatch (plan-declared files always tier 1) is
  the workaround. Binary/huge files: omitted with reasons, never
  inlined. Unparseable files: included-whole if tier 1 (better safe),
  signature-skipped with reason otherwise.

## Orchestrator brief
T001/T002 parallel (pure, per-language); T003 after both; T004 gates on
the segment registry. Put the tier table verbatim in every order — the
tiers are the contract. Reject any diff adding a TS parser dependency.

## Do not touch
Prompt composition (registry owns it), retrieval/embedding approaches
(later), repo-map features. Suggested tests:
tests/orchestration/test_context_compiler.py.

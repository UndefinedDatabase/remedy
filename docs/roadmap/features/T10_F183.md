# T10_F183 — Per-person notification routing
**Tier 10 · Depends on: F059, F175, F178 · Blocks/used by: M11 daily usability**

## Goal & Done
Notifications learn addresses: per-user notify config (a users.toml
section or users.d/ files) declares channels (webhook/ntfy/mail)
and event filters (assigned_to_me, job_finished_mine,
all_decisions) plus a personal mute flag — plainly on/off, whoever
is muted stays muted until they change it, no time windows; the
router maps each event to its recipient set (assignee first, then
filter subscribers) and dedupes per (user, event). DONE when
routing matches the documented rule table on fixture events
(assignment events reach the assignee's channels; finished jobs
reach their owner per job attribution; all_decisions subscribers
get the rest), per-user channel delivery reuses the notify
machinery (one delivery core — the F059/F167 consolidation
inherited), mute suppresses everything for that user (and ONLY
that user) with the state visible to them, dedupe holds when a
user matches multiple filters, and single-user mode routes exactly
as today (regression).

## How it fits (inspect current shape before building)
F059 built channels and delivery (webhook/ntfy/mail senders,
retry) keyed by project-level config — this feature adds the
PERSON layer: recipient resolution before delivery (event →
users via the rule table → each user's configured channels →
the existing senders). "Mine" attribution: jobs carry their
initiating user (F177's context — verify the job record gained
initiated_by; additive if not), assignments carry assignees
(F178). Config placement: per-user sections in the org store's
domain (users.toml [users.<id>.notify] or users.d/<id>.toml —
the store's validation grows; secrets in channel configs use the
secret:// provider, F171's interlock). The mute flag is a user-
level boolean read at routing time (immediate effect, audited
change — someone silencing their pager is a fact worth a line).

## Design (suggested shape)
- Config: per user {channels [{kind, target(secret:// capable),
  }], filters [assigned_to_me | job_finished_mine |
  all_decisions], mute}; validation via the store.
- The router: event → candidate users (the rule table: decision
  assignment events → assignee (+delegates per F178's routing);
  job lifecycle → initiated_by for *_mine; decision lifecycle →
  all_decisions subscribers) → mute filter → channel fan-out via
  the delivery core → dedupe per (user, event id) (one ping per
  event per human, however many filters matched).
- Ordering rule: assignee-first is a PRIORITY statement for
  digest/batching contexts (the assignee's copy never batches
  away — documented), not a delivery-order promise (async
  reality, honest).
- Visibility: `remedy user notify show [--user]` renders the
  effective config + mute state; the UI settings surface per
  the reference's forms.

## Task slicing
- **T001** config schema + validation + secret:// interlock +
  the store growth + unit tests.
- **T002** the router (rule table, attribution reads, mute,
  dedupe) + table tests per event kind × filter × mute.
- **T003** delivery integration (per-user channels through the
  core) + the show CLI/UI surface + single-user regression +
  the end-to-end (two users, distinct filters: an assignment
  pings the assignee only; a finished job pings its owner;
  a muted user gets silence — and sees their mute state).

## Acceptance
- The routing table exact per fixture matrix. Dedupe proven on
  multi-filter matches. Mute total-and-personal (the other
  user's delivery unaffected) with the audited flip. Channel
  secrets via the provider (never plaintext — the walk).
  Single-user byte-identical. Delivery reuses the one core
  (grep).

## Edge cases & assumption defaults (A9)
- Users with no channels but filters: routing computes them,
  delivery no-ops with a doctor hint (config incomplete —
  visible, not silent). Broadcast storms (all_decisions on a
  busy day): the existing digest/batching mechanics apply per
  user (inherited, noted). Deactivated users: routing skips
  them (the identity store's active flag).

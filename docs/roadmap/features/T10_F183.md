# T10_F183 — Per-person notification routing
**Tier 10 · Depends on: F059, F175, F178 · Blocks/used by: M11 daily usability**

## Goal & Done
See ROADMAP.md F183; the Done criterion there is binding.

## Context (existing code & prior features)
F059 channels are project-global; assignments need targeted delivery.

## Design
Per-user notify config (users.toml section or users.d/): channels (webhook/ntfy/mail), event filters (assigned_to_me, job_finished_mine, all_decisions), a personal mute flag (plainly on/off - whoever is muted stays muted until they change it; no time windows). The router maps event -> recipient set (assignee first, then filter subscribers), dedupes per (user, event).

## Task slicing
T001 recipient resolution + filters + dedupe + routing matrix tests. T002 sender integration (F059 channels per user) + a minimal settings UI.

## Acceptance & tests
Matrix tests: the assignee receives exactly once; mute suppresses only that user's delivery; one user's dead channel never blocks others.

## Risks / anti-goals
No delivery-guarantee illusion (best effort; failures logged); the event filter catalog stays small and frozen per version (F245).

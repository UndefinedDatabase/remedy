# T10_F176 — SSO/OIDC for the cockpit
**Tier 10 · Depends on: F175, F009 CSRF · Blocks/used by: F177, F201 remote**

## Goal & Done
Enterprise login without a framework: OIDC authorization code +
PKCE implemented lean — discovery, token exchange via stdlib HTTP,
JWT verification against the provider's JWKS — establishing an
HttpOnly SameSite=Strict session cookie mapped to a server-side
session store {sid → user_id, exp}; command paths read the user
from the session; a claims mapping ([oidc] role_claim) translates
provider claims to the F175 roles; and the local token fallback
stays fully supported with the mode in config. DONE when the flow
round-trips against a scripted OIDC fixture provider (discovery →
redirect → code+PKCE exchange → verified id token → session), JWT
verification enforces the full check set (signature via JWKS,
issuer, audience, expiry, nonce), the session store expires and
revokes correctly, claims map to roles per config with unmapped
claims defaulting to viewer (least privilege, stated), CSRF
protections hold across the session world, and the JWT dependency
ships as the org extra with the local fallback untouched when
absent.

## How it fits (a dependency note + composition)
JWT/JWKS verification needs real crypto — pyjwt (with its crypto
backend) joins a `remedy[org]` extra (the extras stance: base
installs never carry it; OIDC mode unavailable without it, the
honest message naming the extra). The flow is deliberately
frameworkless: discovery (one GET, cached), the authorize
redirect (state + nonce + PKCE verifier server-held), the token
exchange (stdlib urllib POST), verification (pyjwt against
fetched JWKS with rotation-tolerant key caching). Sessions: the
server-side map is process state with a persisted spill (the
data root — restarts don't log everyone out; documented
lifetime), sid random per stdlib secrets; the cookie flags per
the draft (HttpOnly, SameSite=Strict, Secure when TLS —
the deployment doc's rule). The write channel's CSRF (double-
submit) coexists: session auth PLUS the CSRF header on mutations
(defense stacking, stated). Role mapping: [oidc] role_claim +
a value map {claim value → role}; unmapped → viewer.

## Design (suggested shape)
- `packages/org/oidc.py`: discovery/config, the redirect
  builder, the callback handler (state check, code exchange,
  token verification, user provisioning: sub → user id, name
  from claims, roles from the mapping — provisioned users live
  beside token users in the store with source=oidc), session
  issue.
- Sessions: create/read/expire/revoke (`remedy user sessions
  revoke <user>`), sliding vs absolute expiry per config
  (documented defaults), the spill file's custody (hashed sids).
- Mode config: [auth] mode = local | oidc | both (default
  local); the UI's login surface renders per mode (the SSO
  button vs token entry — per the design reference's auth
  patterns).
- The fixture provider: a scripted local OIDC server for tests
  (keys, discovery, token endpoint) — the test substrate, also
  useful for demos.

## Task slicing
- **T001** the extra + discovery + redirect + PKCE/state/nonce
  handling + unit tests.
- **T002** exchange + verification (the full check set, JWKS
  rotation fixture) + provisioning + claims mapping (unmapped →
  viewer) + tests.
- **T003** sessions (store, cookie flags, expiry, revocation,
  spill) + CSRF coexistence tests + the mode config + UI login
  surfaces + the end-to-end against the fixture provider.

## Acceptance
- The flow round-trips; each verification check's negative
  fixture fails it (bad signature, wrong aud, expired, replayed
  nonce, tampered state). Unmapped claims → viewer (the
  least-privilege fixture). Revocation immediate; expiry per
  config; restart preserves sessions via the spill. Mutations
  require session AND the CSRF header. Absent extra → the
  honest mode-unavailable message; local mode untouched.

## Edge cases & assumption defaults (A9)
- Providers with rotated keys mid-session: JWKS cache refresh
  on kid miss (the rotation fixture). Clock skew: a bounded
  leeway (config, small default, documented). Logout: local
  session destruction + the documented note that provider
  single-logout is out of v1 scope (honesty over ceremony).

## Orchestrator brief
Gate on F175 + the channel's CSRF. T003's negative-fixture set
is the security acceptance — enumerate every check in the
order. The least-privilege default and the extras stance go
verbatim.

## Do not touch
The channel's CSRF mechanics (coexist), identity store
semantics, remote-access features (later). Suggested tests:
tests/org/test_oidc.py.

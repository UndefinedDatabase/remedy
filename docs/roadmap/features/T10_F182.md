# T10_F182 — Presence display
**Tier 10 · Depends on: F008, F176 sessions · Blocks/used by: team awareness**

## Goal & Done
You can see who's looking: a UI-session heartbeat (20 s,
registered server-side on the SSE connection) fills a presence map
{job_id → [{user, last_seen}]}; avatars/initials render in the job
header with a 'watching' tooltip; entries vanish after 60 s
without a heartbeat; and deliberately NO cursor/selection sync.
DONE when heartbeats register per authenticated session against
the currently-viewed job (the SSE connection's declared scope),
the map expires entries at the timeout exactly (a clock-controlled
test), avatars render per the reference's presence treatment with
overflow handling (+N beyond a few), presence is ephemeral by
design (no persistence, no history — a privacy stance stated and
grep-proven), and the anti-goal is documented (no cursor sync —
the scope fence in the docs and the feature's tests).

## How it fits (inspect current shape before building)
The SSE layer (F008) knows connections; sessions (F176/F175) know
users — presence is the join, kept deliberately in-memory: the
server holds {job → {user → last_seen}} fed by a lightweight
heartbeat (the SSE connection reports its viewed job on connect
and on navigation — verify how the UI scopes SSE subscriptions
today: per-job streams make the mapping free; a global stream
needs the heartbeat to CARRY the job id — the finding decides,
the design supports both). Expiry is lazy (reads prune stale
entries — no timer daemon, the unattended-first discipline).
Rendering joins the job header chrome (the reference's avatar
cluster treatment; the actor initials from F177's rendering
reused — one identity rendering).

## Design (suggested shape)
- Heartbeat: the UI posts/piggybacks {job_id} every 20 s while a
  job view is focused (visibility-aware: hidden tabs stop —
  honesty of attention, documented); the server updates the map
  keyed by (job, user) with last_seen.
- The map: in-memory per server process; reads prune >60 s;
  exposed on the job payload/SSE as presence [{user_id, name}]
  (no timestamps to the client — just who, the minimal
  disclosure).
- UI: the avatar cluster (initials, up to k visible + "+N",
  tooltip "watching now"), updates via the existing SSE
  channel's events (presence.changed per job, coalesced).
- Privacy stance: nothing persisted, nothing logged beyond
  debug level (grep guard on the audit/ledger writers — presence
  is not evidence), viewers appear like anyone (roles don't
  change visibility — symmetric awareness, stated).

## Task slicing
- **T001** the heartbeat protocol (scoping finding first) +
  the map + lazy expiry + unit tests (clock-controlled expiry;
  multi-user multi-job isolation).
- **T002** SSE presence events (coalescing, per-job scoping) +
  the payload exposure + the no-persistence grep guard + tests.
- **T003** the UI cluster (treatment, overflow, tooltip,
  visibility-aware heartbeat) + the end-to-end (two sessions
  viewing → both see each other → one hides the tab → gone
  after the timeout).

## Acceptance
- Expiry exact at the boundary (clock test). Isolation across
  jobs/users proven. No presence data in any persisted store
  (grep + walk after fixtures). The cluster renders per
  reference with overflow; updates coalesce (no event floods —
  a rate assertion). Hidden tabs drop out.

## Edge cases & assumption defaults (A9)
- Multi-server deployments: v1 presence is per-process (the
  single-server reality of the cockpit — documented; a shared
  map is later territory if remote features demand it). The
  same user in two tabs: one presence entry (keyed by user, not
  session — dedup stated). Clock skew: server-side timestamps
  only (clients never report times).

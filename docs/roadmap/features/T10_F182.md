# T10_F182 — Presence display
**Tier 10 · Depends on: F008, F176 sessions · Blocks/used by: team awareness**

## Goal & Done
See ROADMAP.md F182; the Done criterion there is binding.

## Context (existing code & prior features)
SSE infrastructure with sessions exists.

## Design
A UI-session heartbeat (20 s, registered server-side on the SSE connection) fills a presence map {job_id -> [user, last_seen]}; avatars/initials in the job header with a 'watching' tooltip; entries vanish after 60 s without a heartbeat. Deliberately NO cursor/selection sync.

## Task slicing
T001 the presence registry + the presence.changed SSE event + tests (two simulated sessions, timeout). T002 the header UI.

## Acceptance & tests
Two sessions visible <2 s; the timeout cleans reliably; presence data persists NOWHERE (ephemeral by design, tested).

## Risks / anti-goals
No realtime-collaboration project; presence informs, it never locks (conflicts are handled by F009 idempotency + queue semantics).

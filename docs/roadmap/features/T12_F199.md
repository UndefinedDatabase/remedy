# T12_F199 — Self-health & crash reports
**Tier 12 · Depends on: F010 · Later integrates: F202 adds data_v/migration checks to doctor · Blocks/used by: operability; F220 support**

## Goal & Done
See ROADMAP.md F199; the Done criterion there is binding.

## Context (existing code & prior features)
F010 classifies JOB failures; Remedy's own process/data health is unobserved.

## Design
`remedy doctor`: checks - config coherence (F245 schemas), ledger.sqlite integrity (PRAGMA integrity_check + manifest samples), evidence manifests (hash samples), orphaned worktrees/locks (F006), adapter reachability + isolation (F152), disk thresholds. Output: a PASS/WARN/FAIL table + fix hints (the F010 advice pattern). A crash handler (sys.excepthook + the F200 supervisor) writes a LOCAL report ~/.remedy/crash/<ts>.md (traceback, version, redacted config digest) - NEVER auto-sent (the F219 law); it points to `remedy feedback`.

## Task slicing
T001 doctor checks + advice + tests (injected corruption per check kind). T002 the crash handler + redaction (the F171 corpus over crash reports) + daemon coupling.

## Acceptance & tests
Every injected corruption is found with a usable hint; the crash fixture yields a secret-free report; doctor exit codes are CI-usable.

## Risks / anti-goals
doctor never auto-repairs (it names commands); crash reports are local-only by design.

## Amendment — DECISION F199 D1 (2026-10-13)
This section governs where the text above disagrees with it.

- **The checks** live in `packages/orchestration/self_health.py`, in this order: `config`,
  `ledgers`, `snapshots`, `worktrees`, `providers`, `staging_copies`, `disk`, and from T002
  `crash_reports`. Each answers PASS, WARN or FAIL with a detail and a hint that names a command or
  an edit; no check repairs anything. The evidence manifests sampled are the newest workspace
  snapshot manifests, the evidence that records a hash per file; a token ledger carries no
  manifest, so its check is SQLite's own integrity check.
- **The command** is `remedy doctor health [--json]`, beside `doctor core` and `doctor toolchain`;
  it exits 0 without a FAIL and 1 with one.
- **A crash report** is a Markdown file under `<data root>/crash/`, not `~/.remedy/crash/`: Remedy
  keeps nothing outside its data root. It is never sent. It names no `remedy feedback` command,
  which F220 has not built.
- **Not here:** the worker isolation half of the adapter check (F152), the F171 corpus (the report
  uses today's evidence redaction), the schema registry (F245; the configuration's own key
  registry is checked).

### Slices
- **T001** — the module and its checks with a test that injects each corruption; the structural
  step moving the catalog's `doctor` group to `apps/cli/command_catalog_doctor.py`; the command
  `remedy doctor health` with its exit codes and its page.
- **T002** — the crash report, written at the CLI's catch-all and when a serve supervisor's thread
  ends on an exception; a fixture crash whose report carries no planted secret; the check
  `crash_reports`.
- **T003** — the supervisor reports its own health: `GET /api/v1/health` on its public API.

# T17_F250 — Long-term consolidation into a project handbook
**Tier 17 · Depends on: F045, F117-F128, F138, F073/F145 · Blocks/used by: the knowledge dividend; onboarding humans AND workers**

## Goal & Done
See ROADMAP.md F250; the Done criterion there is binding.

## Context (existing code & prior features)
Cards (Tier 4), ADRs (F138), playbooks (F145) and postmortems (F010/F073) accumulate knowledge in fragments; the F122 dossier is the 800-token short form - the BOOK is missing.

## Design
A routine (F045, manually triggerable: `remedy handbook build`): distills all active knowledge sources into a docs/HANDBOOK.md PROPOSAL (a PR draft, never a direct commit): chapters architecture (from architecture cards + ADRs), conventions (the resolved view, F209), known traps (lessons + postmortem patterns), operations knowledge (runtime/deploy cards), a decision register (an ADR index with one-sentence essences). EVERY paragraph carries a source anchor (card/ADR/playbook id) - the F038 validation: anchors must resolve or the paragraph is dropped. Idempotence: a second run produces deltas only (stable chapter slugs; content-hashed sections). The handbook feeds back: new workers receive chapter extracts as context segments (an F118 budget class handbook); humans read it as onboarding.

## Task slicing
T001 source aggregation + chapter renderers + anchor validation + tests. T002 the idempotence mechanics + the PR-draft path + the context-segment coupling + a fixture (30 cards / 5 ADRs -> a coherent handbook; a second run is delta-only).

## Acceptance & tests
Every fixture-handbook paragraph anchor resolves (a link suite); the second-run diff contains only real changes (hash test); segment usage is provable in a follow-up job's trace; the PR path is enforced (no writer touches docs/ directly - a fence).

## Risks / anti-goals
The handbook replaces no source (cards/ADRs stay normative; the handbook links - its header says so); no unsourced LLM prose (unproven paragraphs are dropped; the F063 proof-duty spirit).

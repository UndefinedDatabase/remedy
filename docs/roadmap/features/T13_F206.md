## Amendment — DECISION F206 D1 (2026-10-12)
This section governs where the text above disagrees with it.

- **The file** is `<data root>/org/catalog.toml`, a durable class `org` of the data root, written
  by hand. Each `[[repo]]` table holds `pid`, a registered project's slug or id, and optionally
  `name`, `root`, `owner`, `depends_on`, `publishes` and `consumes`.
- **The module** is `packages/orchestration/repo_catalog.py`: it refuses invalid TOML, an unknown
  key, a missing or duplicate `pid`, a dependency on a `pid` it does not hold, and a cycle, shown
  as its path `a -> b -> a`; it orders an order's repositories so that one comes after every
  repository it depends on, directly or through others, and cites each such edge.
- **The planner** orders an order's projects by the catalog when it exists; the init step's
  detail and each job's order text name the edges. An invalid catalog plans nothing.
- **The commands** are `remedy org catalog-check` and `remedy org catalog-show`.

## Amendment — DECISION F206 D4 (2026-10-12)
The commands are `remedy project catalog-check` and `remedy project catalog-show`, in the
`project` group, which first moves to `apps/cli/command_catalog_project.py` as the catalog file's
written boundary orders; no group `org` is made. Each takes `--catalog <path>` and `--json`.
`catalog-check` prints every plausibility warning with its proof and exits 1 only on an invalid
catalog; `catalog-show` prints every entry and the order of all its repositories with each edge.

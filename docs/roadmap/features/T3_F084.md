## Goal & Done
Anyone can see Remedy work in under a minute, offline, honestly
labeled: `remedy demo` replays a RECORDED deterministic fake job —
real evidence, real report, real timeline, zero providers, zero
network — with an unmistakable DEMO banner on every surface it
touches. DONE when the demo runs on a fresh install with no config,
finishes in under sixty seconds, produces a browsable job whose every
artifact carries the demo marking, and cleans up after itself on
request.

## How it fits (inspect current shape before building)
The run manifest and evidence formats define what a "recorded job"
is: a bundled fixture (packaged data, like the routine library) of
pre-produced events, call evidence, report inputs and a final state —
the demo REPLAYS it through the normal storage/evidence writers at a
scripted pace, so every viewer (status, report, later the cockpit)
renders it exactly like real work. The fake-provider test machinery
already produces such corpora — the recording is curated from one
good run, then frozen and versioned.

## Design (suggested shape)
- Recording: a small but story-complete job (a few tasks, one repair
  round that heals, one decision auto-answered, green DoD) captured
  as an event/evidence bundle with a manifest; regeneration is a
  maintained script so the recording can be refreshed when formats
  evolve (format drift breaks demos silently otherwise — a CI check
  replays the bundle and fails on schema mismatch).
- `remedy demo [--speed N] [--keep]`: creates a demo project + job
  under the normal data root, flagged demo=true end to end (job
  record, evidence, report header, status line all render the DEMO
  banner/prefix); replays events at a presentation pace; prints the
  follow-along commands as it goes ("now try: remedy status").
  Without --keep, `remedy demo --clean` removal is offered at the
  end; demo data never mixes into stats (aggregations exclude
  demo-flagged jobs — one shared predicate, tested per consumer).
- No providers, no network, no git repo required — the demo carries
  its own tiny fixture workspace; preflight failures (nothing to
  create the data root on) produce clear messages.
- The Tier 5 cockpit later replays the same recording visually —
  the bundle is the contract; keep it renderer-agnostic.

## Task slicing

## Acceptance
- Fresh environment: demo completes < 60 s, status/report show the
  banner, follow-along commands work against the demo job. No
  network sockets opened (asserted). Stats/bench/autonomy exclude
  the demo job (loop test). --clean removes exactly the demo
  project's data.

## Edge cases & assumption defaults (A9)
- Running demo twice: second demo project gets a numbered slug; both
  clean targets listed. Demo inside a real project's repo: fine —
  the demo project is its own scope; nothing touches the host repo.

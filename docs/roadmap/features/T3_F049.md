# T3_F049 — Parallelism
**Tier 3 · Depends on: F006, F048, F057 · Blocks/used by: wall-time KPI**

## Goal & Done
Disjoint work stops waiting in line: up to N ready tasks whose declared
scopes are path-disjoint run concurrently — provider calls overlap
(the real wall-time win), while worktree APPLIES stay serialized
through one lock (the real corruption risk) — under one thread-safe
budget/stop evaluation and the rate governor's pacing. DONE when a
three-branch fixture completes in materially less wall time than
serial with byte-identical final state, budgets/stops behave exactly
as in serial runs, and any scope overlap forces serial execution
honestly.

## How it fits (inspect current shape before building)
The DAG scheduler provides the ready set; fences/files_hint provide
declared scopes; the rate governor's acquire is the natural concurrency
throttle; safe points already centralize stop/budget checks — they need
a thread-safety pass (audit for shared mutable state; the budget
evaluation cache per round is the suspect). The applicator and job
persistence were written single-writer — serialize them with one lock
rather than making them concurrent (A6: smallest true change). Tasks
within a job share the job's worktree: disjointness is therefore a hard
precondition, checked, not assumed.

## Design (suggested shape)
- `parallel_scheduler.py`: take up to max_parallel (config, default 1 —
  parallelism is opt-in until proven) ready tasks with pairwise-disjoint
  scopes (declared fences ∩ files_hint closure; unknown scope = overlaps
  everything = serial); run each task's provider phase on a worker
  thread; queue apply/verify/persist operations through the single
  writer lock in completion order.
- One safe-point evaluation guards dispatch of EVERY task (under a
  lock); a stop/budget signal prevents new dispatches and lets in-flight
  calls finish — identical semantics to serial, tested identically.
- Evidence: per task, its thread lane and timing; the cycle summary
  records parallel width achieved.
- Failure isolation: one task's failure rolls back that task only
  (existing semantics), never poisons siblings; the ready set
  recomputes after each completion as before.

## Task slicing
- **T001** scope-disjointness computation + unknown-scope rule + unit
  tests (overlap matrices).
- **T002** thread-safety audit + fixes on safe points/budget cache/
  ledger writer (each with a targeted concurrency test).
- **T003** the scheduler + single-writer apply lock + the three-branch
  fixture (wall-time assertion with a sleepy fake provider; final state
  byte-identical to the serial run) + stop-mid-parallel test.

## Acceptance
- Fixture wall time under serial by a clear margin; final repo state
  and job JSON equal to serial (hash compare). Overlapping-scope
  fixture runs serial with the reason in evidence. Stop request: no
  new dispatch, in-flight finish, state consistent. max_parallel=1 is
  byte-identical to pre-feature behavior (regression).

## Edge cases & assumption defaults (A9)
- Provider rate ceilings under parallelism: governor acquire per
  dispatch handles it (waits are per-lane, evidenced). Python GIL:
  irrelevant — the waits are subprocess/IO-bound; say so in the
  docstring to preempt "optimization" PRs. Deadlocks: one lock
  hierarchy documented (safe-point lock < writer lock, never nested
  the other way) with a lint-style test if feasible.

## Orchestrator brief
T002 before T003, always — order the audit as its own deliverable
(list of shared state found + fix per item). The fixture's
byte-identical-state assertion is the acceptance heart; reject timing
tests that sleep-and-hope instead of using the sleepy fake provider.

## Do not touch
Cross-job process parallelism (queue consumers already cover it),
applicator internals, DAG rules. Suggested tests:
tests/orchestration/test_parallel_scheduler.py.

# T1_F047 — Checkpoint & resume (kill-proof)
**Tier 1 · Depends on: F046, F006 · Blocks/used by: F056, F079, F136, F200**

## Goal & Done
See ROADMAP.md F047; the Done criterion there is binding.

## Context (existing code & prior features)
A killed long run currently loses its place; self-build needs crash-safety before anything else.

## Design
`checkpoints.py`: after every cycle an atomic (tmp+rename) checkpoint_<n>.json {job_state, worktree_head_sha, queue_cursor, budget_spent, test_digest, next_intent}. `remedy jobs resume <id>` loads the newest hash-valid checkpoint, verifies the worktree head, continues.

## Task slicing
T001 writer/loader + hash + tests. T002 resume CLI + a kill -9 integration test (subprocess marker).

## Acceptance & tests
kill -9 mid-cycle then resume equals an uninterrupted run (F012 fake-provider comparison); a redaction test proves checkpoints hold no secrets.

## Risks / anti-goals
Checkpoints are state, not evidence - they never substitute for artifacts.

# T3_F060 — Long-run certificate
**Tier 3 · Depends on: F053, F012 · Blocks/used by: the sales proof, F140, F165**

## Goal & Done
A finished run can prove itself to someone who wasn't there: `remedy job
certificate <id>` packs report, token truth, verdicts, ownership
extract, the run manifest and a hash manifest into one portable
certificate bundle, and `remedy verify <bundle>` checks integrity and
summarizes the claims — reusing the existing review-bundle machinery
(A6). DONE when a fixture certificate verifies green, any tampered
member fails verification naming the file, and the bundle stays small
with diffs referenced, not embedded wholesale.

## How it fits (inspect current shape before building)
A review-bundle exporter already exists (the bundles used for external
review) — the certificate is a CURATED PROFILE of it plus an integrity
manifest and a verifier; extend the exporter with a profile parameter
rather than writing a second packer. Inputs are all existing artifacts:
the final report, ledger-backed cost summary with bases, DoD/verdict
matrices, the run manifest (inputs verified / outputs recorded — the
honesty sentence belongs on the certificate's face), and the evidence
hash tree.

## Design (suggested shape)
- Certificate profile: a manifest.json {bundle_v, job, project, created,
  members: [{path, sha256, size}], claims: {terminal state, DoD matrix
  summary, cost with basis, decisions count, regression status}} + the
  member files; total size budget (config, single-digit MB) enforced by
  referencing large diffs/logs via their hashes + an obtain-hint instead
  of embedding.
- `remedy job certificate <id> [--out path]` builds it at any terminal
  state (a failed run's certificate is equally valid proof — honesty
  includes failures).
- `remedy verify <bundle>`: hash-checks every member, cross-checks the
  claims against the contained artifacts (the claimed terminal state
  must match the report, the cost must match the token summary), prints
  a verdict block; exit nonzero on any mismatch with the member named.
  Verify runs standalone on any machine with Remedy installed — no
  project context needed.
- What it is NOT (say so in output): a cryptographic attestation of
  authorship — integrity yes, provenance signature later (a signing
  hook field is reserved in the manifest, empty in v1).

## Task slicing
- **T001** profile + manifest + size budget + exporter extension +
  goldens.
- **T002** the verifier (hash + claim cross-checks) + tamper fixtures
  (each member class tampered once → named failure).
- **T003** CLI both sides + standalone-verify test (fresh temp dir, no
  data root) + docs including the not-a-signature note.

## Acceptance
- Fixture bundle verifies green; each tamper fixture fails naming the
  member; a failed-run certificate builds and verifies. Size budget
  enforced on a big-diff fixture via referencing. Claims cross-checks
  catch a doctored report (fixture).

## Edge cases & assumption defaults (A9)
- Certificates of stopped/blocked runs state their terminal plainly —
  no green-washing vocabulary anywhere in the renderer. Re-issuing
  after a resume supersedes: the manifest carries an issue counter;
  verify prints it.

## Orchestrator brief
Confirm the existing bundle exporter's shape first (T001 deliverable:
what was reused vs added). The tamper matrix in T002 is the acceptance
heart — one fixture per member class, no shortcuts.

## Do not touch
Cryptographic signing (reserved field only), publishing/hosting of
certificates, review-bundle semantics for its existing consumers.
Suggested tests: tests/orchestration/test_certificate.py.

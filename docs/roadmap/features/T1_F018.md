# T1_F018 — Budget & Stop-Bedingungen im Flight Plan
**Tier 1 · Abh.: F014, F003 · Blockiert: F045/F046, F104**

## Ziel & Done
Jeder Job deklariert BUDGET (€/Tokens), STOP (alles grün | N Zyklen | Deadline),
REPORT-Ziel. Done: erstes erreichtes Limit stoppt sauber am Checkpoint.

## Design
- flight_plan.py: `budgets{usd?,tokens?}`, `stop{all_green:bool,max_cycles?,deadline?}`,
  `report{level: summary|full}` — Defaults aus config; CLI-Flags überschreiben.
- Enforcement-Hook: `budget_guard.check(job)` an denselben Checkpunkten wie F011;
  Ausgang: Status `budget_exhausted` | `deadline_reached` + Checkpoint. (Harte
  Durchsetzung €: erst ab F003-Actuals; bis dahin tokens-Schätzung MIT Label.)
- UI: Budgetbalken-Daten via SSE `budget.tick` (spent, limit, basis:actual|estimated).

## Task-Schnitt
- T001: Modell+Guard+Checkpunkte+Tests (Mini-Budget stoppt nach Task 1).
- T002: SSE budget.tick + CLI-Flags.

## Akzeptanz & Tests
- Stop-Reihenfolge deterministisch (zuerst erreichtes Limit gewinnt, Tie: budget vor deadline).

## Risiken / Anti-Ziele
- Nie estimated als actual im Balken (P6): basis-Feld Pflicht.

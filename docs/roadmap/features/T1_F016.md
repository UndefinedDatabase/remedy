# T1_F016 — Scaling task granularity
**Tier 1 · Depends on: F014 · Blocks/used by: F144 input, self-build plan quality**

## Goal & Done
See ROADMAP.md F016; the Done criterion there is binding.

## Context (existing code & prior features)
Task counts are currently whatever the planner feels like; self-build needs predictable slicing.

## Design
Planner rules in flight_plan.py: target input budget per task (class-based), min 1, max_tasks from config (default 40); size_hint steers the slicing prompt; ladder feedback (F144) later adds a bias. plan_rationale (one sentence per task) lands in evidence. The prompt explicitly forbids one-file micro-tasks (A3 spirit).

## Task slicing
T001 rules + prompt + fixtures (S:2, M:6-10, L:~25 tasks) + tests.

## Acceptance & tests
Fixture tolerances within +/-20%; max_tasks hard.

## Risks / anti-goals
No micro-task confetti; deliberately large tasks remain welcome (A3).

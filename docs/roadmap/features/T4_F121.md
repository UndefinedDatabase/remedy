# T4_F121 — Decision cards from ADRs
**Tier 4 · Depends on: F117 · Later integrates: F138 auto-drafted ADRs feed this generator (manual ADRs suffice until then) · Blocks/used by: decision permanence**

## Goal & Done
Architectural decisions stop being forgotten by the workers they
bind: every confirmed ADR generates a decision card (summary, ADR
link, scope = the affected paths), in-scope decision cards reach
reviewer prompts through the normal selector, and a proposal that
contradicts one becomes a review FINDING citing the ADR — surfaced,
never auto-blocking beyond the review's normal weight. DONE when a
fixture ADR yields its card deterministically, the card reaches a
reviewer prompt on an in-scope task, and a seeded contradicting
change produces the citing finding.

## How it fits (inspect current shape before building)
ADRs exist as repo documents (locate the convention — the features
that required ADRs, like the gauntlet flip and autonomy levels,
established the directory and format; parse THAT, don't invent a
second format). Card generation is deterministic extraction (title,
status, decision summary section, affected paths where the ADR
declares them — absent declarations scope project-wide with a
generation note), through the gated store path with origin=adr and
an evidence ref of type file to the ADR. The reviewer-prompt side is
ALREADY DONE by the selector (decision cards weight high for the
reviewer role in the relevance table) — this feature only ensures
the cards exist and the contradiction rule reaches the reviewer's
conventions/prompt.

## Design (suggested shape)
- `adr_cards.py`: scan the ADR directory; per confirmed ADR without
  a current card (id derives from the ADR filename — stable), 
  generate/update the card; superseded/deprecated ADR statuses
  archive the card with the status in the note; run on demand
  (`remedy memory sync-adrs`) and as a cheap step in the hygiene
  loop later. Update rule: regeneration only touches generated
  sections (a marker-fenced body region) — human additions below the
  marker survive (cards are human-curated; the generator is a
  guest).
- Contradiction surfacing: the reviewer conventions gain one
  sentence ("in-scope decision cards are binding context; flag
  conflicts citing the ADR") — a conventions-file change through
  its owning feature's cap rules; the finding is a normal review
  finding whose message cites the ADR path (golden-tested with a
  seeded conflict fixture).
- Traceability: card frontmatter carries adr_ref; the provenance
  resolver treats it as a file ref (staleness detection inherited).

## Task slicing
- **T001** ADR discovery/parsing per the existing convention +
  deterministic extraction + generation/update/archive rules + the
  marker-fenced region + table tests (fresh, updated, superseded,
  human-annotated).
- **T002** sync CLI + idempotence + provenance wiring + tests.
- **T003** the reviewer-conventions sentence (within cap) + the
  seeded-contradiction end-to-end (in-scope card attaches; the
  finding cites the ADR) + goldens.

## Acceptance
- Fixture ADR set generates exactly the expected cards; re-sync is
  a no-op (idempotence hash test); human annotations survive
  regeneration; superseded archives with the reason. The
  contradiction fixture yields the citing finding through a real
  review round (fake provider scripted to notice — the test proves
  the CONTEXT arrived, plus a mechanical assertion that the card
  text was in the prompt evidence).

## Edge cases & assumption defaults (A9)
- Malformed ADRs: reported by the sync with file precision, skipped
  — never a crash, never a guessed card. ADRs without confirmed
  status markers: treated as drafts, no card, listed in the sync
  summary.

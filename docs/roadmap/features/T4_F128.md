# T4_F128 — Memory as a detachable module
**Tier 4 · Depends on: F118 · Blocks/used by: architecture honesty**

## Goal & Done
Memory proves it is a module, not a tumor: [memory] enabled=false
empties the selector (attached_cards=[] everywhere), the UI renders
a designed module-off state, and NOTHING else changes — enforced by
an import contract that lets core packages reach memory only through
one narrow API surface, checked in CI. DONE when the off-switch
fixture run is behaviorally identical to a memory-less build
everywhere outside memory surfaces, the import contract fails the
build on a violating import, and flipping the switch requires no
restart semantics beyond normal config precedence.

## How it fits (inspect current shape before building)
Memory consumers are enumerable at this point: the selector's
segment in prompt composition, the graph payload's cards field, the
collection UI/endpoint, hygiene/harvest hooks, the KPI views —
inventory them (the first deliverable) and route every one through
`memory_api.py`: a thin facade (select_for_task, list_cards,
get_card, record hooks) that honors the switch centrally, so
consumers never check the flag themselves (one switch, one home).
The import contract: an import-linter-style rule (a guard test in
the established pattern if the tool is too heavy) — packages outside
the memory modules may import ONLY memory_api.

## Design (suggested shape)
- `memory_api.py`: the facade; disabled → select returns the empty
  result WITH evidence {memory: disabled} (truthful funnels), list/
  get raise a typed MemoryDisabled the CLI/UI render as the designed
  off-state ("memory is disabled for this project — [memory]
  enabled"), hooks become no-ops with a counted skip log.
- Off-state surfaces: the collection route's off card (design
  reference empty-state pattern), the graph badge absent, KPI views
  render "module disabled" for the period, hygiene/harvest loops
  no-op with the honest line.
- The switch respects config precedence (env/project/user) like
  every key; per-project islands work.
- CI: the import rule + an off-mode end-to-end (fixture job runs
  with memory off; its evidence, report, prompts contain zero card
  traces — a denylist grep over the run's evidence tree).

## Task slicing
- **T001** the consumer inventory + facade + central switch +
  per-consumer migration (small orders, each with an off-mode
  assertion).
- **T002** the import contract in CI + a violation fixture proving
  it fails + the allowlist (memory modules only).
- **T003** off-state surfaces per design + the end-to-end zero-trace
  run + docs.

## Acceptance
- Off-mode fixture: zero card traces in prompts/evidence/reports
  (denylist grep), selector evidence says disabled, UI off-states
  render, loops skip counted. The violating-import fixture fails
  CI naming the import. On/off flips purely via config; no stale
  caches (a flip-mid-suite test).

## Edge cases & assumption defaults (A9)
- Existing cards under a disabled module: untouched, listed only by
  direct file inspection — the CLI's off-state says they're
  preserved. KPI history from enabled periods stays queryable with
  the period's mode labeled.

## Orchestrator brief
T001's inventory is the map — require it complete before migrations
dispatch (parallel afterwards). The zero-trace grep is the
acceptance heart; the denylist (card ids, segment heading, badge
fields) goes in the order.

## Do not touch
Card files themselves, selector internals, other modules'
architecture. Suggested tests: tests/test_memory_module_contract.py.

# T15_F227 — Prompt regression tests
**Tier 15 · Depends on: F105, F012 · Blocks/used by: protecting the most expensive asset: the prompts**

## Goal & Done
See ROADMAP.md F227; the Done criterion there is binding.

## Context (existing code & prior features)
The F105 segment registry structures prompts; golden mechanics exist for UI (F020) and reports (F053).

## Design
Golden prompts per role x scenario (fixture tasks) in tests/prompt_golden/: stored as the segment sequence (ids + digests) AND full text. CI checks two-stage: structural (a missing segment / flipped order / burst budget -> HARD FAIL) and content (a text diff -> FAIL with the diff shown; updates only via `remedy golden update prompts` after a displayed review diff). Coupling: any change to prompt_segments/the compiler MUST touch the golden run (a coverage gate on those paths).

## Task slicing
T001 the golden format + capturing the core roles (builder/reviewer/planner/repair) + the CI job. T002 the update command with the review diff + the structural-vs-content distinction + a fixture (a compiler change without a golden update fails CI).

## Acceptance & tests
A deliberate silent reorder fails structurally; a legitimate change passes only through the update command (an audit trace in the commit); goldens are deterministic (F012 clock/seeds).

## Risks / anti-goals
Keep golden scenarios few and stable (5-8, not 50); golden contents use synthetic fixtures (no project secrets).

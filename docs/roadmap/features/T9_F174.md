# T9_F174 — Data classification in the context compiler
**Tier 9 · Depends on: F107, F162, F155 · Blocks/used by: F197 content gating, F236; regulated sales**

## Goal & Done
See ROADMAP.md F174; the Done criterion there is binding.

## Context (existing code & prior features)
F107 selects context by relevance; a confidentiality dimension does not exist. omitted_context.json is the existing disclosure mechanism.

## Design
[data_classes] per project: path/glob rules -> public|internal|confidential (+default). A compiler rule BEFORE relevance: confidential content may only reach workers whose profile (F162) + class clearance (workers.<id>.max_data_class) allow it - otherwise it is never loaded (omitted_context: reason=data_class) and, if the task is unsolvable without it, a split proposal becomes a decision. The same gate guards telemetry content (F197) and live streams (F236).

## Task slicing
T001 class resolver + compiler gate + the omitted disclosure + tests. T002 router coupling (worker clearances) + the split-decision path + a trace corpus scan test.

## Acceptance & tests
Corpus test: confidential canaries reach cloud adapters in NO trace file; an unsolvable task yields a decision instead of a silent leak or silent failure.

## Risks / anti-goals
Classification is path-based in v1 (documented honestly - no content classifier pretending safety); the default may be set conservatively (everything internal).

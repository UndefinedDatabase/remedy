# T9_F174 — Data classification in the context compiler
**Tier 9 · Depends on: F107, F162, F155 · Blocks/used by: F197 content gating, F236; regulated sales**

## Goal & Done
Confidential code stops leaking into the wrong prompts: per-project
[data_classes] path/glob rules classify content public | internal |
confidential (plus a default), and a compiler rule BEFORE relevance
ensures confidential content reaches only workers whose sandbox
profile and clearance (workers.<id>.max_data_class) allow it —
otherwise it is never loaded (omitted_context: reason=data_class),
and if a task is unsolvable without it, a split proposal becomes a
decision; the same gate guards telemetry content and live streams
later. DONE when classification resolves deterministically per path
(most-specific rule wins, documented), the gate provably runs
BEFORE relevance/loading (an over-clearance worker never even reads
the bytes into the pipeline — the ordering test), omissions land in
the established omitted_context evidence with the reason, the
unsolvable case produces the split-proposal decision with the
triple, and the gate exports the reusable check the later content
consumers (telemetry, streams) will import.

## How it fits (inspect current shape before building)
The context compiler owns loading and already has the
omitted_context vocabulary (budget omissions) — classification
adds a reason and an EARLIER stage: rule resolution happens at
file-set assembly (before content reads — the privacy point:
classification gates the READ, not just the prompt). Clearance:
workers.<id>.max_data_class in config joins the worker registry's
spec (additive; the certification suite can attest it later —
noted); the profile linkage (F162) is a coherence rule: a
confidential-cleared worker must run under a profile whose
fs/net posture matches policy (validation, not magic — the rule
table documented). Unsolvable detection: the task's files_hint/
fence closure intersected with omitted paths — when required
inputs are ALL omitted, the compiler raises the split proposal
(options: route to a cleared worker | human provides a sanitized
excerpt | split the task) through the decision queue with the
triple.

## Design (suggested shape)
- Config: [data_classes] {default, rules: [{glob, class}]};
  resolution most-specific-wins (longest matching glob;
  documented tie-break), table-tested; `remedy data-classes
  check <path>` renders the resolution chain.
- The gate: at assembly, per candidate path → class vs the
  resolved worker's clearance → allowed | omitted(reason=
  data_class, class recorded — the CLASS is loggable, the
  content is not); the ordering guarantee: classification
  precedes any file read for the candidate (the pipeline stage
  order asserted by a read-spy test).
- The exported check: classify(path) + permits(worker, class) —
  one module the telemetry/stream features import (their orders
  reference it; the forward contract).
- Evidence/report: omission counts per class (never per-path
  listings in low-clearance contexts — even path NAMES can leak;
  the report shows counts + "details in the project-scoped
  evidence" — the layered honesty documented).

## Task slicing
- **T001** rules + resolution + the check CLI + table tests
  (specificity, tie-break, default).
- **T002** the compiler gate + ordering guarantee (read-spy) +
  omission evidence + clearance/profile coherence validation +
  fixtures per class×clearance cell.
- **T003** the unsolvable split proposal (detection, options,
  triple) + the exported check module + the layered report
  honesty + the end-to-end (a confidential-touching task on an
  uncleared worker → omitted + solvable continues; the
  unsolvable fixture → the decision).

## Acceptance
- Resolution table exact. The read-spy proves no byte of an
  omitted file enters the pipeline. Cell matrix exact (class ×
  clearance). The unsolvable fixture yields the three-option
  decision with real triple content. Path-name leakage rules
  hold (the report fixture). The exported check is the single
  gate (grep).

## Edge cases & assumption defaults (A9)
- Mixed-class tasks (public + confidential inputs): the public
  subset loads; omissions recorded; solvability judged on the
  requirement intersection (partial context with honest
  labeling is the norm, not an error). Clearance changes
  mid-project: runs pin resolution at compile per run (evidence
  truth); no retroactive claims. Classification of NEW files a
  job creates: the rules apply at next compile; creation itself
  is fence territory (stated boundary).

## Orchestrator brief
Gate on the compiler's stage structure + registry config. The
read-before-classify prohibition (the spy test) is the privacy
core — verbatim. The exported-check contract serves two later
features; freeze its signature deliberately.

## Do not touch
Relevance/budget stages, fence semantics, telemetry/stream
features (importers). Suggested tests:
tests/enterprise/test_data_classes.py.

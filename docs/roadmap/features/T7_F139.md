# T7_F139 — Code churn metric
**Tier 7 · Depends on: F103 · Blocks/used by: planner wisdom, F164 kinship**

## Goal & Done
Rework becomes measurable: lines Remedy authored that get rewritten
within 7/30 days — via blame over trailer-marked commits — aggregate
into `remedy stats churn` per module and task class, high churn
feeds planner hints, and refactor orders are exempt via their
label. DONE when churn computes correctly on constructed git
histories (goldens), the commit-trailer convention is verified or
added as the prerequisite (attribution needs a marker), windows and
exemptions behave exactly, the planner hint appears above the
threshold with its evidence, and everything is read-only over git
plus the ledger.

## How it fits (inspect current shape before building)
Attribution ground truth: Remedy's commits need a machine-readable
trailer (Remedy-Job: <id> / Remedy-Task: — verify whether the
applicator's commit path writes trailers today; if not, adding
them is the small prerequisite order, and history before it is
honestly out of scope: "churn measurable from <date>"). The
computation walks git via the existing _git helper: for
trailer-marked commits older than the window, blame the touched
lines at HEAD (or at window-end) — lines whose current commit
differs and is ALSO within the window count as churned; rewrites
by refactor-labeled jobs are exempt (the label travels in the
trailer too). Task class joins via the job/task records (churn per
class feeds the ladder/planner wisdom).

## Design (suggested shape)
- `code_churn.py`: compute(project, windows=[7,30]) → per module
  and per class {lines_authored, lines_churned, ratio, n_commits}
  with the measurable-from date; pure over git+records; snapshot-
  cached (the calibration pattern — churn walks are not free).
- Exemption: churn CAUSED BY refactor-labeled commits doesn't
  count against the original author-lines (the rewrite was
  policy); refactor jobs' OWN lines still get measured going
  forward (symmetry, documented).
- Stats view: the matrix with windows, the measurable-from
  honesty line, top-churn modules with links to the rewriting
  jobs (evidence).
- Planner hint: modules above a config ratio inject one planning
  segment sentence ("<module> shows high 7-day churn — plan
  smaller, verify-heavier tasks there") — the ladder's inform-
  never-block tone verbatim; evidence records hint given.
- F164 kinship (hotspot analysis later) reads the same store —
  schema versioned.

## Acceptance
- Constructed-history goldens exact per window; exemption
  symmetry proven both directions. Measurable-from renders
  whenever pre-trailer history exists. Hint appears exactly above
  threshold with the module named; never blocks. Read-only
  (state diff).

## Edge cases & assumption defaults (A9)
- Squash/rebase workflows mangling trailers: the docs state the
  dependency plainly (trailers must survive the project's merge
  policy — a doctor check can verify a sample); mangled history
  degrades to measurable-from honesty. File renames: follow
  renames via git's detection; misses are noise the ratio
  tolerates (documented).

# T3_F112 — Prompt budget per task class
**Tier 3 · Depends on: F103 · Enhanced by: F074 calibrated class caps (config defaults, honestly labeled, until then) · Blocks/used by: outlier protection**

## Goal & Done
No prompt can silently balloon: every task class carries an input-token
cap, the context compiler must fit under it via its documented demotion
cascade (distant signatures drop first) with full omission disclosure,
and a context that CANNOT fit raises a task-split proposal as a decision
instead of a truncated prayer. DONE when a fixture oversized context is
demoted under the cap with the omissions recorded, an unfittable fixture
produces the split decision, and caps are config with honest
default-basis labels until calibration exists.

## How it fits (inspect current shape before building)
The context compiler already owns tiered selection, budget demotion and
the omissions record — this feature gives it PER-CLASS caps and the
hard-floor behavior; enforcement lives inside the compiler, not as an
outer truncation (mid-file truncation stays forbidden). Class comes from
the same declaration routing uses (one class vocabulary — assert the two
features share the constant set). Cap values are config defaults labeled
estimate_basis=class_default until the calibration feature replaces them
with measured ones.

## Design (suggested shape)
- Config: per-class input caps + a global fallback; validation refuses
  caps below a documented floor (a cap too small to fit tier-1 fenced
  files is a misconfiguration, named).
- Compiler: fit(context, cap) applies the existing demotion order; if
  after full demotion tier-1 content alone still exceeds the cap →
  outcome cannot_fit with the arithmetic (tier-1 size, cap, class).
- cannot_fit at task dispatch → a decision "task context exceeds its
  class cap" with options: split task (seeding the granularity
  machinery's split on the task), raise cap for this job (audited),
  proceed-overcap once (audited, unattended default NO) — the safe
  default for --yes runs is split.
- Evidence: per task, the cap, final size, demotions applied — the
  existing omissions file gains the cap context.

## Task slicing
- **T001** config + validation + the shared class vocabulary assertion
  + tests.
- **T002** compiler cap enforcement + cannot_fit arithmetic + fixture
  (oversized → demoted under cap; unfittable → cannot_fit).
- **T003** the decision wiring + unattended default (split) + an
  end-to-end where the split resolves the fit + tests.
- **T003c** (added, DECISION F112 D5): job task markdown gains a
  "## Files" section, parsed into TaskEntry.files_hint — the fenced
  scope the dispatch loop's run_pingpong call needs before it can
  engage compile_task_context at all (run_pingpong's own
  use_compiled_context gate requires a NON-EMPTY fenced-path list;
  T003b2a's adapter deliberately leaves files_hint empty for the
  split seam only, which is a different, narrower concern). A
  prerequisite for T003b2b2's live wiring, not an alternative to it.

## Acceptance
- Oversized fixture fits under its cap with tier demotions recorded;
  no mid-file truncation anywhere (guard stays green). Unfittable
  fixture: decision with correct arithmetic; --yes path splits and
  completes. Cap labels carry the default basis until calibration.

## Edge cases & assumption defaults (A9)
- Classes without a configured cap use the global fallback and say so.
  A split that cannot help (single huge fenced file) → the decision
  drops the split option and says why — options offered must be real.

## Orchestrator brief
Gate on the context compiler and routing's class vocabulary. T002 is
the substance; include both fixtures in the order. Reject any
implementation that truncates instead of demoting.

## Do not touch
Calibration, the demotion order itself, granularity heuristics (reused,
not modified). Suggested tests:
tests/orchestration/test_class_prompt_budget.py.

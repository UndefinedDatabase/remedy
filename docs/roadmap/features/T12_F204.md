# T12_F204 — Update channel & change transparency
**Tier 12 · Depends on: F086, F202 · Blocks/used by: F215/F221 channels; upgrade trust**

## Goal & Done
See ROADMAP.md F204; the Done criterion there is binding.

## Context (existing code & prior features)
F086 ships packaging + semver + changelog duty; a check/display mechanism is missing.

## Design
`remedy update check`: reads a release index (static JSON on the release host; source in config; air-gap disables it with a note, F173); shows: newest version per channel (stable/beta), a changelog extract, data compatibility (the target data_v; whether `remedy migrate` is needed - the F202 matrix). NEVER auto-update; no download without explicit consent (and even then only a link/per-channel instruction, F215 - package managers stay in charge). A deprecation framework: marked APIs/flags warn exactly once per version with the target version + replacement.

## Task slicing
T001 the index format + the check CLI + the compatibility display + fixture-index tests. T002 the deprecation registry + the warn-once mechanic + docs.

## Acceptance & tests
check against the fixture index is correct incl. the migrate hint; airgapped disables without error; the deprecation warning fires exactly once (counter test).

## Risks / anti-goals
No telemetry piggybacking on the check (the request carries ONLY the channel - a capture test, the F219 line); the index is signed (the F165 backend) once F215 lands.

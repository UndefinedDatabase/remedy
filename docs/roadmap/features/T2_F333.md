## Goal & Done
When a job's test run fails, Remedy runs only the failing tests, by their ids (pytest node ids, Vitest file names), once at the job's base commit in a separate clean checkout. A failure that is there too is pre-existing: named in the evidence and the story (`failed_before_job`, „war schon vorher rot“), told to the reviewer as a fact, no finding against the builder, and no block. Only failures new in the job block as before. When the base run cannot be made (no ids, a runner that takes none, a timeout), the failure blocks as before and the evidence says why. A night run does not stop on a failure it did not cause.

## Acceptance
- A red `project_tests` run whose failing tests are read completely runs only those tests, by id, at the base commit in a throwaway worktree; when every failure is there too, the check passes with `preexisting_failures`, its evidence names them (`preexisting`), and the workspace remembers them.
- A failure new in the job stays red, and `baseline` names the new failures; no ids, a runner that takes no ids, or a base run that cannot be made leave it red, and `baseline` says why.
- A round whose builder's own test run was red gets Remedy's full run in the worktree, judged against the base; the reviewer's test summary names the pre-existing failures as a fact.
- A finding only about those failures (their file, their names, or only that the tests fail) reads `low`, so it does not block; any other finding stays.
- The story's checking step says `failed_before_job` with `n`; contract 1.34 names it and the evidence keys.

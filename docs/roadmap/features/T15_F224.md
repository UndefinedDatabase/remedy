## Context (existing code & prior features)

## Design
packages/intel/repo_archaeology.py: an index over commit messages, PR descriptions (gh export where present), docs/adr/*, failure postmortems - full text below a threshold, the F127 embedding pre-filter above. A per-task query (a budget segment in F112): 'previous attempts/decisions about <task topic>' -> a context block with CITATIONS (anchors: commit sha / file - the F038 validation pattern: anchors must resolve or the block is discarded). The prompt labels it 'historical finding (verify, do not blindly follow)'.

## Task slicing
T001 the indexer + sources + anchor validation + tests. T002 the query block + budget integration + a fixture (a historically failed approach is cited; the builder provably avoids it - trace proof).

## Acceptance & tests
The fixture citation appears in the builder prompt with a resolving anchor; irrelevant history stays out (a precision fixture); the block respects its token budget hard.

## Risks / anti-goals
History is a hint, never a fence (old decisions can be wrong - the wording says so); no indexing outside the project (F148).

# T1_F056 — Missions: persistent goal, jobs as execution units
**Tier 1 · Depends on: F013, F047 · Blocks/used by: F069/F070, lineage UI later**

## Goal & Done
See ROADMAP.md F056; the Done criterion there is binding.

## Context (existing code & prior features)
Long goals need continuity across jobs without inflating the user-facing vocabulary.

## Design
`mission_state.py`: Mission{id, goal, jobs[], status, dossier_ref}. Creation: intake sets mission_candidate=true AND the user confirms in the Flight Plan ('run as mission' checkbox). Follow-up jobs link mission_id; every follow-up starts with a verify step (tests+smoke of the previous state). The cockpit later renders the lineage thread; SSE mission.job_linked exists from day one.

## Task slicing
T001 state + chaining + verify hook + tests. T002 (Tier 5) UI chain band.

## Acceptance & tests
A long goal yields a mission with 3 chained jobs; a simple order stays a single job with zero mission overhead.

## Risks / anti-goals
Missions add NO new prompt species - jobs remain the only execution unit.

# T1_F075 — MILESTONE GATE: 10 flawless self-runs
**Tier 1 · Depends on: Tier 0 complete, F070 · Blocks/used by: unlocks multi-cycle defaults and the A7 handover**

## Goal & Done
Autonomy is earned with data, not granted on vibes: a curated gauntlet of
ten missions must run FLAWLESSLY — no operator command after start,
verifier pass, DoD green, zero unclassified failures — before multi-cycle
defaults flip and the handover proceeds. DONE when the gauntlet harness
runs the set sequentially, produces a per-run result matrix as evidence,
and a passing 10/10 flips the default via an explicit config change with
an ADR — a human-reviewed diff, not an automatic switch (P2).

## How it fits (inspect current shape before building)
Everything under test exists: the golden path, the orchestrator loop, the
DoD gate, budgets, escalation, reports, postmortems. The gauntlet is a
HARNESS plus a curated order set plus a strict pass definition — it adds
no product code paths; any product fix it forces goes through normal
feature/bug work with its own tests.

## Design (suggested shape)
- `scripts/self_run_gauntlet.py`: reads a curated set of ten mission
  orders (fixture files, small to medium, mixed kinds: pure-code change,
  test-add, small app feature with smoke, doc generation, a two-milestone
  mission) → runs each unattended (--yes semantics, fixed budgets) →
  records per run: terminal status, DoD matrix, postmortem classes,
  operator interventions (must be zero), wall/tokens.
- Flawless per run = start command only + terminal green + all blocking
  DoD checks green + every failure along the way classified (no
  `unknown` postmortems) + zero open decisions at the end.
- Host-state isolation: a self-run — including every test and verify step
  it triggers and every reviewer-side verification — runs against an
  isolated data root and leaves the operator's real data root
  byte-untouched (before/after content hash of the data root asserted by
  the gate). Any pollution of host state, however small, disqualifies the
  run. (Earned 2026-07-23: both worker tests and reviewer verification
  wrote stray projects into the real registry during F081.)
- The matrix report (markdown + json) lands under a gauntlet evidence
  area with links into each run's evidence; failed gauntlets are KEPT —
  the history of attempts is part of the proof.
- Passing emits a prepared-but-not-applied config diff + ADR template
  naming the evidence; a human applies it. The harness never edits
  config itself.
- Re-running after fixes is expected and cheap: `--only <n>` reruns a
  single order; a full pass must still be ten consecutive greens from
  one invocation.

## Task slicing
- **T001** harness + pass-definition evaluator + matrix report; dry-run
  mode against recorded fixture evidence proves the evaluator before any
  real run.
- **T002** the curated order set (ten missions with rationale comments —
  why each probes a different risk) + budgets per order.
- **T003** iterate: run, fix product bugs via normal orders, rerun —
  multiple rounds EXPECTED; the gate is done when 10/10 stands and the
  ADR + config diff are prepared.

## Acceptance
- Evaluator: a fixture run with one operator command → not flawless; one
  unknown postmortem → not flawless; all criteria demonstrably
  falsifiable. Matrix golden for a recorded fixture set. 10/10 real pass
  archived with the prepared diff + ADR.
- Operator addition 2026-07-27: a gauntlet run that exhibits any of the
  F070 era-fixture finding classes (R-0141/R-0143/R-0144/R-0145/R-0146/
  R-0147/R-0148 — see T1_F070.md, Design) is by definition NOT flawless;
  the harness's failure classification must be able to name these
  classes.
- Operator addition 2026-08-03: the gauntlet includes a harness-failure
  injection class: provider API error mid-move, truncated/incomplete
  model response, and harness death mid-dispatch and mid-write. A
  flawless run degrades every such event to a LEDGERED failure, retry
  within budget, or escalation (F051 semantics) — never a silent
  success, never a corrupted artifact accepted downstream. The
  artifact-integrity half is already proven in the field: F070's
  closure recovered a transport-corrupted authored text via the
  hash-on-write/verify-on-read mechanism on its first real-world use
  (f070-r3-3); this fixture class makes the process half equally
  provable.

## Edge cases & assumption defaults (A9)
- Provider flakiness during the gauntlet: transport retries are inside
  the loop already; a run failing on provider_unavailable is a FAILED
  run (the world is flaky; flawless includes surviving it) — rerun the
  whole gauntlet after infrastructure fixes. Order set changes reset the
  count (the ten must be from one frozen set, versioned).

## Orchestrator brief
T001/T002 are normal orders; T003 is a CAMPAIGN the orchestrator drives:
run, read the matrix, file targeted fix orders with the failing
evidence attached, rerun. Do not weaken the pass definition to pass the
gate — tightening reality is the feature.

## Do not touch
The pass definition once frozen (changes need an ADR), config defaults
by machine, order-set edits mid-campaign. Suggested tests:
tests/orchestration/test_gauntlet_evaluator.py.

# T9_F166 — Retention & archive export
**Tier 9 · Depends on: F060, F146, F103 · Blocks/used by: F168; long-horizon audits**

## Goal & Done
Evidence ages under policy, not entropy: per-project [retention]
(evidence_years, certificates_years) drives a preview-first
lifecycle — expiry candidates are only LISTED by `remedy retention
preview`, deletion happens exclusively via an explicit command
with a summary — and `remedy export archive --since --until
[--sign]` produces an immutable, optionally signed export
(certificates, reports, ledger extract, lineage, oversight) as a
plain directory tree with INDEX.md, readable in ten years without
Remedy. DONE when preview/delete honor the policy windows exactly
(boundary fixtures), deletion is explicit, summarized and audited
(nothing expires on a timer), the archive's INDEX.md + layout pass
the bare-reader test (a fixture audit answered from the tree with
standard tools only), signing integrates the F165 backend, and
certificates' longer retention survives evidence pruning (the
provenance staleness story stays honest).

## How it fits (inspect current shape before building)
Retention policy slots into project config (the config precedence
as ever); candidates derive from job terminal dates against the
windows — the walker reads job records + the evidence layout (the
resolver's path knowledge reused). The certificate feature's
prune-note mechanism (evidence pruned → the note with hashes)
becomes retention's deletion receipt: deleting evidence WRITES the
receipt where the certificate expects it, keeping verify's
degraded-but-honest path working (the two features interlock —
test the interlock). The archive is a READ composition: selected
artifacts copied byte-exact into a dated tree (no transformation —
fidelity), INDEX.md generated (what, from which job, hashes),
optional manifest+signature via F165; "readable without Remedy"
is enforced by the bare-reader fixture (a container with only
coreutils answering the ten audit questions from the tree).

## Design (suggested shape)
- Policy: [retention] {evidence_years (default generous),
  certificates_years (longer default)}; validation (certificates
  ≥ evidence — proofs outlive their bulk).
- `retention preview`: the candidate table {job, terminal date,
  expires under, sizes} — pure read; `retention apply` requires
  an explicit confirmation naming counts+sizes, writes prune
  receipts per certificate-relevant deletion, audits the action
  (who, when, what).
- `export archive`: window selection → the tree (certificates/,
  reports/, ledger/ extract as CSV+JSONL, lineage/ notes dumps,
  oversight/) + INDEX.md + hashes; --sign via the one signing
  home; the output directory is chattr-agnostic plain files
  (immutability by custody, stated honestly).
- The bare-reader test: the fixture question list is a committed
  artifact (the F079/F186 pattern).

## Task slicing
- **T001** policy + the candidate walker + boundary tests +
  preview rendering.
- **T002** apply (confirmation, receipts, the certificate-verify
  interlock test, audit) + fixtures (delete → verify degrades
  honestly, never breaks).
- **T003** the archive export (tree, INDEX, hashes, signing) +
  the bare-reader fixture + docs + the end-to-end.

## Acceptance
- Boundary fixtures exact (a day inside/outside each window).
  Nothing deletes without the explicit apply (no timer paths —
  grep). Receipts keep verify honest (the interlock fixture).
  The bare-reader answers ≥9/10 from the tree with standard
  tools (the committed question list). Signed archives verify
  via F165.

## Edge cases & assumption defaults (A9)
- Jobs still running past a window (pathological): never
  candidates (terminal-dated only). Archives overlapping prior
  archives: fine — each is self-contained with its window in
  INDEX (dedup is the custodian's concern, stated). Ledger
  extracts: raw rows for the window, the currency/basis columns
  intact (comparability survives the decade).

## Orchestrator brief

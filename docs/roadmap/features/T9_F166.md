# T9_F166 — Retention & archive export
**Tier 9 · Depends on: F060, F146, F103 · Blocks/used by: F168; long-horizon audits**

## Goal & Done
See ROADMAP.md F166; the Done criterion there is binding.

## Context (existing code & prior features)
Evidence grows unbounded; no retention concept exists.

## Design
[retention] per project (evidence_years, certificates_years); packages/enterprise/retention.py: expiry candidates are only LISTED (`remedy retention preview`); deletion happens exclusively via an explicit command with a summary. `remedy export archive --since --until [--sign]`: an immutable export (certificates, reports, ledger extract, lineage, oversight) with a global manifest, optionally signed (F165); target format is a plain directory tree + INDEX.md - readable in ten years without Remedy.

## Task slicing
T001 retention config + preview + guided deletion + tests (nothing vanishes without the command). T002 the archive exporter + INDEX renderer + a verify-without-live-system test.

## Acceptance & tests
The export is complete against the ledger (reconciliation); a fresh machine reads the archive with plain tools; preview provably deletes nothing.

## Risks / anti-goals
No auto-purge, ever; the archive format is boring by design (no proprietary containers).

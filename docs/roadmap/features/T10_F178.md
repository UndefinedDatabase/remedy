# T10_F178 — Decision assignment & delegation
**Tier 10 · Depends on: F177, F031 · Blocks/used by: F183 routing; M11**

## Goal & Done
Decisions stop being everyone's and no one's: queue entries gain
assignee_user?, assignee_role?, delegated_from? and an event-based
escalation list (after n unread reminders, escalate to X);
commands assign_decision and delegate_decision join the catalog;
an away flag routes NEW assignments via the user's delegate while
existing ones stay but render as represented in the delegate's
inbox; the invariant holds that every open decision has at least
one resolvable owner (a role counts when no user is set); and the
inbox filters to 'mine' by default in multi-user mode. DONE when
assignment/delegation round-trip with audit and actor precision,
escalation triggers on the reminder-count event (not a timer —
the event-based rule), the away flag's routing distinguishes
new-vs-existing exactly, the invariant checker refuses states
that would orphan a decision (and the resolver proves role
fallback), and inbox defaults flip correctly by mode.

## How it fits (inspect current shape before building)
The queue is file-based with atomic claims and typed entries —
assignment is additive fields plus catalog commands through the
write channel (person-precise per F177); the inbox (F031) already
filters and renders the queue — 'mine' is a filter default keyed
to the resolved user (assignee_user == me, or my roles ∋
assignee_role, or unassigned-and-I-can-resolve per the matrix —
the visibility rule documented). Escalation is EVENT-based by
design (unattended-first: no daemon timers): the reminder
machinery (notify's digest/reminder events) counts deliveries
per decision+user; n unread reminders (no resolving action
since) emits the escalation event → reassignment per the list +
the audit trail. Away/delegation: a user record flag
{away, delegate_to} (identity store additive); the routing rule
lives in the assignment path (one place).

## Design (suggested shape)
- Fields (additive, schema-versioned): assignee_user?,
  assignee_role?, delegated_from?, escalation [{after_reminders,
  to}]; validation (user/role exist; escalation targets
  resolvable).
- Commands: assign_decision {id, to_user|to_role}, delegate_
  decision {id, to_user, reason?} — matrix-gated (reviewer+ may
  delegate own, operator may assign any — the documented cells);
  audit + the delegated_from chain (bounded depth, documented).
- The away rule: at assignment time only — away(assignee) →
  route to delegate_to with delegated_from set; existing entries
  untouched but the delegate's inbox shows them under a
  represented section (a read-time view, no data change).
- The invariant: on every mutation, ≥1 resolvable owner (user
  present-and-active, or role with ≥1 active member, or
  unassigned-open-to-operators); violating mutations refused
  with the fix named.
- Inbox: mode-aware default filter + the represented section +
  assignment affordances per the reference's list treatments.

## Task slicing
- **T001** fields + validation + commands + matrix cells + audit
  + unit tests (chains bounded, targets resolvable).
- **T002** the away routing (new-vs-existing exactness) + the
  represented view + the invariant checker + refusal fixtures.
- **T003** event-based escalation (reminder counting, the
  escalation event, reassignment + audit) + inbox defaults/
  affordances + the end-to-end (assign → away → new decision
  routes to delegate → reminders accrue → escalation fires →
  resolved person-precise).

## Acceptance
- Round-trips audited with actors. New-vs-existing routing exact
  (fixtures both sides). The invariant refuses the orphan
  mutation naming the fix; role fallback resolves. Escalation
  fires on the count event only (no timers — grep). Inbox
  defaults per mode; represented entries render distinctly.

## Edge cases & assumption defaults (A9)
- Delegate is also away: one hop only — the assignment falls to
  the role/operator pool with the note (no delegation chains
  hunting a human, documented). Escalation target away: same
  rule at escalation time. Role-assigned decisions with an empty
  role (last member deactivated): the invariant catches it at
  the deactivation mutation (refuse or reassign — the operator
  chooses via the named fix).

## Orchestrator brief
Gate on F177 + the queue + notify's reminder events. The
event-not-timer rule and the one-hop delegation rule go
verbatim. T002's exactness fixtures (new vs existing) are the
behavioral core.

## Do not touch
Queue claim atomicity, notify channel mechanics (events
consumed), decision payload schemas. Suggested tests:
tests/org/test_decision_assignment.py.

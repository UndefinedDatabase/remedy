# T10_F178 — Decision assignment & delegation
**Tier 10 · Depends on: F177, F031 · Blocks/used by: F183 routing; M11**

## Goal & Done
See ROADMAP.md F178; the Done criterion there is binding.

## Context (existing code & prior features)
Decision entries carry the evidence triple but no addressee.

## Design
Queue fields: assignee_user?, assignee_role?, delegated_from?, escalation:[{after: event-based (n unread reminders), to}]. Commands assign_decision, delegate_decision (catalog extension). Delegation: a user away flag routes NEW assignments via delegate_to; existing ones remain but are marked represented in the delegate's inbox. Invariant: every open decision has >=1 resolvable owner (a role counts when no user). The inbox filters 'mine' by default in multi-user mode.

## Task slicing
T001 fields + commands + the invariant property test. T002 delegation/escalation logic + inbox UI filters + a fixture scenario (assign -> away -> delegate).

## Acceptance & tests
Property: no ownerless open decision is constructible; the delegation chain is complete in the audit; UI filters correct per user.

## Risks / anti-goals
Escalation is event-based, never time-of-day (Part J law); delegation rules NEVER auto-decide (P2 stays absolute).

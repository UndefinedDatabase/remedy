## Task slicing
Carried from F298, word for word:
- T002 — An order runs in the repository of the project it names. An order that names a project
  runs in that project's registered repository wherever the client stands; an order whose project
  has no registered repository, or whose `--repo` is another project's repository, is refused
  before any step with its own token. One command registers a repository for a client and leaves
  its working copy clean.
- T003 — Honest refusals, and declining. Under `--approve --json` an apply that did not land
  answers `"ok": false` with one fixed error token per cause (the contract refuses the push, no
  upstream, a dirty tree, a detached HEAD, a merge conflict, protected files) and exits non-zero;
  the preview without `--approve` keeps exit 0. One command declines a completed job's result
  with a reason, recorded as the operator's decision the way the cockpit's door records one. A
  declined job, and a job of an abandoned mission, no longer waits for its apply.
- T004 — Commit, push, several jobs, and the same order twice. The second gate test drives an
  order file to `remedy job apply <job> --approve --commit-with-history --push --json` against a
  local bare upstream and reads the commit, the branch and the push from the answer; drives an
  order of two jobs to its end as a program would; and starts one order file twice. The second
  start is refused before any step and names the mission that already runs it, unless a flag asks
  for a new mission.
- T005 — What an approval card needs, from records only. Each completed job in the digest
  carries: the files it changed (a count and a bounded list), each task with its title, its
  reviewer's verdict, its repair rounds and whether a test command ran and what it answered, the
  blocking criteria of its mission's contract with status and text, one recommendation word and
  one risk word. The rules that derive the two words from recorded facts stand in the contract
  document; no word comes from a model. A job on which no check ran says so.
- T006 — Tokens and calls where a client reads a cost. Each job in the digest and each project's
  day carry the provider calls and the tokens the records hold, by kind (input, output, cache
  read, and cache creation where a provider reports it), beside the existing `cost`. The mandatory
  cap of an order may be any one of the job budgets — cost, total tokens, provider calls or
  wall-clock minutes; an order with none is refused as today. The document says exactly which
  tokens the token budget counts.
- T007 — The digest stays small, and templates. By default the digest lists every job that still
  needs something and the jobs that ended inside a window; it names the window and how many jobs
  it left out, and a flag widens it; the first round measures the operator's own data root. The
  round measures whether a small change to an existing repository needs a template of its own and
  adds one if it does.

## Acceptance
Carried from F298, word for word:
- An order with `project: b`, started in repository A or in no repository, changes only b's
  registered repository or is refused before any step; a test stands in each of the three places.
- A blocked apply under `--approve --json` exits non-zero with `"ok": false` and a token the
  document lists; no path answers `"ok": true` for an apply that did not land.
- A declined job reads `waits_for_apply` false, is not in `awaiting_apply`, and its decision is in
  the job's ownership record.
- The second gate test is green through the command line alone, with a stdin that fails the test
  on any read.
- The digest names calls and tokens by kind for a job run with a provider that reports them, and
  an order capped only by provider calls or by total tokens is accepted and stopped at its cap.
- With 1,000 settled jobs on a scratch data root the default digest stays under a size the first
  round fixes from its measurement, and names the count it left out.
- A second `remedy do` of an order file a running mission records exits 2 before any step.
- F295's gate test and its path are unchanged and green.

## Goal & Done
Results become tangible without leaving the cockpit: README renders
as sanitized markdown, screenshots open in a lightbox, and 'open
app' issues a start_preview command that starts the runtime and
reveals the live port link ONLY after a successful probe — no dead
links, no XSS, no fake liveness. DONE when the sanitizer passes its
attack corpus, the preview flow round-trips (command → supervisor
start → probe → link) with every failure mode rendered honestly,
screenshots lightbox per the reference, and stopping the preview is
as easy as starting it.

## How it fits (inspect current shape before building)
The runtime harness owns start/probe/stop and the supervisor's
state — start_preview is a channel command whose effect enqueues a
runtime start intent consumed by the existing supervisor mechanics
(inspect the current serve/probe verbs; the UI never spawns
processes). The probe-before-link rule is the harness's readiness
fingerprint reused: the link renders only on probe pass, with the
probe detail on failure ("started but health check failed:
<reason>"). Markdown sanitization is a real security surface: a
vetted sanitizer approach with a maintained ATTACK CORPUS test
(script tags, event handlers, javascript: URLs, SVG payloads, data
URIs — the corpus is a deliverable, extended on every finding).

## Design (suggested shape)
- Artifact endpoints: README/markdown files from the job's
  worktree/evidence rendered server-side to a sanitized fragment
  (sanitize AFTER render, allowlist-based); images served with
  content-type discipline from evidence paths only (no arbitrary
  path reads — the fence vocabulary applied to serving).
- The preview panel per reference: README fragment, screenshot
  grid → lightbox (keyboard, captions from filenames), the app
  card with state (stopped | starting | probing | live @ port |
  failed: reason) driven by supervisor events over SSE.
- Commands start_preview/stop_preview {job_id}: audited, effect =
  supervisor intents; concurrent previews bounded by the
  supervisor's existing port/instance rules (inherit, don't
  invent); auto-stop on idle (config TTL) with the state honest.
- The tour's stop anchors can target the preview (the enhancement
  noted there — wire the anchor kind here).

## Acceptance
- Attack corpus fully neutralized (and the corpus grows on any
  new vector — the test file says so). Link never renders before
  probe pass; every failure mode's card matches its fixture. No
  server path read outside the job's allowlisted roots (traversal
  fixtures). Auto-stop leaves no processes (the harness's checks).

## Edge cases & assumption defaults (A9)
- Projects without a runtime: the app card renders not-applicable
  (the smoke feature's honesty). Huge READMEs: rendered with a
  size cap + "open full file" link. Multiple screenshots
  directories: the evidence's designated captures dir is the
  source (coordinate with the screenshot feature's output
  convention when it lands).

probe-before-link rule is verbatim acceptance material.

## Do not touch

## Built State (F041, 2026-09-29)

What exists on disk at the close of F041, built in six rounds over two sessions on
`feature/f041-artifact-preview`, cut from `main` at `45c584e6`. Every DECISION named lives in
`.agent/decisions.md`; every round's verdict in `.agent/live_review.md` or, once rotated, its archive.

**T001 — the sanitized README and the serving discipline.** `packages/orchestration/artifact_markdown.py`
renders a closed markdown subset with the standard library alone, escaping every source character so
raw HTML is text, then rebuilds the output from an allowlist of tags and attributes; a link keeps only
http, https or mailto with `rel="noopener noreferrer nofollow"`, an image only a path with no scheme,
and a README over 256 KiB is cut at its last full line (DECISION F041 D1). The attack corpus is
`tests/orchestration/test_artifact_markdown.py`, written by the reviewer with every vector's whole
output as a literal, and it says it only grows. `packages/orchestration/artifact_preview.py` derives
the two roots, the staging workspace and the job's evidence directory, from the data-root registry,
and `resolve_artifact_path` refuses an absolute name, a `..` part, a backslash, a NUL and a symlink
leaving its root; `/api/jobs/<id>/artifacts` answers the sanitized README and the screenshots under
`captures/`, never SVG, at most 200. The file route serves exactly `README.md` as plain text and one
`captures/<name>` image, at most 10 MiB, with `nosniff`, a sandboxing content security policy and
`no-store` (D2); R-1105 made the static asset route's containment a path test.

**T002 — the preview.** `preview_control.py` holds one record per job, `preview.json`, whose state is
stopped, starting, probing, live, failed or not applicable; `preview_runner.py` runs the harness's own
`runtime serve`, `probe` and `stop` through their JSON envelopes, and only a passed probe writes the
link, which is the probe's own, so the harness's free-port fallback shows the port that answered
(D3). `remedy job preview-start` and `preview-stop` drive it from the command line. The write door's
`job.preview-start` and `job.preview-stop` record the request and hand it to the UI server's
`preview_worker.py`, whose thread runs the verbs, probes every live preview again each fifteen
seconds, stops one nobody has viewed for `preview.idle_ttl_seconds`, default 900, and stops them all
when the server closes; `/api/jobs/<id>/preview` counts as a view and shows a link only while live (D4).

**T003 — the Results panel, the tour's preview stop and the end-to-end run.** A `Results` button in
the right panel opens `components/artifacts/ArtifactsPanel.tsx`, portaled to the document body: the
app card, the README through the one `dangerouslySetInnerHTML` of `apps/ui/src`, with an "Open the
full README" link when it was cut, and a screenshot grid whose pictures open in `ArtifactLightbox.tsx`,
stepped by the arrow keys and closed by Escape (D5). The rules are pure in `api/artifactPreview.ts`:
the two decoders, the paths, `readmeCockpitHtml`, which points a README image at the file route only
when it names a listed capture and otherwise writes its alt text, in one pass since R-1106, the
captions, and the card's words, which offer a link only while live and only to an http or https
address; `api/previewSend.ts` sends the pair through the door. `AppPreviewCard.tsx` reads the view
only while the page is visible, so a closed panel or a hidden tab lets the idle stop run. The guided
tour gains a `preview` anchor and a "See it running" stop for a job whose own project folder resolves
a runtime, whose "Show me" opens the panel (D6). `tests/ui_server/test_preview_end_to_end.py` starts a
real UI server and a real stdlib app, sends the start through the door, finds no link before the probe
passes, fetches the live link, and waits on the record until the server's own worker stops the app
for want of a viewer, with no process left. A headless render of the panel read eight checks of eight.

**Acceptance and edge cases, line by line.** The corpus is neutralized and grows by rule; the link
never renders before a probe passes, in the view, the card, the render and the end-to-end test; the
failure modes are a dead start, a failed probe and a project with nothing to run, each with its own
test, and a taken port is the harness's own free-port fallback, whose effective port the link carries
(`test_the_link_is_the_probes_not_the_serves`); no path is read outside the two roots, by the
traversal tests; the idle stop leaves no process. A project without a runtime shows "This project has
no app to run."; a long README is cut with the link to the whole file; the screenshots come from the
evidence directory's `captures/` alone.

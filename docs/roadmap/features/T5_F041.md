## Goal & Done
Results become tangible without leaving the cockpit: README renders
as sanitized markdown, screenshots open in a lightbox, and 'open
app' issues a start_preview command that starts the runtime and
reveals the live port link ONLY after a successful probe — no dead
links, no XSS, no fake liveness. DONE when the sanitizer passes its
attack corpus, the preview flow round-trips (command → supervisor
start → probe → link) with every failure mode rendered honestly,
screenshots lightbox per the reference, and stopping the preview is
as easy as starting it.

## How it fits (inspect current shape before building)
The runtime harness owns start/probe/stop and the supervisor's
state — start_preview is a channel command whose effect enqueues a
runtime start intent consumed by the existing supervisor mechanics
(inspect the current serve/probe verbs; the UI never spawns
processes). The probe-before-link rule is the harness's readiness
fingerprint reused: the link renders only on probe pass, with the
probe detail on failure ("started but health check failed:
<reason>"). Markdown sanitization is a real security surface: a
vetted sanitizer approach with a maintained ATTACK CORPUS test
(script tags, event handlers, javascript: URLs, SVG payloads, data
URIs — the corpus is a deliverable, extended on every finding).

## Design (suggested shape)
- Artifact endpoints: README/markdown files from the job's
  worktree/evidence rendered server-side to a sanitized fragment
  (sanitize AFTER render, allowlist-based); images served with
  content-type discipline from evidence paths only (no arbitrary
  path reads — the fence vocabulary applied to serving).
- The preview panel per reference: README fragment, screenshot
  grid → lightbox (keyboard, captions from filenames), the app
  card with state (stopped | starting | probing | live @ port |
  failed: reason) driven by supervisor events over SSE.
- Commands start_preview/stop_preview {job_id}: audited, effect =
  supervisor intents; concurrent previews bounded by the
  supervisor's existing port/instance rules (inherit, don't
  invent); auto-stop on idle (config TTL) with the state honest.
- The tour's stop anchors can target the preview (the enhancement
  noted there — wire the anchor kind here).

## Task slicing

- **T002** preview commands + supervisor intent wiring + state

## Acceptance
- Attack corpus fully neutralized (and the corpus grows on any
  new vector — the test file says so). Link never renders before
  probe pass; every failure mode's card matches its fixture. No
  server path read outside the job's allowlisted roots (traversal
  fixtures). Auto-stop leaves no processes (the harness's checks).

## Edge cases & assumption defaults (A9)
- Projects without a runtime: the app card renders not-applicable
  (the smoke feature's honesty). Huge READMEs: rendered with a
  size cap + "open full file" link. Multiple screenshots
  directories: the evidence's designated captures dir is the
  source (coordinate with the screenshot feature's output
  convention when it lands).

## Orchestrator brief
Gate on the channel + harness. The attack corpus is a security
deliverable — its list goes in the order and grows in review. The
probe-before-link rule is verbatim acceptance material.

## Do not touch
Supervisor process semantics, harness probe logic, evidence
layout. Suggested tests: tests/ui_contract/test_artifact_preview.py
+ the sanitizer corpus suite.

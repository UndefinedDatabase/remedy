# T1_F014 — Flight Plan (Plan-Vorschau)
**Tier 1 · Abhängigkeiten: F013, F005 · Blockiert: F015–F018, F034, F064, F069**

## Ziel & Done
Vor Ausführung: Task-DAG, Kosten-/Dauer-Bänder (ehrlich als Schätzung), Risiken,
berührte Pfade, Klärblock. Done: Flight Plan für jeden Job; Start erst nach
Bestätigung (`--yes` überspringt).

## Design
- `packages/orchestration/flight_plan.py`: Modell `FlightPlan{tasks[{id,title,intent,
  allowed_paths[],depends_on[],size,est_cost_band,est_duration_band,risk_notes[]}],
  clarifications[], budgets, stop_conditions, mission_decision}` (Schema F005).
- Schätzbänder aus F074-Kalibrierung sobald vorhanden, v1: statische Klassenbänder,
  Label `estimate_basis:"class_default"` (P6-Ehrlichkeit).
- Persistenz: `jobs/<jid>/flight_plan.json` + Hash; Ausführung validiert gegen Hash
  (user_edited_plan-Vermerk bei F015-Edits).
- UI: `apps/ui/src/components/flightplan/FlightPlan.tsx` — Karte über dem Graph,
  Task-Zeilen mit Größen-Chip (S/M/L/XL), Kosten-Band, Start-Button (F009 `approve_plan`
  … Achtung: approve_plan in Katalog aufnehmen — CONVENTIONS-Update im Task!).
- CLI-Ansicht: kompakte Tabelle (golden.do).

## Task-Schnitt
- T001: Modell + Planner-Prompt + Fixtures.
- T002: Persistenz/Hash + CLI-Render + approve_plan-Command.
- T003: FlightPlan.tsx + SSE `plan.task_created`-Vorschau (Nodes „geplant", H2).

## Akzeptanz & Tests
- Kein Start ohne approved-Plan (außer --yes); Hash-Drift → Abbruch mit Meldung.

## Risiken / Anti-Ziele
- Bänder nie als Punktwerte anzeigen; keine Auto-Approve-Defaults außer --yes.

## Context (existing code & prior features)

## Design
`flight_plan.py`: FlightPlan{tasks[{id,title,intent,allowed_paths,depends_on,size,est_cost_band,est_duration_band,risk_notes}], clarifications[], budgets, stop_conditions, mission_decision} (schema F005). Bands from calibration once F074 exists; v1 uses class defaults labeled estimate_basis=class_default (P6). Persisted as flight_plan.json + hash; execution validates the hash (user_edited_plan noted after edits). CLI renders a compact table; the UI card comes with Tier 5. New catalog command approve_plan.

## Task slicing
T001 model + planner prompt + fixtures. T002 persistence/hash + CLI render + approve_plan. T003 (Tier 5) FlightPlan.tsx + plan.task_created preview nodes.

## Acceptance & tests
No start without an approved plan (except --yes); hash drift aborts with a message.

## Risks / anti-goals

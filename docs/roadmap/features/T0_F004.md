# T0_F004 — Roh-Stream-Archiv (stream-json Evidence)
**Tier 0 · Abhängigkeiten: F003 (Flag-Konventionen) · Blockiert: F021, F023, F140**

## Ziel & Done
Optional `--stream-evidence`: Provider-Calls laufen mit `--output-format stream-json
--verbose`; Roh-JSONL wird per tee gesichert UND geparst. Done: agent_run_trace zeigt
echte Tool-Call-Sequenz statt „reconstructed".

## IST-Bezug
- `agent_run_trace.py` rekonstruiert heute aus Prompts. `prompt_trace.py` existiert.
- Evidence-Ordner je Task vorhanden (`evidence/current/task_runs/Txxx/`).

## Design
Neues Modul `packages/orchestration/stream_evidence.py`:
- Subprozess-Wrapper: stdout → tee nach `task_runs/Txxx/raw_stream.jsonl` + Inline-Parser.
- Parser extrahiert Events: tool_use (name, input-Digest), api_retry, message_delta
  (Token-Deltas), result. Ergebnis: `run_events.jsonl` (normalisiert, Envelope wie
  CONVENTIONS SSE-Typen `run.tool_call` etc.) — dieselbe Quelle speist später F008.
- Größenlimit: raw_stream rotierend (max 50 MB/Task), Digest statt Volltext bei Inputs.

## Task-Schnitt
- T001: Wrapper + Parser + Fixtures (aufgezeichnete Streams).
- T002: Provider-Flag `--stream-evidence` + agent_run_trace speist sich aus run_events.
- T003: Live-Smoke mit echtem Mini-Task; Trace-Vergleich alt/neu.

## Akzeptanz & Tests
- Jeder run_events-Eintrag rückführbar auf raw_stream-Zeile (Offset-Feld).
- api_retry-Events sichtbar; Token-Deltas summieren sich ~ auf F003-Actuals.

## Risiken / Anti-Ziele
- Kein Zwang: Default bleibt json (F003); stream ist Opt-in (Kosten: verbose-Ausgabe).
- Keine Secrets in raw_stream: Redaction-Filter (bestehende redaction_patterns) VOR tee.

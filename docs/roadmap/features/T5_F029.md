## Goal & Done
"Do that part again" becomes safe and cheap: per-task-end snapshots
of the worktree enable reset-to-before-X, rerun_subtree resets a task
and its downstream to planned, prior runs stay in the graph as an
attempt fan, and an optional model override applies to the rerun.
DONE when a rerun from a mid-DAG task restores the exact pre-task
worktree state (hash-proven), the fan renders attempts with their
verdicts, cost preview gates the command (it's the canonical
expensive action), and overrides are evidenced.

## How it fits (a mechanics correction versus an earlier draft)
An earlier sketch said "stash-based" — stashes are fragile,
unaddressable state; the worktree is git, and checkpoints already
record heads per cycle. Corrected mechanics: at every task
finalization the applicator's commit discipline yields an
addressable per-task ref (inspect how task-end commits/refs work
today — if task ends don't commit, adding a lightweight per-task ref
at the finalize seam is the prerequisite order); reset-to-before-X =
checkout of the ref preceding X on the job branch, with uncommitted
drift detected and refused (the checkpoint feature's mismatch
discipline reused verbatim).

## Design (suggested shape)
- Command rerun_subtree {task_id, model_override?}: cost preview
  first (the preview feature's expensive-command wiring — subtree
  size × calibrated bands), then: verify clean worktree vs the
  target ref lineage → reset → X and downstream(X) to planned with
  attempt++ → prior run evidence immutable, linked into the fan →
  optional override recorded as intended-vs-routed (the failover
  disclosure vocabulary reused: reason=human_override).
- The fan: the graph renders attempts per the design reference
  (fan/badge treatment); L2 popovers list attempts with verdicts and
  diffs between attempts.
- Completed-elsewhere safety: tasks NOT in downstream(X) keep their
  state and their commits — the reset only rewinds the subtree's
  file effects; if file effects interleave (a later task touched the
  same files), the reset is refused with the interleaving named
  (honest conservatism over clever surgery; the human can widen the
  rerun scope).
- CLI parity `remedy job rerun-subtree`.

## Task slicing
- **T001** the per-task ref finding/prerequisite + reset mechanics +
  interleaving detection + unit tests (clean reset, drift refusal,
  interleave refusal with names).
- **T002** command + preview gating + attempt fan state + override
  evidence + tests.
- **T003** UI fan + popover attempts + the end-to-end (run → rerun
  mid-task with override → downstream re-executes, hash of the
  pre-task tree equal, fan complete, ledger shows both attempts).

## Acceptance
- Pre-task tree hash equality on reset. Interleaving fixture refused
  with the exact files. Fan renders attempts with verdicts; evidence
  of attempt 1 untouched. Preview shown and threshold respected;
  override in evidence and report.

## Edge cases & assumption defaults (A9)
- Rerun of the first task = rerun of everything (allowed, previewed
  accordingly). Reruns under a mission: the dossier notes the rerun
  (iteration facts). Storage growth from refs: retention follows the
  checkpoint policy (first+latest+N), documented.

# T8_F152 — Worker config isolation
**Tier 8 · Depends on: F151 · Blocks/used by: neutrality of every run; F156 certificate**

## Goal & Done
A worker tool's PERSONAL configuration never contaminates a run:
each adapter declares its isolation method — (a) the tool's own
documented isolation flag/env (preferred), (b) a cleaned env
allowlist plus a throwaway HOME with a neutral minimal config,
(c) the sandbox profile as reinforcement — the call builder logs
the effective method as evidence (worker_isolation {method, home,
env_digest}) per run, `remedy doctor` gains an isolation check,
and a MANDATORY research task per adapter verifies the tool's
current mechanism and pins it in an ADR (tools change flags).
DONE when the reference adapter's isolation is researched,
pinned and enforced with an A/B proof (a poisoned user config
demonstrably not influencing the isolated run), the evidence
field lands on every call, doctor detects a broken isolation
setup, and the per-adapter research duty is encoded as a
conformance-kit requirement (no adapter certifies without its
isolation ADR).

## How it fits (inspect current shape before building)
The sandbox feature built env-scrubbing mechanics for spawned
commands (allowlist, scrubbed environments) — isolation for
WORKER invocations composes it with the throwaway-HOME technique
and, preferably, the tool's own flag (research per tool: many
CLIs honor a config-dir env or a no-user-config flag; the ADR
pins the verified mechanism + version). The A/B proof pattern:
run a canonical fixture prompt twice — once with a deliberately
poisoned user-level config (a marker instruction that would
visibly alter output), once isolated — the marker must not
appear isolated (the proof the certification suite later
re-runs per adapter). Evidence: the invocation seam (where the
loop executes adapter invocations) attaches worker_isolation;
env_digest = a hash of the effective allowlisted env (comparable
without leaking values — the redaction discipline).

## Design (suggested shape)
- Contract: adapter.isolation() → {method: tool_flag | clean_env
  | sandbox_reinforced, details (flag/env names, home strategy),
  adr_ref} — adr_ref REQUIRED (the research duty made
  structural).
- Runtime: the call builder applies the method (throwaway HOME
  under the job's scratch area, created/destroyed per run; the
  allowlist from sandbox's machinery; the tool flag appended per
  the declaration) and records the evidence field.
- doctor: per configured adapter — verify the mechanism still
  works (a cheap probe variant of the A/B where feasible, else a
  static check: flag accepted, HOME strategy writable) with
  actionable failures.
- The A/B proof: a reusable test utility (poison, run, assert
  absence) parameterized per adapter — conformance-kit member.

## Task slicing
- **T001** the contract member + evidence field + throwaway-HOME
  mechanics + unit tests.
- **T002** the reference adapter's research (findings + ADR) +
  enforcement + the A/B proof utility + its passing run.
- **T003** doctor checks + the conformance-kit requirement
  (adapter without adr_ref/failing A/B refuses certification —
  the handshake with F156 stated) + docs.

## Acceptance
- The poisoned-config A/B: marker present un-isolated, absent
  isolated (the reference adapter). Evidence on every call with
  a stable env_digest at equal config. doctor catches a broken
  HOME strategy and a rejected flag (fixtures). adr_ref required
  structurally (validation).

## Edge cases & assumption defaults (A9)
- Tools caching under XDG paths beyond HOME: the research per
  tool enumerates its paths; the throwaway strategy covers the
  documented set with the ADR as the source. Isolation costs
  (cold caches per run): honest — the evidence lets the
  scoreboard show it; per-adapter warm-scratch reuse is a later
  optimization, noted, never at neutrality's expense.

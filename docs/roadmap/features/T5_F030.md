## Goal & Done
The disabled input under the feed comes alive: steer_task delivers a
human note into a per-task steering inbox, injected at the NEXT round
start as a binding operator note in the volatile prompt tail, the
feed shows the user's line (as in ux_design.png: "Please ensure
symlink loops are detected") — and there is no fake chat: the
builder's answer is its next action. DONE when a steering note
demonstrably lands in the following round's prompt trace at the
volatile rank, the feed renders the user line and the builder's
next humanized action as the reply, notes never interrupt in-flight
calls, and unconsumed notes surface honestly at task end.

## How it fits (inspect current shape before building)
Delivery discipline is the prompt-segment registry's volatile tail
(steering was rank 5 from day one — the slot exists, empty until
now); the inbox is a small per-task queue in job state (additive),
consumed at round start in arrival order, each note marked consumed
with the round reference (the trace-proof pattern from runtime
edits). The feed already renders event lines — a steering.sent
event kind (envelope coordination, Part E) carries the user line
into the same stream that shows the builder's subsequent actions;
the design deliberately frames the exchange as note→action, and the
UI copy must not promise conversation (the honest-tooltip era ends,
the honest-framing era begins).

## Design (suggested shape)
- Command steer_task {task_id, text: bounded length}: enqueue +
  audit + the event; notes to non-running tasks are accepted for
  the task's next run (waiting/paused) or refused on terminals with
  the state.
- Injection: round start drains the inbox into ONE operator-note
  segment ("OPERATOR NOTES (binding):" + numbered lines), rank
  steering; the trace grep proves presence; consumed markers +
  round refs in evidence.
- Unconsumed notes at task end (task finished before the next
  round): the task report lists them under "steering not consumed"
  — the human learns their note missed, instead of wondering.
- Feed/NowCard: the user line renders with the user avatar style
  per reference; no synthetic "builder says" reply is ever
  fabricated — the next humanized action IS the response
  (documented in the humanize catalog's framing).
- CLI parity `remedy job steer <id> --task Txxx "text"`.

## Acceptance
- Trace grep exact at the steering rank; in-flight calls never
  interrupted (call-boundary test). Ordering preserved across
  multiple notes; each consumed once. Unconsumed listing renders on
  the fast-finish fixture. No fabricated replies anywhere (copy
  audit + humanize framing test).

## Edge cases & assumption defaults (A9)
- Steering the whole job (no task): v1 targets tasks — the input
  requires a focused task context (the zoom state provides it);
  job-wide direction is the mission/decision layer's business,
  stated in the empty-focus tooltip. Prompt-injection hygiene: the
  note renders inside a clearly delimited operator block; content
  is the operator's responsibility (their job, their authority) —
  documented.

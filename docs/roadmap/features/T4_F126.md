## Goal & Done
Memory becomes visible where work happens: task nodes in the brain
graph carry a small card-count badge (from attached_cards), the L2
popover lists the attached cards with their rank dots, and a click
opens the collection's detail sheet for that card. DONE when the
badge and popover render from run evidence alone (no live selector
calls from the UI), the data contract is a documented part of the
graph node payload, and everything ships UI-ready but dormant until
the Tier 5 graph exists — with the data/contract half testable now.

## How it fits (inspect current shape before building)
attached_cards evidence per task is the single source — the graph's
node payload (defined with the Tier 5 ontology) gains an additive
cards field {count, top: [{id, title, rank}]} populated by the same
backend that builds node payloads from evidence; this feature ships
that payload extension + contract tests NOW (backend half), and the
badge/popover components against fixtures (frontend half), wired
into the real graph when it lands — the split is explicit in the
task slicing so the orchestrator can schedule the halves apart.

## Design (binding specifics)
- Payload contract: cards on task-kind nodes only; count = attached
  total; top = up to 3 by rank for the popover preview; absent when
  zero (payload leanness).
- Badge: a small pill at the node's upper-right per the design
  reference's badge pattern — token colors, JetBrains Mono count,
  never obscuring the state glyph; hidden at L0 zoom (organism view
  stays calm), visible from L1.
- L2 popover section "Memory": rows of title + rank dot
  (bronze/silver/gold/platinum tokens; neutral until the value
  feature), click → the F119 detail sheet via the collection route
  (deep-link contract: /memory?card=<id> — defined here, honored
  there; verify F119's route params and align).
- Evidence-only rule: the UI reads what the run recorded; a
  re-selection would lie about what the worker actually saw.

## Task slicing
- **T001** payload extension + population from evidence + contract
  tests (zero/few/many cards; task-only; leanness).
- **T002** badge + popover-section components against payload
  fixtures (visual conformance per the design checklist; zoom-level
  visibility rules).
- **T003** deep-link alignment with the collection route + the
  dormant-wiring flag + an integration test on the fixture graph
  payload end to end (badge → popover → sheet link resolves).

## Acceptance
- Contract tests green independent of any UI; fixtures render the
  badge/popover per design (token-only colors guard); L0 hides, L1+
  shows. Deep links resolve on the collection side (cross-feature
  contract test). No selector/live-store calls from graph rendering
  (import guard on the component).

## Edge cases & assumption defaults (A9)
- Tasks re-run with different attachments: the payload reflects the
  LATEST run's evidence with the run id in a tooltip (truth has a
  timestamp). Archived cards in old evidence: the sheet link renders
  the archived state — history stays inspectable.

## Orchestrator brief

## Do not touch

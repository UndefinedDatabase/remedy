## Goal & Done
An order in everyday words, with no header and no file path, is sent over the public HTTP API by
a client granted `host_tools`, planned with claude-cli, built as ONE job, tested by its builder,
accepted by its reviewer and taken over with `remedy apply` (`remedy job apply`); the complete
evidence lies under `evidence/`. No `manual_operator_repair`: the evidence shows real provider
calls.

## Why this exists
The six features closed before it (F315, F314, F157, F152, F162, F158) never touched this goal:
the default planner, builder and reviewer were the local model, the planner ignored the project's
`[roles]` table, an order without a file path became up to twelve milestones by regular
expressions, the claude-cli builder could not run a command, the worker's environment allowlist
was never run against the real `claude` program, and a dollar calculation the operator had
rejected was added.

## What it rests on (operator amendment amend1024-one-real-order)
- Part A: claude-cli is the product default for the planner, the builder, the reviewer and repair;
  the planner reads `[roles]`; a `host_tools` client's order runs on that default over HTTP.
- Part B: the planner's scope decision makes an order one job unless it gives a reason for
  several (`packages/orchestration/scope_decision.py`).
- Part C: the claude-cli builder may run the project's tests and a fixed list of reading commands.
- Part D: the isolation allowlist, checked against the real program.
- Part E: tokens and calls, not dollars, by default.

# T8_F162 — Sandbox profiles per adapter
**Tier 8 · Depends on: F085, F151 · Blocks/used by: F173, F174, F238/F246 sandboxes**

## Goal & Done
See ROADMAP.md F162; the Done criterion there is binding.

## Context (existing code & prior features)
F085 hardens globally (stage 1); per-adapter profiles are missing.

## Design
packages/workers/sandbox_profiles.py + profiles/<name>.toml (fs_scope, net deny|allowlist, ulimits, allowed_binaries, tmp_quota). Each adapter declares a default profile; a project may TIGHTEN, never loosen below the policy minimum (F172). Stage 2 per adapter: a container runner (podman/docker) consuming the same profile format - selection per config, trade-offs in an ADR. Honesty doc docs/system/sandbox-model.md: a table of what each profile does and does NOT prevent, every row linked to a test.

## Task slicing
T001 profile format + stage-1 application + escape fixtures per rule kind. T002 the container stage for one adapter + the honesty table + a certificate note (F156 gains profile_used).

## Acceptance & tests
Every doc row has a green test (coupling enforced); a profile violation is an infra fail (F010) with a clear message; the certificate names the profile.

## Risks / anti-goals
No security claim without a test (P6); docker stays optional (stage 1 must be documented as self-sufficient).

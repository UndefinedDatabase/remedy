# T8_F162 — Sandbox profiles per adapter
**Tier 8 · Depends on: F085, F151 · Blocks/used by: F173, F174, F238/F246 sandboxes**

## Goal & Done
What a worker process MAY touch becomes a named, testable profile:
sandbox_profiles.py plus profiles/<name>.toml declare fs_scope,
network (deny | allowlist), ulimits, allowed binaries and a tmp
quota; each adapter declares its default profile; projects may
TIGHTEN but never loosen below the policy minimum; stage 2 adds a
container runner (podman/docker) consuming the SAME profile format;
and an honesty document — docs/system/sandbox-model.md — tables
what each profile does and does NOT prevent, every row linked to a
test. DONE when profiles enforce their declared limits on fixture
processes (per-dimension tests), the tighten-only rule refuses
loosening with the pack minimum named, adapters carry their default
with the effective profile in run evidence, the container runner is
an optional-dependency stage behind config with its trade-offs in
an ADR, and the honesty doc's every row resolves to a green test.

## How it fits (inspect current shape before building)
The exec-guard/env-scrubbing layer (F085) is the enforcement seed —
profiles are its DECLARATIVE face: fs_scope maps to the path rules
the guard already applies, net deny to the no-network posture,
binaries to the allowlist; ulimits and tmp quotas are new
enforcement (resource limits on spawned processes — the stdlib
mechanics per platform, honesty where a platform can't enforce a
dimension: the profile record says enforced|unenforced per
dimension per platform, and the honesty doc carries it). Stage 2's
container runner is OPTIONAL (podman/docker detected, never a base
dependency — the extras stance); same profile TOML compiles to
container flags; selection per config with the ADR documenting the
isolation-strength trade-offs.

## Design (suggested shape)
- Profile TOML: {fs_scope: [paths], net: deny | {allow: [hosts]},
  ulimits: {cpu_s?, mem_mb?, nofile?}, allowed_binaries: [],
  tmp_quota_mb} + a built-in set (strict, standard, net-local);
  validation + the tighten-only comparator (a partial order over
  profiles — documented per dimension, table-tested).
- Runtime: the invocation seam applies the resolved profile
  (adapter default ∩ project tightening); evidence
  worker_sandbox {profile, dimensions {enforced|unenforced},
  runner: process|container}.
- The container stage: profile → runner flags (mounts from
  fs_scope, network mode, limits); availability-gated; the ADR
  (process-level vs container trade-offs) is a deliverable.
- The honesty doc: generated skeleton from the profile set (rows =
  profile × dimension × prevents/does-not) with test links — the
  docs test walks rows to test ids (the F043 audit pattern).

## Task slicing
- **T001** profile schema + built-ins + the partial-order
  comparator + tighten-only refusals + table tests.
- **T002** process-level enforcement per dimension + platform
  honesty records + fixture processes proving each limit (a
  net-deny process failing egress; an fs violation blocked; a
  ulimit hit).
- **T003** evidence + adapter defaults + the container stage
  (optional, flags mapping, ADR) + the honesty doc generation +
  the row→test walk + the end-to-end.

## Acceptance
- Each dimension's fixture enforced or honestly marked
  unenforced per platform. Loosening refused naming the minimum.
  Evidence complete per run. Container stage inert without the
  runtime, equivalent limits with it (shared fixtures both
  runners). Honesty-doc rows all resolve to green tests (the
  walk).

## Edge cases & assumption defaults (A9)
- Adapters needing network (API-based): their default is a
  net-allowlist profile naming their endpoints — deny-by-default
  applies to everything else (the air-gap feature leans on
  exactly this). Windows: the platform-honesty record carries
  the truth per dimension; unenforced dimensions warn in doctor.

## Orchestrator brief
Gate on F085 + the contract. T001's partial order is the policy
math — table tests verbatim. The honesty doc with test links is
the feature's soul; its generation ships with T003, reviewed
like customer docs.

## Do not touch
Exec-guard internals (extended, not forked), isolation HOME
mechanics, air-gap policy (consumer). Suggested tests:
tests/workers/test_sandbox_profiles.py.

# T2_F262 — List commands v2 (dates, sort, filter)

> Registered 2026-08-31 by operator order amend0831-vocab-registrations.
> REGISTRATION ONLY — nothing in this file has been implemented.

## Goal & Done
Every list command — `job list`, the `do` run listings, `queue list`,
`mission list`, `memory list`, `event list` and the rest — shows a CREATED and
an UPDATED date, and supports the SAME flags with the SAME spelling:

    --sort <field> [--desc]   --since <when>   --until <when>   --limit <n>

Default ordering is NEWEST FIRST, everywhere, without a flag.

DONE when a specific run from the day before yesterday is findable by command in
under ten seconds, and every list uses the same words for the same flags.

## Why this exists
The lists are the only way to find anything Remedy has done, and today they are
each their own dialect: some carry a date, some do not; some have a limit flag,
some do not; the default order is whatever the underlying store happens to
return. The operator's actual failure case is mundane and repeats daily — "the
run from the day before yesterday, the one that was about X" — and it currently
costs a directory listing and a guess. This is a usability feature with a
measurable acceptance test, not a polish round.

## Design
- ONE shared listing-option surface, defined once and attached to every list
  command, so the flags cannot drift apart again. A new list command gets the
  flags by construction, not by remembering.
- `--sort <field>` validates the field against that list's own columns and
  fails with the valid set named, never silently ignoring an unknown field.
- `--since`/`--until` accept both an absolute date and a relative form
  (`2d`, `12h`); the accepted grammar is written down in the help text of the
  shared surface, in one place.
- Dates are rendered in the text UI in a form a human reads, and in `--json`
  as ISO-8601 with a timezone. A probe reads the TEXT-UI value, never the
  internal one.
- Newest-first is the DEFAULT, not a flag. A list whose store cannot order
  says so rather than presenting arbitrary order as recency.

## T001 — The shared option surface
Define the flags once, wire them into the argument layer, and pin by a test
over the command catalog that EVERY list command carries all four — the test
derives the list-command set from the catalog, never from a hand-written list.

## T002 — Dates on every row
Created and updated timestamps surfaced from each store. Where a store does not
record one today, recording it is part of this slice; inventing one is not —
an unknown date renders as unknown.

## T003 — Sort, filter, limit
The behaviour behind the flags, plus the newest-first default.

## Acceptance
- The ten-second demo: find a named run from two days ago with one command.
- The catalog test proves no list command is missing a flag.
- `--sort` with an unknown field exits non-zero and names the valid fields.
- A list whose rows have no recorded date says so instead of ordering randomly.

## Do not touch
The stores' own schemas beyond adding a missing timestamp, and the `--json`
contract's existing keys — this feature ADDS keys, it does not rename them.

## Orchestrator brief
T001 first: the shared surface is what stops this feature from becoming eight
separate small features. T002 is the widest slice and the one that touches the
most stores — plan its commit split before starting. T003 depends on both.

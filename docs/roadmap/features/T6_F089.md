**Tier 6 · Depends on: F087, F005, F076 · Blocks/used by: plan quality, F096**

## Goal & Done
The reference stops being an undifferentiated picture: a vision call
decomposes each reference into design_spec.json — layout grid,
regions with bounding boxes and purposes, token candidates (colors,
fonts, radii, shadows), components with states — feeding plan tasks
their region hints and the token-extraction feature its input; on
any conflict between spec and screenshot, the screenshot wins (A9).
DONE when fixture references decompose into schema-valid specs whose
region boxes visually match (human-reviewable overlay artifact),
plans on design jobs carry region hints from it, the
screenshot-wins rule is documented AND encoded (downstream
comparisons key on pixels), and non-vision configurations degrade
honestly.

## How it fits (inspect current shape before building)
One more structured-output pipeline: the schema lives with the
others (versioned design_spec_v1), the call routes vision-capable
(the planner-vision plumbing reused — same capability gate, same
degradation: no vision anywhere → no decomposition, the tier's
features that require it say "decomposition unavailable" rather
than faking one). The spec is per-reference (R-number keyed into
the addressing table's evidence area); the overlay artifact
(regions drawn onto a copy of the reference) is generated
deterministically from the spec for human review — trust through
inspectability.

## Design (suggested shape)
- Schema design_spec_v1: {r_ref, layout_grid {columns?, gutters?},
  regions: [{name, bbox [x,y,w,h] normalized 0..1, purpose}],
  tokens: {colors: [{hex, role_hint}], fonts: [{family_hint,
  usage}], radii: [], shadows: []}, components: [{name, region,
  states: []}]} — bbox normalization documented (resolution
  independence); validators: boxes within bounds, names unique.
- The call: reference image + the scope note + the schema string;
  parse-retry standard; spec stored beside the reference; the
  overlay PNG rendered from spec (a pure drawing pass).
- Plan feeding: UI tasks' design_refs gain region hints (task ↔
  region mapping proposed by the planner from purposes) — the
  builder prompt's style block grows the task's regions (the
  staged content from F088 lands).
- Token candidates flow to F096 (candidates, not truth — that
  feature reconciles); the screenshot-wins rule: comparisons and
  reviews (F091/F092) measure against PIXELS; the spec is an
  index into the image, never a replacement (write this into the
  schema docstring — the tier's epistemology).

## Task slicing
- **T001** schema + validators + the overlay renderer + unit tests
  (bounds, normalization, overlay golden on a synthetic spec).
- **T002** the vision call + storage + degradation + fake-vision
  tests (valid, retry, unavailable).
- **T003** plan feeding (region hints on tasks, style-block growth)
  + the end-to-end (fixture reference → spec → overlay → plan
  tasks with hints → builder prompt contains its regions).

## Acceptance
- Fixture specs schema-valid with in-bounds boxes; overlays render
  (goldens on synthetic; human-review artifacts on real fixtures).
  Plans carry hints traceable to regions. Degradation honest.
  The screenshot-wins docstring present and quoted by downstream
  features (grep).

## Edge cases & assumption defaults (A9)
- Dense designs (many regions): a region cap with the largest/
  purposeful kept and the rest summarized (the model is guided;
  the validator enforces the cap). Multiple references: one spec
  each; cross-reference layout claims are out of scope v1.

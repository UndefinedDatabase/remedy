# T4_F145 — Playbook distillation
**Tier 4 · Depends on: F073, F118 mechanics · Blocks/used by: order-level learning**

## Goal & Done
Remedy learns at the ORDER level, not just the fact level: after
enough similar orders (same task class + a keyword/shape heuristic),
a distillation pass drafts a playbook PROPOSAL — the proven slicing,
the typical traps, the reference cards — and matched playbooks reach
the planner prompt as a dedicated block whose efficacy is measured
with the memory-KPI pattern. DONE when the similarity grouping finds
seeded order families without false merges, distillation drafts cite
only evidence from the family's runs, planner prompts include
matched playbooks with attachment recorded, and the KPI view gains
the playbook dimension.

## How it fits (inspect current shape before building)
Playbooks (store, format, gate) exist from the failure-miner
feature — distillation is a second PRODUCER into the same store and
gate (kind playbook through the idea queue; one store, one approval
path). Order similarity: job intake goals + plan shapes are the
material — the grouping heuristic is deterministic (class equality
+ normalized keyword overlap above a threshold + comparable plan
shape: task count band, dependency shape) with the thresholds
table-tested; an LLM never decides membership (auditability). The
planner-prompt block follows the card segment's discipline (stable
slot, budget, whole-units, evidence of what attached) — reuse the
selection mechanics' shape for a much simpler matcher (playbooks
match by the same class+keyword signature they were distilled
from).

## Design (suggested shape)
- `playbook_distiller.py`: scan completed jobs in the window →
  group by the signature → families with ≥3 members and a healthy
  majority (config: e.g. ≥2 green) → draft: proven slicing (the
  family's common plan skeleton, generalized deterministically —
  shared task titles/order), typical traps (the family's postmortem
  classes + healed-repair patterns, cited per run), reference cards
  (cards attached across ≥2 members), each section evidence-referenced
  → proposal via the queue; approval materializes
  `.remedy/playbooks/<signature>.md` with frontmatter (signature,
  members, distilled_at).
- Matching at plan time: an incoming order whose signature matches
  an approved playbook → the playbook block (capped tokens, whole
  playbook or nothing) into the planner segment slot; evidence
  attached_playbooks.
- Efficacy: ledger rows carry attached_playbooks (the KPI ledger
  pattern, additive); the memory-KPI view gains the dimension with
  the same honesty headers.

## Task slicing
- **T001** the signature + grouping heuristic + table tests (seeded
  families found; near-miss families NOT merged; thresholds
  boundary-tested).
- **T002** deterministic draft assembly + evidence citations +
  goldens (drafts contain nothing uncited).
- **T003** proposal/approval flow + plan-time matching + segment +
  evidence + the KPI dimension + the end-to-end (three similar
  fixture orders → proposal → approve → the fourth order's plan
  prompt contains the block, recorded).

## Acceptance
- Grouping goldens exact both directions (found and not-merged).
  Draft citation completeness (a grep proves every claim carries a
  ref). Matching attaches whole-or-nothing within its cap; evidence
  and ledger rows carry it; the KPI view renders the dimension with
  headers. No unapproved playbook ever reaches a prompt.

## Edge cases & assumption defaults (A9)
- Families evolving (the codebase changed since distillation):
  playbooks are cards' cousins — the hygiene liveness pass extends
  to playbook refs (small addition noted there, wired here).
  Signature collisions across projects stay per-project (as with
  the miner).

## Orchestrator brief
Gate on the miner's store + the KPI ledger pattern. T001's
determinism (no LLM membership) is the audit line — verbatim.
T002's nothing-uncited grep is the honesty line — verbatim.

# T3_F114 — Cost preview per command
**Tier 3 · Depends on: F103 · Enhanced by: F074 calibration (class-default bands, honestly labeled, until then) · Blocks/used by: UI honesty about expensive actions**

## Goal & Done
Expensive actions stop starting silently: commands that will spend real
money (rerunning subtrees, long explanations, mission runs) show an
upfront estimate band with its basis and require confirmation above a
configured threshold — in attended mode; unattended runs rely on
budgets, not prompts (never violate the no-interactive rule). DONE when
a fixture expensive command shows the band, respects the threshold,
`--yes`/unattended paths skip the prompt while budgets still guard, and
every shown number carries its basis label.

## How it fits (inspect current shape before building)
Estimation reuses the predictive-budget arithmetic (class defaults ×
price basis — one estimator, two consumers; extract it if the budget
feature inlined it). The interactive-input guard forbids prompting in
the execution packages — so confirmation lives in the CLI layer ONLY,
implemented with the CLI's existing confirmation pattern if one exists
(inventory first), and the guard's allowlist stays empty (the CLI
package is outside the guarded packages — verify that boundary and
document it).

## Design (suggested shape)
- A small `cost_preview.py`: estimate(command_context) → {band_usd_low,
  band_usd_high, basis, inputs} from task classes/counts involved.
- CLI decorator/helper for expensive commands: render "estimated
  $X–$Y (basis: class defaults)" + confirm when estimate high-end >
  confirm_above_usd (config, default around half a dollar); `--yes`
  skips with an audited line in evidence; non-tty stdin counts as
  unattended → no prompt, proceed only if under threshold OR --yes,
  else exit with the estimate and the flag hint (never hang waiting on
  a pipe).
- The command registry marks which commands are expensive (explicit
  list, reviewable) — creeping prompts on cheap commands are a UX bug.
- Preview never blocks on estimation failure: unknown classes →
  "estimate unavailable" + confirm above threshold by rule (unknown is
  treated as expensive).

## Task slicing
- **T001** the shared estimator extraction (if needed) + band
  computation + basis labels + unit tests.
- **T002** the CLI helper + threshold + tty/non-tty semantics + tests
  (pipe never hangs; --yes audited).
- **T003** marking the expensive commands + goldens for their preview
  lines + docs.

## Acceptance
- Fixture expensive command: band shown with basis; above threshold
  prompts on a tty, exits-with-hint on a pipe, proceeds audited with
  --yes. Cheap commands never prompt (regression loop over the
  registry). Estimator failure → unavailable + conservative confirm.

## Edge cases & assumption defaults (A9)
- Estimates are bands, never points, and the basis label is mandatory
  wherever a number renders (grep-style test). Currency is USD-labeled;
  no conversion guessing.

## Orchestrator brief

## Do not touch
The interactive guard's package boundary, budget enforcement,
calibration. Suggested tests: tests/cli/test_cost_preview.py.

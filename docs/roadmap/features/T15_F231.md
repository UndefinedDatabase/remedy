# T15_F231 — Playbooks v2 with value ranking
**Tier 15 · Depends on: F145, F150, F123 · Blocks/used by: knowledge compounding**

## Goal & Done
See ROADMAP.md F231; the Done criterion there is binding.

## Context (existing code & prior features)
F145 distills playbooks; the F150 value mechanics exist for cards - the transfer is missing.

## Design
Playbook frontmatter gains the F150 fields (value/uses/wins, the same update rules: a use = the playbook segment in the prompt + the task outcome as the signal; the same exploration quota for new playbooks). Intake/planner: on a pattern match (the F145 heuristic) the best-ranked playbook is ACTIVELY proposed in the job plan ('playbook api-endpoint v3, gold, 12 uses - apply?'); application = a segment (F105-stable). Measurement rides the F123 mechanics with playbook_id analogous to attached_cards.

## Task slicing
T001 frontmatter + signal coupling (ONE shared value updater with F150 - a refactor to shared) + tests. T002 the job-plan proposal + the segment + the F123 extension + a fixture (playbook value rises only through uses).

## Acceptance & tests
Property: value changes only via signals (the shared code path with F150 is tested); the proposal appears only on a match; a rejection memory (the F064 dedupe pattern) prevents nagging.

## Risks / anti-goals
One value updater for cards + playbooks (no twin logic); playbook contents stay human-approved (the F145 rule).

## Context (existing code & prior features)

## Design
Full keyboard coverage of the core flows: the inbox (j/k navigate; a/r approve/reject WITH a confirmation overlay that shows the evidence triple - no blind approve by keystroke), the diff (n/p hunks, x toggles a hunk approval (F033), ]f/[f files), the graph (F044 plus g+digit for zoom levels), a global '?' overlay generated from the shortcut registry - ONE source, and the registry maps exclusively onto catalog commands/navigation actions so the audit stays intact via F009. A vim scheme as an alternative registry ([ui] keymap=default|vim).

## Task slicing
T001 the shortcut registry + the '?' overlay + catalog coupling + an audit test (a keyboard approve appears in the audit identically to a click). T002 the inbox/diff flows + the confirmation overlay + the vim registry + playwright (a complete approve flow without a mouse).

## Acceptance & tests
The mouseless E2E flow passes; no shortcut exists outside the registry (an event-handler audit script); 'a' on a decision ALWAYS shows the triple overlay before taking effect (test).

## Risks / anti-goals
No ghost actions outside the catalog; no shortcuts on destructive actions without an overlay (stop/veto included).

# T3_F116 — Cost anomaly alarm
**Tier 3 · Depends on: F103 · Enhanced by: F074 class expectations (config defaults until then) · Blocks/used by: protection in unattended operation**

## Goal & Done
A runaway between checkpoints can no longer burn quietly: a burn-rate
detector watches spend velocity per job against expectations, and an
outlier raises a warning event and — on unattended runs — a pause
decision; optionally it throttles parallel width. DONE when a fixture
burn spike trips the detector with the numbers in the decision, normal
expensive-but-expected work does not trip it, and the detector shares
its definition of "expected" with the watchdog story (one home per
rule).

## How it fits (inspect current shape before building)
The ledger provides timestamped per-call costs — the detector is a
sliding-window query, evaluated at the same cadence as other run-level
checks (call finalization / batch boundaries), not a background thread.
The autonomy watchdog already owns a SELF-RELATIVE burn tripwire for
missions; this feature owns the CLASS-EXPECTATION check for jobs and,
per that feature's note, UNIFIES the two: the watchdog's burn tripwire
becomes a consumer of this detector — remove the duplicate there as
part of this feature (one detector, two callers). Notifications attach
when the notification feature lands; until then surfacing is decision +
status + report.

## Design (suggested shape)
- `burn_detector.py`: evaluate(job|mission, window) → {rate_usd_h,
  expected_basis (class_default|trailing_baseline), multiplier,
  tripped} — expectation = class expectation where bands exist, else
  the run's own trailing baseline; trip when rate exceeds expectation
  by a config multiplier with a minimum-spend floor (tiny absolute
  numbers never trip — noise discipline).
- On trip (attended): a prominent warning in status/report + a ledger
  event. On trip (unattended/--yes): additionally a pause decision with
  the arithmetic (window, rate, expectation, basis) and options
  resume|abandon; optional parallel-width throttle to a config floor
  while the decision is open.
- Dedup: one open trip decision per run; re-trips update its evidence.
- Unification: replace the watchdog's internal burn check with a call
  into this detector (its tests keep passing — the behavior contract
  stays).

## Task slicing
- **T001** detector + window math + floors/multipliers + table tests
  (spike trips; expected-expensive doesn't; tiny-spend never).
- **T002** trip actions per mode + dedup + throttle hook + fixture
  runs (attended warn; unattended pause with arithmetic).
- **T003** watchdog unification (one detector) + its regression suite
  green + docs.

## Acceptance
- Spike fixture trips with correct arithmetic in the decision; the
  steady-expensive fixture doesn't. Unattended trip pauses before the
  next dispatch. Watchdog burn tests pass against the unified
  detector. All rates/expectations carry basis labels.

## Edge cases & assumption defaults (A9)
- Bursty-but-legit patterns (many tiny calls at batch start): window
  minimum spans a full batch — documented. Clock skew: all timestamps
  UTC from the ledger; no wall-clock reads in the math.

## Orchestrator brief
Gate on the ledger and the watchdog. T003's unification is the
architectural point — require the watchdog diff to DELETE its private
check, not wrap it.

## Do not touch
Notification channels, budget limits (separate mechanism), calibration.
Suggested tests: tests/orchestration/test_burn_detector.py.

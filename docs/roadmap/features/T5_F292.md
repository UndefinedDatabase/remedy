## Goal & Done
The cockpit can do the seven writes the write door already accepts but no screen offers: the six
edits of a plan that waits for approval (DECISION F015 D3) and the approval or rejection of a
change's hunks (F033). DONE when a plan view shows the stored plan with its version, its approval
state and, for each planned task, its dependencies and acceptance criteria, and offers each of the
six edits against the version it shows, with a version conflict told in plain words; when the diff
view lets a person approve a hunk or reject it with a reason; and when the command palette's seven
form entries open these surfaces instead of standing disabled.

## Why this exists
F015 left its edits to "the plan view, a later feature", and no feature was registered for it. F033
left hunk decisions to the command line. F044 made every write the door accepts reachable from the
palette, and measured at `5cbbe6c8` what these seven need: the browser can read no plan version, no
approval state and no dependency of a planned task, because no read route serves them, so a plan
edit cannot name the version it was made against; and although the diff envelope already carries
each hunk's id and its task run, no screen shows hunk controls. A palette is the wrong place to
merge, split or reorder planned tasks, so the palette opens these surfaces rather than holding them.

## Task slicing
- T001 — the plan read: one builder in `packages/orchestration/plan_editing.py` shared by
  `remedy job plan-show --json` and a dashboard section, serving the version, the approval, whether
  the plan is open for editing and why not, and each planned task with its entry id, dependencies
  and acceptance; the plan view that renders it.
- T002 — the six edits in the plan view, each sent with the version shown, a version conflict and a
  refused edit told in plain words, and the view read again after each accepted edit.
- T003 — hunk controls in the diff view: approve, reject with a reason, the job's own scope sent
  without a task run; the palette's seven form entries become surface entries opening these views;
  an end-to-end run.

## Acceptance
- The plan view's version, approval and tasks equal `remedy job plan-show --json` for the same job.
- Each of the six edits reaches the door with the version shown and is refused with a plain reason
  when the plan moved on.
- A hunk approved or rejected in the diff view lands in the hunk decision record exactly as
  `remedy patch approve-hunks` would record it.
- The palette lists no form entry disabled.

## Do not touch
The write door's argument checks and refusal codes; the plan's own validation; the diff view's
reading of the envelope.

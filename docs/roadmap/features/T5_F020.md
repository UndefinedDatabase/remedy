## Goal & Done
Every node tells its truth at a glance: one glyph per kind, one
visual state language, rendered from a single Path2D source that
the legend reuses as SVG — so the graph and its legend can never
drift apart. DONE when every kind×state combination renders per
the binding spec below, the legend is generated from the same
paths, state transitions animate per the motion tokens, and a
conformance fixture walks the full matrix against reference
renders.

## How it fits (binding visual spec, restated)
glyphPaths.ts: Path2D per kind — job_core gradient sphere with the
'</>' mark (assets_spec §4), task circle, builder_run a drawn '</>'
path, review_run head-and-shoulders, test_run flask, repair_run
'</>' + ring, artifact doc-with-folded-corner, synapse dot, cluster
circle+count. States via token colors: open #a78bfa, planned pale +
90% size, in_progress #4c83ff pulse 1.6 s, pass #34c27e, fail
#ef6363 + status dot, vetoed gray + strike. The legend popover
renders THE SAME paths as SVG (single source; on any conflict,
graph_spec.md §5 + assets_spec.md §4 win over this prose). Blocked
(the ontology's remaining state) follows graph_spec §5's blocked
treatment — the builder reads it there, not from memory.

## Design (suggested shape around the binding spec)
- `glyphPaths.ts`: kind → {path2d factory, bounds, svg path string}
  — ONE geometry definition consumed by canvas (nodeCanvasObject)
  and legend SVG alike; unit-testable via the svg strings.
- `nodeStates.ts`: state → {color token, size factor, decorations
  (dot/ring/strike), animation (pulse timing)} — token references
  only (the raw hexes above are the TOKEN VALUES per the design
  reference; components reference tokens; the guard test enforces
  it).
- Transition motion: state changes tween per motion tokens (color
  cross-fade, the pass "settle" and fail "shake-subtle" if
  graph_spec defines them — follow it); in_progress pulse runs on
  the render loop with visibility-aware pausing (background tabs
  don't spin CPU).
- The legend popover: kinds and states enumerated from the same
  modules (no hand-written legend rows), rendering svg paths +
  token swatches; opened from the graph chrome per the design
  reference.
- Conformance fixture: a story-grid rendering of the full matrix
  (kinds × states) for visual review + pixel-region assertions on
  the discriminating details (the dot, the ring, the strike).

## Task slicing
- **T001** glyphPaths + nodeStates as pure modules + svg-string
  unit tests + the token guard.
- **T002** canvas integration (replacing T5_F019's slots) + legend
  generation from the same source + the matrix fixture.
- **T003** transition/pulse motion + visibility pausing + the
  conformance assertions + a live fixture pass (states change on a
  streamed fake job and animate correctly).

## Acceptance
- Matrix fixture matches references (regions asserted); legend
  enumerates from source (delete a kind in the module → legend
  loses it — the anti-drift test). Pulse pauses when hidden (a
  visibility test). Token guard green. graph_spec/assets_spec
  precedence documented in the module headers verbatim.

## Edge cases & assumption defaults (A9)
- Tiny zoom levels: glyphs degrade to state-colored dots below a
  size threshold (graph_spec's rule — follow it) so truth survives
  distance. Color-vision accessibility: the decorations (dot,
  ring, strike, shapes) carry state redundantly to color — state
  is never color-alone (assert on the fail/vetoed cases).

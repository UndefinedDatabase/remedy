## Goal & Done
Every node tells its truth at a glance: one glyph per kind, one
visual state language, rendered from a single Path2D source that
the legend reuses as SVG — so the graph and its legend can never
drift apart. DONE when every kind×state combination renders per
the binding spec below, the legend is generated from the same
paths, state transitions animate per the motion tokens, and a
conformance fixture walks the full matrix against reference
renders.

## How it fits (binding visual spec, restated)
glyphPaths.ts: Path2D per kind — job_core gradient sphere with the
'</>' mark (assets_spec §4), task circle, builder_run a drawn '</>'
path, review_run head-and-shoulders, test_run flask, repair_run
'</>' + ring, artifact doc-with-folded-corner, synapse dot, cluster
circle+count. States via token colors: open #a78bfa, planned pale +
90% size, in_progress #4c83ff pulse 1.6 s, pass #34c27e, fail
#ef6363 + status dot, vetoed gray + strike. The legend popover
renders THE SAME paths as SVG (single source; on any conflict,
graph_spec.md §5 + assets_spec.md §4 win over this prose). Blocked
(the ontology's remaining state) follows graph_spec §5's blocked
treatment — the builder reads it there, not from memory.

## Design (suggested shape around the binding spec)
- `glyphPaths.ts`: kind → {path2d factory, bounds, svg path string}
  — ONE geometry definition consumed by canvas (nodeCanvasObject)
  and legend SVG alike; unit-testable via the svg strings.
- `nodeStates.ts`: state → {color token, size factor, decorations
  (dot/ring/strike), animation (pulse timing)} — token references
  only (the raw hexes above are the TOKEN VALUES per the design
  reference; components reference tokens; the guard test enforces
  it).
- Transition motion: state changes tween per motion tokens (color
  cross-fade, the pass "settle" and fail "shake-subtle" if
  graph_spec defines them — follow it); in_progress pulse runs on
  the render loop with visibility-aware pausing (background tabs
  don't spin CPU).
- The legend popover: kinds and states enumerated from the same
  modules (no hand-written legend rows), rendering svg paths +
  token swatches; opened from the graph chrome per the design
  reference.
- Conformance fixture: a story-grid rendering of the full matrix
  (kinds × states) for visual review + pixel-region assertions on
  the discriminating details (the dot, the ring, the strike).

## Acceptance
- Matrix fixture matches references (regions asserted); legend
  enumerates from source (delete a kind in the module → legend
  loses it — the anti-drift test). Pulse pauses when hidden (a
  visibility test). Token guard green. graph_spec/assets_spec
  precedence documented in the module headers verbatim.

## Edge cases & assumption defaults (A9)
- Tiny zoom levels: glyphs degrade to state-colored dots below a
  size threshold (graph_spec's rule — follow it) so truth survives
  distance. Color-vision accessibility: the decorations (dot,
  ring, strike, shapes) carry state redundantly to color — state
  is never color-alone (assert on the fail/vetoed cases).

## Built State (F020, 2026-09-25)

What exists on disk at the close of F020, built in five rounds in one session on
`feature/f020-node-lifecycle-glyph-language`, cut from `main` at `955a6240`. Every DECISION named
lives in `.agent/decisions.md`; every round's verdict in `.agent/live_review.md` or, once rotated,
its archive.

**T001 — one glyph source and one state language.** `apps/ui/src/components/graph/renderers/`
holds the path `assets_spec.md` §4 names. `glyphPaths.ts` stores every node kind's glyph once, as a
stroke string and a fill string of SVG path data in a 24-unit box, with the status dot, the strike
and the ring as state marks in the same form; the canvas builds its Path2D from those strings, cached
per glyph, and run glyphs show from the L1 zoom, 1.6, up. `nodeStates.ts` gives every node state a
treatment naming tokens only: its fill, its glyph ink and body lines, its halo, its size factor, its
marks, its pulse, the glow it asks of its branch, and the dimming below a veto (DECISION F020 D1).
Both headers quote `assets_spec.md` §4's precedence rule verbatim. The veto's grey is the new token
`--remedy-state-vetoed`, and the app sheet carries `--remedy-graph-node-ring`.

**T002 — the canvas, the legend and the matrix.** `palette.ts` resolves every token the painter
reads once per mount, and names a missing one on the canvas container instead of guessing a colour;
`paintNode.ts` paints every non-core node from the two modules and nothing else, and
`ForceBrainGraph.tsx` routes every non-core kind to it, holding no state colour of its own
(DECISION F020 D2). A cluster carries its count as `+n` from the layout's label. `legendModel.ts`
enumerates the legend's rows from the two modules, and `GraphLegend.tsx`, a "Legend" button beside
the view toggle, renders them as SVG through `var()` of the same tokens. `glyphMatrix.ts` is the
kind-by-state matrix fixture, every non-core kind in every state painted by the live painter
(DECISION F020 D3).

**T003 — motion, visibility and conformance.** `stateMotion.ts` crossfades every state change of a
non-core node over 300 ms and ripples a change into `pass`, and schedules nothing under reduced
motion; the pulse is ±8% over `--remedy-dur-pulse`; and `brainNeedsAnimationFrames` asks for no
frame on a hidden page, which `usePageVisible.ts` follows, while the edge particles stop with the
page too (DECISION F020 D4). `glyphConformance.ts` places a pixel probe on every discriminating
detail of every matrix cell and on every place the dot and the strike must not be, judged against
the binding spec written out beside it, and the harness `.agent/authored/f020-r5-conformance_*`
reads those pixels in headless Chrome (DECISION F020 D5).

**Acceptance, by the test that proves it.** Matrix fixture matches references, regions asserted:
the harness transcript `.agent/authored/f020-r5-conformance.txt` reads 144 of 144 probes passing,
and `.agent/authored/f020-r5-harness_redproof.py` turns it red four ways; its CI home is F044's

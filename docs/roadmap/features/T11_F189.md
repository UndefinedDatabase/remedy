# T11_F189 — Service contract tests
**Tier 11 · Depends on: F061, F007 (single-service runtime) · Enhanced by: F190 compose environments for multi-service targets · Blocks/used by: API jobs made robust; F207 safety**

## Goal & Done
See ROADMAP.md F189; the Done criterion there is binding.

## Context (existing code & prior features)
F061 runs custom commands; OpenAPI handling does not exist.

## Design
DoD kind contract: (a) schema conformance via a budgeted schemathesis sample (n cases, seed-pinned) against the running instance (an F190 environment), (b) consumer contracts as files .remedy/contracts/<consumer>.yaml (endpoints + example interactions) checked by provider jobs. Findings carry endpoint+field+a request replica.

## Task slicing
T001 the schemathesis runner (budgeted, deterministic seeds) + the finding formatter + tests. T002 the consumer contract format + checker + fixtures (schema break and contract break separately).

## Acceptance & tests
The fixture API with a removed field trips both paths precisely; the budget keeps runtime <90 s on the fixture; seeds make runs reproducible.

## Risks / anti-goals
No pact-broker ecosystem in v1 (files in the repo suffice; an ADR if that changes); the sample is honestly labeled a sample.

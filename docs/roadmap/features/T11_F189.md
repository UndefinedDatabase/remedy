# T11_F189 — Service contract tests
**Tier 11 · Depends on: F061, F007 (single-service runtime) · Enhanced by: F190 compose environments for multi-service targets · Blocks/used by: API jobs made robust; F207 safety**

## Goal & Done
APIs get held to their word: a DoD kind contract checks (a) schema
conformance via a budgeted, seed-pinned sample of generated cases
against the RUNNING instance, and (b) consumer contracts — files
.remedy/contracts/<consumer>.yaml with endpoints and example
interactions — verified by provider jobs; findings carry endpoint,
field and a request replica. DONE when the conformance stage runs
its n-case sample (seed-pinned — reruns generate the same cases,
comparable across rounds) against a runtime-provisioned instance
with violations rendered as findings {endpoint, field, expected
per schema, got, the replayable request}, consumer-contract files
validate and check example interactions exactly (request → the
asserted response subset), the generator tooling ships in the
quality extra with honest degradation while consumer contracts
work WITHOUT it (plain replay — base capability, the split
stated), findings enter the normal repair flow, and multi-service
targets ride the compose environments when F190 lands (the
single-service runtime path works now — the enhancement note
honest).

## How it fits (inspect current shape before building)
The runtime layer (F007) starts the target service for smokes —
the contract kind reuses exactly that provisioning (single
service now; the F190 handle later — the kind's environment
input is already the abstraction). Stage (a): schemathesis-style
generation from the service's schema (OpenAPI discovered per
config/convention) joins the quality extra; the budget (n cases,
time cap) and the seed pin follow the mutation feature's
sampling honesty ("a survey, not a proof" — the label verbatim);
absent extra → stage (a) reports tool_unavailable while stage
(b) still runs (plain HTTP replay is stdlib work). Stage (b):
consumer contracts are curated files (who calls us and how —
example interactions {request {method, path, headers subset,
body}, expect {status, body subset match rules documented}});
provider jobs touching those endpoints (the diff-to-endpoint
mapping via route conventions or the schema) run the affected
consumers' examples.

## Design (suggested shape)
- The DoD kind contract {schema_sample?: {n, seed}, consumers?:
  [names | all-affected]}: environment up (runtime/compose
  handle) → stages → findings → down.
- Findings: {stage, endpoint, field/path, expected, got,
  request_replica (the exact request as a curl-able record —
  redaction-checked)} — into review/repair as ever.
- Contract files: schema-validated; `remedy contracts check`
  runs them standalone; authoring docs with an example file
  (the customer-facing artifact).
- Affected-consumer selection: endpoints touched by the diff
  (route extraction per ecosystem convention — conservative:
  unmappable diffs run ALL consumers, stated) → their files.
- Budget/seed evidence: the run records {n, seed, cases digest}
  — comparability across repair rounds (the same seed re-tests
  the same ground).

## Task slicing
- **T001** the kind + environment reuse + consumer-contract
  format/validation/replay (base capability) + fixtures (a
  fixture service + a consumer file; a seeded violation →
  the finding with the replica).
- **T002** the schema-sample stage (extra packaging, discovery,
  budgeted seeded generation, violation mapping) + degradation
  split tests + the survey label.
- **T003** affected-consumer selection + repair-flow injection
  + authoring docs + the end-to-end (a provider job breaking a
  consumer example → blocked → repaired → green; conformance
  sample honest under budget).

## Acceptance
- Consumer replay works without the extra (the split fixture).
  Seed-pinned reruns generate identical cases (digest test).
  Findings carry working replicas (replayed in the test —
  redaction-checked). Affected selection conservative on
  unmappable diffs. The survey label renders on stage (a)
  outputs. Environment always torn down (the trap fixture).

## Edge cases & assumption defaults (A9)
- Services without discoverable schemas: stage (a) reports
  not-applicable honestly; stage (b) carries the weight (the
  split again). Stateful endpoints (auth flows): contract
  examples may declare a setup sequence (documented, bounded);
  beyond that, honesty over heroics — the docs say what the
  kind is for. Consumer files drifting from reality: they are
  curated repo content — normal PR hygiene, the check's
  failures are the drift alarm.

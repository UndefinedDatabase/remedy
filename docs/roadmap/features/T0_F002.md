# T0_F002 — Operator repair as a valid evidence path
**Tier 0 · Depends on: none · Blocks/used by: unblocking any manual intervention**

## Goal & Done
See ROADMAP.md F002; the Done criterion there is binding.

## Context (existing code & prior features)
evidence_mode.py already knows manual_operator_repair, but nothing writes that provenance - manually repaired tasks still block (missing review.json, manual_repair_provenance=absent).

## Design
`packages/orchestration/repair_attest.py`: collects the workspace diff since the last valid state, hashes it, writes provider_evidence.json (execution_mode=manual_operator_repair), review.json (verdict=operator_attested), token_accounting.json (actual_available=false, reason=manual) and manual_repair_provenance.json (diff sha, files, note, ts). CLI `remedy do repair-attest <job> <task> [--note]` with a confirm prompt showing the diff stat. The final verifier accepts operator_attested as PASS-equivalent WITH a visible badge in the report.

## Task slicing
T001 module + artifact writers + tests. T002 CLI + verifier/gate acceptance + report badge. T003 end-to-end: blocked fake job -> attest -> verifier PASS.

## Acceptance & tests
Generated JSONs are schema-valid; without attest BLOCKED, with attest PASS+badge; token truth stays honest (actual_available=false for these tasks).

## Risks / anti-goals
Attest applies per task, never per job. No new gate layer - existing checks merely learn the new mode.

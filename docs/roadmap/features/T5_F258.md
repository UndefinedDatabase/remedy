## Why this exists
F257 proved the consumption point but left three gaps the operator must not be
needed for: the queue is hand-curated and now empty, consumed items are
planned but never run, and nothing binds run-findings to the development loop.
F258 closes all three so "Remedy is used on Remedy" runs indefinitely with
zero operator input.

## T001 — Self-replenishing queue
A generator that fires at the closure consumption point whenever the queue
holds no pending item, and produces EXACTLY ONE new item per close, dated,
with a `provenance` field naming its source. Source priority: (1) the oldest
OPEN Medium or Low finding in the reviewer ledger that is self-contained,
repo-scoped and repairable as one small job; (2) a concrete
documentation-staleness target measured by grep (a docs page contradicting
shipped code); (3) an actionable `remedy doctor core` warning. If NO source
qualifies, record `self-use NONE (no eligible source)` honestly — the
generator never invents work.

This DELIBERATELY REVERSES the queue description's "Remedy never invents an
item and never appends one" clause on `scripts/self_use_queue.json` — that
clause describes v1's operator-curated-only shape. The reversal is a dated
operator decision (this amendment, 2026-08-29) and, when T001 is built, must
be written into the queue file's description and into
`docs/roadmap/features/T5_F257.md` as an amendment paragraph, so both files
tell the truth about which mechanism is adding items at that point.

## T002 — Consumed means executed
The consumed item is not only planned via
`packages/orchestration/self_use_job.py` but RUN through the real job path
(builder/reviewer loop in an isolated worktree) under a small dedicated
budget using the existing budget machinery, stopping at the normal approval
gate like any other job. The closure paragraph records planned → ran →
outcome. Landing any resulting change happens ONLY through the normal
reviewed-round machinery — never automatically from inside the closure
sequence; if the run's diff is not landed, that fact is recorded, not hidden.

## T003 — Findings flow back
Any defect surfaced while planning or running a self-use item is registered
in the standard finding ledger in the same session under the normal rules
(red-proof required for a repair), and the closure paragraph names every
finding raised and whether it was repaired. This binds existing machinery; it
invents nothing new.

## Acceptance
- A feature close on an empty queue still consumes one generated item, with
  provenance.
- That item is executed with a recorded outcome, not merely planned.
- One full generate → plan → run → record cycle is proved end-to-end by a
  test fixture.
- The operator never edits `scripts/self_use_queue.json` by hand for the
  track to keep running.

## Do not touch
The scope-fence builtin deny list (F017), the normal approval gate, and
STATUS semantics — a job must never check itself off. The v1 queue schema's
existing fields (`id`, `title`, `why`, `job_markdown`, `consumed_by`) are
extended, never replaced, so `packages/orchestration/self_use_queue.py`'s
existing readers keep working against a v2 queue file.

## Orchestrator brief
T001 is the generator and is the largest piece — settle its source-priority
logic and the `provenance` field's shape before writing the executor. T002
depends on T001 producing a real item to run against. T003 is largely wiring
existing finding-ledger machinery into the closure path, once T002 exists.

## Built State (F258, 2026-08-30)

What exists on disk at the close of F258, so a later reader need not
reconstruct it from this file's future tense.

**T001 — the self-replenishing queue.**
`packages/orchestration/self_use_generator.py:generate_and_append_if_empty(queue_path=None, ledger_path=None)`
(line 254) fires only when `packages.orchestration.self_use_queue.pending_self_use_items`
answers empty, and produces at most ONE new item per call, dated and
carrying a `provenance` field naming its source. Source priority, in
order: Tier 1 (`_ledger_tier`, line 153) reads the oldest OPEN
Medium/Low finding in `.agent/live_review.md` that is self-contained
and repo-scoped; Tier 2 (`_doc_staleness_tier`, line 198) and Tier 3
(`_doctor_warning_tier`, line 203) are honest placeholders that always
answer `None` — the feature file's own acceptance criterion ("If NO
source qualifies, record `self-use NONE`") is met by falling through
all three rather than inventing work. `scripts/self_use_queue.json`'s
`schema_version` moved to 2 (DECISION F258 D1) to carry the required
`provenance` field; `packages/orchestration/self_use_queue.py`'s
six-key `_ITEM_KEYS` and its loader validate it on every read.

**T002 — consumed means executed.**
`packages/orchestration/self_use_runner.py:run_next_self_use_item(dest_dir, repo_path=".", queue_path=None, ...)`
composes `self_use_job.plan_next_self_use_item` with
`pingpong_job.run_job` under a small `JobBudgets`
(`max_provider_calls=6`, `max_cost_usd=0.50`, `max_tasks=1`), stopping
at whatever status `run_job` returns — `JOB_COMPLETED` or
`JOB_BLOCKED` — and never calling `job_promote.promote_job`. Run in an
isolated worktree (`isolation_mode="worktree"` for any git target),
never mutating the caller's own checkout. Round 8 discharged this for
real against the shipped queue's first pending item (SU-002), reaching
the approval gate with a genuine `JobPlan` on disk.

**T003 — findings flow back.**
`packages/orchestration/self_use_findings.py:describe_self_use_run_defects(result)`
reads a run's own `JobPlan` and answers a tuple of plain strings — one
per defect, quoting the job's and each task's own `error` field
verbatim, inventing nothing and judging no severity. Registering an
`- R-XXXX` line from that tuple is deliberately left to the closing
session (never automated), per `planner_reviewer_prompt.md` §3 item
30's search-before-minting discipline.

**What round 8's real run surfaced.** The one call path this feature
ships (`run_next_self_use_item` with no explicit provider) resolves
`pingpong_job.run_job`'s own literal `"fake"` default rather than
`role_config.DEFAULT_PROVIDER`'s `"ollama"`, so an unflagged self-use
run is currently a synthetic, zero-real-provider-call simulation —
registered as R-0757 (Medium, OPEN), NOT repaired on this branch
(AGENTS.md forbids mixing an unrelated fix into a feature branch; the
fix touches `self_use_runner.py`'s own provider resolution or its
docstring, a normal follow-up round, not a closure blocker for a
Medium finding).

**What is deliberately NOT here.** No generator Tier 2/3 source is
real yet — both are honest placeholders. `self_use_runner.py` does
not resolve a real default provider (R-0757). Landing any diff a
self-use run produces stays a normal reviewed round; F258 never
auto-lands one.

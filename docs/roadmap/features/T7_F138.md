# T7_F138 — ADR automation
**Tier 7 · Depends on: F063 mechanics · Blocks/used by: F121, decision hygiene**

## Goal & Done
Architectural decisions stop slipping by undocumented: heuristics —
a new dependency, a new top-level module, a schema change,
tech-choice keywords in plans — draft an ADR (docs/adr/NNN) for
confirmation; confirmed ADRs feed the decision-card generator.
DONE when each heuristic fires on its seeded fixture and stays
silent on noise, drafts follow the repo's discovered ADR convention
with status=draft and the triggering evidence quoted, confirmation
is a human act (the proposal gate — drafts never self-confirm),
numbering is collision-safe, and the card generator picks up
confirmations (the F121 handshake proven).

## How it fits (inspect current shape before building)
The ADR convention exists (F121's discovery order documented path,
format, status vocabulary — import those findings; this feature
WRITES what that one reads). Detection sources are structured
evidence: dependency manifest diffs (touched-files + manifest
parsing per ecosystem), new top-level modules (tree diff),
schema-change signals (the schemas package's files or SCHEMA_V
bumps in diffs), and plan keywords (a curated tech-choice term
list, versioned — "introduce", "migrate to", "replace X with").
Drafting flows the idea machinery (kind adr_draft, evidence-typed
refs to the trigger); approval MATERIALIZES the draft file via the
gated path into docs/adr/ as status=draft-for-confirmation —
confirmation itself is the human editing status to confirmed in a
normal PR (two human touches by design: "yes, document this" and
"yes, this is our decision" — cheap, deliberate).

## Design (suggested shape)
- Detectors (pure over evidence, one module each shape):
  dependency (manifest diff → added deps with versions), module
  (new top-level dirs/packages under source roots — the ignore
  notion applies), schema (SCHEMA_V additions/bumps in the diff),
  keywords (plan/intake text against the term list, matched terms
  quoted).
- The draft: the convention's template with Context (trigger
  evidence quoted + refs), Decision (a neutral statement of what
  the change DOES — never invented rationale; the rationale
  section says "to be written at confirmation"), Status
  draft-for-confirmation, and the trigger metadata.
- Numbering: next-NNN from the directory at materialization time
  under a claim-marker (the queue's atomic-create idiom) —
  collision-safe under parallel approvals.
- Post-terminal hook (the harvest funnel, never-block) + on-demand
  `remedy adr scan <job>`.
- The F121 handshake: confirmed status → the card sync generates —
  an integration test spanning both features.

## Task slicing
- **T001** the four detectors + term-list versioning + table tests
  (fire/noise per detector; the ignore notion respected).
- **T002** drafting (template, neutral-decision rule, quoted
  triggers) + the proposal flow + materialization + numbering
  safety + goldens.
- **T003** the funnel hook + scan CLI + the F121 handshake test +
  the end-to-end (a job adding a dependency → proposal → approve →
  draft file → human confirms → card exists).

## Acceptance
- Detector matrix exact (each fires on its fixture, silent on the
  noise set). Drafts follow the discovered convention (validated
  against F121's parser — the round-trip test); rationale never
  invented (the placeholder golden). Parallel-approval numbering
  collision-free (the two-process test pattern). Handshake green.

## Edge cases & assumption defaults (A9)
- Multiple triggers in one job (dep + module): one draft per
  DISTINCT decision candidate, cross-referenced — the keyword
  detector dedupes against structural detections of the same
  change. Reverted changes before terminal: detection runs on the
  FINAL diff only (no ghosts of abandoned approaches).

## Orchestrator brief
Gate on F121's convention findings + idea provenance. The
neutral-decision/no-invented-rationale rule and the two-human-
touches design go verbatim. T001 detectors are four parallel
small orders.

## Do not touch
The ADR convention itself, card generation (handshake only),
confirmation semantics (human PR). Suggested tests:
tests/orchestration/test_adr_automation.py.

## Goal & Done
Time becomes navigable: a phase bar (Job → Planning → Build → Test
→ Review → Finalized) with event sub-glyphs spans the run, and a
scrubber rebuilds the graph state from the event prefix
events[0..s] — memoized snapshots keep it instant — while a LIVE
toggle returns to the present like a video player. DONE when
scrubbing any fixture position renders exactly the reducer state
of that prefix (the determinism dividend), snapshot memoization
meets the interaction budget, phase boundaries derive from events
(never wall-clock guesses), and scrubbed mode is unmistakably
labeled with live updates queuing behind the toggle.

## How it fits (inspect current shape before building)
The reducer (F019) is pure over event prefixes — the scrubber IS
that purity made visible: state(s) = reduce(events[0..s]),
memoized every 200 seq (the binding spec) so any position costs
one snapshot + ≤200 reductions. Events arrive/persist ordered
(the SSE/ledger contract); phases derive from marker events (plan
approved, first build call, verify start, review start, terminal
— map the actual Part E kinds; the mapping table is part of this
feature and golden-tested). Scrubbed mode disconnects RENDER from
live while the store keeps ingesting (a bounded buffer; LIVE
jumps to head).

## Design (binding specifics)
- Phase bar CSS core:
```css
.phasebar{height:64px;border-radius:14px;background:var(--remedy-card);box-shadow:var(--remedy-shadow-soft);
  display:flex;align-items:center;padding:0 18px}
.phase{flex:1;position:relative;height:4px;background:var(--remedy-blue-100);border-radius:2px}
```
  Phases fill as their span completes; the active phase pulses
  per motion tokens; sub-glyphs (decisions, failures, heals,
  stops) sit on the track at their seq position with hover
  humanized lines (reuse the humanize catalog — one vocabulary)
  and click → scrub there.
- Scrubber: drag/click on the track sets s; keyboard arrows step
  events, shift-arrows step phases; the position readout shows
  seq + relative time; a SCRUBBED banner state per the reference
  (the DEMO banner's visual cousin) replaces ambiguity.
- Snapshots: every 200 seq per the spec; memory-bounded (drop
  distant snapshots beyond a cap, rebuild on demand — instant
  beats infinite); invalidation only on snapshot-refetch resets
  (gap recovery) — then rebuilt lazily.
- LIVE toggle: returns render to head, drains the queued
  ingestion visually per the reference's catch-up treatment
  (fast-forward, not teleport, under a duration cap).

## Edge cases & assumption defaults (A9)
- Jobs with sparse events: phases with zero span render as
  compact ticks (a plan-only job is honest about it). Scrubbing
  during heavy live traffic: ingestion buffer bounds documented;
  overflow forces a labeled snapshot-refetch on LIVE return
  (truth over seamlessness).

## Built State (F024, 2026-09-25)

What exists on disk at the close of F024, built in five rounds in one session on
`feature/f024-phase-timeline-scrubber`, cut from `main` at `1bb3a35d`. Every DECISION named lives
in `.agent/decisions.md`; every round's verdict in `.agent/live_review.md` or, once rotated, its
archive.

**T001 — the phase mapping, the boundaries and the sub-glyphs.** `apps/ui/src/components/timeline/phaseMapping.ts`
reads the event ledger the server really writes. Its phase mapping table sends the three
`planning_*` kinds to Planning, `task_run_started` and the two `builder_*` kinds to Build, the
`test_run_*` and `verification_*` kinds to Test, and a `task_round_completed` carrying a reviewer's
verdict to Review; Job begins at the ledger's first row. `readPhases` gives any prefix's phases:
each begins at the first row that marks it or a later one, so the bar only moves forward, and a
skipped phase has a zero span. No completion event exists, so Finalized is derived from the
reducer's own task states and holds only while every task has passed. The sub-glyphs — decision,
failure, heal, stop — come from a second table and the review verdict, each with the humanize
catalog's line. `tests/ui_contracts/test_phase_mapping.py` holds both tables to
`packages/orchestration/event_names.py` and the six phases to the bar's and the dashboard's
(DECISION F024 D1).

**T002 — the snapshots.** `scrubSnapshots.ts` serves the reducer state at any seq from snapshots
every 200 seq, capped at 64 and dropped farthest-first, built lazily from the nearest lower one,
invalidated by the rows they should have held and forgotten on a snapshot-refetch reset. Its
property test holds the state at fuzzed positions of seeded ledgers equal to `rebuildBrainModel`
over the prefix, and `tests/ui_contracts/test_scrub_snapshots.py` binds the spacing to this file's
and the roadmap's figure (DECISION F024 D2).

**T003 — the bar, the scrubber, LIVE and the end-to-end.** `timelineIndex.ts` reads every prefix's
phases from one fold and is held equal to `readPhases` at every position; `scrubState.ts` is the
machine with its keyboard and LIVE's capped fast-forward; `timelineView.ts` is the bar's view model
of six equal segments with the track's geometry (DECISION F024 D3). The shell reads the one ledger
and builds the one scrubber in `useTimelineScrub.ts`; `PhaseTimeline.tsx` is a slider over the six
segments, moved by pointer, keyboard and sub-glyph clicks, with a readout and a LIVE button; the
stage draws the scrubbed prefix under a SCRUBBED banner and the pill says REPLAY
(DECISION F024 D4). `tests/ui_server/test_timeline_scrub_live.py` scrubs a real fake job's ledger at
every position with these modules, and the scrub budget on the 500-node fixture is measured with a
red control that fails (DECISION F024 D5).

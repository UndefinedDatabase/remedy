## Goal & Done
The self-use generator gains two more sources that always have real work, so that a closure's
self-use reading "queue exhausted" becomes rare. DONE when, on a queue that reads exhausted for
tiers 0 to 3, three consecutive generator requests produce three different items, a closure's
self-use reading is never "exhausted" while any tier has an item, and the first item runs to the
approval gate within the default budget.

## Why this exists
Nine of the last thirteen closures read "self-use NONE (queue exhausted)". The generator's four
sources are the toolchain order every fourteen days, open findings with a FIX clause, the
documentation-staleness catalog and the actionable warnings of `remedy doctor core`. On the real
repository they are dry most of the time. The operator's second priority is that Remedy is used
on itself continuously, and today that is met on paper only.

## The order of tiers
Tier 0 is the toolchain order, tier 1 the open findings, tier 2 the documentation staleness,
tier 3 the doctor warnings, tier 4 the excused blind handlers and tier 5 the test-less modules.
Tiers 4 and 5 sit last because they always have an item, so they would otherwise starve the
tiers above them.

## Task slicing
- T001 — Tier 4, excused blind handlers. An item is one file's oldest `# noqa: BLE001` mark, an
  `except Exception` handler that the linter was told to excuse. `tests/test_ble001_ratchet.py`
  freezes how many such marks may exist in `MAX_EXCUSED`. The job's one task narrows that handler
  to the exception types it really needs and lowers `MAX_EXCUSED` by one in the same change.
  Acceptance is that the ratchet test is green and the mark is gone. The operator estimated about
  260 such items; 290 marks were counted under `packages/`, `apps/` and `scripts/` at `4e643440`.
- T002 — Tier 5, test-less modules. An item is a production module under `packages/` or
  `apps/cli/` that no file under `tests/` imports. The operator measured about 15 such modules on
  2026-09-29, most of them command modules. The job's one task writes that module's first test
  file, with at least one meaningful test per public function. Acceptance is that the new test
  file imports the module and passes.
- T003 — the requirement. On a queue that reads exhausted for tiers 0 to 3, three consecutive
  requests produce three different items; the closure's self-use reading is never "exhausted"
  while any tier has an item; and the first item runs to the approval gate within the default
  budget.

## Acceptance
- Tier 4 renders one file's oldest `# noqa: BLE001` mark as a one-task job whose task also lowers
  `MAX_EXCUSED` by one, and no queue entry is offered twice.
- Tier 5 renders one test-less production module as a one-task job that writes its first test
  file, and no queue entry is offered twice.
- Three consecutive requests on a queue exhausted for tiers 0 to 3 produce three different items,
  and the first runs to the approval gate within the default budget.

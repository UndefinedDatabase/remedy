# T8_F158 — Cost normalization & price catalog
**Tier 8 · Depends on: F103, F151 · Blocks/used by: F159, F222, F228**

## Goal & Done
Cross-vendor money becomes comparable, honestly: a versioned price
catalog per adapter (input/output/cache prices per model, currency,
valid_from, a source URL comment), ledger rows gain raw_counters{},
a normalized cost, pricing_version and basis (provider_reported |
catalog_computed) — provider-reported wins, the catalog cross-checks
(deviation beyond a threshold warns), a stale catalog warns without
ever blocking, and `remedy worker pricing update` imports maintained
catalogs. DONE when normalization matches goldens across mixed
bases, the cross-check fires on a seeded deviation, staleness warns
per the window, and — a consistency correction — normalization
targets ONE configured currency shared with the budget fields
(default USD, matching max_cost_usd and friends), with foreign-
currency catalogs converted only via an explicitly configured rate
or left unnormalized with the note (no invented FX).

## How it fits (a currency correction + composition)
An earlier draft normalized to EUR while every budget field the
product shipped (max_cost_usd, confirm_above_usd, cost_usd rows)
speaks USD — one product, one money language: the normalization
currency is a config key (cost.currency, default usd) that budgets,
previews, the ledger and this catalog all share (a small
consolidation order aligns any stragglers; mixed-currency displays
are forbidden by a guard test). The ledger's additive-column
pattern applies (raw_counters, normalized_cost, pricing_version,
basis); the writer computes at record time when a catalog covers
the model, cross-checks when the provider also reported; backfill
recomputes historical rows idempotently by pricing_version (rows
keep EVERY version's computation? No — rows store the version used;
recomputation under a new catalog version updates normalized_cost
with the version bump, raw counters immutable — the raw truth
never changes, the valuation may, stated).

## Design (suggested shape)
- Catalogs: `pricing/<adapter>.toml` in-repo (reviewable, the
  source-URL comments make audits possible): per model {input,
  output, cache_read, cache_write, currency, valid_from};
  validation (positive prices, known models cross-checked against
  the registry, currency ∈ configured set).
- Writer integration: basis rules (provider_reported wins;
  catalog_computed otherwise; both present → cross-check, >
  threshold (config, default 5%) → a warning event + the stats
  flag); unpriced models → normalized null with basis unknown
  (the established unmeasured honesty).
- Staleness: valid_from age > window (config 60d) → warnings in
  stats/doctor, never blocking; `pricing update` imports/merges
  maintained catalog files with a shown diff before accepting
  (the baselines-update pattern).
- Consumers: the scoreboard and cost stats read normalized_cost +
  basis; every rendering carries the basis label (inherited
  discipline).

  One-currency guard green with a violation fixture. Update
  shows the diff before writing.

## Edge cases & assumption defaults (A9)
- Local models: basis local_zero stands (F113's rule) —
  normalized 0 with the basis, never blended silently into
  averages (aggregations group by basis, the established rule).
  Providers reporting costs in another currency: converted only
  via the configured rate, else unnormalized-with-note.

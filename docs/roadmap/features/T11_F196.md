# T11_F196 — Flake-resistant E2E discipline
**Tier 11 · Depends on: F094, F135 · Blocks/used by: trust in generated suites**

## Goal & Done
See ROADMAP.md F196; the Done criterion there is binding.

## Context (existing code & prior features)
F135 quarantines flakes reactively; preventive discipline for GENERATED specs is missing.

## Design
A spec lint for generated playwright flows: forbidden patterns (waitForTimeout/sleep, index selectors, race-prone chains) fail the generator (the builder retries with the lint finding quoted); mandatory patterns (web-first assertions, data-testid selectors - the generator receives a testid convention via the conventions registry). Retry policy: max 1 retry ONLY with automatic F135 linkage (a retry success = a flake-suspicion entry). A flake budget per suite as an F142 tile.

## Task slicing
T001 the lint rules + generator coupling + per-pattern tests. T002 the retry-F135 coupling + the budget tile + a fixture (a sleep spec is rejected).

## Acceptance & tests
The sleep spec fails lint and the finding reaches the next builder prompt; retry successes surface as suspicion entries; the tile links raw data.

## Risks / anti-goals
The lint governs GENERATED specs (existing project specs get a report note only - no uninvited rewriting; scope discipline).

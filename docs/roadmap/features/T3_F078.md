# T3_F078 — Autonomy levels
**Tier 3 · Depends on: F075, F077 · Blocks/used by: trust rollout**

## Goal & Done
Autonomy becomes an explicit, auditable dial instead of scattered
flags: a configured level (L2–L5) states what Remedy may START on its
own — L2 every start is manual; L3 the loop starts follow-up jobs
inside an approved mission; L4 adds recurring order files (DECISION
amend0905-vocab D7); L5 adds idea-draft
execution under budget caps — while every gate, fence, budget and
watchdog applies unchanged AT EVERY LEVEL. DONE when each level's
permitted/forbidden start matrix is enforced by one shared check at
every job-starting seam, level changes require a manual config edit
plus an ADR reference, and the current level is visible everywhere
it matters.

## How it fits (inspect current shape before building)
The starting seams exist and are countable: the golden-path `remedy do`
(manual, always allowed), the orchestrator loop's dispatch, recurring
order files started by hand or by a later scheduler, and idea approval (which plans but
never starts — verify that stays true; L5 changes it to may-start
within caps). Levels do NOT replace approvals: --yes semantics,
plan gates and budgets are orthogonal and still required — a level
only answers "who may INITIATE". Autonomy levels also gate what
`remedy do --apply` may do on its own (DECISION amend0905-vocab D8/D10);
every L-level references `apply`, never promote. The gauntlet gate governs the
multi-cycle default; levels reference it (L≥3 requires the gate
passed — encode that prerequisite in config validation).

## Design (suggested shape)
- Config [autonomy] level (default L2), validated: L3+ refused unless
  the gauntlet pass evidence reference is present (the ADR from that
  feature); every level change is detected (config source tracking)
  and logged with the ADR reference field (required key
  autonomy.change_adr — validation refuses a level change without
  it; the honest paper trail).
- `autonomy_gate.py`: may_start(origin: manual|orchestrator|
  order-file|idea, context) → allow|deny(reason) — the ONE check every
  starting seam calls; the matrix is a table constant with tests per
  cell; denials are logged events with the level and origin (visible
  in status: "2 starts deferred by autonomy level L2").
- L5 caps: idea-origin starts require the idea's effort band within
  a config cap and a per-period start budget (count + usd) — beyond
  it, defer to a decision (never silent unbounded initiative).
- Surfacing: status/report header shows the level; the autonomy
  stats feature gains the level dimension on its snapshots.

## Task slicing
- **T001** config + validation (gauntlet prerequisite, ADR
  requirement) + the gate matrix + per-cell unit tests.
- **T002** seam integration (one small order per starting seam,
  each with an allow and a deny fixture at boundary levels).
- **T003** L5 caps + deferral decisions + surfacing + the end-to-end
  per level (a fixture per level proving exactly its increment).

## Acceptance
- Matrix tests cover every origin×level cell. L3 without gauntlet
  evidence refused at config load. Level change without ADR refused.
  Deferred starts are visible, resumable manually, and never lost.
  All existing gates provably still fire at L5 (regression loop).

## Edge cases & assumption defaults (A9)
- Downgrading mid-mission: running work finishes; only NEW starts
  consult the new level (no mid-air aborts from a config edit —
  stopping is the kill switch's job). Multiple projects share the
  level per config scope (project config wins over user config, as
  everywhere).

## Orchestrator brief
Gate on gauntlet + watchdog. T002 is several tiny orders — perfect
parallel dispatch; give each seam's worker the matrix table verbatim.
The ADR-required rule is the trust story: reject any softening.

## Do not touch
Approval semantics, budget mechanics, the gauntlet's pass definition.
Suggested tests: tests/orchestration/test_autonomy_gate.py.

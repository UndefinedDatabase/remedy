# T13_F208 — Monorepo workspaces
**Tier 13 · Depends on: F017, F107, F148 · Blocks/used by: large customer repos; honest test scopes**

## Goal & Done
See ROADMAP.md F208; the Done criterion there is binding.

## Context (existing code & prior features)
Fences (F017) and the context compiler (F107) work path-based; workspace semantics are missing.

## Design
Workspace detection (pnpm-workspace.yaml, yarn/npm workspaces, uv/rye, cargo): the package list + internal dependency edges. Effects: (a) fences + allowed_paths expressible at package level (pkg:web-app), (b) an affected-packages analysis per diff -> the test scope 'changed packages + dependents' (edges from the workspace graph), suite invocations filtered accordingly, the report labels 'scoped test: n of m packages' HONESTLY, (c) the F016 task slicing receives package hints.

## Task slicing
T001 detection per toolchain + the graph + tests. T002 fence/compiler/test-scope coupling + a monorepo fixture (a change in A tests A + dependents, not bystanders) + the report label.

## Acceptance & tests
The fixture: the unaffected package-B suite provably does not run AND the report says so; the full suite is forceable via a flag; package fences trip on violation (test).

## Risks / anti-goals
Scoped green is labeled as such - a DoD may demand the full suite for release gates (the F221 coupling; no silent shortcut).

# T3_F067 — Routine missions
**Tier 3 · Depends on: F045 · Later integrates: F124 card-cleanup loop entry · Blocks/used by: maintenance**

## Goal & Done
Common maintenance becomes one install away: a curated library of
ready-made loop definitions — dependency updates (majors always
escalate to a decision), lint debt, doc sync, test gaps — ships with
Remedy, and `remedy loop install <name>` copies a commented, editable
definition into the project's config with its scope and budget
defaults. DONE when each library routine installs, validates and runs
against a matching fixture repo with sensible behavior, install is
idempotent-with-honesty (existing loop → refuse with a diff hint,
never overwrite), and every routine's definition is self-documenting.

## How it fits (inspect current shape before building)
Loops are `[[loop]]` tables in the project config (the loop feature's
deliberate placement) — install therefore APPENDS a commented block to
the config file, preserving the file's existing content byte-for-byte
elsewhere (the init feature's never-rewrite discipline applies; reuse
its config-editing care or add a tiny append-block helper both can
share). Routines are DEFINITIONS ONLY — their actions run through the
completely normal pipeline; a routine whose action needs a capability
that isn't built yet must not ship in the library.

## Design (suggested shape)
- Library location: packaged data (ships in the wheel), one file per
  routine: the [[loop]] block + rich comments (what it does, what it
  costs typically, which decisions it may raise) + metadata (name,
  summary, required capabilities).
- Routines v1: dependency_updates (scan manifests for outdated deps —
  scoped to the ecosystem files; minor/patch bumps become a normal
  job; MAJOR bumps always raise a decision before any change — the
  escalation is in the goal template's contract, tested), lint_debt
  (run the configured linter, fix a bounded batch per run),
  doc_sync (drift check between exported symbols and docs — proposes,
  as findings, a doc-update job), test_gaps (modules without any test
  file → a proposal decision listing them, no silent test generation
  in v1 — quality over volume).
- `remedy loop install <name>` (append + validate + print the block),
  `remedy loop library` (list with summaries), refusal on name
  collision with the existing-loop diff hint.
- Each routine has a fixture repo and an end-to-end test at least in
  --rehearse/plan depth (full runs where cheap).

## Task slicing
- **T001** library packaging + install/append helper + collision
  refusal + validation + tests (config byte-preservation outside the
  appended block).
- **T002** the four routine definitions + their fixtures + plan-depth
  end-to-ends; dependency_updates' major-escalation contract tested
  fully.
- **T003** library listing CLI + docs + the capability-gate check
  (a routine declaring an unbuilt capability is excluded from listing
  with a build-order note — honesty toward the roadmap).

## Acceptance
- Install → validate → list shows it → run reaches the expected plan
  shape per fixture. Major-bump fixture raises the decision and
  changes nothing without it. Config outside the block untouched
  (hash compare). Double install refused with the hint.

## Edge cases & assumption defaults (A9)
- Projects without the relevant toolchain (no linter configured):
  the routine's run degrades to an honest not-applicable report line
  (the smoke feature's pattern). Library versioning: installed blocks
  carry the library version in a comment; upgrades are a manual
  re-install decision, not automatic.

## Orchestrator brief
Gate on loops. T002 is four independent small orders (one per
routine, fixture each) — ideal parallel dispatch. The major-bump
escalation contract goes verbatim into its order.

## Do not touch
Scheduler execution, test GENERATION, card systems (later
integration). Suggested tests: tests/orchestration/test_routines.py.

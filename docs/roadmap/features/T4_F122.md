# T4_F122 — Project dossier card
**Tier 4 · Depends on: F117 · Later integrates: F149 study pre-fills the card (manual fill until then) · Blocks/used by: cold-start context**

## Goal & Done
Every worker's first read is the same trusted page: ONE pinned
architecture card per project — stack, structure, conventions
digest, start commands — hard-capped at 800 tokens, always attached
first for every role, maintained by proposals rather than silent
edits. DONE when the pinned card attaches at the top of the card
segment for all roles regardless of scope math, the cap is enforced
with helpful errors, exactly-one-pinned is invariant, and staleness
(referenced paths/commands gone) is detected and proposed for
repair, never auto-fixed.

## How it fits (inspect current shape before building)
The selector owns attachment — pinning is a small, explicit bypass:
a card with pinned=true (frontmatter, only valid on type
architecture, enforced) skips scope/relevance/value stages and
occupies the segment's first slot; its tokens count against the card
budget (the rest of the funnel gets what remains — arithmetic
tested). Creation: `remedy memory init-dossier` scaffolds the
template with honest placeholders ("fill me: start command") until
the study feature pre-fills it; content quality is human
responsibility, structure is enforced.

## Design (suggested shape)
- Template sections (validated present, placeholders allowed):
  Stack (languages, frameworks, versions where known), Structure
  (top-level map, one line per area), Conventions digest (the five
  rules a stranger needs first — pointing at the conventions files
  rather than duplicating them), Run/Test commands, Landmines (the
  honest section: what surprises newcomers).
- Invariants in the store: at most one active pinned card per
  project (the second pin is refused naming the first); pinned
  cards cannot be archived while pinned (unpin first — deliberate
  two-step).
- Staleness check (a hygiene-loop step and on-demand `remedy memory
  check-dossier`): referenced paths exist, commands' executables
  resolve — failures file an update PROPOSAL through the harvest
  kind with the diff-shaped suggestion (the checker may draft, the
  human approves — the standing rule).
- Selector integration: first-slot bypass + budget arithmetic +
  evidence marks it pinned (so the funnel view stays truthful).

## Task slicing
- **T001** template + scaffold CLI + pinned invariants + cap +
  tests (double-pin refused; archive-while-pinned refused).
- **T002** selector bypass + budget arithmetic + evidence marking +
  goldens (all roles get it first; the remaining budget math).
- **T003** staleness checker + proposal filing + fixtures (moved
  path, vanished command → proposals with drafts; clean dossier →
  silence).

## Acceptance
- Scaffold → fill → the card leads every role's segment on fixture
  tasks; remaining-budget math exact. Cap refusal message includes
  the token count and the section sizes (actionable). Staleness
  fixtures file proposals; nothing edits the card itself. Invariants
  hold under concurrent-ish CLI abuse (double-pin fixture).

## Edge cases & assumption defaults (A9)
- Projects that outgrow 800 tokens: the card links deeper docs; the
  cap is the point (a dossier that needs more is hiding structure
  problems — say so in the docs). Multi-repo projects: one dossier
  per registered project; cross-repo realities go in Structure as
  links.

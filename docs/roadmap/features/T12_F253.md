# T12_F253 — Headless API contract
**Tier 12 · Registered by operator decision 2026-08-03 · Depends on:
F070 (domain seams), F009 (gateway), F031/F032 (decisions) · Enhanced
by: F200 daemon mode · Blocks/used by: any third-party UX replacing
the shipped one; F201 consumes the same endpoints (its "no
mobile-special API" rule)**

## Goal & Done
Everything the shipped UI can do is possible through a PUBLIC,
versioned HTTP API — so any third-party UX can replace the shipped
one. The existing ui_server API (default port 8787) is the seed; this
feature promotes it to a contract. DONE when every shipped-UI
capability is reachable through the published surface, the shipped UI
itself consumes ONLY the public API (no privileged side channels —
the honesty mechanism), a versioning/deprecation policy exists, and
contract tests pin every published endpoint.

## Shape (binding, operator ruling 2026-08-03)
- The API exposes DOMAIN operations — missions, jobs, plans,
  approvals/decisions, reports, ledger, artifacts — the same seams
  the F070 orchestrator loop consumes. It is NOT a 1:1 mirror of CLI
  commands.
- Long-running operations get job/event semantics (create →
  poll/subscribe), never blocking request-response.
- Operator-console maintenance commands (destructive/local recovery)
  are explicitly OUT of the remote surface. Initial exclusion list
  (tighten-only — it may grow, never shrink, without its own
  operator decision): host/workspace mutation and recovery
  (`patch.apply`, `patch.revert`, `rollback.*`, `snapshot.create`),
  host configuration (`config.set`, `config.init`, `init.run`),
  self-repair approval (`self-repair.proposal-approve`,
  `self-repair.proposal-deny`), host process lifecycle
  (`worker.unload`, `runtime.stop`, `ui.stop`), queue surgery
  (`queue.rm`, `queue.reclaim`).

## Security constraints (binding, tighten-only)
- Default bind is localhost-only.
- Token auth is required for every mutating endpoint.
- No cloud relay (the F201 philosophy).
- Every API call writes a ledger entry.
- The sandbox/allowlist posture extends to the API layer unchanged.
- Any remote-exposure story is its own later feature with its own
  threat model — never a flag on this one.

## Task slicing
- **T001** Inventory: map every shipped-UI capability to a domain
  operation; publish the surface spec (endpoints, versioning and
  deprecation policy, the exclusion list) as the contract document.
- **T002** Promote/extend ui_server endpoints to the spec: domain
  operations, job/event semantics for long-running work, token auth
  on mutations, ledger entries per call; contract tests pin every
  published endpoint.
- **T003** The shipped UI migrates to the public API only; a test
  proves no privileged side channel remains (the UI's traffic uses
  only published endpoints).

## Acceptance & tests
- The shipped UI consumes ONLY the public API (asserted by test).
- A versioning/deprecation policy exists and is published with the
  contract document.
- Contract tests pin every published endpoint; an unpinned endpoint
  fails the suite.
- A mutating call without a token is rejected; every accepted call
  leaves a ledger entry (tests).

## MCP facet (amendment amend0805-v3, 2026-08-05)
The headless API is also exposed as an MCP server (2026-07-28 spec
line: stateless core, OAuth) offering verify / gate_status /
evidence_bundle as tools, so third-party orchestrators (Claude Code
Agent Teams, Gas Town class) can consume Remedy's gates without
adopting its loop. Allowlist closed-by-default per T8 invariants.

## Non-goals
SDKs, remote multi-user auth, cloud hosting.

# T12_F253 — Headless API contract
**Tier 12 · Registered by operator decision 2026-08-03 · Depends on:
F070 (domain seams), F009 (gateway), F031/F032 (decisions) · Enhanced
by: F200 daemon mode · Blocks/used by: any third-party UX replacing
the shipped one; F201 consumes the same endpoints (its "no
mobile-special API" rule)**

## Goal & Done
Everything the shipped UI can do is possible through a PUBLIC,
versioned HTTP API — so any third-party UX can replace the shipped
one. The existing ui_server API (default port 8787) is the seed; this
feature promotes it to a contract. DONE when every shipped-UI
capability is reachable through the published surface, the shipped UI
itself consumes ONLY the public API (no privileged side channels —
the honesty mechanism), a versioning/deprecation policy exists, and
contract tests pin every published endpoint.

## Shape (binding, operator ruling 2026-08-03)
- The API exposes DOMAIN operations — missions, jobs, plans,
  approvals/decisions, reports, ledger, artifacts — the same seams
  the F070 orchestrator loop consumes. It is NOT a 1:1 mirror of CLI
  commands.
- Long-running operations get job/event semantics (create →
  poll/subscribe), never blocking request-response.
- Operator-console maintenance commands (destructive/local recovery)
  are explicitly OUT of the remote surface. Initial exclusion list
  (tighten-only — it may grow, never shrink, without its own
  operator decision): host/workspace mutation and recovery
  (`patch.apply`, `patch.revert`, `rollback.*`, `snapshot.create`),
  host configuration (`config.set`, `config.init`, `init.run`),
  self-repair approval (`self-repair.proposal-approve`,
  `self-repair.proposal-deny`), host process lifecycle
  (`worker.unload`, `runtime.stop`, `ui.stop`), queue surgery
  (`queue.rm`, `queue.reclaim`).

## Security constraints (binding, tighten-only)
- Default bind is localhost-only.
- Token auth is required for every mutating endpoint.
- No cloud relay (the F201 philosophy).
- Every API call writes a ledger entry.
- The sandbox/allowlist posture extends to the API layer unchanged.
- Any remote-exposure story is its own later feature with its own
  threat model — never a flag on this one.

## Task slicing
- **T001** Inventory: map every shipped-UI capability to a domain
  operation; publish the surface spec (endpoints, versioning and
  deprecation policy, the exclusion list) as the contract document.
- **T002** Promote/extend ui_server endpoints to the spec: domain
  operations, job/event semantics for long-running work, token auth
  on mutations, ledger entries per call; contract tests pin every
  published endpoint.
- **T003** The shipped UI migrates to the public API only; a test
  proves no privileged side channel remains (the UI's traffic uses
  only published endpoints).

## Acceptance & tests
- The shipped UI consumes ONLY the public API (asserted by test).
- A versioning/deprecation policy exists and is published with the
  contract document.
- Contract tests pin every published endpoint; an unpinned endpoint
  fails the suite.
- A mutating call without a token is rejected; every accepted call
  leaves a ledger entry (tests).

## MCP facet (amendment amend0805-v3, 2026-08-05)
The headless API is also exposed as an MCP server (2026-07-28 spec
line: stateless core, OAuth) offering verify / gate_status /
evidence_bundle as tools, so third-party orchestrators (Claude Code
Agent Teams, Gas Town class) can consume Remedy's gates without
adopting its loop. Allowlist closed-by-default per T8 invariants.

## Non-goals
SDKs, remote multi-user auth, cloud hosting.

## Amendment — DECISION amend1007b D3 (2026-10-07)
Operator's ruling R2 of 2026-10-07: this API is the one bridge a client uses, and Luna is its
first client. The last sentence of the amend1006 section above, which named a file mailbox and a
runner as Luna's transport, is withdrawn: the universe workspace built that mailbox on 2026-10-07,
a review drove its runner against Remedy, and no real order could complete. Where this section and
the text above disagree, this section governs.

This feature moves to directly behind F298 and is built in two features. This one keeps the first
two tasks, for the operations a machine client needs. The third task, the shipped interface's
migration, and the capabilities only the shipped interface uses are split off to F303, which
stands where this feature stood in Luna gate C.

The operations of this feature, each a domain operation in the shape this file binds:
- submit an order (create, then poll or subscribe): the order's text and the fields F295's order
  file carries; Remedy writes the order as a file under its data root and runs it exactly as
  `remedy do <file> --json --no-ui --yes` runs it;
- read the digest of F295 and F298;
- read what changed since a cursor the client holds — orders, jobs, decisions, applies — so a
  client is current without reading everything again; the event stream that exists stays;
- read and answer a decision; approve an apply with its commit and its push; decline a result;
  read the proof;
- read the contract document of F298: its version, the operations, the state words, the refusal
  tokens, the templates and the budget kinds. This is the call by which a client learns what this
  Remedy can do; inside one major version the document only grows.

Binding additions (ruling R3):
- No second server and no second write protocol. The routes are added to the request handler the
  cockpit and the supervisor already share; a write goes through the F009 door as a new command;
  every route calls the function its command-line twin calls, and a test compares each route's
  answer with its command's envelope.
- The supervisor (`remedy serve`, F200) serves the API on a localhost port the configuration
  names, beside its socket, so that a client that is another user of the same machine reaches it.
  Nothing is bound beyond localhost, and nothing here adds TLS or a remote story (F201).
- A client token carries a policy the operator writes: the projects it may order work on, the
  largest limits it may set, and whether it may approve an apply. A call outside the policy is
  refused with its own token; every call writes a ledger entry, as bound above.
- Limits and usage are told in tokens and provider calls (ruling R1).
- A client's tests need the real thing: the supervisor started on a scratch data root with the
  fake providers behaves exactly as the real one, and the contract document says how a client's
  test starts it.

Acceptance, added: F295's gate test and F298's second gate test pass again driven through HTTP
alone; two orders at once never corrupt a record — both run or the second is refused with a
token; a client token outside its policy is refused; the contract document read over HTTP equals
the command's.

## Amendment — DECISION F253 D1 (2026-10-08)
The MCP facet above moves to F303, whose file carries it from this date; this feature builds the
HTTP API alone. The product calls this feature the public HTTP API, published in
`docs/system/public-http-api-v1.md`.

## Amendment — DECISION F253 D21 (2026-10-09)
The binding sentence above that "a write goes through the F009 door as a new command" is met by
the design DECISION F253 D9 chose, which this section records: every write under `/api/v1` runs
the command-line command it twins as a child process of the supervisor and answers that command's
own envelope, and an order and a run are started by the supervisor's own launchers. The F009 door
records a command and never applies one, so a write that applies a result or starts work cannot
pass through it, and running the command itself keeps one copy of each command's logic and
refusals. The rest of that bullet stands. The operator may overturn this ruling.

## Built State (2026-10-09)
Built on `feature/f253-public-http-api` in 27 rounds over six sessions, by DECISIONs F253 D1 to
D25.
- `PUBLIC_API_ROUTES` in `packages/orchestration/public_api.py` publishes the routes under
  `/api/v1`, at version `1.11`. Reads: `GET /api/v1/interface`, `GET /api/v1/digest`,
  `GET /api/v1/jobs/{job}/proof`, `GET /api/v1/changes`, `GET /api/v1/orders/{order}` and
  `GET /api/v1/jobs/{job}/run`. Writes: `POST /api/v1/jobs/{job}/decisions/{decision}`,
  `POST /api/v1/jobs/{job}/decline`, `POST /api/v1/jobs/{job}/apply`, `POST /api/v1/orders` and
  `POST /api/v1/jobs/{job}/run`. Each route names its command-line twin. The contract page
  `docs/system/public-http-api-v1.md` carries the version rule, the exclusion list, how a client's
  test starts a supervisor, and a table generated from the registry that a test holds equal to it.
- `remedy serve` (F200) serves the API on `127.0.0.1`, at the port `REMEDY_SERVE_API_PORT` or the
  configuration names, beside its socket, through the request handler the cockpit shares
  (`packages/orchestration/ui_server.py`, `packages/orchestration/serve_daemon.py`). Every call
  needs a bearer token, the supervisor's own or a client token from `api/clients.json` whose
  policy names its projects, its limits and whether it may apply, and every call writes one line
  to `api/calls.jsonl`.
- A write runs its command-line twin as a child process and answers that command's envelope
  (DECISIONs F253 D9 and D21). An order and a run are started by the supervisor's `OrderLauncher`
  and `RunLauncher` in `packages/orchestration/serve_runs.py` and followed through their GET routes
  or `remedy client order` and `remedy client run`. An order may carry `order_key`, and a resent
  order with the key of an order whose mission has not ended is refused `order_already_running`
  (DECISION F253 D22); an answer that would read `lost` waits up to two seconds for a recorded end
  (DECISION F253 D23).
- `tests/orchestration/test_public_api_gate_paths.py` drives F295's gate path and F304's five paths
  through a real supervisor over HTTP alone.
- The MCP facet and the shipped interface's migration moved to F303 (DECISIONs amend1007b D3 and
  F253 D1). The reserved namespace `apps/api` was deleted by DECISION F253 D25; the HTTP API it
  reserved is this feature's `packages/orchestration/public_api.py`.

Hardening stage (operator amendment amend0930b-slow-cap): 32 statements were audited; 23 had a

# T2_F277 — Machine contracts: event vocabulary, JSON envelope, exit codes
**Tier 2 · Depends on: F275 (which deletes `progress_ledger.py`, holder of one of the two dead readers), F261 (which deletes roughly two thirds of the CLI error sites), F268 (which rewrites `do`) · Blocks/used by: the cockpit, the self-use runner and every `--json` consumer**

> Registered 2026-09-08 by operator order amend0908-brainstorm-intake.
> REGISTRATION ONLY — nothing in this file has been implemented.

## Goal & Done
Three machine-facing contracts stop being conventions and become declarations a test
can read: the event vocabulary written into the run ledger, the JSON envelope every
`--json` command emits, and the meaning of each exit code.

DONE when the Acceptance list holds.

## Why this exists
Measured at `a5bf8949`:

- `RunEvent.event` is a bare `str`. Roughly forty modules read the ledger back by
  literal comparison, and two literals are read and never written anywhere in this
  repository. `packages/orchestration/autonomy_readiness.py::_has_worker_adapters`
  compares against `worker_adapters_listed`, so that readiness dimension has scored
  absent since the day it was written.
  `packages/orchestration/progress_ledger.py` compares against `proof_gap_detected`,
  so its proof-gap branch is unreachable. That module dies with F275; the point of
  recording it here is that the reader must not be re-created.
- `remedy readiness job not-a-uuid --json` prints `Error: invalid job ID: 'not-a-uuid'`
  and exits 1. Not JSON.
- `remedy do plan --json` prints `Error: --task-file is required for planning.` and
  exits 2. Not JSON.
- `apps/cli/grouped.py` calls `handler(args)` with no error boundary, so an uncaught
  exception reaches the operator as a traceback.
- 288 of the catalog's 339 commands declare `supports_json`. There is no `read_only`
  field; the read-only set derived as `not may_mutate_repo and not
  may_execute_commands` holds 320 commands, 49 of which do not declare
  `supports_json`.
- Of a 56-command output sample taken by the 2026-09-08 orchestrator, 30 carried a
  version key and 26 carried none.
- Exit codes 1, 2, 3 and 4 are in use and none of them has a documented meaning.

## Design
One declaration module per contract, each with an AST or catalog test that reads the
code rather than the prose, and each landing before the sites that consume it.

## T001 — The event vocabulary
`packages/orchestration/event_names.py`, dependency-free, in the shape
`model_aliases.py` already uses. An AST test over `packages` and `apps` collects
WRITTEN names (the first argument of `RunLogWriter.log`, `"event"` dict keys,
resolving module-level constants and tuples) and READ names (`e.get("event") ==
<literal>` and set-literal membership), then asserts read ⊆ written ⊆ declared. Red
proof: adding a reader for a name nothing writes reddens it. `RunLogWriter.log`
rejects an undeclared name under a `REMEDY_*` development flag.

The `worker_adapters_listed` reader is either given its writer in the worker command
handler or deleted together with its score contribution. The round decides which and
records the decision; both are correct, and leaving the dimension permanently absent
is not.

## T002 — The JSON envelope and the error boundary
`apps/cli/json_envelope.py` with `emit_ok` and `emit_error` over one shape —
`{"schema_version": 1, "ok": bool, ...}`, `sort_keys=True`. An error boundary around
dispatch in `grouped.py` maps this project's exception base to an exit code and routes
through `emit_error` under `--json` and through the current stderr text otherwise.
A traceback never reaches the operator.

## T003 — The `fail()` helper and the JSON gaps
A shared `fail(code, message, *, json_output)` replaces the `print(...); sys.exit(1)`
pairs, one command group per commit, and only for groups that survive F261. The three
commands that accept `--json` and ignore it are fixed. The set of read-only commands
that do not declare `supports_json` becomes empty, asserted by a catalog test.

## T004 — The exit-code taxonomy and the sweep
The taxonomy is documented under `docs/guides/` and asserted from the catalog.
`tests/cli/test_json_contract.py` sweeps every `supports_json` command reachable
without a positional argument and asserts a parseable envelope on success AND on a
deliberately invalid argument — the invalid-argument half is the one the two examples
above fail today. Catalog-to-dispatch parity is asserted in the same file.

## Acceptance
- `event_names.py` declares every event name; read ⊆ written ⊆ declared holds, and a
  reader for an unwritten name reddens the test (red proof).
- `worker_adapters_listed` either has a writer or has no reader, with a dated DECISION
  naming which.
- Every `supports_json` command emits a parseable envelope carrying `schema_version`
  and `ok`, on success and on an invalid argument.
- An uncaught handler exception produces an envelope under `--json` and a one-line
  stderr message otherwise, never a traceback (red proof: a handler that raises).
- The read-only-without-`supports_json` set is empty.
- Every exit code in use is documented and the documentation is asserted from the
  catalog, not from prose.

## Do not touch
The event names themselves: this feature declares the vocabulary that exists, it does
not rename it. The catalog's command SET, which F261 owns. `progress_ledger.py`, which
F275 deletes — its dead reader is recorded here as history, not as work.

## Orchestrator brief
T001 is independent and lands first. T002 before T003, because the helper the groups
migrate onto has to exist. T004 last: its sweep is the acceptance evidence for T002
and T003 and is meaningless before them. Do not start T003 until F261 has settled which
groups survive — migrating a group F261 deletes is work thrown away.

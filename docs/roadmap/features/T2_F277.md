## Goal & Done
Three machine-facing contracts stop being conventions and become declarations a test
can read: the event vocabulary written into the run ledger, the JSON envelope every
`--json` command emits, and the meaning of each exit code.

DONE when the Acceptance list holds.

## Why this exists
Measured at `a5bf8949`:

- `RunEvent.event` is a bare `str`. Roughly forty modules read the ledger back by
  literal comparison, and two literals are read and never written anywhere in this
  repository. `packages/orchestration/autonomy_readiness.py::_has_worker_adapters`
  compares against `worker_adapters_listed`, so that readiness dimension has scored
  absent since the day it was written.
  `packages/orchestration/progress_ledger.py` compares against `proof_gap_detected`,
  so its proof-gap branch is unreachable. That module dies with F275; the point of
  recording it here is that the reader must not be re-created.
- `remedy readiness job not-a-uuid --json` prints `Error: invalid job ID: 'not-a-uuid'`
  and exits 1. Not JSON.
- `remedy do plan --json` prints `Error: --task-file is required for planning.` and
  exits 2. Not JSON.
- `apps/cli/grouped.py` calls `handler(args)` with no error boundary, so an uncaught
  exception reaches the operator as a traceback.
- 288 of the catalog's 339 commands declare `supports_json`. There is no `read_only`
  field; the read-only set derived as `not may_mutate_repo and not
  may_execute_commands` holds 320 commands, 49 of which do not declare
  `supports_json`.
- Of a 56-command output sample taken by the 2026-09-08 orchestrator, 30 carried a
  version key and 26 carried none.
- Exit codes 1, 2, 3 and 4 are in use and none of them has a documented meaning.

## Design
One declaration module per contract, each with an AST or catalog test that reads the
code rather than the prose, and each landing before the sites that consume it.

## T001 — The event vocabulary
`packages/orchestration/event_names.py`, dependency-free, in the shape
`model_aliases.py` already uses. An AST test over `packages` and `apps` collects
WRITTEN names (the first argument of `RunLogWriter.log`, `"event"` dict keys,
resolving module-level constants and tuples) and READ names (`e.get("event") ==
<literal>` and set-literal membership), then asserts read ⊆ declared and written ⊆ declared, where declared is
`EVENT_NAMES | RETIRED_EVENT_NAMES`. Red proof: adding a reader for a name nothing
writes reddens it. `RunLogWriter.log`
rejects an undeclared name under a `REMEDY_*` development flag.

The `worker_adapters_listed` reader is either given its writer in the worker command
handler or deleted together with its score contribution. The round decides which and
records the decision; both are correct, and leaving the dimension permanently absent
is not.

Amended 2026-09-20 by DECISION F277 D5, after the measurement. The collector found
SIX names read and never written, not two, and they are not one kind of thing. Four
were accidents and are resolved as this paragraph requires: `worker_adapters_listed`
and the readiness half of `patch_intent_reverted` deleted with what they fed,
`approval_decision` repointed at the names the repository writes, and
`command_discovery_completed` given the writer its readers had always named. The
remaining two — `patch_intent_reverted` and `stop_reason_recorded` — are RETIRED:
a dated decision removed each one's writer and kept its readers so that run logs
already on disk keep rendering (DECISION F271 D3 under finding R-0982, and DECISION
F031 D2 and D9). For those, minting a writer would resurrect a mechanism a decision
deleted, which AGENTS.md's "Replacing is deleting" forbids, and deleting the readers
would break the rendering the same decisions preserved. They live in
`RETIRED_EVENT_NAMES`, each entry citing its ruling and naming a reading module,
both asserted by the test. The rule above is therefore unchanged for an accident and
does not reach a retirement.

## T002 — The JSON envelope and the error boundary
`apps/cli/json_envelope.py` with `emit_ok` and `emit_error` over one shape —
`{"schema_version": 1, "ok": bool, ...}`, `sort_keys=True`. An error boundary around
dispatch in `grouped.py` routes through `emit_error` under `--json` and through the
current stderr text otherwise, and exits 1. A traceback never reaches the operator.

Amended 2026-09-20 by DECISION F277 D6, after the measurement. This paragraph said the
boundary maps "this project's exception base" to an exit code. There is no such base:
`RoadmapGrammarError`, `WorktreeError`, `ReviewZipError` and two dozen siblings derive
straight from `Exception` or `RuntimeError` with nothing in common above them, and the
failures that actually reach an operator as a traceback are the undeclared ones —
`KeyError`, `AttributeError`, `OSError`. A base-class boundary would catch the declared
few and let the undeclared many through, which is the opposite of what this slice buys,
so the boundary catches `Exception`. `SystemExit` and `KeyboardInterrupt` pass through:
the first is how every handler in this CLI ends deliberately, and swallowing the second
would make Ctrl-C look like a crash. The exit code is 1 and T004 documents it.

## T003 — The `fail()` helper and the JSON gaps
A shared `fail(error, message, *, json_output, exit_code=1, **payload)` replaces the
`print(...); sys.exit(1)` pairs, one command group per commit, and only for groups that
survive F261. The commands that accept `--json` and answer a failure in prose are fixed.
The set of read-only commands that do not declare `supports_json` becomes empty, asserted
by a catalog test.

Amended 2026-09-20 by DECISION F277 D7, after the measurement. (a) THE SIGNATURE. This
paragraph called the first parameter `code`, which in a function that also carries an exit
code names two different things with one word. It is `error` — the same spelling the
envelope's own key and `emit_error`'s first parameter already use, so one concept keeps one
name — and the exit code is `exit_code`, defaulting to 1 because that is what all but a
handful of the migrated sites pass. `**payload` is carried through to the envelope so a
call site can attach the job id it already knows. `fail` returns `NoReturn`, which is what
makes a call site that writes code after it a type error rather than dead code.
(b) THE NUMBERS THIS SLICE WAS PLANNED AGAINST ARE STALE, AND THE SCOPE IS LARGER, NOT
SMALLER. Measured at `62b40261`: the catalog holds 145 commands, not the 339 the "Why this
exists" section counted, because F261 deleted the rest; 132 of them are read-only by the
derived rule and 33 of those do not declare `supports_json`, not 49; and there are 237
`print(...); sys.exit(...)` pairs across 28 files under `apps/cli/`. (c) "THE THREE
COMMANDS" IS NOT A LIST THIS FILE EVER HELD, AND ONE OF THE TWO IT NAMED IS GONE. The
"Why this exists" section names two of the three by hand and the third is not recoverable;
of the two named, `remedy readiness job` no longer exists, because F261 deleted its whole
group at `2f46e267`, and `remedy do plan --json` still answers a failure the way the
section describes — a JSON body on stdout followed by a bare `Error: ...` line on stderr
and exit 1. This slice therefore does not chase a list of three. It repairs the failure
path at every site it reaches, `do plan` included when the `do` group is migrated, and the
sweep of T004 is what proves the property over the whole surface rather than over three
examples. (d) A SEPARATE DEFECT, FOUND WHILE MEASURING (c) AND FIXED WITH THE READ-ONLY
SET. `init run` and `dev status` each carry a `--json` argument and each honours it in its
handler, yet both declare `supports_json = False` in the catalog. That is a false
declaration rather than an ignored flag: a machine consumer reading the catalog is told
these two cannot answer in JSON when they can.

## T004 — The exit-code taxonomy and the sweep
The taxonomy is documented under `docs/guides/` and asserted from the catalog.
`tests/cli/test_json_contract.py` sweeps every `supports_json` command reachable
without a positional argument and asserts a parseable envelope on success AND on a
deliberately invalid argument — the invalid-argument half is the one the two examples
above fail today. Catalog-to-dispatch parity is asserted in the same file.

## Acceptance
- `event_names.py` declares every event name; read ⊆ declared and written ⊆ declared
  hold, where declared is `EVENT_NAMES | RETIRED_EVENT_NAMES`, and a reader for a
  name neither set holds reddens the test (red proof).
- Every `RETIRED_EVENT_NAMES` entry cites the dated decision that retired it and
  names a module that still reads it, both asserted from the source (DECISION F277
  D5); a retired name that gains a writer moves into `EVENT_NAMES` and one that
  loses its last reader is deleted, both asserted.
- `worker_adapters_listed` either has a writer or has no reader, with a dated DECISION
  naming which.
- An uncaught handler exception produces an envelope under `--json` and a one-line
  stderr message otherwise, never a traceback (red proof: a handler that raises).

Three further bullets stood here until 2026-09-21 — the envelope sweep over every
`supports_json` command, the emptying of the read-only-without-`supports_json` set, and
the documented exit-code taxonomy asserted from the catalog. DECISION F277 D10 moved
them to `docs/roadmap/features/T2_F283.md`, which carries them verbatim, together with
the slices that earn them. They are struck here rather than left standing because an
Acceptance list that names what the feature does not ship is the thing a closure is
supposed to make impossible.

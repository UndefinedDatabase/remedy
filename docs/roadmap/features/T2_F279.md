## Goal & Done
Three things this repository asserts about itself become measurable: which environment
variables exist, which tool versions its ceilings were measured against, and which
checklist items a machine can check instead of a reviewer.

DONE when the Acceptance list holds.

## Why this exists
Measured at `a5bf8949`:

- 82 distinct `REMEDY_*` variables appear as string literals under `packages/`,
  `apps/` and `scripts/`; 48 distinct ones appear under `docs/`; 41 appear in both.
  There is no registry, `remedy doctor` validates none of them, and a typo is
  silently ignored — the variable reads as unset and the default wins.
- No Python lockfile or constraints file exists. Meanwhile
  `packages/orchestration/ci_budgets.py` carries `LINT_ERROR_CEILING = 26`, a ceiling
  on an UNPINNED `ruff`, and the test count floats under an unpinned `pytest`.
  `.github/workflows/ci.yml` pins `python-version: '3.10'` and nothing else.
- `docs/agents/planner_reviewer_prompt.md` §3 carries a frozen pre-emission checklist
  executed by hand on every delegated round — 37 live item numbers at this date.
  Several items are purely arithmetic, and the record shows those are the ones that
  slip.

## Design
Three independent slices sharing one idea: a claim this repository makes about its own
configuration is only true if something reads it.

## T001 — `packages/orchestration/env_registry.py`
One entry per variable — name, type, default, owner, `operator_facing`, description —
populated from the measured set. An AST guard asserts that every
`os.environ[...]`, `os.environ.get(...)` and `os.getenv(...)` whose first argument is
a `REMEDY_` literal is registered. Reads go through `env_registry.get`, so the type
and the default live in one place. `remedy doctor` reports unknown `REMEDY_*`
variables in the environment, naming the closest registered match, and reports
registered variables whose value does not parse as their declared type. A generated
`docs/guides/environment.md` is indexed in `docs/README.md`, with a drift test pinning
it to the registry.

AMENDED 2026-09-23 by DECISION F279 D2, measured at `62c689e1`: the registry is the existing
key registry `_CONFIG_KEY_SPECS` in `packages/orchestration/config.py`, which already carries a
name, type, default and description per variable, so no `env_registry.py` is added. The guard
is `tests/orchestration/test_env_registry.py`, over every literal environment read and over
every whole `REMEDY_*` string literal in `packages/`, `apps/` and `scripts/`.
AMENDED 2026-09-23 by DECISION F279 D4, measured at `0a529d69`: the typed reads go through
`env_value` in `packages/orchestration/config.py`, which parses each variable as its spec
declares; text reads, the standalone scripts under `scripts/` and the two runtime port reads keep
their own, the last two named in the guard with their reason.

## T002 — A pinned toolchain
A committed, hash-pinned constraints file for the `dev` extra on the Python version
`ci.yml` pins. The install step carries `-c constraints.txt`, and
`test_ci_workflow.py` asserts that it does. One test asserts the `ruff` version in the
constraints equals the version `LINT_ERROR_CEILING` was measured against — a ceiling
against a moving linter is not a ceiling. Bounds on `pydantic` and `psutil`.

AMENDED 2026-09-23 by DECISION F279 D1, measured at `c9bc5c20`: `LINT_ERROR_CEILING` no longer
exists (DECISION amend0911-feedback D7 replaced it with zero findings), `ruff` is already pinned
in the `dev` extra, and pip refuses an editable install beside a hashed constraints file. The
slice is therefore: `constraints.txt` generated by `uv pip compile` over the `dev` and `ollama`
extras with `--universal --python-version 3.10 --generate-hashes` and an `--exclude-newer`
cut-off, its header recording the command; CI installs it with `--require-hashes -r`, then
Remedy with `--no-deps -e .`, then runs `pip check`; the `ruff` version it pins equals the
`ruff==` pin in `pyproject.toml`.

## T003 — `remedy block lint <path>`
`packages/orchestration/block_lint.py`, one pure function per checkable item returning
`(item_number, ok, detail)`. It starts with the arithmetic and reference items of §3:
line count, replacement cap, open-set recomputation, quoted gate command exists, no
duplicate R-ids across the live ledger and the archive, and gate ordinal precedes the
claim. Every rule cites its item number and the sentence it enforces. A guard asserts
that no rule references a retired item number. `--json`; exit 1 on any violation.

## T004 — Toolchain refresh
Pinning (T002) freezes versions; this slice is how they move. A maintenance
order file `docs/orders/toolchain-refresh.md` describes a recurring self-use
order: read which pinned packages (the `dev` extra, `pydantic`, `psutil`) have a
newer release, raise the constraints, FETCH THE RELEASE NOTES of every raised
package and place them in the builder's context before it migrates (no model
knows the newest version of a package from training), run the full suite once,
and open a pull request only on green. The self-use generator may mint an item
from this order file no more than once every 14 days. `remedy doctor toolchain`
reports, per pinned tool: installed version, pinned version, newest known
version (network permitting; "unknown" offline, never "0"). The CI matrix runs
the oldest supported Python and the newest stable Python that GitHub's runners
offer; the same order raises both when one of them moves. Nothing in this slice
auto-merges; the human approval gate stays. (Operator question of 2026-09-21,
DECISION amend0921-operator-feedback D6.)

## Acceptance

  adding an unregistered read reddens the guard (red proof).
- `remedy doctor` names an unknown `REMEDY_*` variable in the environment together
  with its closest registered match, and names a registered variable whose value does
  not parse as its declared type.
- `docs/guides/environment.md` is generated from the registry, indexed in
  `docs/README.md`, and a drift test reddens when the registry changes without it.
- A hash-pinned `constraints.txt` exists and pins every package `pyproject.toml` declares,
  with the `dev` and `ollama` extras; CI installs it with `--require-hashes -r constraints.txt`
  before Remedy itself with `--no-deps`, asserted by `test_ci_workflow.py` (DECISION F279 D1).
- The `ruff` version `constraints.txt` pins equals the `ruff==` pin in `pyproject.toml`,
  asserted by a test that names both (DECISION F279 D1).
- `remedy integrity block <path>` returns one result per implemented item, cites the item
  number and sentence for each, exits 1 on any violation, and supports `--json` (DECISION
  F279 D5).
- No `block_lint` rule references a retired §3 item number (red proof: pointing a rule
  at a retired number reddens the guard).
- `remedy doctor toolchain` exists and reports the three columns;
  `docs/orders/toolchain-refresh.md` exists and a docs test pins its section
  headings; a test asserts the CI matrix names exactly two Python versions.

## Built State

Every `REMEDY_*` name production code spells is registered in `_CONFIG_KEY_SPECS` in
`packages/orchestration/config.py`, which DECISION F279 D2 made the registry instead of a new
`env_registry.py`. The guard is `tests/orchestration/test_env_registry.py`: its tests
`test_every_literal_env_read_names_a_registered_variable`,
`test_every_remedy_name_production_code_spells_is_registered` and
`test_every_remedy_name_a_shell_script_expands_is_registered` cover `packages/`, `apps/` and
`scripts/`, and each went red at round 2 or round 3 when an unregistered name was planted.
The typed reads go through `env_value` in the same module (DECISION F279 D4), held by
`test_a_typed_variable_is_read_through_the_registry_reader`. `remedy doctor core` names an
unknown `REMEDY_*` variable with its closest registered match, and names a registered variable
whose value does not parse as its declared type without printing the value; both are asserted in
`tests/cli/test_worker_facade_cmd.py` and in the `TestTheEnvironmentAgainstTheRegistry` class of
the guard file (DECISION F279 D3). `docs/guides/environment.md` is rendered from the registry,
indexed in `docs/README.md`, and held to it by `tests/docs/test_environment_guide.py`.

`constraints.txt` is generated by `uv pip compile`, its header records the command, and it pins
every package `pyproject.toml` declares, with the `dev` and `ollama` extras, each with a hash.
CI installs it with `pip install --require-hashes -r constraints.txt`, then Remedy with
`--no-deps -e .`, then runs `pip check`; `tests/orchestration/test_ci_workflow.py` asserts that
order, and `tests/orchestration/test_toolchain_pins.py` asserts that the pinned `ruff` equals the
`ruff==` pin in `pyproject.toml` (DECISION F279 D1). The file is the one commit of this feature
that is larger than the 500-line cap, declared at round 1.

`remedy integrity block <path>` checks a step block against items 1, 3, 10, 24, 30, 31 and 37 of
the reviewer checklist, prints one result per item with the item's number and the sentence it
enforces, supports `--json`, and exits 1 on any violation (DECISION F279 D5). It lives in
`packages/orchestration/block_lint.py`. `tests/orchestration/test_block_lint.py` holds every rule
to a live item number and to a sentence that item really contains, and its
`test_no_rule_references_a_retired_item_number` is the guard the Acceptance list names.

`remedy doctor toolchain` reports, for every runtime dependency and every tool of the `dev`
extra, the installed version, the pinned version and the newest version the package index knows,
and it writes "unknown" whenever the index was not asked or did not answer (DECISION F279 D6). It
lives in `packages/orchestration/toolchain.py` and is tested in
`tests/orchestration/test_toolchain.py`. The CI matrix runs exactly two Pythons, the oldest one
`pyproject.toml` supports and one current one, which
`test_hosted_workflow_matrix_names_exactly_the_floor_and_one_current_python` asserts.
`docs/orders/toolchain-refresh.md` is written as a job file of five tasks, its headings are held
by `tests/docs/test_toolchain_refresh_order.py`, and the self-use generator queues it word for
word, ahead of every other source, no more than once every fourteen days (DECISION F279 D7).

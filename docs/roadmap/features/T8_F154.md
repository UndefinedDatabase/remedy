# T8_F154 — Gemini CLI adapter
**Tier 8 · Depends on: F151, F152, F153 blueprint · Blocks/used by: F159; vision comparison**

## Goal & Done
The second vendor proves the blueprint scales: a Gemini-CLI adapter
follows the F153 template exactly — research ADR first, recorded
samples, conformance + isolation, live smoke — with vision mapped
ACTIVELY (the image-attachment syntax verified and wired) and
schema support via the tool's response-schema mechanism where
present; the extra proof is one full design-to-code job (the Tier 6
chain) with Gemini as the builder and an honest fidelity report.
DONE when the conformance kit and isolation A/B pass, vision
capability is verified by a probe that round-trips a known image
(declared true only on proof), the design-job proof run archives
its fidelity numbers unvarnished (whatever they are — comparison
material, not marketing), and blueprint deviations (where Gemini's
CLI differs structurally from Codex's) are documented as template
amendments rather than silent forks.

## How it fits (blueprint discipline — the template is the law)
Mirror F153's structure: research ADR (version, flags,
non-interactive mode, output shapes, usage reporting, vision
syntax, isolation mechanism, quirks) → recorded samples →
adapter module → mappings → kit + A/B → live smoke. The
DELIBERATE additions: the vision probe (send a fixture image with
a question only the image answers — the declared capability's
proof, reused by certification), and the design-job proof (the
tier's vision-comparison interest: F088's image-attachment path
exercised on a second vendor end to end — the fidelity loop's
archives become cross-vendor comparison material for the
scoreboard). Template amendments: differences that would improve
F153's structure flow BACK as small orders there (two adapters,
one blueprint — divergence is debt).

## Design (suggested shape)
- `packages/workers/gemini_adapter.py` per the blueprint;
  capabilities: vision from the probe, json_schema via
  response-schema (verified; else the prompt+retry path
  declared), streaming/usage per the researched shapes; the
  error mapping table per its shapes.
- The vision probe: fixture image + the discriminating question →
  the answer must contain the image-only fact (deterministic
  check); recorded for certification reuse.
- The design-job proof: the standard Tier 6 fixture mission run
  with routing pinned to Gemini for builder (config, audited) —
  archives + the honest report filed under the adapter's evidence
  as comparison material.

## Task slicing
- **T001** the research order (ADR + samples + the vision-syntax
  verification) — reviewed before code.
- **T002** adapter + mappings + kit + A/B + the vision probe +
  goldens.
- **T003** live smoke + the design-job proof run (marker-gated) +
  template-amendment orders back to F153 where found + docs.

## Acceptance
- Kit + A/B green; vision declared only with the probe passing
  (a probe-failing fixture forces false). Mapping goldens exact.
  The design-job archives complete with unedited numbers; the
  report's honesty vocabulary intact. Any blueprint divergence
  exists as a documented amendment, not an ad-hoc difference
  (review + grep for structural parity).

## Edge cases & assumption defaults (A9)
- Multi-model CLIs (flash vs pro): capabilities per resolved
  model (the contract's per-pair rule); the registry lists the
  researched models. Rate/limit behaviors differing: the error
  table maps them to the governor's normalized signals — the
  research documents the shapes.

## Orchestrator brief
Strict blueprint mirroring — the T001 order includes F153's ADR
as the template. The probe-gated vision declaration and the
amendments-flow-back rule go verbatim. The design-job proof is a
campaign-style deliverable.

## Do not touch
The blueprint's structure (amend, don't fork), routing gates,
fidelity thresholds. Suggested tests:

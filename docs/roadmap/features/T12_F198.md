# T12_F198 — Prometheus metrics endpoint
**Tier 12 · Depends on: F103, F048, F008 · Blocks/used by: ops integration; F199 SLO basis**

## Goal & Done
See ROADMAP.md F198; the Done criterion there is binding.

## Context (existing code & prior features)
The ui_server has GET infrastructure; numbers live scattered in ledger/queue/state.

## Design
GET /metrics (token-protectable, config-disableable), text exposition format (prometheus_client allowed): remedy_jobs_active{project}, remedy_jobs_total{status}, remedy_pass_rate (window n=50), remedy_cost_eur_total{basis}, remedy_queue_depth, remedy_decisions_open, remedy_decision_wait_seconds (histogram, event-based), remedy_worker_errors_total{adapter,class}. Every value comes from the SAME aggregation layer as the stats CLI (one truth).

## Task slicing
T001 aggregation reuse + the endpoint + format tests (promtool check in CI). T002 auth/disable + fixture reconciliation metrics == ledger/queue.

## Acceptance & tests
promtool validates; the triangle reconciliation with the stats CLI passes; a disabled endpoint 404s cleanly.

## Risks / anti-goals
No push gateway, no metric zoo (the catalog freezes per version; extensions per ADR); no per-person metrics (the F181 principle).

# T1_F019 — Live-Node-Materialisierung (Growing Brain)
**Tier 1 · Abh.: F008, F004, F014 · Blockiert: F020, F023 · Referenz: Teil H, growing_brain.png**

## Ziel & Done
Das Netz wächst live gemäß Ontologie H2: Task-Nodes sprießen beim Planen, Run-/Synapsen-/
Artefakt-Nodes bei Ausführung — einzeln, animiert, in Ereignis-Reihenfolge, rückführbar
auf SSE-Events. Done-Kriterium siehe Masterplan.

## Technologie-Entscheidung (verbindlich, Stufenmodell)
**Stufe 1 (JETZT): `react-force-graph-2d` behalten** — ist bereits Dependency, Canvas-
basiert, d3-force-Layout, unterstützt nativ: `nodeCanvasObject` (eigenes Zeichnen →
Glow/Glyphen), `linkDirectionalParticles` (Partikelfluss = aktive Provider-Calls!),
Zoom-API (`zoom()`, `centerAt()`, `onZoom`) für semantischen Zoom, `d3VelocityDecay`/
Forces-Tuning für das organische Wachsen. Damit sind ALLE H2/H3-Anforderungen ohne
Neuaufbau erreichbar.
**Stufe 2 (Upgrade-Pfad, erst wenn Messung es verlangt):** PixiJS v8 (WebGPU mit WebGL-
Fallback) als Renderer hinter identischem Datenmodell (`brainOntology.ts` bleibt),
Kriterium: <60 fps bei 500 L0-Nodes auf Referenzhardware (F044-Budget) trotz Tuning.
Entscheidung dokumentieren als ADR (F138-Vorgriff, decision-Karte).
**Nicht wählen:** three.js/3D (Lesbarkeit/Screenshot-Fidelity leidet), sigma.js
(WebGL, aber Partikel/Custom-Glow aufwendiger), D3-pur (alles selbst bauen).

## Datenmodell
`apps/ui/src/components/brain/brainOntology.ts`:
```ts
export type NodeKind='job_core'|'task'|'builder_run'|'review_run'|'repair_run'
  |'test_run'|'synapse'|'artifact'|'cluster';
export type NodeState='open'|'planned'|'in_progress'|'pass'|'fail'|'blocked'|'vetoed';
export interface BrainNode{id:string;kind:NodeKind;state:NodeState;parent?:string;
  label:string;seq:number;meta:Record<string,unknown>}
export interface BrainLink{source:string;target:string;active:boolean}
```
Reducer `useBrainStream.ts` konsumiert SSE (F008): `plan.task_created`→task-Node,
`run.started`→run-Node+aktive Kante, `run.tool_call`→synapse (throttled, max 1/300 ms
/Run, Rest aggregiert in Node-meta.tool_count), `artifact.created`→artifact-Node,
`task.state_changed`→state. Backfill beim Mount: `GET /api/jobs/{jid}/graph`.

## Wachstums-Animation
- Neuer Node startet an Eltern-Position mit r=0, animiert zu Ziel-r (spring, 420 ms,
  cubic-out) + kurzer Glow-Puls (opacity 0→.9→.55). Implementation im
  `nodeCanvasObject` via per-Node `bornAt`-Timestamp (kein setState-Storm).
- Reduced-Motion (bestehender Provider): statt Wachstum 200 ms Fade, keine Partikel.

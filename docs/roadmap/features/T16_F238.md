## Design
A plugin = a signed bundle (manifest.json {name, version, slots[], permissions[], publisher} + assets); signature mandatory (the F165 backend, publisher keys). Slots v1: job_panel_tab, node_badge, dashboard_tile. Runtime: a sandboxed iframe (sandbox=allow-scripts; its own origin via srcdoc + CSP; NO allow-same-origin); communication exclusively over a typed postMessage bridge: a read API (curated GET extracts: job summary, task list, own storage quota) and a command API (ONLY catalog commands; every call raises a user confirmation prompt showing command + args - plugins never press buttons themselves). permissions[] declares needed reads/commands; installation displays them (`remedy plugin install|list|remove`; the store is ~/.remedy/plugins/).

## Task slicing
T001 manifest + signature verify + load/sandbox mechanics + tests. T002 the bridge + read/command APIs + the confirmation prompt + escape fixtures (a same-origin attempt, prompt bypass, overbroad reads - all must fail). T003 an example plugin 'ticket link' (reads a job, renders a tile, offers add_comment via the prompt) + third-party docs.

## Acceptance & tests
The example plugin works end-to-end; every escape fixture fails provably; unsigned/tampered bundles refuse to load; the confirmation prompt is unbypassable (E2E).

## Risks / anti-goals
No access to raw evidence files/prompts (curated reads only; v1 stays narrow); slots grow only per ADR; plugins can NEVER block the core (timeouts + isolation; an iframe crash is inconsequential - tested).

# T9_F171 — Secret hygiene v2 & vault
**Tier 9 · Depends on: F085 redaction, F164 commit path · Blocks/used by: F174, F197 content opt-in, F236**

## Goal & Done
See ROADMAP.md F171; the Done criterion there is binding.

## Context (existing code & prior features)
Redaction patterns exist for evidence; diffs and runtime secrets are unprotected.

## Design
Two parts. (1) A diff secret scanner in the commit helper (F164 site): pattern catalog (key formats, private-key headers) + an entropy heuristic per added line; a hit BLOCKS the commit with a precise finding (file:line, pattern); exceptions only via .remedy/policy/secret_allow.toml (commented false positives). (2) A runtime secret provider for F007/F190: secret://<name> references resolved from env or a vault backend (hashicorp/env-file behind one interface), never plaintext on disk. A redaction corpus suite (canary secrets) runs over ALL artifact writers including streams (F004/F236).

## Task slicing
T001 diff scanner + block + allow mechanics + tests. T002 the secret provider + F007 integration + tests. T003 the corpus suite across writers (LARGE, A3).

## Acceptance & tests
Canaries appear in no artifact/stream/commit (corpus green); the block names the exact site; a vault outage is a clean infra fail, never a plaintext fallback.

## Risks / anti-goals
The entropy heuristic stays conservative (false positives are cheaper than leaks; the allow path must be friction-light and documented).

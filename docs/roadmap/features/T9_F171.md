# T9_F171 — Secret hygiene v2 & vault
**Tier 9 · Depends on: F085 redaction, F164 commit path · Blocks/used by: F174, F197 content opt-in, F236**

## Goal & Done
Secrets neither land in commits nor live in plaintext: part one, a
diff secret scanner in the ONE commit helper — a pattern catalog
(key formats, private-key headers) plus an entropy heuristic per
added line — where a hit BLOCKS the commit with file:line and the
pattern named, exceptions only via a commented allow file; part
two, a runtime secret provider resolving secret://<name>
references from env or a vault backend behind one interface,
never plaintext on disk; plus a redaction corpus of canary
secrets running over ALL artifact writers including streams. DONE
when the seeded-secret matrix blocks at commit with precise
findings, exceptions require file+pattern+reason (validated), the
provider resolves references across both backends with values
absent from every artifact (the canary walk), entropy tuning has
a false-positive budget with its log, and the corpus suite is the
standing CI guard over writers.

## How it fits (inspect current shape before building)
The commit helper (F164's consolidation) is the enforcement site
— the scanner is a pre-commit pass over the staged diff's added
lines (fast by construction: only additions, only the commit's
files). The redaction machinery (F085) owns output scrubbing —
part two EXTENDS its reach: the provider hands values to runtime
consumers (DoD commands, compose seeding later) via env injection
at spawn (the exec-guard seam), registering each live value with
the redactor for the process's outputs (values scrubbed even
when a tool echoes them — the canary test's core). Vault backend:
ONE interface (get(name) → value) with env and file-vault
implementations in base; a HashiCorp-style HTTP backend as the
documented extension point (config-selected, small, optional —
the extras stance where a client dependency would appear).

## Design (suggested shape)
- Scanner: the pattern catalog (versioned data: known key
  prefixes/formats, private-key headers, token shapes) + entropy
  per added line (threshold config; the tuning log records
  threshold changes with reasons — the security gate's
  discipline); hit → commit refused {file, line, pattern |
  entropy score}; .remedy/policy/secret_allow.toml entries
  {file, pattern_ref, reason} (reason required).
- Provider: secret://<name> in configs (runtime commands, later
  compose/telemetry consumers) → resolve at use → inject via
  env → register with the redactor for the lifetime; never
  written to any file (a walk over evidence/tmp after fixture
  runs).
- The corpus: canary values planted through every writer path
  (evidence, reports, streams, exports, audit events) — the
  suite asserts absence everywhere; new writers must join (a
  registry the test enumerates — the F157-style completeness
  guard).
- CLI: `remedy secrets check` (scan the worktree diff on
  demand), `remedy secrets list` (names only, sources — never
  values).

## Task slicing
- **T001** the scanner (catalog + entropy + refusal + allow file
  + tuning log) + the seeded matrix + false-positive fixtures.
- **T002** the provider (interface, env/file backends, spawn
  injection, redactor registration, the never-on-disk walk) +
  tests.
- **T003** the corpus suite over the writer registry + CI wiring
  + the CLI + docs + the end-to-end (a run using secret://
  completes; canaries absent everywhere; a seeded key blocks
  its commit).

## Acceptance
- Seeded matrix blocks with precise findings; the clean corpus
  passes under the tuning threshold (the budget documented).
  Exceptions validated (reason required). Provider values absent
  from evidence/tmp/streams (walks + canaries); the echoing-tool
  fixture scrubbed. The writer registry completeness holds (a
  new unregistered writer fails the guard fixture).

## Edge cases & assumption defaults (A9)
- Secrets legitimately IN the target repo (test fixtures with
  fake keys): the allow file per file+pattern with the reason —
  the scanner's findings teach the syntax. Binary additions:
  scanned by pattern only (entropy on binaries is noise —
  documented). Vault outages at resolve time: the honest runtime
  failure naming the reference, never a silent empty value.

## Orchestrator brief
Gate on F164's helper + F085's redactor. The reason-required
and never-on-disk rules go verbatim. T003's writer registry is
the standing guard — its completeness fixture protects the
future.

## Do not touch

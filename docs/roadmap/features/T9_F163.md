# T9_F163 — Prompt->code lineage (audit trail v2)
**Tier 9 · Depends on: F004, F033, F146 (F139 commit trailers) · Enhanced by: F164 full trailer standard (worker/model fields) · Blocks/used by: F165/F168/F169; M10**

## Goal & Done
See ROADMAP.md F163; the Done criterion there is binding.

## Context (existing code & prior features)
prompt traces, hunks (F033) and commit trailers exist; the cross-link hunk->run->prompt->approval is not queryable.

## Design
packages/enterprise/lineage.py: on applying each hunk (the F033/F111 path and the regular patch path) append to jobs/<jid>/lineage.jsonl:
{hunk_id, file, line_span, run_id, prompt_anchor (trace file+offset), worker_id, model, task_id, approval_ref?}. At commit time: an aggregated note to refs/notes/remedy-lineage (json: per file, line spans -> lineage refs). Query `remedy audit lineage <file>[:line] [--at <sha>]`: resolves via git blame + notes to the full chain and renders it on one screen - exactly the auditor question 'which agent wrote this line, with which prompt, who approved'. Integrity: lineage.jsonl in the hash manifest (F060); the notes digest in the certificate.

## Task slicing
T001 writers at both apply paths + jsonl format + tests (LARGE, A3). T002 git-notes aggregation + the audit CLI + blame resolution + fixture-repo tests. T003 verify integration (a tampered note fails).

## Acceptance & tests
The fixture query yields a gapless chain; a human-authored line answers honestly 'not Remedy-generated'; the rebase case documented (notes follow via --at).

## Risks / anti-goals
No prompt FULL TEXTS in notes (anchors only - contents stay in evidence under F166 retention); notes writes batched per commit.

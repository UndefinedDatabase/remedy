# T9_F163 — Prompt->code lineage (audit trail v2)
**Tier 9 · Depends on: F004, F033, F146 (F139 commit trailers) · Enhanced by: F164 full trailer standard (worker/model fields) · Blocks/used by: F165/F168/F169; M10**

## Goal & Done
The auditor's question — "which agent wrote this line, with which
prompt, who approved it" — gets a one-screen answer: every applied
hunk appends a lineage record (hunk id, file, line span, run id,
prompt anchor into the trace, worker id, model, task id, optional
approval ref), commits aggregate the records into git notes
(refs/notes/remedy-lineage), and `remedy audit lineage
<file>[:line] [--at <sha>]` resolves via blame plus notes to the
full chain. DONE when a fixture job yields complete lineage for
every applied hunk (both the hunk-approval path and the regular
patch path — ONE recording seam), the notes round-trip through
clone/fetch documented, the query renders the chain for a line at
historical shas, lineage.jsonl joins the certificate's hash
manifest with the notes digest in the certificate, and records
never contain prompt CONTENT (anchors only — the redaction
posture).

## How it fits (inspect current shape before building)
The applicator is the one write seam (regular patches and the
hunk-approval subset path both materialize through it — verify
the seam covers both; a second materialization path is the
finding to consolidate first). Anchors: run evidence already
stores prompt traces per call — the anchor is {trace file, offset/
segment ref}, resolvable by the provenance machinery (content
stays in evidence under its own retention/redaction rules —
lineage POINTS, never copies). Line spans shift as later commits
edit — that is git's problem by design: the query walks blame to
the WRITING commit, whose note holds the spans as written (the
docs state this model plainly: lineage is per writing commit, not
a live overlay). Worker/model fields arrive fully with F164's
trailer standard; until then records carry what routing evidence
knows (the enhancement note honest).

## Design (suggested shape)
- `packages/enterprise/lineage.py`: record_hunk(...) called at
  the applicator seam → jobs/<jid>/lineage.jsonl (append-only,
  schema-versioned); at the commit helper: aggregate the commit's
  hunks → one JSON note (per file: spans → record refs) attached
  to refs/notes/remedy-lineage.
- Query: blame the line → the writing commit → its note → the
  record → resolve refs (job, task, run, trace anchor, approval)
  → the one-screen rendering (the chain top-down, each element a
  resolvable ref with its resolution badge); --at <sha> blames at
  that sha.
- Integrity: lineage.jsonl in the manifest (F060), the notes
  digest (deterministic serialization) as a certificate claim;
  verify cross-checks.
- Note hygiene: notes ship via the documented fetch refspec (docs
  + a doctor check that the refspec is configured where lineage
  is expected).

## Task slicing
- **T001** the seam verification/consolidation finding + the
  record schema + append at apply + unit tests (both paths, one
  seam).
- **T002** commit aggregation + notes writing + deterministic
  digests + clone/fetch round-trip tests (a bare-clone fixture).
- **T003** the query (blame+notes resolution, --at, rendering) +
  manifest/certificate integration + the end-to-end (a fixture
  job → edit a line later → the query at both shas answers
  correctly).

## Acceptance
- Every applied hunk has exactly one record (both paths); no
  prompt content in records (grep + schema). Notes survive the
  clone fixture with the refspec docs verified. Query goldens at
  current and historical shas; unresolvable elements render the
  staleness badges honestly. Certificate verify covers the notes
  digest (tamper fixture fails naming it).

## Edge cases & assumption defaults (A9)
- Human commits interleaved: no records, and the query says
  "not Remedy-authored" via the trailer absence (F164's audit
  lists them). Squash merges destroying notes: the docs state
  the workflow dependency (the churn feature's stance) — the
  archive export (F166) preserves lineage independently of
  git-note survival.

## Goal & Done
Calm control over a running brain: pause_job halts the whole run,
pause on a node halts one branch — always taking effect before the
next provider call while running calls finish — and resume continues
EXACTLY where things stood, session ids intact. DONE when both scopes
round-trip through the write channel on a live fake job, paused nodes
render their state per the design language, the resumed run provably
reuses its provider sessions where supported, and no pause can strand
a job in an unresumable state.

## How it fits (inspect current shape before building)
Global pause is the kill switch WITHOUT the terminal: reuse the
safe-point machinery (stop file idiom) with a distinct pause control
kind — the runner parks in a paused state (additive job state)
instead of STOPPED, keeping the process's choice honest (v1: the
process exits after persisting paused, resume relaunches — no idle
daemons; the checkpoint/resume path already proves continuation is
exact). Node-level pause is a scheduling mask: the DAG ready-set
computation excludes paused tasks (their downstream shows
waiting-on-paused in evidence, the escalation feature's branch
semantics reused). Session continuity is the resume feature's
contract — cite it, don't rebuild.

## Design (suggested shape)
- Commands pause_job/resume_job, pause_task/resume_task (catalog
  schemas; effects: control files / a paused-task set on the job —
  persisted, additive) through the single write channel; CLI parity
  verbs.
- Semantics table (documented + tested): in-flight provider call
  finishes; nothing new dispatches in the paused scope; budgets keep
  counting wall clock honestly (a paused day is a spent deadline —
  the tick says so); stop beats pause (a stop request on a paused job
  terminates it).
- UI: paused nodes per the design reference's paused treatment; the
  graph chrome shows a global paused banner; the NowCard says
  "paused by you" (ownership vocabulary).
- Resume: consumes the mask/control, recomputes the ready set,
  reuses sessions per capability with resume_used evidence.

## Task slicing
- **T001** control kinds + job/task paused states + safe-point and
  ready-set integration + unit tests (mask math, stop-beats-pause).
- **T002** channel commands + audit + CLI parity + live fake-job
  tests both scopes (call N finishes, N+1 never starts; branch pause
  leaves siblings running).
- **T003** UI states + banner + NowCard line + resume with session
  evidence + the end-to-end (pause mid-build, resume, byte-identical
  final state to an unpaused control run).

## Acceptance
- Both scopes pause before the next call and resume exactly (final
  state equality vs control). Downstream of a paused node waits with
  the reason visible; siblings proceed. Deadline honesty during
  pause asserted. No daemon lingers (process checks).

## Edge cases & assumption defaults (A9)
- Pausing a job that is between cycles: trivially parked. Pausing an
  already-terminal job: refused with the state named. Double pause:
  idempotent. Resume with a pending decision: the decision still
  gates (pause never bypasses approvals).

## Orchestrator brief
Gate on the write channel. T001's semantics table goes verbatim into
the order with one test per row. Reject any implementation that
keeps a paused process alive waiting.

## Do not touch
Kill-switch terminals, checkpoint format, session mechanics.
Suggested tests: tests/orchestration/test_pause_resume.py.

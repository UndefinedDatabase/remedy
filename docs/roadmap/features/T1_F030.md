# T1_F030 — Steering-Nachrichten
**Tier 1 · Abh.: F009, F004 · Referenz: Design-Chat („Please ensure symlink loops…")**

## Ziel & Done
Freitext-Hinweis an laufenden/nächsten Task; Injektion in nächste Builder-Runde;
Evidence-Vermerk. Done: Hinweis nachweislich im Prompt-Trace.

## Design
- Command `steer_task{task_id?, message}` (ohne task_id: aktiver Task) → steering_inbox
  je Task; pingpong_loop liest Inbox VOR jedem Provider-Call und injiziert Block
  `## Operator-Hinweis (verbindlich)\n{msg}` ans Prompt-Ende (volatiler Teil, F105!).
- Feed zeigt User-Nachricht als eigene Zeile (Design: User-Avatar-Zeile); Builder-
  „Antwort" ist KEINE Chat-Antwort, sondern die nächste echte Aktion (Ehrlichkeit —
  kein Pseudo-Dialog; humanize zeigt z. B. „Builder berücksichtigt Hinweis: nächste Runde").
- Rate: max 5 offene Hinweise/Task (dann 429 + UI-Hinweis).

## Task-Schnitt
- T001: Inbox+Injektion+Prompt-Trace-Feld steering_applied[]+Tests.
- T002: Rail-Eingabe scharf schalten (F021-Feld), Feed-Darstellung.

## Akzeptanz & Tests
- Trace enthält Hinweis exakt einmal pro Runde; nach Anwendung als applied markiert.

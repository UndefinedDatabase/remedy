# T3_F108 — Tiered artifact summaries
**Tier 3 · Depends on: F107 · Enhanced by: F113 local generation / F110 cheap-model routing for summary calls · Blocks/used by: long jobs**

## Goal & Done
Huge artifacts stop flooding follow-up prompts: any oversized artifact
(diffs, logs, reports) gets a tiered representation — a short L1
summary, sectioned L2 summaries, and the full reference path — and
prompt assembly consumes L1 plus only the relevant L2 sections. DONE
when a fixture long log enters a follow-up prompt at a fraction of its
size with the reference path present, summaries are generated by the
configured cheap route and labeled, and a missing/failed summary NEVER
blocks the run (full-inclusion fallback under the context budget).

## How it fits (inspect current shape before building)
The context compiler owns selection and budgets; tiered summaries are a
NEW REPRESENTATION it can select instead of full content when an
artifact exceeds a size threshold. Summary generation is a provider
call like any other (evidence, actuals, schema-validated output);
routing it to a cheap/local model is configuration owned by the routing
features — this feature only declares the role summary. Storage: tiers
live next to the artifact in evidence.

## Design (suggested shape)
- Threshold (config, e.g. lines/tokens): oversized artifacts get
  `artifact.summary.json` — {l1: ~200-token summary, l2: [{section,
  span_ref, summary}], full_ref: path, generator: model+basis,
  generated_at} — schema-validated; sectioning is mechanical first
  (diff per file, logs per time/marker blocks), summaries per section.
- Generation timing: lazily on first need (a follow-up prompt wants the
  artifact) — not eagerly for every artifact (cost discipline);
  cached thereafter, invalidated by artifact hash.
- Consumption: the context compiler, when selecting an oversized
  artifact, takes L1 + the L2 sections matching the task's
  files_hint/failure references, plus the full_ref line so the model
  knows more exists (honesty to the model, too).
- Fallback: generation failure → include a truncated head+tail with an
  explicit "[summary unavailable — truncated view]" marker and a
  postmortem-classified note; never silent, never blocking.

## Task slicing
- **T001** schema + mechanical sectioners (diff, log) + storage/caching
  + unit tests (hash invalidation; section spans correct).
- **T002** generation call with the summary role + validation +
  fallback + fake-provider tests.
- **T003** compiler integration (selection rules, relevant-L2 matching)
  + an end-to-end fixture (long log → small prompt footprint, full_ref
  present) + the size comparison recorded.

## Acceptance
- Fixture prompt footprint reduced by an order of magnitude on the long
  log with references intact; relevant sections chosen for a failure
  that names a file. Failed generation → labeled truncated fallback,
  run completes. Regeneration only on artifact change (cache test).

## Edge cases & assumption defaults (A9)
- Binary artifacts: never summarized, referenced by path+size only.
  Artifacts just over threshold: summarizing costs more than including
  — the threshold check compares both and picks the cheaper (a small
  honest heuristic, documented).

## Orchestrator brief
Gate on the context compiler. T001 pure; T002 declares the summary role
— note it for the routing feature's class table. The lazy-generation
rule goes verbatim into T002's order.

## Do not touch
Routing decisions, local-model setup, dossier compression (separate
mechanism). Suggested tests:
tests/orchestration/test_artifact_summaries.py.

## Built State — what F108 delivered

T001-T003 built the full tiered-artifact-summary pipeline described above, gated as planned on the context compiler research (DECISION F108 D2 corrected the integration point after R-0765 found the context compiler never reads a job-evidence artifact at all).

- `packages/orchestration/artifact_summary.py` (T001) - `ArtifactSummary`/`ArtifactSummarySection` schema, `compute_artifact_hash`, mechanical sectioners for diffs and logs, `save_summary`/`load_cached_summary` (hash-invalidated disk cache), and the fallback path (`_fallback_summary`, `FALLBACK_MARKER`, head+tail truncation) for a failed or missing summary.
- Same module (T002/T003a) - `summary_call_fn()` bridges the `"summary"` role (registered in `KNOWN_ROLES`, DECISION F108 D1) into `make_structured_call_fn`; `select_relevant_sections(summary, file_refs)` is the relevant-L2 matching rule (exact `section` string equality, empty on no match - never a silent fallback to everything).
- `packages/orchestration/pingpong_loop.py` (T003b, DECISIONs D3/D4) - the builder's repair-diff branch and the reviewer's scoped-diff branch each replace their flat character-capped diff with a tiered summary once the diff exceeds a threshold, narrowed to the caller's own relevant file set (`prior_findings` for the builder, the scope packet's full `changed_files` for the reviewer). The existing flat-cap truncation stays as the hard backstop underneath. The reviewer's fallback branch (`elif safe_diff:`, reached only when scope-packet construction itself failed) is explicitly deferred, T003b-iii, DECISION F108 D4 - a documented, intentional gap, not an oversight.
- Same module (T003c, DECISION D5) - the tiered diff is persisted to a real, resolvable path under the run's own trace directory (`_pingpong_runs_dir()/<run_id>/calls/<role>/round-NN/tiered_diff.diff`), with T001's hash-invalidated cache wired at both call sites, discharging the feature's own "the reference path present" Done condition.
- T003d (DECISION D6) fixture - `TestTieredSummariesReduceComposedPromptSize` in `tests/orchestration/test_pingpong_cli.py` drives `run_pingpong` end to end with a monkeypatched fake-content author (goal-independent, ~86000 characters) and asserts the real composed-prompt length is under a tenth of the raw diff at both the builder and reviewer call sites - the feature's own "enters a follow-up prompt... at a fraction of its size" Done wording, measured on the real call sites.

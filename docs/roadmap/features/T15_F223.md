# T15_F223 — Best-of-N builds
**Tier 15 · Depends on: F006, F110, F114 · Later integrates: F226 risk-triggered activation (--best-of stays manual until then) · Blocks/used by: a quality lever for risky tasks**

## Goal & Done
See ROADMAP.md F223; the Done criterion there is binding.

## Context (existing code & prior features)
F132 compares REVIEWERS; comparing builds is missing. Worktrees and the cost confirm are the guardrails.

## Design
Trigger: an F226 risk score above threshold OR --best-of N. Mechanics: N parallel candidates (different adapter.model/temperature per router proposal), each in its own worktree; selection is DETERMINISTIC via a documented score function: DoD checks passed > test quota > fidelity (if UI) > smallest diff complexity as the tiebreak. Losing candidates remain inspectable artifacts (diff + scorecard) - learning material + audit. Costs: the F114 confirm above threshold; the budget counts xN honestly.

## Task slicing
T001 candidate orchestration + the score function + the selection protocol + tests (a fixture where candidate 2 objectively wins). T002 trigger coupling (F226/flag) + the UI (a candidate fan on the task node, F026 pattern) + the cost confirm.

## Acceptance & tests
The fixture: candidate 2 wins and the protocol proves each criterion; aborting one candidate never contaminates others (worktree isolation test); the ledger shows xN transparently.

## Risks / anti-goals
No LLM judge in the selection (measurable signals only - the F150 philosophy); N is hard-capped (config, default max 3).

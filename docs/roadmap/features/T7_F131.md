# T7_F131 — Adversarial second review
**Tier 7 · Depends on: F110 routing · Blocks/used by: hard-target quality**

## Goal & Done
Hard targets get a second, hostile pair of eyes: a red-review role
("find ways this diff breaks: edge cases, races, injections") runs
in ADDITION to the standard review for XL tasks, security-labeled
tasks, or under --paranoid — its findings entering the normal
repair flow in the same schema. DONE when the trigger matrix fires
exactly (XL | security label | flag), the red reviewer's prompt is
a distinct conventions-grade document (versioned, capped like the
others), findings merge into the round's repair with their origin
marked (red_review), routing may assign a DIFFERENT model than the
standard reviewer (diversity documented as intent), and cost
accounting shows the second review plainly.

## How it fits (inspect current shape before building)
Pure role addition on existing rails: the review round machinery
runs a second call with the red conventions (a new
docs/agents/red_reviewer_conventions.md under the F105 cap
discipline — extracted intent: adversarial stance, the three named
attack families as STARTING categories, the finding schema
unchanged); routing gains the red_review class (hard rule: never
weaker than the standard reviewer — diversity means equal-or-
stronger different, encoded); triggers read plan metadata (band
XL), task labels (security — the label vocabulary is the plan
schema's, additive), or the job flag. Findings carry origin so
reports/stats can separate the channels (does red review find
things standard missed? — the trust features read this later).

## Design (suggested shape)
- Trigger: evaluate at review time per task; the decision recorded
  (red_review: triggered_by xl|label|flag|none) — silence is also
  evidence.
- The call: same diff/context inputs as the standard review, the
  red conventions segment, same schema; findings tagged origin.
- Merge: both verdicts' findings union into the repair round
  (dedup by identity where both found the same thing — counted as
  agreement, a quality signal); blocking semantics unchanged
  (severity rules the round, whoever found it).
- Routing: red_review class + the equal-or-stronger hard rule +
  the prefer-different-model soft preference (reason recorded when
  honored/violated by availability).
- Cost: the second call is visible per review in the ledger (role
  red_review) and in the report's cost breakdown.

## Task slicing
- **T001** the conventions file (extracted, capped) + the class +
  hard/soft routing rules + tests.
- **T002** trigger matrix + the second call + origin tagging +
  agreement dedup + fixtures (each trigger; both-found dedup).
- **T003** merge into repair + report/stats separation + the
  end-to-end (a seeded race-condition fixture the scripted red
  fake catches → repair round addresses it, origin visible).

## Acceptance
- Trigger matrix exact including none (recorded). Findings merge
  with origin; agreement counted. The routing rules enforced
  (violating config refused; availability fallback recorded).
  Cost rows per role. Conventions under cap, loader-enforced.

## Edge cases & assumption defaults (A9)
- Red review on tiny diffs (XL task, small final diff): runs
  anyway — the trigger is task risk, not diff size (documented).
  Contradictory findings (standard says fine, red says broken):
  both stand; severity mechanics arbitrate action — reviewers
  don't vote, evidence does.

## Orchestrator brief
Gate on routing + the review round seam. The conventions
extraction lists its sources (the F105 discipline). The
equal-or-stronger rule goes verbatim. T003's seeded-race fixture
is the demo of value.

## Do not touch
Standard review mechanics, severity semantics, tournament
machinery (next feature). Suggested tests:
tests/orchestration/test_red_review.py.

## Goal & Done
Human taste enters the loop with pixels attached: on a fidelity
screenshot the human draws rectangles and writes comments, sends
them as a design_feedback command, and the NEXT repair round
receives the cropped regions plus the comments as first-class
findings alongside the machine's. DONE when annotations round-trip
(draw → command → stored → cropped → in the round's prompt with the
images, trace-proven), the findings carry the human actor
(ownership vocabulary), coordinates survive display scaling
exactly, and feedback on stale screenshots (a newer round exists)
is caught and offered against the current shot.

## How it fits (inspect current shape before building)
The loop's round artifacts are the canvas: the annotation targets a
specific rounds/n/shot_*.png by evidence path + hash (staleness =
hash mismatch with the latest round's shot). The command flows
through the single write channel (schema: shot ref {path, hash},
rects [{bbox normalized 0..1, comment}]) — normalization at the
CLIENT (display scaling is the client's problem; the server stores
normalized truth). Injection reuses the visual reviewer's finding
shape: human feedback becomes findings {criterion: from a small
selector the UI offers (default layout), region: "operator-rect-N",
expected: the comment, actual: "see crop", severity: config default
high — the human drew it, it matters}, plus the cropped images
attached via the builder-reference budget rules (crops are small —
they fit).

## Design (suggested shape)
- UI: rectangle drawing on the round-strip's shot view (the
  reference's annotation treatment), comment per rect, a criterion
  selector, send; pending-round state shows "feedback queued for
  the next round".
- Storage: feedback.json per round under the loop's archive
  (versioned; multiple feedback submissions append); crops rendered
  server-side from normalized boxes (deterministic).
- Injection: the next repair round's findings = machine findings +
  human findings (human first — priority is the point), crops as
  image parts where the route has vision, else the crop's region
  description via the established description path (the honest
  fallback chain inherited).
- Staleness: hash mismatch → the command returns the current
  shot's ref with "the run moved on — re-annotate on the current
  round?" (the client re-renders; nothing silently re-targets).
- Ownership: entries land in the ledger ("You flagged 2 regions on
  round 3").

## Task slicing

- **T002** injection (human-first findings, crops via the budget

- **T003** the drawing UI + queued state + ownership entries + the

  crop → the repair addresses the region — scripted fake asserts

## Acceptance
- Round-trip exact at scaling factors (property test on
  normalization). Human findings precede machine findings in the
  round's prompt; crops attached or described per route
  (trace goldens). Stale annotation caught with the re-offer.
  Ownership sentence golden.

## Edge cases & assumption defaults (A9)
- Feedback arriving mid-round: queued for the round AFTER the
  in-flight one (round boundaries are the delivery points — the
  steering rule). Rects outside the image: clamped with a client
  warning. Many rects: a per-submission cap (config) keeps prompts
  sane; the UI says so.

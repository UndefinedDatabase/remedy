# T2_F105 — Cache-optimal prompt ordering
**Tier 2 · Depends on: F003 cache metrics · Blocks/used by: all prompt builders, F071, F118**

## Goal & Done
See ROADMAP.md F105; the Done criterion there is binding.

## Context (existing code & prior features)
Prompts are assembled ad hoc; cache reads are luck. The conventions segment
has no canonical source yet; role rules live implicitly in code and heads.

## Design
Prompt-compiler rule: stable prefixes first (system, conventions, dossier, cards), volatile parts last (task, steering). `prompt_segments.py` registry with stability ranks; cache_read share measured per role in the ledger.
Canonical conventions content: `docs/agents/worker_conventions.md` (worker/builder role) and `docs/agents/reviewer_conventions.md` (review role), each hard-capped at ≤800 tokens; the registry loads the role's file verbatim as the conventions segment. The orchestrator's conventions segment remains the generated Part A block (F070) — no second source. `docs/agents/model_routing_policy.md` is policy input for F110, NOT a prompt segment.

## Task slicing
T001 registry + compiler rework (LARGE, A3: touches every prompt producer). T002 cache-share measurement + report. T003 conventions segment wiring: load docs/agents/ per role, token-cap lint, goldens extended.

## Acceptance & tests
Cache share measurably rises vs. the recorded baseline in the benchmark; role golden prompts guard semantics. Additionally: worker and reviewer prompts provably contain their docs/agents conventions segment at a stable prefix position; a conventions file exceeding 800 tokens fails the lint.

## Risks / anti-goals
No reordering that changes meaning - goldens are the tripwire. Conventions files stay lean; they are prompt payload, not documentation (P4). No new rule taxonomies beyond the two role files (A6).

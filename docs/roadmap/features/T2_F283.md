## T001 — The refusal sweep (carried over from F277's T003, the part not applied)
F277's T003 reads, and the text below is that slice verbatim:

> A shared `fail(error, message, *, json_output, exit_code=1, **payload)` replaces the
> `print(...); sys.exit(1)` pairs, one command group per commit, and only for groups that
> survive F261. The commands that accept `--json` and answer a failure in prose are fixed.
> The set of read-only commands that do not declare `supports_json` becomes empty, asserted
> by a catalog test.

DECISION F277 D7, which amends that slice, travels with it whole and is not re-decided here:
the signature is `error` and `exit_code` and never `code`, `fail` returns `NoReturn`, and
the slice repairs the failure path at every site it reaches rather than chasing a list of
three. DECISION F277 D8 (a token is named for the CONDITION) and DECISION F277 D9 (a
catch-all exception gets a catch-all token named for the layer that refused) are the token
rules the remaining groups follow.

What F277 already applied, and what is therefore NOT in scope here: the nine modules its
Built State names.

`apps/cli/commands/runtime_cmd.py` is its own round and is the hardest of what remains: its
refusal sites sit behind a local `_fail` prototype, use exit codes 2 to 5, and carry an
`error_class` key that is a contract with the supervisor SUBPROCESS and with
`packages/runtimes/dev_server.py` — so `error_class` survives the migration rather than
folding into the envelope's token.

## Built State
What F283 has on disk after round 21, so a later reader need not reconstruct it from the
ledger. Two new files this feature added, since a closure precondition asks this file to
name a new module: `apps/cli/exit_codes.py`, the exit-code taxonomy's two tables, and
`tests/cli/test_json_contract.py`, the sweep that is the acceptance evidence for T001 and
T002 alike.

**Acceptance line 1 — every `supports_json` command emits a parseable envelope carrying
`schema_version` and `ok`, on success and on an invalid argument.** MET.
`tests/cli/test_json_contract.py` sweeps both halves: the INVALID half runs all 144
`supports_json` catalog commands with one unrecognised option and asserts an envelope with
`ok` false at exit 2; the SUCCESS half runs the 33 commands that need no positional
argument, are `read_only`, and are not excluded by name (`ui.stop` is the one exclusion,
under finding R-1034) and asserts an envelope with `ok` true. Both halves assert the output
parses as one JSON object, that it carries `schema_version` 1 and a boolean `ok`, and that
the exit code is 0 if and only if `ok` is true (DECISION F283 D13). Content beyond the
envelope shape is pinned by the per-module tests landed one command group per commit across
rounds 1 through 21, not by the sweep, which deliberately prepares no project, job or ledger
(D13 (6)).

**Acceptance line 2 — the read-only-without-`supports_json` set is empty.** MET, closed at
round 16 (`488fd05a`). `tests/test_command_catalog.py::TestReadOnlyWithoutSupportsJSONRatchet`
asserts the derived set equals the empty constant, red-proved by a handler that declares
`read_only` without `supports_json`.

**Acceptance line 3 — every exit code in use is documented and the documentation is
asserted from the catalog, not from prose.** MET at round 20 (DECISION F283 D12). The
meanings are written once as two tables in the module `apps/cli/exit_codes.py`: the CLI's
own (0 `ok`, 1 `failed`, 2 `usage`, 3 `not_ready`, 4 `environment`) and the `runtime` group's
own contract beside it (2 `config`, 3 `start`, 4 `ready`, 5 `state`), which a process outside
the CLI reads and which D12 therefore leaves unrenumbered. The guide `docs/guides/exit-codes.md`
carries both tables and one row per command that declares more than the floor `(0, 1, 2)`.
`CommandEntry.exit_codes` declares each command's codes in the catalog, and
`tests/cli/test_exit_codes.py` reads every handler statically and asserts the codes above the
floor it reaches equal the codes above the floor it declares, with every declared code
resolving to a meaning in its group's table.

**R-1019 — RESOLVED at F283 round 8**, C7 `4048f470`. `_cmd_worker_unload` now checks for
`--model`/`--all` immediately after the provider check and before `shutil.which("ollama")`,
so the `missing_argument` refusal no longer depends on whether the provider is installed.

**R-1020 — RESOLVED at F283 round 4**, C3 `ea17a50b` through C8 `aa5e1c40`, on the layer
round 3's C3 `6ce6a67c` landed. No module under `apps/cli/` calls
`packages.orchestration.data_paths.resolve_job_id` any more; the fourteen `supports_json`
commands that reached it now answer through `apps/cli/job_id_arg.py::resolve_job_id_or_fail`,
and the strict xfail pinning the gap went green with its mark removed.

are finished and one is half applied: the `fail()` helper exists and nine CLI modules call

are still a non-empty set, and no exit code has a documented meaning.

## T001 — The refusal sweep (carried over from F277's T003, the part not applied)
F277's T003 reads, and the text below is that slice verbatim:

> A shared `fail(error, message, *, json_output, exit_code=1, **payload)` replaces the
> `print(...); sys.exit(1)` pairs, one command group per commit, and only for groups that
> survive F261. The commands that accept `--json` and answer a failure in prose are fixed.
> The set of read-only commands that do not declare `supports_json` becomes empty, asserted
> by a catalog test.

DECISION F277 D7, which amends that slice, travels with it whole and is not re-decided here:
the signature is `error` and `exit_code` and never `code`, `fail` returns `NoReturn`, and
the slice repairs the failure path at every site it reaches rather than chasing a list of
three. DECISION F277 D8 (a token is named for the CONDITION) and DECISION F277 D9 (a
catch-all exception gets a catch-all token named for the layer that refused) are the token
rules the remaining groups follow.

What F277 already applied, and what is therefore NOT in scope here: the nine modules its
Built State names.

`apps/cli/commands/runtime_cmd.py` is its own round and is the hardest of what remains: its
refusal sites sit behind a local `_fail` prototype, use exit codes 2 to 5, and carry an
`error_class` key that is a contract with the supervisor SUBPROCESS and with
`packages/runtimes/dev_server.py` — so `error_class` survives the migration rather than
folding into the envelope's token.

## Acceptance
Carried from F277, whose own Acceptance list drops them in the same commit that registers
this file:
- Every `supports_json` command emits a parseable envelope carrying `schema_version`
  and `ok`, on success and on an invalid argument.
- The read-only-without-`supports_json` set is empty.
- Every exit code in use is documented and the documentation is asserted from the
  catalog, not from prose.
- R-1019 is resolved: `worker unload` with neither `--model` nor `--all` refuses with
  `missing_argument` whether or not `ollama` is on PATH.
- R-1020 is resolved: no `supports_json` command reaches a shared helper that prints a
  refusal and exits, and the strict xfail pinning that gap is green with its mark gone.

## Findings this feature owns
R-1014, moved from F277 by DECISION F277 D10 — the §3 consolidation pass its fix clause
asks for is F277's closure work, and whichever half of it F277's closure does not land is
this feature's. `.agent/live_review.md` is append-only, so its entry keeps its old owner
line and the move is recorded by that DECISION and by F277's closure re-assignment.

R-1019, registered at F277's Open PR Gate on 2026-09-21 and assigned here under operator
amendment amend0911-feedback rule A — `_cmd_worker_unload` probes `shutil.which("ollama")`
before it checks that a target was named, so a malformed invocation answers with a success
envelope and exit 0 on any machine without the provider installed. That is refusal shape,
which is this feature's T001.

R-1020, registered at this feature's round 2 authoring dry run on 2026-09-21 — for 52 of
the catalog's 111 `supports_json` commands the refusal that fires is in a shared EXITING
helper under `packages/` (`resolve_job_id`, `_exit_ambiguous`, `require_job_plan`), which
prints prose and exits before the handler's own failure path. It is the reason T001's
Acceptance line cannot be met by migrating `print(...); sys.exit()` pairs inside
`apps/cli/` alone, and its repair comes BEFORE T001's catalog half.

## Do not touch
The event names themselves and `packages/orchestration/event_names.py`: F277 declared that
vocabulary and this feature does not rename it. `apps/cli/json_envelope.py`'s shape — the
envelope, its two reserved keys and `fail`'s signature are F277's contract, and a change to
them is a new decision, not a sweep. The catalog's command SET, which F261 owns.

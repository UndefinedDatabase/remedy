## Context (existing code & prior features)
F193 built axe integration for TARGET projects; the cockpit itself is unaudited; the canvas graph is inherently inaccessible.

## Design
The axe suite (the F193 runner turned on our own UI) covers the core screens (cockpit, inbox, job plan, digest, cards) as a CI gate at level AA. The graph alternative: a structured list per zoom level (L0: tasks with status/progress; L1: children of the focused task) as real DOM parallel to the canvas (a toggle; automatic for screen readers via roles/aria), the feed with aria-live=polite (throttled), a focus order + a visible focus ring (the token --remedy-focus), evidence-triple cards with correct labels. Playwright + aria-snapshot tests cover the decision flow entirely through screen-reader semantics.

## Task slicing
T001 the axe CI gate + fixing findings across core screens (a LARGE task, A3: many small fixes across components). T002 the list alternative + aria-live + the focus system + the screen-reader E2E of the approve flow.

## Acceptance & tests
axe AA passes on core screens (CI); the decision E2E works purely via keyboard + screen-reader semantics (aria snapshots as goldens); default-token contrast passes the F193 matrix.

## Risks / anti-goals
No a11y claims beyond audited screens (docs list the scope); the list alternative is first-class, not an alibi (an action-parity test proves equal capabilities).

# T1_F034 — Bundled clarification in the Flight Plan
**Tier 1 · Depends on: F013, F014 · Blocks/used by: unattended runs (P7/A9)**

## Goal & Done
See ROADMAP.md F034; the Done criterion there is binding.

## Context (existing code & prior features)
Runtime questions would kill unattended self-build; ambiguity handling must be front-loaded.

## Design
Intake/planner classify gaps: blocker (contradictory/mandatory-missing) -> clarifications[] answered ONCE in the plan (numbered block, one submit -> approve_plan with answers{}); default_ok -> assumption_log entry {topic, default, source: reference|convention|token} in task evidence. Builder prompt header: 'Ask no questions. On ambiguity: the reference verbatim; otherwise a documented default in the assumption_log.'

## Task slicing
T001 classification + assumption_log writer + a 3-ambiguity fixture. T002 clarification block UI/CLI + answer embedding into task prompts.

## Acceptance & tests
3 ambiguities -> 1 block, 0 runtime questions; a lint over prompt traces finds zero ask-the-user patterns.

## Risks / anti-goals
Never resolve blockers by guessing; never ask at runtime - both directions are hard failures of this feature.

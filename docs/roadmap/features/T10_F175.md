# T10_F175 — Identities & roles
**Tier 10 · Depends on: F141 · Blocks/used by: all of Tier 10; F185**

## Goal & Done
See ROADMAP.md F175; the Done criterion there is binding.

## Context (existing code & prior features)
F141 has the single enforcement point require(action) with an action x level matrix; the person dimension is missing. The ui_server knows one bearer token.

## Design
packages/org/identity.py: User{id, name, roles: operator|reviewer|viewer, tokens}. Stage 1: ~/.remedy/users.toml, per-user tokens (`remedy user token issue <id>`). The F141 matrix gains a third dimension: require(action, level, role). Role semantics documented: viewer = GET only; reviewer = + decisions/reviews/card approvals; operator = everything incl. stop/policy. Single-user mode stays the default (implicit operator) - zero added friction for existing users.

## Task slicing
T001 identity + users.toml + token issuance + tests. T002 the matrix extension + wiring at require() callers (mechanical; ONE enforcement point remains) + a role test matrix.

## Acceptance & tests
The action x role matrix is fully tested; a viewer token provably cannot send any command (403 + audit entry); single-user regression: all old tests green without users.toml.

## Risks / anti-goals
No own password management (tokens + OIDC in F176); keep the role list small - extensions only per ADR.

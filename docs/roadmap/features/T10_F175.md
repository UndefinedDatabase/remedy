# T10_F175 — Identities & roles
**Tier 10 · Depends on: F141 · Blocks/used by: all of Tier 10; F185**

## Goal & Done
Remedy learns who is asking: identity.py defines User {id, name,
roles: operator | reviewer | viewer, tokens}; stage 1 stores users
in a users.toml with per-user tokens (`remedy user token issue
<id>`); the permission matrix gains its third dimension —
require(action, level, role) — with role semantics documented
(viewer = GET only; reviewer = plus decisions/reviews/card
approvals; operator = everything including stop/policy); and
single-user mode stays the default with an implicit operator —
zero added friction for existing users. DONE when the user store
round-trips with hashed tokens (never plaintext at rest), the
matrix's role dimension enforces the documented semantics per
cell (the three-role test sweep over exposed actions), token
issuance/revocation work with audit entries, single-user mode
provably changes nothing (the regression sweep), and — a
placement correction — the store lives under the DATA ROOT's org
area, not a home dotfile.

## How it fits (a placement correction + the matrix evolution)
The old draft wrote ~/.remedy/users.toml — corrected to
<data_root>/org/users.toml (the established convention; org state
is machine-scoped data). The matrix (F141) was built as the ONE
gate — the role dimension is a signature evolution:
require(action, context) grows role in the context (defaulting to
operator in single-user mode — the implicit-operator rule made
structural), and the table constant becomes action × level × role
with the documented collapse: viewer rows are deny-all-mutations
regardless of level (roles cap what levels grant — the
composition rule stated and tested). Token auth: the UI server's
existing bearer story gains user resolution (token → user);
hashing at rest (a standard KDF via stdlib hashlib — no new
dependency), constant-time comparison, fingerprints in audit
(the channel's rule upgraded to real identity).

## Design (suggested shape)
- `packages/org/identity.py`: the store (load/validate users.toml,
  hashed tokens, unique ids), resolve(token) → user, issue/revoke
  commands (revocation immediate — the session/token check reads
  live), audit entries for lifecycle actions.
- Role semantics as a documented table (the customer-facing
  doc + the matrix rows generated consistently — the F141
  render-from-constant discipline extended).
- Matrix evolution: the third dimension + the roles-cap-levels
  composition rule + per-cell tests for the exposed action set ×
  three roles × boundary levels.
- Single-user: no users.toml → implicit operator everywhere
  (resolve returns the implicit user; audit says operator as
  today) — the regression sweep proves byte-level indifference
  on existing fixtures.
- Multi-user activation: the file's presence flips the mode
  (explicit, inspectable); a lone user in the file is still
  multi-user semantics (their token required) — documented.

## Task slicing
- **T001** the store (data-root placement, hashing, validation,
  issue/revoke, audit) + unit tests (plaintext-at-rest grep,
  constant-time comparison, revocation immediacy).
- **T002** the matrix's role dimension + the composition rule +
  the three-role sweep + docs generation.
- **T003** resolution wiring at the auth seam + single-user
  regression sweep + the end-to-end (issue a reviewer token →
  their decision answer lands person-precise at the matrix's
  allowance; a viewer's mutation refused citing the cell).

## Acceptance
- No plaintext tokens at rest (grep + store fixture).
  Role×level×action sweep matches the documented table; the
  roles-cap-levels rule proven (an operator-level action denied
  to a reviewer at L5). Single-user fixtures byte-identical.
  Revocation takes effect on the next request. Docs render from
  the constant.

## Edge cases & assumption defaults (A9)
- Users with multiple roles: the union of allowances (documented;
  the sweep includes a dual-role fixture). Token loss: revoke +
  reissue is the story (no recovery of hashes — stated). The
  operator lockout risk (revoking the last operator): refused
  with the honest message (an org needs one operator —
  invariant).

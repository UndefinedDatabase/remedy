# T10_F186 — Human-to-human handoff package
**Tier 10 · Depends on: F178, F053, F035, F079 pattern · Blocks/used by: vacation/shift changes; M11**

## Goal & Done
Shift changes stop losing context: `remedy handoff human
[--project|--mission]` renders handoff_<date>.md — open decisions
WITH their evidence triples and current recommendation state,
running jobs in the interim short form, recent ownership entries,
active policies and autonomy levels, and 'recommended next
actions' aggregated from existing report recommendations — with
recipient quality measured like F079: ten state questions, target
at least nine answerable from the package alone. DONE when the
package renders complete on fixture states (each section from its
real source, goldens), triples and recommendations appear verbatim
(no summarizing away the substance — the fidelity rule),
scoping (--project | --mission) selects exactly, the ten-question
list is a committed artifact evaluated against fixture packages
(the F079 discipline reused), the package is a pure read, and
person-precision makes the 'who was carrying what' section real
(assignments, delegations, away states — the F178 data rendered
for a successor).

## How it fits (pure composition — the sources all exist)
Every section reads a finished feature: open decisions from the
queue (entries + triples + the assignment/delegation state —
F178's fields are exactly what a successor needs: "these three
are assigned to the person you're replacing"), running jobs via
the interim summary form (F053's short form per job — imported,
not reimplemented), ownership from the ledger/aggregation
(recent window, person-precise), policies/levels from their
stores (autonomy level, applied pack@version, active loops),
next actions from report recommendation sections (the harvest:
latest report per active job, its recommendations block —
provenance-linked). The quality gate reuses the F079 pattern
verbatim: a committed question list ("what is blocked and why",
"what decisions await whom", "what would you do next", ...)
scored against the package by review (and by the scripted
answerability check where questions map to sections).

## Design (suggested shape)
- `remedy handoff human`: scope resolution → section builders
  (each pure, each returning md + source refs) → assembly with
  the date/scope header + the successor preamble (one paragraph:
  what this is, how fresh, where the live views are — links into
  the cockpit).
- The decisions section: per open decision — the ask, the triple
  verbatim, assignee/delegation state, age, the deep link;
  ordered by blocking impact (blocked jobs first — the
  documented order).
- Fidelity rule: triples and recommendations are QUOTED blocks
  (structure-preserved), never paraphrased — the renderer copies
  (the grep-able discipline: source text appears byte-equal).
- Freshness: every section stamps its source read time; the
  package header states "a snapshot — live state supersedes"
  (honest decay).
- The question list: docs/org/handoff_questions.md (ten,
  committed, versioned); the answerability check maps questions
  to required sections/fields (structural: a package missing a
  mapped section fails).

## Task slicing
- **T001** section builders (decisions with F178 state, jobs via
  F053 import, ownership window, policies/levels) + fidelity +
  goldens.
- **T002** next-actions harvest (latest reports, recommendation
  blocks, provenance links) + assembly + scoping exactness +
  the pure-read proof.
- **T003** the question list + the structural answerability
  check + the review-scored fixture evaluation (≥9/10) + docs +
  the end-to-end (a busy fixture state → the package answers
  the successor's morning).

## Acceptance
- Section goldens with byte-equal quoted triples/recommendations
  (the fidelity grep). Scoping exact. Freshness stamps present;
  the snapshot disclaimer renders. The structural check fails on
  a doctored package missing a mapped section; the fixture
  evaluation documents ≥9/10. Pure read (state diff).

## Edge cases & assumption defaults (A9)
- Quiet states (nothing open, nothing running): the package
  says so plainly per section — a calm handoff is a valid
  handoff. Mission scope spanning projects the recipient can't
  access: the package renders per the GENERATOR'S access;
  the header names the scope so mismatches surface (access is
  the reader's own problem at the live links — stated).
  Sensitive content: the package inherits report-level
  redaction (it's a report sibling).

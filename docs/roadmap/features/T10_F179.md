# T10_F179 — Node comments
**Tier 10 · Depends on: F177, F023 L3 · Blocks/used by: F180 reviews; team context**

## Goal & Done
Teams can talk WHERE the work is: add_comment {target: {task | run
| artifact, id}, body_md, anchor?} stores to jobs/<jid>/
comments.jsonl (append-only; delete = an author tombstone),
renders as sanitized markdown with anchors clicking into diff
hunks/artifacts, shows as a comments tab in the EvidencePanel plus
a subtle counter badge on nodes, and joins reports via
--with-comments as a discussion appendix. DONE when the command
round-trips person-precise with validation (target exists, anchor
resolvable at write), tombstone deletion hides content while
preserving the audit fact (author+time remain), the sanitizer is
the SHARED one (F041 — one sanitizer home, import-guarded),
anchors resolve into the diff viewer/artifact views (the
provenance click paths), badges follow the graph's restraint
discipline (F126 — counts, never content, on nodes), and the
report appendix renders threads in stable order.

## How it fits (inspect current shape before building)
Storage follows the append-only JSONL discipline (schema-versioned
entries {id, author, ts, target, anchor?, body_md, parent? for
one-level replies, tombstone?}); the write channel carries the
command (person precision free via F177). Anchors reuse the
provenance vocabulary: a diff-hunk anchor is {task, hunk id} (the
hunk-approval addressing), an artifact anchor is {evidence path,
optional line} — resolution via the established resolver with
staleness badges when evidence was pruned (honest decay).
Rendering: the EvidencePanel gains the tab (component per the
reference's panel treatments); the node badge is a count chip in
the L3 detail zoom only (restraint: L1/L2 stay clean — the F126
rule applied). The sanitizer import: comments are user content on
a served surface — the F041 pipeline verbatim (its tests extended
with comment fixtures).

## Design (suggested shape)
- Command + validation (target/anchor at write; body size cap
  config; rate-friendly — no flood guard in v1 beyond the cap,
  team trust stated).
- Threading: parent? one level (replies flat under a root —
  bounded complexity, documented); ordering by ts stable.
- Tombstones: delete_comment {id} author-or-operator only
  (matrix cells); the entry gains tombstone {by, ts}; renderers
  show "comment removed by author" (the audit fact visible,
  content gone — grep the store: content remains in the JSONL
  history by append-only nature, so tombstone REPLACES rendering
  only; a true content-erasure variant (privacy/legal) is the
  operator command redact_comment writing a redaction entry AND
  the rendering rule — both documented, the stronger one
  audited).
- UI: the tab (list + composer + anchor pickers from the current
  diff/artifact selection), the L3 badge, deep links (a comment
  URL opens the panel at the thread).
- Report: --with-comments appends threads grouped by target with
  anchors as links (the provenance rendering).

## Acceptance
- Round-trip person-precise; invalid targets/anchors refused at
  write. Tombstone hides content, keeps the fact; redaction
  removes content with the audit entry. One sanitizer (import
  guard + corpus green on comments). Badges only at L3 (the
  restraint test). Report appendix golden with resolving links.

## Edge cases & assumption defaults (A9)
- Comments on pruned evidence: the thread persists; anchors
  render the staleness badge (the resolver's honesty). Editing:
  v1 has no edit — delete + repost (simplicity, documented);
  the tombstone chain keeps history honest. Cross-job comments:
  out of scope (targets are job-scoped, stated).

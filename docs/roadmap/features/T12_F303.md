## Goal & Done
Everything the shipped cockpit can do is reachable through the public API of F253, and the cockpit
itself consumes only that API. DONE when every capability of the shipped interface is mapped to a
published operation, the cockpit's traffic uses only published routes (a test proves no privileged
side channel remains), and contract tests pin every published route.

## Task slicing
- T001 — Inventory: every capability of the shipped interface that F253 did not publish for the
  machine client, mapped to a domain operation and added to the contract document.
- T002 — The routes for them, on the same request handler and the same write door, with contract
  tests.
- T003 — The cockpit migrates to the published routes only, and the routes it used before are
  deleted in the same feature (replacing is deleting).

## Acceptance
As F253's own acceptance lines about the shipped interface: it consumes only the public API, an
unpinned route fails the suite, and no route outside the contract document is served.

The cockpit's logs view, moved here from F203 by DECISION F203 D5: the cockpit's view of a run
gains a logs button that reads `GET /api/v1/jobs/{job}/logs?run=<run id>` and shows that run's
operations-log lines, oldest first.

R-1329, moved here from F307 by DECISION F303 D1: `POST /api/v1/jobs/{job}/note` takes a
steering note for one task of a job, twinned with `remedy job steer` and held to a client
token's projects, and the story's `note_open` reads whether the job takes a note now.

## Do not touch
F253's binding shape and security constraints, which hold here unchanged.

# T6_F097 — Component catalog
**Tier 6 · Depends on: F093, F117 · Blocks/used by: reuse economy**
> **CANONICAL DESIGN REFERENCE:** This feature MUST follow the canonical Remedy
> UI design reference in `docs/ui/design_reference/`. `ux_design.png` is the
> visual authority; the written specs, tokens, component rules, graph rules and
> motion rules in that folder are binding for this feature. Builders must not
> invent a new visual language; any visual deviation must be documented in the
> assumption_log with a technical reason. All UI work uses the shared design
> tokens (`--remedy-*`) and component rules from the design reference.
> **ASSET REFERENCE:** fonts, icons, graph glyphs, logo and visual assets
> follow `assets_spec.md` in the same folder (the asset authority). No new
> font, icon library, glyph style, logo treatment or asset source may be
> introduced unless `assets_spec.md` is updated and the deviation is
> documented in assumption_log with a technical reason.

## Goal & Done
Fidelity that passed once becomes reusable capital: components that
PASSED the fidelity loop are extracted — TSX+CSS, a screenshot, a
props doc — into the target repo's design-system area, a gallery
route in the cockpit browses them, and follow-up jobs receive the
catalog index as a stable prompt block; optionally each component
mirrors as a component card. DONE when a loop-passed fixture
component extracts with all four artifacts, the gallery renders the
catalog per the design reference, the prompt block provably reaches
follow-up builder prompts at its stable rank, extraction is
proposal-gated (the human curates the design system), and the
catalog index stays deterministic.

## How it fits (inspect current shape before building)
Placement follows the curated-knowledge rule: components live IN
THE TARGET REPO at `.remedy/design_system/components/<name>/`
(they are the project's capital, travel with it, appear in PRs) —
writes flow through jobs/the applicator within fences like all
target changes; the EXTRACTION itself is a proposal (a harvest-kind
idea: "promote component X to the design system" with the loop's
pass evidence) so the human decides what becomes canon (the F061
promotion spirit). The prompt block is a segment (catalog rank near
the conventions — stable prefix discipline) composed from the
index; component CARDS (type component, origin harvest) mirror
optionally for the memory selector's benefit — the card links the
component dir (one source, the card is a pointer).

## Design (suggested shape)
- Extraction (on approval): component sources identified from the
  task's diff + the spec's component mapping → <name>/
  {Component.tsx, styles (token-compliant — the lint applies),
  screenshot.png (the loop's passing shot cropped to the
  component's region), props.md (generated from the TSX interface
  — deterministic extraction, the signature extractor's cousin),
  meta.json (source job, fidelity numbers, spec region)}.
- Index: catalog.json generated from the directory (name, purpose
  from spec, screenshot ref, props summary) — regenerable,
  deterministic, the prompt block renders from it (names +
  one-liners + "reuse before rebuilding" mandate; budgeted like
  all segments).
- Gallery route per the reference: tiles (screenshot, name,
  fidelity badge), detail (props doc, usage snippet, the source
  job link); read-only from the repo's catalog (the UI never
  writes the design system).
- Cards mirror (optional config): component cards with the dir
  ref; the hygiene liveness pass covers them (a vanished component
  stales its card — the provenance machinery).

## Task slicing
- **T001** extraction mechanics (source identification, props doc
  generation, crop, meta) + determinism tests on the fixture
  component.
- **T002** the proposal gate + applicator-path writes + the index
  + regeneration determinism + tests.
- **T003** the gallery + the prompt-block segment + trace proof on
  a follow-up fixture job + the optional card mirror + the
  end-to-end (loop pass → proposal → approve → extracted →
  follow-up prompt carries the index → gallery renders).

## Acceptance
- All four artifacts golden on the fixture; props.md regenerates
  deterministically. Nothing extracts without approval (state
  diff). The index block in follow-up traces at its rank.
  Gallery read-only (no write endpoints). Mirrored cards point,
  never duplicate content (the pointer test).

## Edge cases & assumption defaults (A9)
- Components spanning files: the diff+spec mapping names the set;
  ambiguity → the proposal lists candidates for the human to
  scope (curation is the point). Non-React targets: v1 extracts
  TSX ecosystems; others get the honest "catalog supports React
  targets in v1" note (the tier's stack reality, stated).

is the maintenance contract — golden it.

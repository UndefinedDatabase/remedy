# T8_F156 — Worker certification suite
**Tier 8 · Depends on: F151, F152, F082 · Blocks/used by: routing gates, F159, F232**

## Goal & Done
"Can this worker do this work?" becomes a certificate, not an
opinion: `remedy worker certify <adapter>` runs the staged suite —
(1) capability probes (declared vs real, mini-calls per
capability), (2) format discipline (a batch of schema answers,
error rate measured), (3) a mini-gauntlet (bench orders S–M),
(4) the isolation A/B — and writes worker_certificate.json
{adapter, version, cli_version, suite_v, date,
capabilities_verified, format_error_rate, classes_passed,
cost_basis, isolation_ok} under the DATA ROOT's workers area; the
router reads classes_passed as a hard gate. DONE when each stage
fails its seeded-defect fixture (a lying capability, a sloppy
formatter, a failing order, a leaky isolation), certificates
invalidate on version drift (adapter or suite), the router gate
consumes them live (the F155 handshake closes), and certification
cost is previewed before running (it spends real money).

## How it fits (a placement correction + composition)
An earlier draft wrote a home-directory path — certificates live
under `<data_root>/workers/<adapter>/worker_certificate.json`
(the established convention; machine-scoped state belongs to the
data root). Stages compose existing machinery: capability probes
reuse the vision-probe pattern (F154) generalized per capability
(schema probe = a strict-schema round-trip; resume probe = a
two-call session check; streaming = event-shape verification);
format discipline runs the conformance kit's schema fixtures at
batch scale with the error rate from validation outcomes; the
mini-gauntlet reuses the bench harness with the S–M subset and
the adapter pinned; the isolation stage runs F152's A/B utility.
classes_passed derives from the gauntlet per-class results
against documented pass bars (the promotion-discipline thresholds
— import the constants, one home). A signing hook field stays
reserved (the certificate feature's stance).

## Design (suggested shape)
- `packages/workers/certify.py`: the stage runner (each stage a
  named function with its own evidence bundle; a stage failure
  stops the suite with the honest partial certificate marked
  invalid:stage_failed), the certificate writer (schema-versioned,
  suite_v bumps invalidate — recertify on suite evolution, stated),
  drift checks (adapter/CLI version vs the ADR pin).
- The router gate: certificate loading + validity rules (version
  match, age config, suite_v current) → classes_passed membership;
  invalid/stale certificates gate CLOSED with the recertify hint.
- CLI: certify (with the cost preview — the expensive-command
  wiring), `remedy worker certificates` (list, validity, ages).
- Recorded-vs-live: probes and the gauntlet are LIVE by nature
  (that's the point) — marker-gated in CI, run deliberately;
  the suite's own tests use scripted adapter fakes per stage.

## Task slicing
- **T001** stage framework + certificate schema/writer + validity/
  drift rules + scripted-fake tests per stage (each seeded defect
  caught).
- **T002** the probes (per capability) + format batch + gauntlet
  reuse + isolation reuse + the pass-bar imports.
- **T003** the router-gate consumption (F155's handshake closes:
  a certified class opens, revocation closes it) + cost preview +
  CLI + the end-to-end on the reference adapter (certify → gate
  opens → suite_v bump → gate closes → recertify).

## Acceptance
- Each stage's seeded defect fails with the stage named; partial
  certificates invalid. Drift (adapter version, suite_v)
  invalidates with the hint. The gate round-trip exact (open/
  close/reopen). Pass bars imported (grep). Data-root placement
  (grep against home-dir paths). Cost preview shown.

## Edge cases & assumption defaults (A9)
- Capabilities honestly declared false: their probes SKIP as
  not-declared (certifying absence is free) — the certificate
  records declared-false distinctly from probe-failed.
  Recertification cadence: age warnings (config) — stale
  certificates warn in doctor/stats before the gate hardens
  (grace, then closed; documented).

## Orchestrator brief
Gate on the kit + bench + isolation utility. T001's scripted-
fake-per-stage discipline keeps the suite's tests cheap — verbatim.
The placement correction and the pass-bar import go into orders
explicitly.

## Do not touch
Bench orders, pass-bar constants (imported), routing beyond the
gate, signing (reserved). Suggested tests:
tests/workers/test_certification.py.

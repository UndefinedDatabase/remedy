# T13_F209 — Org conventions with inheritance
**Tier 13 · Depends on: F172, F125 pattern · Blocks/used by: cross-project consistency; F210/F211**

## Goal & Done
See ROADMAP.md F209; the Done criterion there is binding.

## Context (existing code & prior features)
CONVENTIONS.md is project-local; F125 shows the two-level resolution pattern for cards.

## Design
~/.remedy/org/CONVENTIONS.md as the parent level (same format); resolution in the context compiler: org base + project overrides, where overrides MUST carry an explicit note ('Override org: <section> - reason'). `remedy org conventions check` finds silent contradictions (same registry entry, different value, no note) as drift findings. The prompt block uses the RESOLVED view (one segment, F105-stable).

## Task slicing
T001 resolution + the note duty + tests. T002 the drift check + the compiler segment + a fixture (org says X, project silently Y -> a finding).

## Acceptance & tests
Resolution priorities tested; the silent contradiction is found with both locations; the resolved segment is deterministic (F105 cache-hit stability).

## Risks / anti-goals
No registry server (files + inheritance suffice); the org file changes only via deliberate commits in the org store (recommend versioning it as its own git repo - a recommendation, not a requirement).

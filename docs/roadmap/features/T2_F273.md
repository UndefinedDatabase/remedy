## Why this exists
Because a finding ledger that only grows stops being read. When the amend0827
process diet opened, the record held 270 findings, 253 of them open against 17 ever
resolved, and the diagnosis then was that ids were being spent on the reviewer's own
prose as readily as on the product. That diagnosis was right and the triage measured
it: 204 of 298 — more than two thirds — are the review process describing its own
artifacts, and they buy no repair because there is nothing on disk to repair. What
was left underneath is a real and reviewable list, and it is this one.

The finding text IS the spec. Not one slice below re-plans a fix, states a design or
adds a requirement: each names its ids and its module, and the round that takes it
reads those findings. Where a finding's own text names a fix, that fix binds.

(a) THE DIRECT-API PROVIDER DISCARDS THE USAGE IT WAS GIVEN AND CALLS IT
UNAVAILABLE. `packages/orchestration/pingpong_provider.py::ClaudeProvider._call`
reads only `response.usage.output_tokens`; `input_tokens`, `cache_read_input_tokens`
and `cache_creation_input_tokens` are dropped, and `build`/`review` then stamp
`actual_missing_reason="provider_actuals_unavailable"` while the SDK response carried
all four. The request is one flat user message — no `system` block, no
`cache_control` — so the cache-optimal prompt ordering buys zero cache hits on this
path. `except Exception as exc` keeps only `type(exc).__name__`, so a 429, a bad model
id and a missing key are one opaque string. `anthropic` is imported but declared in no
`pyproject.toml` extra. Repair: return the whole usage and route it through the same
`usage_actuals` shape the CLI provider uses; split the stable prefix into a cached
`system` block; most-specific-first exception chain keeping status code and message;
an `anthropic` optional extra named in the ImportError text. Severity Medium: the
operator's real path is the CLI provider (subscription), so the cost-truth defect is
latent for him — but a ledger that says "unavailable" while holding the numbers is an
evidence defect regardless of who is billed. Decided 2026-09-11: repair, as written

(b) NOTHING PROVES THE CI STAGE TABLE PARTITIONS THE TEST CORPUS. In
`packages/orchestration/ci_stages.py`, `fast` excludes `slow` and `standard` selects

stage with `pytest_argv_for_stage`, and asserts the union of node ids equals the corpus

count. Red proof: a throwaway `slow`-only test in a scratch worktree reds it and is
named in the failure. Severity Medium.

(c) THE VITEST RUN IN CI HAS A 30-SECOND CEILING NOBODY MEASURED.

promise is untested. Repair: `__str__` on `RunState` returning `self.value` (the
same on any other `(str, Enum)` in `packages/core/models.py` that a renderer
formats), the failing test kept as the guard, and a second interpreter column in

# T3_F068 — Autonomy balance (on demand)
**Tier 3 · Depends on: F010, F103 · Enhanced by: F035 ownership aggregation once the cockpit tier lands (decision-queue data suffices until then) · Blocks/used by: steering numbers**

## Goal & Done
"How much can Remedy already do alone?" gets a data answer on demand:
`remedy stats autonomy` computes, over a period, the total runs, the
autonomous share (runs needing zero operator commands after start),
interrupts per thousand tasks, median decision latency, and success
rate — every number defined precisely, sourced from existing stores,
and labeled where the source is incomplete. DONE when the report
matches goldens on a fixture history, every metric's definition is
documented next to its number, and periods with thin data say so
instead of implying precision.

## How it fits (inspect current shape before building)
All inputs exist: job records and terminals, the ledger for periods
and volumes, the decision queue's request/answer timestamps,
postmortems for interrupt causes, and the gauntlet/report notions of
"operator command" (the flawless definition already had to define it
— REUSE that definition verbatim, one home). This is a read-only
aggregation + renderer; if any needed timestamp is missing from a
store, adding it is a tiny additive prerequisite order, named early.

## Design (suggested shape)
- Metric definitions (in the module docstring, rendered in --explain):
  autonomous run = started by one command, reached a terminal with
  zero further operator commands and zero human-answered decisions
  (auto-approved --yes decisions count as autonomous — they're the
  point); interrupt = a human-answered decision or an operator stop,
  normalized per 1000 completed tasks; decision latency = requested→
  answered, median + p90, human-answered only; success rate = green
  terminals over all terminals, with blocked/stopped broken out.
- `autonomy_stats.py`: compute(period) → the metrics + per-metric
  sample sizes; small-N honesty: any metric with fewer than a config
  floor of samples renders with "(n=<k> — low sample)" and the
  summary refuses a headline number when the total is tiny.
- CLI: `remedy stats autonomy [--since] [--json] [--explain]`; the
  table leads with the autonomous share and its trend versus the
  prior equal period where data exists.
- The trend of this number over releases is the steering instrument —
  the bench history pattern applies (append a snapshot per invocation
  with --record for longitudinal tracking, opt-in).

  from its single home (grep guard against a second definition).
  Low-sample fixtures render the caveat; empty periods render an
  honest empty report. Read-only (state diff test).

## Edge cases & assumption defaults (A9)
- Legacy runs missing decision timestamps: excluded from latency with
  a counted note, included elsewhere. Mixed --yes and attended runs
  in one period are fine — the definitions handle each run on its
  own terms.

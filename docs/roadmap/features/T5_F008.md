## Goal & Done
The cockpit gets its heartbeat: a per-job SSE endpoint streams the
event ledger from a cursor — monotonic sequence numbers, heartbeats,
Last-Event-ID resume — consumed by a client hook with reconnect,
gap detection and an honest polling fallback. DONE when a live fake
job streams into a test client with zero gaps across forced
disconnects, resume replays exactly the missed span, the heartbeat
keeps proxies alive, and the fallback path labels itself visibly
("delayed") instead of pretending to be live.

## How it fits (inspect current shape before building)
Events exist as the file-based ledger with stable ordering — the
stream is a READER: tail the job's events from a cursor, assign/
carry monotonic seq (verify whether ledger entries already carry an
index — they do by construction; the stream must not renumber),
serve via the existing UI server process (inspect how the current
server handles long-lived responses; the stdlib server may need a
threading confirmation — a prerequisite finding, not an assumption).
The envelope follows the roadmap's Part E event contract — cite it,
don't restate it.

## Design (binding specifics)
- GET /api/jobs/{jid}/events/stream: SSE; event id = seq; data =
  the Part E envelope; a 15 s heartbeat comment frame;
  Last-Event-ID (header or query) resumes from seq+1 with the
  missed events replayed from the ledger (the ledger IS the
  buffer — no in-memory ring to lose); unknown job → 404 before
  streaming.
- Backpressure/lifecycle: closed connections detected and cleaned;
  a max-connections-per-job config guard with 429 beyond it.
- Client hook useBrainStream: EventSource + reconnect with backoff
  + gap detection (seq discontinuity → snapshot refetch via the
  existing state endpoint, then resume) + status surface
  (live | reconnecting | delayed).
- Polling fallback (config/auto on EventSource failure): interval
  fetch of the events tail with the SAME hook interface and the
  "delayed" badge state — one consumer contract, two transports.
- Contract tests are the deliverable style here (ui_contract
  marker): stream framing, resume spans, heartbeat cadence golden.

## Task slicing
- **T001** the server threading/long-response finding + the stream
  endpoint + heartbeat + 404/429 + contract tests (framing golden).
- **T002** resume via Last-Event-ID + gap replay exactness + forced-
  disconnect tests (kill the connection mid-stream N times; the
  client transcript equals the ledger).
- **T003** the client hook + fallback + status states + a fixture
  live-job end-to-end (fake job streaming into a headless client).

## Acceptance
- Disconnect-hammer test: final client transcript byte-equals the
  ledger's envelope sequence. Heartbeats at cadence (timing test
  with injected clock where feasible). Fallback engages on a
  disabled EventSource and labels delayed; recovery returns to
  live. No renumbering (seq equals ledger index throughout).

## Edge cases & assumption defaults (A9)
- Very long jobs: resume from ancient cursors streams from disk in
  chunks (bounded memory — test with a large fixture ledger).
  Multiple tabs: independent connections under the cap. Auth: the
  same bearer story the UI server already has (inherit, don't
  invent).

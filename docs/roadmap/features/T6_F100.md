# T6_F100 — Multi-reference consistency
**Tier 6 · Depends on: F087, F089, F096 · Blocks/used by: multi-page fidelity**
> **CANONICAL DESIGN REFERENCE:** This feature MUST follow the canonical Remedy
> UI design reference in `docs/ui/design_reference/`. `ux_design.png` is the
> visual authority; the written specs, tokens, component rules, graph rules and
> motion rules in that folder are binding for this feature. Builders must not
> invent a new visual language; any visual deviation must be documented in the
> assumption_log with a technical reason. All UI work uses the shared design
> tokens (`--remedy-*`) and component rules from the design reference.
> **ASSET REFERENCE:** fonts, icons, graph glyphs, logo and visual assets
> follow `assets_spec.md` in the same folder (the asset authority). No new
> font, icon library, glyph style, logo treatment or asset source may be
> introduced unless `assets_spec.md` is updated and the deviation is
> documented in assumption_log with a technical reason.

## Goal & Done
Multiple references stop contradicting each other silently: token
fusion across references produces ONE token set with a conflict
report — same role, different value becomes ONE upfront
clarification item (the bundled rules), never a silent average —
and the page↔reference mapping is recorded in the plan so every
task knows which picture is its law. DONE when a conflicting
two-reference fixture yields exactly the expected clarification
with both values and their sources, resolution flows into the
token file deterministically, the mapping lands on plan tasks and
gates which reference each fidelity comparison uses, and
consistent references fuse without questions.

## How it fits (inspect current shape before building)
This SITS BETWEEN decomposition and extraction: decomposition
yields per-reference candidates; extraction's reconciliation
already clusters within tolerance — this feature owns the ABOVE-
tolerance case across references (a real design conflict: R1's
primary blue vs R3's different primary blue) and turns it into
the plan-time clarification (the bundled-clarification machinery:
question, default = the majority/first-reference value with the
rule documented, impact = which pages shift). The page mapping
extends F087's scope notes into a validated plan-level table
(route/task ↔ R-number), consumed by the fidelity loop's pair
accounting (each comparison already keys on reference — the
mapping tells it WHICH).

## Design (suggested shape)
- Fusion pass (between decomposition and extraction, pure):
  cluster candidates by role across references → within tolerance
  → merge with sources; above tolerance on the same role →
  conflict {role, values [{value, refs}], suggested_default (rule:
  the value covering more references, ties → lowest R-number —
  deterministic), impact};
- Conflicts → clarification items on the plan approval (the F034
  payload — one human touchpoint), answers write the fused set;
  --yes takes the documented default, assumption log carries it.
- Mapping: plan tasks with design_refs validate against a
  job-level page_map [{route/component, r_ref, source: scope_note
  | planner | human}] rendered in plan.md; unmapped UI tasks are a
  plan-validation warning ("which reference governs T007?") that
  becomes a clarification when ambiguous.
- The fidelity loop reads the map for pair selection (one source);
  cross-reference comparisons never happen implicitly.

## Task slicing
- **T001** fusion + conflict detection + the deterministic default
  rule + unit tests (consistent set silent; seeded conflict exact;
  tie-break).
- **T002** clarification wiring + answer/default write-back into
  extraction's input + assumption-log entries + tests.
- **T003** the page map (validation, plan.md rendering, loop pair
  selection) + the end-to-end (two conflicting references → one
  question → answered → tokens fused per answer → each page
  compared against its mapped reference only).

## Acceptance
- Conflict fixture: exactly one clarification with both values,
  sources and impact; the default rule golden; the answered value
  in tokens.css with the sources note. Consistent fixture: zero
  questions. Pair selection obeys the map (a cross-pair attempt is
  unconstructable — unit-tested). No averaging anywhere (grep for
  the sin).

## Edge cases & assumption defaults (A9)
- More than two conflicting values: one question listing all
  (bounded by the clarification cap — beyond it, the top values by
  coverage with "others in the report"). References at different
  fidelity (a sketch + a final): the scope note can mark a
  reference advisory — advisory refs contribute candidates but
  never conflicts (documented flag).

## Orchestrator brief
Gate on decomposition + extraction + bundled clarifications. The
no-silent-averaging rule and the deterministic default go verbatim.
T003's pair-selection gate is the fidelity-correctness line.

## Do not touch
Extraction's within-tolerance clustering, clarification mechanics,
loop thresholds. Suggested tests:
tests/orchestration/test_multi_reference.py.

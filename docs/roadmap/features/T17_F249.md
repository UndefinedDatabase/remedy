# T17_F249 — Anonymized research exports
**Tier 17 · Depends on: F219, F103, F171 · Blocks/used by: publications; benchmarks; selling with numbers**

## Goal & Done
See ROADMAP.md F249; the Done criterion there is binding.

## Context (existing code & prior features)
F219 governs opt-in discipline; the ledger/evidence hold raw data; F171 redaction targets secrets, not identifiers.

## Design
packages/ecosystem/research_export.py + `remedy export research --since`: an aggregate data package (PASS rates per class, cost/duration distributions, repair statistics, autonomy quotas - ONLY distributions/counters, never individual events) with an anonymization suite: path/name/prompt freedom BY CONSTRUCTION (the aggregation selects from a field whitelist; the F245 schema research_export_v1), a k-anonymity threshold per cell (cells with n<k are suppressed; k config, default 5), and a re-identification test corpus (known project details must not be reconstructible from the export - a scripted check). Opt-in per export as in F219, with the package displayed before creation.

## Task slicing
T001 the whitelist aggregation + schema + k suppression + tests. T002 the re-identification corpus + the display flow + a golden package.

## Acceptance & tests
The export contains exclusively whitelist fields (schema validation); n<k cells are suppressed (test); the corpus check passes; a double run reproduces from the ledger.

## Risks / anti-goals
No per-run data, not even 'anonymized' (aggregate-only is the line); the purpose is declared in the package manifest; F219 opt-in applies per export (no standing hook).

# T2_F261 — CLI vocabulary v2 (rename & prune)
**Tier 2 · Depends on: F259 (the binding concept model), F260 (one job model) · Blocks/used by: everything later that names a command**

> Registered 2026-08-31 by operator order amend0831-vocab-registrations.
> REGISTRATION ONLY — nothing in this file has been implemented.

## Goal & Done
The command tree is renamed ONTO the concept model of F259.

In particular the triplet `do plan` / `do job-plan` / `job plan` is dissolved:
three different things carry three different, self-explaining words from here
on. The `job-*` hyphen family under `do` is folded into the ordinary tree
structure, so a group is a group and a subcommand is a subcommand.

DONE when the canary test (`tests/cli/test_golden_path.py`) has been moved onto
the new names and is green, `remedy --all-commands` no longer shows two
commands that — by the concept model — use the same word for different things,
and every command in `apps/cli/command_catalog.py` carries a one-sentence
description good enough for REMEDY_EINSTIEG.

## Why this exists
`do plan`, `do job-plan` and `job plan` are three separate operations whose
names claim kinship they do not have; `apps/cli/command_catalog.py` already
carries `subcommand="plan"` under several different groups. A user who learns
one of the three learns the wrong thing about the other two. The `job-*`
hyphen family (`do job-plan`, `do job-run`, `do job-report`, `do job-evidence`,
`do job-promote`) encodes a second grouping level in a hyphen because the tree
did not have one — which is why the same concept is spelled `do job-run` in one
place and `job stop` in another. F259 decides the words; this feature is where
the CLI starts using them.

## DECISION D-B (2026-08-31, operator order amend0831-vocab-registrations)
CLI words stay ENGLISH. Old commands that have become meaningless are DELETED,
not carried along as aliases — UNLESS a test or a script in the repository
demonstrably depends on one, in which case the dependent is converted in the
SAME move.

Consequence, stated plainly: "keep the old name as a deprecated alias" is not
available in this feature. A grep that finds an old name in `tests/` or
`scripts/` is a work item, not a reason to keep the name. Reverse this decision
by deleting this paragraph.

## DECISION D-D (2026-08-31, operator order amend0831-vocab-registrations)
`settings` becomes a pure ALIAS SURFACE over the existing `config` group — ONE
implementation, two words. The help text of each names the other word.

This is deliberately not a rename: `config` keeps working, `settings` reaches
the same code, and neither help text pretends the other does not exist. The
group already describes itself as "View or change settings.", so the second word
is already in the product; D-D makes it reachable. Reverse this decision by
deleting this paragraph and the alias registration it authorises.

## Design
- The catalog (`apps/cli/command_catalog.py`) is the single place where a name
  lives; the rename is a catalog edit plus the handler wiring, not a scatter of
  string literals.
- One rename at a time, each with the canary green before the next starts. A
  batch rename that reds the canary cannot be bisected.
- The alias of D-D is registered as an alias — one `GroupDef`, two reachable
  words — never as a duplicated set of command definitions.
- The "no two commands use one word differently" property is checked BY A TEST
  over the catalog, not by review. The test derives the collision set from the
  concept model's binding terms; it does not carry a hand-written list.

## T001 — Dissolve the plan triplet
`do plan`, `do job-plan` and `job plan` get three distinct names from F259's
vocabulary. Old names deleted per D-B; dependents converted in the same commit.

## T002 — Fold the `job-*` family into the tree
The hyphen family becomes real subcommands. Same rule: delete, do not alias.

## T003 — The `settings` alias
Per D-D. One implementation, two words, each help text naming the other.

## T004 — Descriptions and the collision test
Every catalog entry gets a REMEDY_EINSTIEG-grade one-sentence description, and
the collision test described under Design lands green with a red proof.

## Acceptance
- `tests/cli/test_golden_path.py` is on the new names and green.
- `remedy --all-commands` shows no two commands using one binding term
  differently — proved by the collision test, not by inspection.
- No deleted name survives anywhere in `tests/`, `scripts/` or `docs/`.
- `remedy settings --help` and `remedy config --help` each name the other word.

## Do not touch
The concept model itself (F259 owns the words), the job model (F260 owns what a
job is), and STATUS semantics. This feature renames; it does not change
behaviour behind a name.

## Orchestrator brief
T001 is the sharpest edge and comes first while the tree is otherwise
untouched. T002 is mechanical but wide — it is the slice most likely to exceed
the commit-size cap, so plan its split before starting. T003 is small and
independent of T001/T002. T004 must come last: the collision test is meaningless
until the renames it measures have landed.

## Context (existing code & prior features)
tokens.css (--remedy-*) is the single color/shape source (F096 lint); baselines (F098) hang off the default look.

## Design
A theme = a token overlay file themes/<name>.css (ONLY --remedy-* variables may be overridden; the linter enforces: no new selectors); selection via [ui] theme= + a runtime switcher. White-label (the org edition, F214): a logo slot (a header SVG path) and a product-name slot in titles/report footers - certificates (F060/F165) ALWAYS additionally carry 'powered by Remedy <version>' inside the signed manifest (provenance honesty, non-negotiable). The baseline guard (F098) runs exclusively against the default theme; shipped themes get their own optional snapshot sets.

## Task slicing
T001 the overlay mechanics + linter + switcher + tests. T002 the white-label slots + the manifest field + report footers + snapshots per shipped theme (default/dark/print).

## Acceptance & tests
A theme switch breaks no layout (snapshots); the linter catches selector smuggling; the provenance manifest field is unremovable without breaking the signature (a verify test); the contrast check (the F193 matrix) passes per theme.

## Risks / anti-goals
No theme marketplace in v1; white-label never obscures evidence provenance (audit artifacts stay unbranded-honest).

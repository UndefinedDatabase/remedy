# T3_F055 — Rehearsal (dry check)
**Tier 3 · Depends on: F014 · Blocks/used by: start discipline**

## Goal & Done
Operators get a cheap "what would happen": `remedy do --rehearse` runs
the pipeline exactly up to the approved-plan boundary — intake, plan,
normalization, DoD compilation — then renders estimate bands, the risk
list, and a fence simulation of which paths WOULD be writable, with
zero builder calls and the planner's real cost shown honestly. DONE
when a rehearsal produces rehearsal.json plus a readable summary,
provably makes no builder/worktree changes, and a subsequent real run
can reuse the rehearsed plan instead of paying for planning twice.

## How it fits (inspect current shape before building)
Everything rehearsal shows already exists as artifacts of the planning
half: the job plan, transformations, the DoD, budgets/fences on the
job, and the cost-preview estimator for bands. Rehearsal is a MODE that
stops the pipeline at the approval gate and renders — plus the reuse
hook: a rehearsed job is a normal PLANNED job whose approval decision
is simply left open, so "run it for real" is answering the approval;
no parallel object model.

## Design (suggested shape)
- `--rehearse` on the do path: run intake → plan → normalize → DoD
  compile as normal (these cost planner tokens — the summary prints
  that cost with basis, honestly); then instead of enqueueing a plain
  approval, render the rehearsal: per-task estimate bands (shared
  estimator), the plan's risks + normalization flags, DoD check matrix
  (uncompiled kinds listed), and the fence simulation — the effective
  FenceSpec evaluated against the plan's files_hint closure, shown as
  would-write / would-block lists.
- Outputs: rehearsal.json (machine) + the summary block (human) in the
  job's evidence; the job stays PLANNED with its approval open and the
  status view labels it rehearsed.
- Guarantees, tested: zero builder-role provider calls, zero applicator
  invocations, zero worktree mutations (state snapshot equality).
- `remedy do --resume-rehearsal <job>` (or answering the approval)
  proceeds without replanning; a config staleness window warns when
  the repo head moved since rehearsal (the plan may be stale — honest
  warning, human decides).

## Task slicing
- **T001** the mode + pipeline stop + guarantees tests (call-role
  counters, snapshot equality).
- **T002** rehearsal rendering (bands via the shared estimator, fence
  simulation, DoD matrix) + goldens.
- **T003** reuse path + staleness warning + status labeling + the
  end-to-end (rehearse → approve → real run completes without a second
  planning call — asserted via call counts).

## Acceptance
- Golden rehearsal on the fixture mission; planner cost line present
  with basis. Guarantees hold (all three counters zero). Reuse runs
  without replanning; a moved head warns. Rehearsal of a mission goal
  works identically through the mission compile boundary (compile,
  don't execute — which is already that compiler's contract).

## Edge cases & assumption defaults (A9)
- Rehearse with --yes is contradictory → refused with a one-line
  explanation. Fence simulation on plans without files_hint: shows
  "scope undeclared — whole worktree writable under current fences",
  which is itself useful information.

## Orchestrator brief
Small feature over existing parts — the orders should read like
composition. The three guarantees are the acceptance spine; require
their counters as reusable test utilities (parallelism and others can
reuse them).

## Do not touch
Approval semantics, estimator internals, planning content. Suggested
tests: tests/cli/test_rehearsal.py.

## Goal & Done
See ROADMAP.md F210; the Done criterion there is binding.

## Context (existing code & prior features)
The F142 trust dashboard is project-scoped with the raw-link principle; the project ACL (F185) governs visibility.

## Design
GET /api/org/trust: a read-only aggregation over the projects.json registry (calling the SAME F142 aggregation functions per project - no second computation), filtered by the requester's F185 rights. A UI route /org: F142-style tiles plus a project comparison strip, the org-wide worker scoreboard (an F159 aggregate), costs per project/period. Every number: click -> the project tile -> raw data (a two-step, same P6 chain).

## Task slicing
T001 the aggregation API (reuse enforced: importing the F142 functions) + the ACL filter + tests. T002 the UI route + the comparison strip + the reconciliation test aggregate == sum of project values.

## Acceptance & tests
The aggregate reconciliation passes; a viewer without a project-B role sees B in NO tile (the property with F185); every tile clicks through to raw data (a playwright path test).

## Risks / anti-goals
No org-level metric definitions of their own (sums/comparisons of project truths only); no people rankings (the F181 principle holds org-wide).

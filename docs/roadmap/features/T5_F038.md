## Context (existing code & prior features)
Questions deserve evidence-bound answers; operators are used to a
conversational entry point. Existing building blocks: project brain
(`project_brain.py`, read-only project aggregate), decision queue
(`decision_queue.py`), job intake (`do_cmd.py`), F005 schemas, redaction
patterns, role-based provider config (local-capable). PART J stands: the
cockpit is the control stand — chat is one input inside it, never a second
product surface or a second write path.

## Design
Per the spec: read path in two scopes — node scope from that node's evidence
only (trace, verdicts, diff); project scope ONLY from the defined evidence set
(project brain aggregate, progress ledger, decision queue state, roadmap
position from STATUS.md, latest reports; F071 dossier and F103 ledger views
join the set when built). Citation chips [1][2] anchor into artifacts;
uncited claims render 'unsupported'; a canary test asks about absent facts
and must get 'not in evidence'.
Write path: free text parses (F005 schema) into exactly one existing verb —
job intake (F013 `do`), steer_task (F030), decision answer (F031/F032),
pause/resume (F025) — rendered as a confirmable action card; nothing executes
unconfirmed; the confirmed action dispatches through the normal audited write
channel (F009) and is indistinguishable in audit from the same action via
UI/CLI. Unparseable intent → honest "no matching action" + verb list.
Composer/parser/answer live as UI-independent modules in
`packages/orchestration/` (chat_evidence, chat_answer, chat_intent); chat
classes route cheap/mid per F110 (local-capable, F113); composed evidence is
deterministic code, redacted, hard-capped ≤4000 tokens until F112 governs it.

## Task slicing
T001 CLI-first: evidence composer (project scope over existing providers) +
grounded answer + citations + canary; ships as `remedy chat` (Part B
CLI-first). T002 node scope + cockpit chat UI + chip navigation into
EvidencePanel + canary E2E. T003 intent parser (schema) + action cards +
dispatch through F009 + fixture set + audit-equivalence test.

## Acceptance & tests
All citation anchors resolve; the canary answers honestly in both scopes.
Intent fixtures (≥10, incl. job submission, steering, decision answer,
pause/resume, 2 unparseable) map to the correct verb+args or an honest
rejection; an unconfirmed card provably executes nothing; a chat-dispatched
action is indistinguishable in audit from the same action taken via UI/CLI;
composed-evidence token cap holds; local-model smoke (Ollama) passes for
answer + parse.

## Risks / anti-goals
Chat never mutates anything directly — dispatch only via confirmed verbs. No
second write path, no fake chat (the builder's answer to steering stays its
next action, F030). No project-scope answer from sources outside the defined
evidence set; no raw source-code ingestion (project-brain boundary). No
top-tier model calls from the chat path.

## Goal & Done
See ROADMAP.md F201; the Done criterion there is binding.

## Context (existing code & prior features)
The cockpit is desktop-first; the digest (F040) and the inbox (F031) are the mobile-relevant surfaces; session auth exists.

## Design
A PWA upgrade of the EXISTING cockpit (no second app): manifest.json + a service worker (app-shell cache ONLY, no data persistence - the artifact rule), a responsive breakpoint <=430px for exactly four surfaces: project/job status (the bare-CLI equivalent), the digest (F040), the decision inbox (approve/reject with the triple, F031/F032), stop/pause actions. The graph shows a list alternative on mobile (an F242 preview: a structured task list instead of canvas). Exposure is explicitly the user's job (tailscale/reverse-proxy docs with two tested example configs); mobile session timeouts are shorter (config).

## Task slicing
T001 PWA basics + the four breakpoint layouts + playwright mobile tests. T002 the graph list alternative + exposure docs + a lighthouse PWA gate in CI (the F044 extension).

## Acceptance & tests
A decision is resolved end-to-end at a 390px viewport (E2E); the lighthouse PWA category passes; the service worker provably caches no API data (test).

## Risks / anti-goals
No own cloud relay service (the Part J SaaS rule); no mobile-special API (the same endpoints).

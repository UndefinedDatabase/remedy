# T0_F146 — Project identity & repo autodetection
**Tier 0 · Depends on: none · Blocks/used by: F147, F148, project dimension everywhere**

## Goal & Done
Remedy has ONE canonical notion of "project": a registry entry with a
stable id, resolvable automatically from the current directory. DONE when
`remedy project current` answers correctly from any subdirectory of a
registered repo, the two identity notions that exist today are reconciled
by an explicit written rule, and nothing ever auto-creates a project.

## How it fits (this is a RECONCILIATION, not greenfield)
A project registry already exists (UUID-identified project records with
save/load/list, repo and job attachment, a not-found error type, storage
under the data root's projects area) — extend it. Separately, the worktree
layer derives a path-based key it calls a project id for workspace naming.
Two identities exist today; this feature ends the ambiguity. The project
CLI module also exists — extend it, don't add a parallel command.

## Design (suggested shape)
- **Canonical rule (write it into both modules' docstrings):** the registry
  UUID is the project identity everywhere user-visible and everywhere data
  is scoped. The worktree-derived value is demoted, in documentation, to
  "workspace key" — keep its name for compatibility, forbid new call sites
  outside the worktree module via a guard test (the repo already has
  guard-test patterns to copy).
- Extend the project record additively: a unique kebab-case `slug`
  (derived from the repo directory name at registration; collisions get a
  numeric suffix) and resolved repo real-paths for matching.
- `resolve_project(cwd)`: walk up to the git repo root (reuse the existing
  helper; non-git yields none), resolve symlinks, match against registered
  real-paths; inside a Remedy-managed worktree, map back to the parent
  repo. Never writes. `require_project(cwd)` raises the not-found error
  with the exact fix-it line: "No project registered for this repo. Run:
  remedy init".
- Selection precedence, implemented once as a shared helper all commands
  use: `--project <slug|uuid>` flag > REMEDY_PROJECT env > cwd
  autodetection > error.
- CLI: `remedy project current` (slug, uuid, repo, job count; exit 3 with
  the fix-it when unresolved), slug added to the list output, and a thin
  `remedy project attach --repo .` for re-binding moved repos.

## Task slicing
- **T001** slug + real-path fields with migration-safe loading (a
  pre-existing record without a slug derives one on load and saves back;
  fixture test) + resolve/require + unit tests (subdir, non-git,
  unregistered, worktree mapping, same dirname twice → distinct slugs).
- **T002** the precedence helper + tests over all permutations (one test
  sets flag, env and cwd simultaneously).
- **T003** CLI additions + docstring reconciliation + guard test against
  new workspace-key call sites.

## Acceptance
- From deep inside a registered repo: correct slug; from an unrelated dir:
  exit 3 with the exact fix-it. Env beats cwd; flag beats env.
- Registering the same repo twice is idempotent (returns the existing
  record).
- Legacy data with two records claiming one real-path: newest wins with a
  logged warning naming both — never a crash.

## Edge cases & assumption defaults (A9)
- Moved repo → resolution fails with the attach suggestion. Case-only path
  differences: compare resolved paths as the OS reports them; document the
  macOS caveat, no special-casing.

## Orchestrator brief
T001 first and alone (it changes the record shape others build on). Then
T002/T003 in parallel. Have the worker read the current registry and
worktree modules and confirm the attachment semantics before writing.

## Do not touch
Data directory layout (scoping is the next feature), job storage, worktree
naming. Suggested tests: tests/orchestration/test_project_resolution.py,
tests/cli/test_project_current.py.

## Built State
- **T001 — Strict registration, slug validation, deterministic migration:**
  `RemyProject` with `slug` + `canonical_repo_path` fields.
  `register_project_repo()` requires Git repo (raises `NotAGitRepoError`
  for plain dirs), resolves git root, derives slug from repo directory
  name (not display name). `save_project()` validates slug: non-null,
  kebab-case (`_SLUG_RE`), unique via `_validate_slug()`. Atomic save
  via `tempfile.mkstemp` + `os.replace`. `migrate_legacy_projects()`
  deterministic batch migration sorted by `(created_at asc, UUID asc)`
  before slug allocation. `_lookup_by_slug_or_uuid_readonly()` is
  read-only (uses `_load_project_readonly`, `_list_projects_readonly`).
  `ProjectNotFoundError` includes `selector_value` and `selector_source`
  for diagnostic messages.
- **T002 — Read-only selector and canonical attach authority:**
  `select_project(flag, cwd)` fully read-only for flag/env/cwd paths.
  Source values: `"flag"`, `"environment"`, `"cwd"`. Empty flag/env
  raises `InvalidProjectSelectorError`. Duplicate slug raises
  `AmbiguousProjectError`. Unknown selector error includes value+source.
  `attach_repo_canonical(project, repo_path)` is canonical attach
  service shared by `project.attach` and `project.attach-repo`: git
  validate, resolve root, ownership check, canonical rebind, deduplicate
  `repo_paths`, persist atomically. Legacy `_cmd_attach_project_repo`
  delegates to canonical service. CLI catches all typed errors with
  deterministic exit codes (1=ambiguous/conflict, 2=not-git, 3=not-found).
- **T003 — Worktree proof, AST guard, feature-aware gate:**
  `_managed_worktree_parent()` validates via git common-dir only — no
  unsafe `.git` file fallback. AST guard detects aliased module imports
  (`import X as Y; Y.project_id`) via `ast.Import` nodes. Feature-aware
  Runtime Gate: `_select_checks_for_feature(feature_id)` selects generic
  pipeline checks + feature-specific checks; `build_runtime_integration_gate`
  and `write_runtime_integration_gate` accept `feature_id` parameter.
  F146 Evidence requires only F146 checks (13 static + 2 test execution
  bindings); F018 test suites not mandatory for F146.
  `_bind_test_execution` accepts `bindings_override`.
- **R3 — Auto-derive slug, read-only CLI truth, feature-id Evidence propagation:**
  `save_project()` auto-derives slug when `slug is None`: tries
  `canonical_repo_path` dir name, then `repo_paths[0]` dir name, then
  `project.name`; allocates unique suffix via `_unique_slug()`; assigns
  before serialization — never writes null. Existing 5 registry tests
  pass without modification (production compat restored).
  CLI `project.list` and `project.show` (`action_class="read_only"`)
  now use `_list_projects_readonly` / `_load_project_readonly` — no
  disk writes on read-only commands.
  `create_manual_completion_bundle` accepts `review_feature_id` and
  threads it as `feature_id` to `build_manual_completion_gates`, which
  threads it to `write_runtime_integration_gate`. F146 Evidence
  emits an F146-scoped runtime gate (F018 checks excluded).
  F018 E2E test suite updated: `_make_verification_data` includes all
  6 test files (4 F018 + 2 F146); check count assertions 19 → 34
  (28 static + 6 bindings).
  `test_rejects_null_slug` renamed to `test_null_slug_auto_derives`
  (behaviour intentionally changed by auto-derive).

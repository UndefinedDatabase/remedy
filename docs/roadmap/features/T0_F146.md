# T0_F146 — Project identity & repo autodetection
**Tier 0 · Depends on: none · Blocks/used by: F147, F148, project dimension everywhere**

## Goal & Done
See ROADMAP.md F146; the Done criterion there is binding.

## Context (existing code & prior features)
project_registry.py is a stub; data lives repo-local without a project dimension.

## Design
`packages/core/project_identity.py`: detect(cwd) walks up (.remedy/ first, then .git); pid = sha256(realpath)[:12], registered in ~/.remedy/projects.json on first contact; the id is also stored in .remedy/config.toml [project] and wins on conflict; `remedy init --relink` handles moved repos. Data split: repo-local .remedy/{config,memory/cards,ledger.md,STOP}; machine-local ~/.remedy/projects/<pid>/{jobs,cache,ledger.sqlite,locks}. Every evidence artifact gains project_id (legacy shim: absent => local-default). Outside a project: clear message + init hint, exit 2.

## Task slicing
T001 module + registry IO + tests (first contact, relink, conflict). T002 wiring through job/evidence/ui_server (LARGE task, A3). T003 migration shim + docs.

## Acceptance & tests
tmp repos A/B fully separated (base leak test); pid stable across a path move.

## Risks / anti-goals
No central cross-project DB beyond the small projects.json.

THE PARITY VOID, and its named cause
------------------------------------

parity.txt records the void: all four files under the base worktree's
apps/ui/dist have mtime 1787918302.05 (13:58:22), which is 77 s inside the
13:57:05 → 13:59:40 run window, and the asset FILENAMES changed across the run —
index-B5aVi7qQ.js → index-D_a-qpxM.js and index-DBZlPUBM.css → index-D0y3OK7n.css.
Changed hashed filenames are a real vite rebuild, not a touch.

The cause is named by direct evidence and is a test that removes the flag ON
PURPOSE. In the base worktree,
tests/ui_server/test_dashboard_contract.py::TestAutoBuildBehavior::test_auto_build_runs_by_default
(lines 574-584) does:

    env = os.environ.copy()
    env.pop("REMEDY_UI_NO_AUTO_BUILD", None)
    with patch.dict(os.environ, env, clear=True):
        result = _auto_build_frontend()

It pops REMEDY_UI_NO_AUTO_BUILD from a CLEARED environment and then calls the
real, unmocked _auto_build_frontend(). Its own docstring assumes the call cannot
build — "Returns None because package.json path doesn't match test env, but it
tried" — but a git worktree is a full checkout, apps/ui/package.json is present
and apps/ui/node_modules was copied in for parity, so `npm run build` DID run and
rewrote apps/ui/dist from the BASE sources. The env= the block ordered was
correctly passed and correctly honoured by _auto_build_frontend at line 3083; it
was removed inside the process by the test, which is exactly the "spawned build
path ignored it" class integration_gate.md attributes to R-0169.

WHAT THE VOID DOES AND DOES NOT COST HERE. It costs the right to say "the base
run saw the same dist bytes throughout". It does not weaken either attribution
above, because neither rests on parity: the branch-only id passed 10/10 serially
in the primary checkout, and the base-only id passed 10/10 serially IN THE BASE
WORKTREE AFTER the rebuild. It also does not silently favour the branch — the
rebuild replaced the branch's copied bundle with the base's own bundle, which is
the more conservative direction for a base run.

THE CAUSE IS MEASURED, NOT INFERRED. That single node id was re-run ALONE in the
base worktree, with REMEDY_UI_NO_AUTO_BUILD=1 supplied through env= exactly as
the base run supplied it, and the four dist mtimes moved again:

- **The `exit_code` answer-key collision, left to me.** D13 (4) names `exit_code` as one of
  `client.order`'s answer keys, but `tests/cli/test_client_interface.py`'s static reader treats
  any literal `exit_code=...` keyword at an `emit_ok`/`fail` call site as `fail()`'s OWN
  exit-code parameter, not a payload key (`_NOT_ANSWER_KEYS`) — the same collision a direct
  `emit_ok(exit_code=record.exit_code, ...)` call would always hit for a decision-mandated answer
  key of that exact name. `_cmd_client_order` builds a `payload` dict literal and calls
  `emit_ok(**payload)` instead, which the reader resolves by its literal keys rather than by
  keyword name, so the declared and reached key sets agree without weakening either. Explained
  inline where the handler builds it.

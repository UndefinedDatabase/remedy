### C2 — `F311 R1 C2: the worker pulse, written by every Pi call`
Paths: `packages/orchestration/worker_pulse.py` (NEW FILE), `packages/orchestration/data_paths.py`,
`packages/orchestration/pi_provider.py`, `packages/orchestration/pi_loop_limits.py`,
`tests/orchestration/import_reachability_allowlist.txt`.
1. `data_paths.py`: `worker_pulse_path(job_id: str, root: Path | None = None) -> Path`, returning
   `job_dir(job_id, root) / "worker_pulse.json"`, defined directly below `job_record_path`, with a
   docstring naming DECISION F311 D2 and saying the file is written by `worker_pulse` alone.
2. NEW `worker_pulse.py`, exactly as DECISION F311 D2 states, with a module docstring naming
   DECISION F311 D2 and saying why the pulse is a file of its own (the runner rewrites `job.json`
   whole). Public names, each with a one-line `#:` or `# WHY` comment directly above it:
   - `WORKER_PULSE_VERSION = 1`; `PULSE_STREAM_KINDS = ("model_text", "tool_call", "tool_result",
     "system")`; `PULSE_STREAM_LIMIT = 200`; `PULSE_TEXT_LIMIT = 200`;
     `PULSE_WRITE_INTERVAL_S = 2.0`.
   - `class WorkerPulse`, constructed as `WorkerPulse(job_id, path, *, clock=None)` where `clock`
     is a callable returning an aware UTC `datetime` (default: the current time), with:
     `bind()` — writes a fresh pulse: every call field null, `stream` empty, `bound_at` and
     `last_output_at` both the clock's time; `begin_call(*, role, provider, model, round_no, kind)`
     — sets the call fields, `call_started_at` to now and `call_ended_at` to null, and writes;
     `observe_output()` — moves `last_output_at` to now; `add_pi_record(record)` — maps one parsed
     Pi record to at most one stream entry (below), moves `last_output_at`, and drops the oldest
     entries beyond `PULSE_STREAM_LIMIT`; `end_call()` — sets `call_ended_at` and writes at once;
     `snapshot()` — a copy of the pulse as the dictionary D2 names. `observe_output` and
     `add_pi_record` write only when at least `PULSE_WRITE_INTERVAL_S` passed since the last write.
     Every method is safe to call from the stream pump's thread (one lock). A write that fails
     with `OSError` is swallowed and leaves the pulse in memory: a pulse never fails a call.
   - Mapping in `add_pi_record`: `message_end` whose message role is `assistant` → `model_text`
     with `text` the joined text blocks, read as `summarize_pi_events` reads them;
     `tool_execution_start` → `tool_call` with `tool` the record's `toolName` (`"?"` when absent)
     and `text` the record's `args` as compact JSON (`json.dumps(..., sort_keys=True,
     separators=(",", ":"), default=str)`), empty when absent; `tool_execution_end` →
     `tool_result` with `tool` as above and `length` the character length of the record's
     `result` as the same compact JSON, 0 when absent; `auto_retry_start` and `agent_settled` →
     `system` with `text` the record's type. Every `text` goes through
     `stream_evidence.redact_text` and is then cut to `PULSE_TEXT_LIMIT` characters. Every entry
     carries `at` (now) and `role` (the current call's role, or null). Any other record adds no
     entry. Times are written in the format `serve_runs._now` writes.
   - `bind_worker_pulse(job) -> WorkerPulse | None`: for a job with a `job_id`, builds the pulse at
     `data_paths.worker_pulse_path(job.job_id)`, calls `bind()`, and stores it in a module
     `ContextVar`; for a job without one it stores None. `current_worker_pulse()` returns what is
     stored.
   - `read_worker_pulse(job_id: str, root: Path | None = None) -> dict | None`: the pulse as
     written, or None when the file is absent, unreadable, not a JSON object, or of another
     `version`.
3. `pi_loop_limits.py`, `PiLoopWatch`: the constructor gains the keyword
   `on_record: Callable[[dict[str, Any]], None] | None = None`; `feed` hands every parsed record to
   it after counting it, outside the watch's own lock. Nothing else in the module changes.
4. `pi_provider.py`:
   (a) `bind_job_clock` calls `bind_worker_pulse(job)` as its last statement, with the one-line
   comment `# DECISION F311 D2: every run of a job starts its worker pulse here.` directly above.
   (b) `PiProvider` gains `begin_stream_call(self, round_no: int, kind: str = "attempt") -> None`,
   which stores the round and kind for the next call (the shape `_begin_stream_call` already
   calls on any provider that has the method); before any call the round reads 1 and the kind
   `attempt`.
   (c) In `_call`, after the preflight and the two early returns: `pulse = current_worker_pulse()`;
   when it is not None, `pulse.begin_call(role=self._role, provider=PI_PROVIDER_NAME,
   model=self._model, round_no=<stored round>, kind=<stored kind>)`, the `PiLoopWatch` is built with
   `on_record=pulse.add_pi_record`, and the guard's `stdout_observer` is a function that calls
   `watch.feed(chunk)` and then `pulse.observe_output()`; after the guarded run returns (or
   raises), `pulse.end_call()`. Without a pulse `_call` behaves exactly as today.
5. `import_reachability_allowlist.txt`: add exactly the lines `test_import_reachability.py`

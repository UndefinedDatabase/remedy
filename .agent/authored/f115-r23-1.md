## Built State — what F115 actually shipped (2026-08-13)

`remedy stats report` is the command (`apps/cli/command_catalog.py:2970`,
`command_id="stats.report"`; handler `_cmd_stats_report`,
`apps/cli/commands/stats_ledger_cmd.py:509`). It takes `--since`, `--until`,
`--job`, `--by`, `--label`, `--project` and `--json`, and deliberately not
`--all-projects` — a cost report spanning projects would sum figures whose
scopes do not compare.

The renderers are pure and live in `packages/orchestration/cost_report.py`:
`render_cost_report_markdown` (:490) and `cost_report_json_bytes` (:334) return
the exact text a caller writes to disk, and `cost_report_json` (:285) returns
the `dict` the bytes are built from. All three take report objects, so nothing
about the output depends on a database being reachable. `COST_REPORT_VERSION`
is 3 (:48) and rides in the json as `report_version` (:296). The queries live
in `packages/orchestration/token_ledger.py` (`SCHEMA_VERSION` 2, :114):
`query_segment_shares` (:1216) for the per-segment breakdown,
`prior_report_period` (:1138) for the comparison window, `record_call_segments`
(:797) and `segment_rows_from_trace_file` (:735) for the manifest persistence
that makes the breakdown possible at all.

Three vocabulary decisions are load-bearing and pinned by tests:
`COST_UNMEASURED_LABEL` is `"unmeasured"` (:57) — a call that reported no usage
is never a zero; `COST_DEFAULT_LABEL` is `"(unlabelled)"` (:64);
`COST_UNNAMED_BUCKET_LABEL` is `"(unnamed)"` (:61). In the json an unmeasured
figure is `null`, never `0`, and the payload says so in `unmeasured_notation`.

The period is half-open and the comparison mirrors it: `prior_report_period`
needs BOTH bounds (`token_ledger.py:1160-1161`), because an open-ended period
has no length to mirror, and it distinguishes a window that never existed from
one that existed and held no calls (`_PRIOR_REASON_OPEN_ENDED` :1074,
`_PRIOR_REASON_UNPARSEABLE` :1078, `_PRIOR_REASON_MIXED_AWARENESS` :1082,
`_PRIOR_REASON_EMPTY_PERIOD` :1086).

Wiring: three previously unwired `build_trace_entry` call sites now pass a
composed prompt — the builder and reviewer in
`packages/orchestration/pingpong_loop.py` (:2844, :3037) and the planner path,
where `plan_job_with_llm` gained the keyword-only `on_prompt_composed` hook
(`packages/orchestration/llm_planner.py:105-110`) that
`apps/cli/commands/job.py:288` uses to collect what it is about to send.

Two breakdowns are deliberately NOT built, and the USER GUIDE says so rather
than the report faking it: a per-role breakdown has ONE bucket, because a task
run's `role` is recorded as `"builder"` for the whole run, and a per-task-class
breakdown has no source at all, because no ledger row carries a task class.
`remedy stats report` prints NEITHER limit — `_cmd_stats_report`
(`stats_ledger_cmd.py:509-568`) mentions neither, and the role note
`_ROLE_LIMIT_NOTE` (:373) has exactly two consumers, `_cache_payload` (:436)
and `_render_cache_human` (:489), both belonging to `remedy stats cache --by
role`. The limits are stated in `docs/guides/cost-report-user-guide-v0.md`
instead, which is where a reader meets them. Both belong to their own features.

The goldens under `tests/orchestration/fixtures/cost_report/golden/` are DATA.
No test regenerates them, and the example in
`docs/guides/cost-report-user-guide-v0.md` is byte-identical to
`cost_report.md` — a renderer change that moves the bytes must move the guide
in the same commit.

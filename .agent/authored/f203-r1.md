- `structured_log.py` — a docstring opening `"""F203 — Remedy's operations log: one setup, one
  JSON line per record, the job, task and run ids on every line.`, citing DECISION F203 D1 and
  saying that the log is operations data and never evidence, that every line is redacted like
  evidence, and that the terminal keeps showing warnings exactly as before; `from __future__
  import annotations`. It imports only from `packages.` and the standard library, never from
  `apps.`, and catches only named exception classes. Public names, each with a one-line WHY
  comment directly above it (AGENTS.md discoverability):
  - `LOG_FILE_NAME = "remedy.log"`; `LOG_FIELD_NAMES: tuple[str, ...] = ("ts", "level", "logger",
    "message", "job_id", "task_id", "run_id")`; `LOG_CONTEXT_KEYS: tuple[str, ...] = ("job_id",
    "task_id", "run_id")`; `DEFAULT_LOG_LEVEL = "INFO"`; `DEFAULT_LOG_MAX_BYTES = 10_000_000`;
    `DEFAULT_LOG_BACKUP_COUNT = 5`.
  - three module-level `ContextVar[str | None]`, default None, named `remedy_log_job_id`,
    `remedy_log_task_id`, `remedy_log_run_id`.
  - `bind_log_context(*, job_id=None, task_id=None, run_id=None)`, a `contextlib.contextmanager`:
    each argument that is not None is set, as `str(value)`, for the code inside the block; on
    exit, normally or by an exception, each is reset to what it was before, in reverse order. An
    argument left None leaves that id as it was.
  - `current_log_context() -> dict[str, str | None]` — the three ids, keyed by `LOG_CONTEXT_KEYS`
    in order.
  - `class LogContextFilter(logging.Filter)` — `filter(record)` sets each of the three ids on the
    record from the context variables unless the record already carries a value that is not None
    (an `extra=` wins), and returns True.
  - `log_timestamp(created: float) -> str` — UTC, `%Y-%m-%dT%H:%M:%S` then `.` then the three
    millisecond digits then `Z`, e.g. `2026-10-13T08:05:09.042Z`.
  - `class JsonLogFormatter(logging.Formatter)` — `format(record)` returns `json.dumps(entry,
    ensure_ascii=False)` of a dict with exactly the keys of `LOG_FIELD_NAMES` in that order —
    `ts` from `log_timestamp(record.created)`, `level` the level name, `logger` the logger name,
    `message` `redact_text(record.getMessage())`, each id `getattr(record, name, None)` — and,
    only when `record.exc_info` is set, a last key `exception`, `redact_text` of
    `self.formatException(record.exc_info)`. Redaction runs on each value BEFORE the dump, never
    on the dumped line, so a line always parses.
  - `class TextLogFormatter(logging.Formatter)` — `format(record)` returns `redact_text` of
    `f"{ts} {level} {logger} job={job_id or '-'} task={task_id or '-'} run={run_id or '-'}
    {message}"`, followed by a newline and the formatted exception when there is one.
  - `class OwnerOnlyRotatingFileHandler(logging.handlers.RotatingFileHandler)` — overrides `_open`
    to open the file with `os.open(self.baseFilename, os.O_WRONLY | os.O_CREAT | os.O_APPEND,
    0o600)` and `os.fdopen(descriptor, "a", encoding=self.encoding, errors=self.errors)`, with a
    WHY comment: the file and every rotated successor are owner-only, like a crash report.
  - `logs_dir(root: Path | None = None) -> Path` — `data_class_dir("logs", root)` (the literal
    class name, so the class registry test finds it).
  - `configure_structured_logging(root: Path | None = None, config: RemedyConfig | None = None)
    -> Path | None`. It first calls `reset_structured_logging()`. It reads `config` (else
    `get_config()`): `logging.level`, upper-cased, must be one of `DEBUG`, `INFO`, `WARNING`,
    `ERROR`, `CRITICAL`, else `DEFAULT_LOG_LEVEL` is used and the unknown name is remembered;
    `logging.json` as a bool; `logging.max_bytes` and `logging.backup_count` through `int(...)`,
    each falling back to its default on `ValueError` or `TypeError`. It installs on the ROOT
    logger, each marked with the attribute `_remedy_structured_log = True`: (a) a
    `logging.StreamHandler(sys.stderr)` at `WARNING` with `logging.Formatter("%(message)s")`;
    (b) the folder `logs_dir(root)` made with mode 0o700 (parents, exist_ok), and an
    `OwnerOnlyRotatingFileHandler` on `<folder>/LOG_FILE_NAME` with `maxBytes`, `backupCount` and
    `encoding="utf-8"`, at the configured level, with `JsonLogFormatter` or `TextLogFormatter`
    and with ONE `LogContextFilter` added to the HANDLER (a filter on the root logger would not
    see records of child loggers). An `OSError` while making the folder or opening the file skips
    (b) and the function answers None; otherwise it answers the file's path. The root logger's
    level becomes the lower of the configured level and `WARNING`. When the level name was
    unknown, it then logs one WARNING on `logging.getLogger(__name__)`: `"unknown logging.level
    %r; INFO is used"` with the name.
  - `reset_structured_logging() -> None` — removes from the root logger, and closes, every
    handler carrying `_remedy_structured_log`, and restores the root logger's level to what it
    was before the first `configure_structured_logging` call since the last reset; handlers it
    did not install are never touched.

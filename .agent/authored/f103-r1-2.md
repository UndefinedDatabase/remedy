# Plan — F103 Token ledger (SQLite)

Branch: feature/f103-token-ledger · claimed `[~]` in
docs/roadmap/STATUS.md. Build mode: one-session self-drive
(docs/agents/self_drive_protocol.md), one delegated worker per round.

## Goal
Token and cost actuals become queryable: every provider call lands as a
row in a per-project SQLite ledger at
`<data_root>/projects/<uuid>/ledger.sqlite`, and `remedy stats cost`
answers per-job, per-role and per-period questions from it. The file
evidence stays the source of truth; the database is a mirror, and a
writer failure never fails the run.

## Current Step
R1 — the claim round: the Open PR Gate (clear — no open PRs), the
authored `[ ]`→`[~]` STATUS line, the R-0214 closure-candidate sweep
that lands the AGENTS.md stated-cause overage clause, and the reset of
live_review, plan, context and candidates to this feature. No
production code in this round.

## Next Steps
- R2 — T001: schema, migration bootstrap, the `record_call(...)` writer,
  the never-fail-the-run discipline, miss counting and unit tests.
- R3 — T002: backfill and reconcile commands, idempotent by call_id.
- R4 — T003: `remedy stats cost` aggregation, basis labeling and
  read-only cross-project aggregation.
- R5 integration gate; R6 closure. Steps R2-R4 follow the feature file's
  Task slicing and its Orchestrator brief, which requires T001 first and
  rejects any diff adding an ORM or a second capture path.

## Risks
- SQLite is new to this repository, so the first slice sets the
  precedent for schema versioning and WAL handling. Keeping transactions
  tiny now is what lets the later queue and scheduler world add writers.
- Calls without reported usage must produce rows with nulls and basis
  `unknown` rather than invented numbers — the F075 campaigns ran
  tokens-unmeasured for exactly that reason.
- Budgets read actuals directly today; switching them to the ledger is
  explicitly out of scope and must not be done opportunistically.

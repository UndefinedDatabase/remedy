# Plan — F251 Full-suite stabilization (R1)

## Goal
The full suite stops churning: three consecutive `python3 -m pytest
-n auto -q` runs on this branch produce identical failure sets, and
that set is empty except for explicitly quarantined tests (T1_F251.md,
operator scope ruling 2026-07-27). Hermetic fix beats quarantine;
quarantine = marker/skip + reason string + backlog reference, never
deletion, never blanket directory skips, never weakened assertions.

## Checklist
- [ ] S1 baseline: two full-suite runs, failure-set diff, wall time
      recorded, per-class catalog (the named classes + any new ones)
- [ ] S2 per-class decision table (root-cause fix vs
      quarantine-with-reason), committed in plan.md before fixing
- [ ] S3 root-cause fixes class by class (xdist suspects first: shared
      tmp/data paths, port collisions, test-order dependencies, global
      process/env state) — separate commit per class
- [ ] S4 quarantine mechanism (existing convention or minimal new one)
      + remaining classes quarantined with reason + backlog ref
- [ ] S5 proof: three consecutive identical-set runs, set empty except
      quarantined; wall time after recorded
- [ ] Handback: per-class item-status table + final line
      "full suite on main: N quarantined, 0 churning"

## Current Step
S1 baseline.

## Risks
- Out of scope: new product features, CLI work, executor changes beyond
  what a hermetic-test fix strictly requires.
- A flaky test exposing a REAL product bug is a finding per normal
  rules, not a default quarantine candidate.
- Stop-on-red: a class that does not converge → hand back early with
  the honest state.

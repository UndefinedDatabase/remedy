## Built State — what F115 actually shipped (2026-08-13)

`remedy stats report` is the command. Its catalog entry is `stats.report` in
`apps/cli/command_catalog.py` and its handler is `_cmd_stats_report` in
`apps/cli/commands/stats_ledger_cmd.py`. It takes `--since`, `--until`,
`--job`, `--by`, `--label`, `--project` and `--json`. It deliberately has no
`--all-projects`, and the catalog entry's own description says why where
`remedy stats --help` will print it: cost folds across projects but the segment
breakdown does not, so an all-projects report would publish one project's
breakdown under a multi-project total.

The renderers live in `packages/orchestration/cost_report.py` and are pure —
they take report objects, so nothing about the output depends on a database
being reachable. `render_cost_report_markdown` and `cost_report_json_bytes`
return the exact text a caller writes to disk; `cost_report_json` returns the
dict those bytes are built from. `COST_REPORT_VERSION` is 3 and rides in the
json as `report_version`.

The queries live in `packages/orchestration/token_ledger.py`, whose
`SCHEMA_VERSION` is 2: `query_segment_shares` for the per-segment breakdown,
`prior_report_period` for the comparison window, and `record_call_segments`
with `segment_rows_from_trace_file` for the manifest persistence that makes the
breakdown possible at all.

Vocabulary: `COST_UNMEASURED_LABEL` is `"unmeasured"` — a call that reported no
usage is never a zero — and in the json an unmeasured figure is `null`, never
`0`. `COST_DEFAULT_LABEL` is `"(unlabelled)"` and `COST_UNNAMED_BUCKET_LABEL`
is `"(unnamed)"`. Of the three only the `unmeasured` word is currently pinned
by a test; the other two literals could change today without turning anything
red, which is worth knowing before anyone relies on them.

The period is half-open and the comparison mirrors it. `prior_report_period`
refuses an open-ended period outright — its first guard returns
`_PRIOR_REASON_OPEN_ENDED` when either bound is missing, because a period with
no length has no equal-length window before it. It also distinguishes a window
that could not be parsed, one whose bounds contradict each other, and one that
existed but held no calls: `_PRIOR_REASON_UNPARSEABLE`,
`_PRIOR_REASON_MIXED_AWARENESS` and `_PRIOR_REASON_EMPTY_PERIOD`. "There was no
window to look at" and "we looked and found nothing" are different facts and
the report keeps them different.

Wiring: three previously unwired `build_trace_entry` call sites now pass a
composed prompt — the builder and the reviewer in
`packages/orchestration/pingpong_loop.py`, and the planner path, where
`plan_job_with_llm` in `packages/orchestration/llm_planner.py` gained a
keyword-only `on_prompt_composed` hook that `apps/cli/commands/job.py` uses to
collect what it is about to send.

Two breakdowns are deliberately NOT built, and the USER GUIDE says so rather
than the report faking it. A per-role breakdown has ONE bucket, because a task
run's `role` is recorded as `"builder"` for the whole run; a per-task-class
breakdown has no source at all, because no ledger row carries a task class.
`remedy stats report` prints NEITHER limit: the body of `_cmd_stats_report`
mentions neither, and the role note `_ROLE_LIMIT_NOTE` has exactly two
consumers, `_cache_payload` and `_render_cache_human`, both belonging to
`remedy stats cache --by role`. The limits are stated in
`docs/guides/cost-report-user-guide-v0.md` instead, which is where a reader
meets them. Both belong to their own features.

The goldens under `tests/orchestration/fixtures/cost_report/golden/` are DATA.
No test regenerates them, and the example report in
`docs/guides/cost-report-user-guide-v0.md` is byte-identical to the
`cost_report.md` golden — a renderer change that moves those bytes must move
the guide in the same commit.

One lesson is worth more than the code. F115's cover for the planner call site
is a test in `tests/orchestration/test_structured_planner_cli.py` that reads
`apps/cli/commands/job.py` with `inspect.getsource` and asserts the wiring
string appears in it. It reads the file instead of executing the call, so it
proved the argument was written and could never prove it worked — and a test
double left with the old two-parameter signature broke six tests that stayed
invisible to every scoped round gate until the integration gate ran (finding
R-0340). A wiring test that does not execute the wiring is not cover.

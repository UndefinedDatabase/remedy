`repo_catalog.py` — module docstring opening `"""F206 — the repository dependency catalog: ...`,
citing DECISION F206 D1; `from __future__ import annotations`; the `tomllib`/`tomli` fallback of
`runtime_config.py`. Public names, each with a one-line WHY comment above it (AGENTS.md
discoverability):
- `REPO_CATALOG_FILENAME = "catalog.toml"`; `REPO_CATALOG_KEYS`, a frozenset of `pid`, `name`,
  `root`, `owner`, `depends_on`, `publishes`, `consumes`.
- `class RepoCatalogError(ValueError)` — any invalid catalog; `class
  RepoCatalogCycleError(RepoCatalogError)` with attribute `cycle: tuple[str, ...]`, the path with
  its first pid repeated at the end, message exactly
  `f"{source}: the repository catalog has a dependency cycle: {' -> '.join(cycle)}"`.
- `@dataclass(frozen=True) class RepoCatalogEntry`: `pid: str`, `name: str = ""`, `root: str =
  ""`, `owner: str = ""`, `depends_on: tuple[str, ...] = ()`, `publishes: tuple[str, ...] = ()`,
  `consumes: tuple[str, ...] = ()`.
- `@dataclass(frozen=True) class RepoCatalog`: `entries: tuple[RepoCatalogEntry, ...]`, `source:
  str`; method `entry(pid) -> RepoCatalogEntry | None`; property `pids -> tuple[str, ...]` in
  file order.
- `class RepoCatalogEdge(NamedTuple)`: `consumer: str`, `library: str`, `path: tuple[str, ...]`
  (from consumer to library, both included); `class RepoCatalogOrder(NamedTuple)`: `pids:
  tuple[str, ...]`, `edges: tuple[RepoCatalogEdge, ...]`.
- `repo_catalog_path(root: Path | None = None) -> Path` — `data_class_dir("org", root) /
  REPO_CATALOG_FILENAME`.
- `parse_repo_catalog(text: str, source: str = "<text>") -> RepoCatalog`. Refusals, each a
  `RepoCatalogError` whose message starts with `f"{source}: "`: TOML that does not parse; a
  top-level key other than `repo`; `repo` not an array of tables; in a table, a key not in
  `REPO_CATALOG_KEYS` (the message names the key and the table's position, 1-based); `pid`
  missing or not a non-empty string; `name`, `root`, `owner` not a string; `depends_on`,
  `publishes`, `consumes` not a list of non-empty strings, or one naming a value twice; a `pid`
  a second table repeats; a `depends_on` value no table's `pid` holds (the message names both
  pids). Then the cycle check: `find_repo_catalog_cycle` below; a cycle raises
  `RepoCatalogCycleError`. A table depending on itself is the cycle `("a", "a")`. An absent or
  empty `repo` is a valid empty catalog.
- `find_repo_catalog_cycle(depends: Mapping[str, Sequence[str]]) -> tuple[str, ...] | None` —
  depth-first over the pids in mapping order and each pid's dependencies in listed order; the
  first back edge found returns the stack from the repeated pid to the top plus that pid again.
- `load_repo_catalog(path: Path | None = None) -> RepoCatalog | None` — `path` defaults to
  `repo_catalog_path()`; `None` when the file does not exist; otherwise
  `parse_repo_catalog(text, str(path))`.
- `repo_catalog_order(catalog: RepoCatalog, pids: Sequence[str]) -> RepoCatalogOrder` — a pid
  given twice raises `ValueError`. For two given pids x and y, x must come after y when y is
  reachable from x through `depends_on` across the WHOLE catalog (so through pids not given); a
  given pid the catalog does not hold has no edge. The order is the stable topological order:
  repeatedly place the first not-yet-placed pid, in the given order, all of whose required
  predecessors are placed. `edges` holds one `RepoCatalogEdge` per ordered pair (x after y), in
  the order of the resulting `pids` by consumer then library, and its `path` is the shortest
  `depends_on` path from x to y, ties broken by listed order (breadth-first).
- `describe_repo_catalog_edge(edge: RepoCatalogEdge) -> str` — `"app depends on toolbox"` for a
  two-pid path, `"app depends on toolbox through brain"` for a longer one, the middle pids joined
  by `", "`.

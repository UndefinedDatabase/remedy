# Context — F103 Token ledger (SQLite)

## Active Branch
feature/f103-token-ledger, cut from main at c1c0fbcb after PR #186 —
the F254 closure — was merged. F103 is claimed `[~]` in
docs/roadmap/STATUS.md; it is the first `[ ]` entry after F254, which is
what Rule A5 names.

## Scope
In: a per-project SQLite ledger at
`<data_root>/projects/<uuid>/ledger.sqlite` with a schema-versioned meta
table and a `calls` table; a `record_call(...)` writer at the seam where
actuals are finalized, which never fails the run and counts its misses;
`remedy stats backfill-ledger` and `remedy stats verify-ledger`;
`remedy stats cost` with per-job, per-role, per-model and per-day
aggregation, `--json`, and read-only `--all-projects`.

Out, per the feature file's Do-not-touch: estimation and calibration,
budgets' own counting — they read actuals directly today and switching
them is a later, explicit change — and provider parsing. Also barred by
the Orchestrator brief: any ORM, and any second capture path. The writer
consumes the records the actuals feature already produces.

## Constraints
- SPLIT rounds are mandatory: this feature touches packages/ and apps/,
  and production code never merges self-certified
  (docs/agents/planner_reviewer_prompt.md §3).
- The main session writes nothing in the work tree; a delegated worker
  subagent makes every commit (docs/agents/self_drive_protocol.md).
- Merges only at the Open PR Gate; never force-push; never touch main.
- Verification is pytest, scoped per round, plus the canary
  tests/cli/test_golden_path.py. A round touching docs/roadmap/ also
  runs tests/docs/. The full suite runs only at the integration gate,
  with `-n auto`. Destructive and mutation checks run only inside a
  disposable git worktree, so resource safety stays intact and no
  background pytest process is ever left running.
- The writer module's docstring must carry the sentence that the files
  remain the source of truth and the database is a mirror.

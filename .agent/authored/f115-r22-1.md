## Built State — what F115 actually shipped (2026-08-13)

`remedy stats report` is the command (`apps/cli/command_catalog.py`, entry
`command_id="stats.report"`; handler `_cmd_stats_report`,
`apps/cli/commands/stats_ledger_cmd.py`). It takes `--since`, `--until`,
`--job`, `--by`, `--label`, `--project` and `--json`, and deliberately not
`--all-projects` — a cost report spanning projects would sum figures whose
scopes do not compare.

The renderer is pure and lives in `packages/orchestration/cost_report.py`:
`render_cost_report_markdown` and `cost_report_json` / `cost_report_json_bytes`
take report objects and return text, so nothing about the output depends on a
database being reachable. `COST_REPORT_VERSION` is 3 and rides in the json as
`report_version`. The queries live in `packages/orchestration/token_ledger.py`
(`SCHEMA_VERSION` 2): `query_segment_shares` for the per-segment breakdown,
`prior_report_period` for the comparison window, `record_call_segments` and
`segment_rows_from_trace_file` for the manifest persistence that makes the
breakdown possible at all.

Three vocabulary decisions are load-bearing and are pinned by tests:
`COST_UNMEASURED_LABEL` is `"unmeasured"` — a call that reported no usage is
never a zero; `COST_DEFAULT_LABEL` is `"(unlabelled)"`; and
`COST_UNNAMED_BUCKET_LABEL` is `"(unnamed)"`. In the json an unmeasured figure
is `null`, never `0`.

The period is half-open and the comparison mirrors it: `prior_report_period`
needs BOTH bounds, because an open-ended period has no length to mirror, and it
distinguishes a window that never existed from one that existed and held no
calls (`_PRIOR_REASON_OPEN_ENDED`, `_PRIOR_REASON_EMPTY_PERIOD`,
`_PRIOR_REASON_UNPARSEABLE`, `_PRIOR_REASON_MIXED_AWARENESS`).

Wiring: three previously unwired `build_trace_entry` call sites now pass a
composed prompt — the builder and reviewer in
`packages/orchestration/pingpong_loop.py` and the planner path, where
`plan_job_with_llm` gained the keyword-only `on_prompt_composed` hook
(`packages/orchestration/llm_planner.py:105-110`) that `apps/cli/commands/job.py`
uses to collect what it is about to send.

Deliberately NOT built, and the report says so rather than faking it: a
per-role breakdown has ONE bucket, because a task run's `role` is recorded as
`"builder"` for the whole run; a per-task-class breakdown has no source at all,
because no ledger row carries a task class. Both limits belong to their own
features.

The goldens under `tests/orchestration/fixtures/cost_report/golden/` are DATA.
No test regenerates them, and the example in
`docs/guides/cost-report-user-guide-v0.md` is byte-identical to
`cost_report.md` — a renderer change that moves the bytes must move the guide
in the same commit.

One lesson is worth more than the code. F115's cover for the planner call site
was `tests/orchestration/test_structured_planner_cli.py:302`, which asserts the
SOURCE TEXT of `job.py` contains the wiring. It reads the file instead of

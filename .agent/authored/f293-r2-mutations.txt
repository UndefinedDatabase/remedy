WHY the scope is broader than predicted: `_SCAN_CACHE` is a module-level dict that persists
for the life of the whole pytest process (not per-test). With a single fixed key, whichever
test runs FIRST within the file populates `_SCAN_CACHE["_only"]` with its own tmp_path's scan,
and every later test in the same process — regardless of its OWN `root=` argument — reads that
same stale entry back, because the key no longer varies with `root`. Declaration order in this
file runs `test_a_command_referenced_nowhere_is_dead` first, which seeds the cache; every
subsequent call in the process (three more tests) then reads that first test's stale scan
instead of its own tmp_path's real content, which is why the failure count is 4 rather than 1.
This is not a defect in the production caching design under test (the fix keys by `root`, not
by a fixed string — that is exactly what this mutation breaks) or in the two new tests; it is a
stronger demonstration of the same defect the mutation introduces, surfacing through more call
sites than the single test written to target it directly.

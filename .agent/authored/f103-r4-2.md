## Goal
Token and cost actuals become queryable: every provider call lands as a
row in a per-project SQLite ledger at
`<data_root>/projects/<uuid>/ledger.sqlite`, and `remedy stats cost`
answers per-job, per-role and per-period questions from it. The file
evidence stays the source of truth; the database is a mirror, and a
writer failure never fails the run. Per DECISION D16 a row is one
finalized TASK RUN, keyed `"<job_id>:<task_id>"`.

## Risks
- `--all-projects` must stay read-only across every project ledger; a
  command that aggregates must never create or migrate another
  project's database as a side effect of reading it.
- SUM over all-NULL must stay NULL. Coercing it to 0 with COALESCE would
  make an unmeasured figure look like a measured zero — the exact P6
  failure the F075 campaigns taught, and the reason the ledger stores
  nulls at all.
- R-0218: the "no perceptible slowdown" criterion is still unmeasured.
  R5 owes it a number.
- Budgets read actuals directly today; switching them to the ledger is
  explicitly out of scope and must not be done opportunistically.

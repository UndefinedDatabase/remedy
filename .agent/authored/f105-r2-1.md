Design, normative:
  - `SegmentStabilityRank(IntEnum)` with exactly the scale the feature file
    documents: SYSTEM=0, CONVENTIONS=1, DOSSIER=2, JOB_CONTEXT=3, TASK=4,
    STEERING=5. A one-line WHY comment sits directly above the definition
    (AGENTS.md Code Discoverability): stable prefixes first so the provider
    cache can hit them, volatile tails last.
  - `PromptSegment`: frozen dataclass — `name: str`, `rank:
    SegmentStabilityRank`, `text: str`. Name must be non-empty and unique
    within a registry.
  - `PromptSegmentRegistry`: `register(name, rank, text, *, token_cap=None)`
    returns the `PromptSegment` and preserves REGISTRATION ORDER. Duplicate
    name raises `PromptSegmentError`. `token_cap` (an int, tokens) is checked
    at registration with the repo's existing estimator
    `packages.orchestration.token_economy.estimate_text_tokens`; over cap raises
    `PromptSegmentError` whose message names the segment, the estimate and the
    cap. Do NOT add a tokenizer dependency.
  - `CONVENTIONS_TOKEN_CAP = 800` — the feature file's cap for the conventions
    segments, exported here so T002's loaders import it instead of restating it.
  - `compose_prompt_segments(segments) -> ComposedPrompt`: sorts by
    `(rank, registration_index)` — a STABLE sort, so equal ranks keep
    registration order — and joins with `PROMPT_SEGMENT_DELIMITER`.
  - `PROMPT_SEGMENT_DELIMITER = "\n\n"` — DECISION F105 D1, record it in
    `.agent/decisions.md`? NO: record it as a WHY comment above the constant
    instead, since `.agent/decisions.md` is not in this round's change set. The
    reason: T003 migrates existing builders under content-equality goldens, so
    the delimiter must be a plain blank line and compose must inject NO headers,
    labels or markers of its own. Anything injected would change the bytes of
    every migrated prompt and make content-equality unprovable.
  - `ComposedPrompt`: frozen dataclass — `text: str` and
    `manifest: tuple[PromptSegmentManifestEntry, ...]`, plus
    `manifest_as_dicts()` returning JSON-ready dicts for the evidence writer
    T003 will add. Wiring the manifest INTO call evidence is explicitly T003's
    work, not this round's — say so in a deliberate-absence comment where a
    reader would look for it (AGENTS.md: document deliberate absences).
  - `PromptSegmentManifestEntry`: frozen dataclass — `name`, `rank` (the int
    value), `sha256` of the segment text encoded UTF-8, `chars`,
    `tokens_estimated`. Manifest order equals composition order.
  - `PromptSegmentError(Exception)` — one error type for this module.
  - Composing an empty sequence returns empty text and an empty manifest; it is
    not an error.
  - Public names carry a domain word and grep to their own definition only
    (AGENTS.md Code Discoverability). Type hints throughout; no `Any` in the
    public signatures.

Tests, `tests/orchestration/test_prompt_segments.py` — each one must FAIL if the
behaviour it names regresses. Cover at least:
  1. Rank ordering: segments registered in scrambled rank order compose in rank
     order.
  2. Tie-break: two segments of the same rank keep registration order.
  3. Byte stability: composing the same registry twice yields identical bytes.
  4. Volatile-tail prefix stability (the feature's acceptance hash test): two
     compositions that differ ONLY in the TASK/STEERING segments have an
     identical byte prefix up to the volatile tail — assert on a hash of that
     prefix, not on a substring.
  5. Delimiter stability: exactly one blank line between adjacent segments; a
     single-segment composition equals that segment's text with nothing added;
     no injected headers or labels anywhere in the output.
  6. Manifest fidelity: names, ranks, sha256, chars and order match the composed
     text; the sha256 is the sha256 of the segment text, verified by recomputing
     it in the test rather than by trusting the module.
  7. Over-cap registration raises `PromptSegmentError`, and the message names
     the segment and both numbers. Under-cap registration does not raise.
  8. Duplicate segment name raises `PromptSegmentError`.
  9. Empty composition returns empty text and an empty manifest.
 10. The documented rank scale is pinned: the enum's members and their integer
     values are asserted exactly, so a silent renumbering fails.

## Goal
Token and cost actuals become queryable: every provider call lands as a
row in a per-project SQLite ledger at
`<data_root>/projects/<uuid>/ledger.sqlite`, and `remedy stats cost`
answers per-job, per-role and per-period questions from it. The file
evidence stays the source of truth; the database is a mirror, and a
writer failure never fails the run. Per DECISION D16 a row is one
finalized TASK RUN, keyed `"<job_id>:<task_id>"` — the granularity the
actuals feature actually puts on disk.

## Current Step
R3 — T002's data layer: `call_id_for_task_run`,
`call_record_from_evidence`, `backfill_ledger` and `verify_ledger` in
`packages/orchestration/token_ledger.py`, reusing `token_truth`'s

finalized, opt-in and inert by default; and the tests that pin
idempotence, the unmeasured case, the malformed case, zero drift on a
clean fixture and an injected missing row. No CLI in this round.

## Risks
- The call site is the round's only edit to an existing production file.
  It must not change `write_evidence_bundle`'s behaviour or return value
  for any existing caller, and it must never touch the real data root
  from a test — hence the explicit opt-in parameter.
- R-0219: a presence-only reconcile cannot see a content-drifted row.
  R3 must rule explicitly — immutable `call_id` documented, or content
  comparison in `verify_ledger`.
- R-0218: the "no perceptible slowdown" criterion is still unmeasured;
  R5 owes it a real number, not a claim.
- Budgets read actuals directly today; switching them to the ledger is
  explicitly out of scope and must not be done opportunistically.

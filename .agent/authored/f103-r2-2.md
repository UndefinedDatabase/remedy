## Goal
Token and cost actuals become queryable: every provider call lands as a
row in a per-project SQLite ledger at
`<data_root>/projects/<uuid>/ledger.sqlite`, and `remedy stats cost`
answers per-job, per-role and per-period questions from it. The file
evidence stays the source of truth; the database is a mirror, and a
writer failure never fails the run.

## Current Step
R2 — T001: `packages/orchestration/token_ledger.py` with the schema, the
migration bootstrap keyed off a `meta` row, the `record_call(...)`
writer, WAL plus tiny transactions, the never-fail-the-run discipline
and its miss counter, plus `tests/orchestration/test_token_ledger.py`
pinning all of it — including the never-fail rule the feature file's
Orchestrator brief demands and a concurrent-read-during-write check.
This is the first and so far only use of SQLite in Remedy, and it adds
NO call site: the writer is not yet wired into the provider path.

## Next Steps
- R3 — T002: wire `record_call` into the seam where actuals are
  finalized (the FIRST item of that round, so the ledger stops being
  dead code), then `remedy stats backfill-ledger` and
  `remedy stats verify-ledger`, idempotent by call_id, with tests on
  fixture evidence.
- R4 — T003: `remedy stats cost` with `--since`, `--job`,
  `--by role|model|day`, `--json` and read-only `--all-projects`, basis
  labeling, and tests.
- R5 integration gate per docs/agents/integration_gate.md; R6 closure
  per docs/roadmap/STATUS_closure_protocol.md. Steps R2-R4 follow the
  feature file's Task slicing and its Orchestrator brief, which requires
  T001 first and rejects any diff adding an ORM or a second capture
  path.

## Risks
- SQLite is new to this repository, so T001 sets the precedent for
  schema versioning and WAL handling. Keeping transactions tiny now is
  what lets the later queue and scheduler world add writers.
- A ledger that nothing calls is dead code, which is why the call-site
  wiring is pinned to the front of R3 rather than left to drift.
- Calls without reported usage must produce rows with nulls and basis
  `unknown` rather than invented numbers — the F075 campaigns ran
  tokens-unmeasured for exactly that reason.
- Budgets read actuals directly today; switching them to the ledger is
  explicitly out of scope and must not be done opportunistically.

── C2 — packages/orchestration/watchdog.py ───────────────────────────
New module. PURE: no disk read, no disk write, no mission mutation, and it
imports nothing from `orchestrator_loop`. Move-kind constants come from
`packages.orchestration.orchestrator_move_schema` (`MOVE_DISPATCH_JOB`,
`MOVE_DECLARE_MILESTONE_DONE`) — one spelling per concept.

Trip kinds: `TRIP_NO_PROGRESS = "no_progress"`,
`TRIP_BURN_ANOMALY = "burn_anomaly"`, `TRIP_GOAL_DRIFT = "goal_drift"`.

`@dataclass(frozen=True) class Trip` — fields `kind: str`, `what: str`,
`since_iteration: int`, `numbers: dict[str, Any]`; plus `to_json()` returning
exactly those four keys. `what` is one human-readable line.

`@dataclass(frozen=True) class WatchdogThresholds` — `no_progress_repeats:
int = 3`, `burn_window: int = 3`, `burn_min_samples: int = 5`,
`burn_multiplier: float = 3.0`. Four module constants name the config keys:
`watchdog.no_progress_repeats`, `watchdog.burn_window`,
`watchdog.burn_min_samples`, `watchdog.burn_multiplier`.

`watchdog_thresholds_from_config(config=None) -> WatchdogThresholds` mirrors
`orchestrator_loop.loop_limits_from_config`: it imports `get_config` lazily
INSIDE the function, and a key that reads None takes the dataclass default.

Helpers, both pure:
  * `dispatched_entries(entries)` — entries whose `move.kind` is
    `MOVE_DISPATCH_JOB` AND whose `outcome.job_id` is non-empty (D3).
  * `measured_tokens(entry) -> int | None` — `None` unless `cost.usage` is a
    dict; else `input_tokens + output_tokens`, each defaulting to 0 (D5).

Evaluators — each takes a `Sequence[dict]` in ledger order, returns
`Trip | None`:
  * `evaluate_no_progress(entries, *, repeats)` — walk in list order keeping a
    run of consecutive dispatched entries (D3) sharing one
    `move.payload.milestone_id`. ANY `declare_milestone_done` entry resets the
    run to empty (D2). A different milestone_id starts a new run. When a run
    reaches `repeats`, trip: `since_iteration` is the run's FIRST entry's
    `iteration`; `numbers` carries `repeats`, `threshold`, `milestone_id`.
  * `evaluate_burn_anomaly(entries, *, window, min_samples, multiplier)` —
    take `measured_tokens` over ALL entries in order, dropping `None` (D5).
    With fewer than `min_samples + window` measured values, return None
    (inert). The last `window` values are the window; every measured value
    BEFORE them is the baseline. Trip when the window mean is STRICTLY
    greater than `multiplier * baseline_mean`. `since_iteration` is the
    `iteration` of the entry the first window value came from; `numbers`
    carries `window_mean`, `baseline_mean`, `multiplier`, `baseline_samples`.
  * `evaluate_goal_drift(entries, *, milestone_ids)` — the FIRST dispatched
    entry (D3) whose `move.payload.milestone_id` is not in `milestone_ids`
    trips. Drift is binary, not counted. `numbers` carries `milestone_id` and
    `known_milestones`.
  * `evaluate_ledger(entries, *, milestone_ids, thresholds)` — returns the
    non-None trips in the fixed order no_progress, burn_anomaly, goal_drift.

Every public name carries its one-line WHY comment directly above it
(AGENTS.md, Code Discoverability). A malformed entry — a missing `move`,
`outcome` or `cost`, or a non-dict where a dict is expected — is SKIPPED, never
raised on: the ledger is forensic evidence and `read_ledger` already tolerates
tears. State that reason in the module docstring.

## Findings

- R-0344 — Medium — a reviewer-block gate decided by the test fixture instead of by the code under test. The R1 block's ITEM 3 test 13 ordered the assertion "no warning contains the word 'loop'" over the WHOLE warning string, but `load_config` composes its warnings as `f"Unknown key in {p_path}: {key}"` (`packages/orchestration/config.py`), so every warning carries the config file's PATH. Under pytest's `tmp_path` that path embeds the test's own function name, which contains "loop", so the assertion's outcome was fixed by the fixture directory's name and not by whether the `[[loop]]` table reaches the unknown-key check at all. The same block also left `user_path` unpinned, so the assertion would additionally have read whatever `~/.config/remedy/remedy.toml` happens to contain on the operator's machine. The R1 worker caught both, scoped the scan to the KEY each warning names and pinned `user_path` at a non-existent file; the property being pinned is unchanged and the test still goes red if the table moves under `[remedy]`. This is the reviewer-arithmetic family after R-0327, R-0328, R-0331, R-0333 and R-0336: an ordered gate whose expected value the reviewer did not compute from the code that produces it, which is exactly pre-emission checklist item 8 (docs/agents/planner_reviewer_prompt.md §3). Counter-measure, applied from R2 on: an ordered assertion may not match against a string that carries a filesystem path. OPEN.

- R-0345 — Low — the R1 block ordered one commit for two separable files totalling 599 insertions. ITEM 3 gave a single commit subject covering both `packages/orchestration/loop_spec.py` (331 insertions) and `tests/orchestration/test_loop_spec.py` (268), over the AGENTS.md 500-insertion cap, which counts insertions only (DECISION F104 D1). The worker split it into `9d415caf` and `5528a569` and declared the deviation rather than claiming inseparability, which was the correct call — a false inseparability claim would have been the worse outcome. Nothing landed wrong, but the round spent a declared deviation proving a reviewer sizing mistake, the R-0252 shape: the block never estimated the insertions it was ordering. Counter-measure, applied from R2 on: every block states a per-commit insertion budget before emission and never bundles a new module with its test file in one commit. OPEN.

- R-0346 — Low — two live DECISIONs existed nowhere the repo looks for decisions. The R1 block recorded DECISION F045 D1 (loops live in a TOP-LEVEL `[[loop]]` table) and D2 (deadline validation is mirrored, not imported) in the `loop_spec.py` module docstring and in its own bytes, but its change set omitted `.agent/decisions.md`, which AGENTS.md ("State Update Triggers") makes a MUST when a meaningful technical decision is made. The worker declared the omission rather than widening its change set — correct, since the change set is the block's to set and "no while-I'm-here edits" binds the worker. The result was two decisions readable only in a docstring and in `.agent/authored/`, not in the file whose entire purpose is to carry them. R2 lands the catch-up entries. Counter-measure: any block that carries a DECISION carries `.agent/decisions.md` in its change set. OPEN.

- R-0347 — Medium — the STOP sentinel has no re-check point, and the handoff that steers a session past it named the wrong rule. `docs/agents/self_drive_protocol.md` guardrail G6 binds `.agent/STOP` "at any point", but the only place the protocol orders it read is the Phase 0 state probe, which runs once at session start; the round loop in Phase 2 (author → delegate → review → verdict) never re-reads it. The F045 R2 handoff, authored by the reviewer, compounded that by stating the next session's first action as "Phase 0 state probe, then the Open PR Gate" — Phase 1 rule 2 — while omitting rule 1, the STOP check that precedes it. In this session the sentinel appeared AFTER the Phase 0 probe had already found the tree clean and the file absent, so a session-start-only reading could not have seen it; it surfaced only because the R3 block's gate (m) ordered `git status --porcelain`, and the R3 worker halted before its first commit, wrote nothing and committed nothing. Nothing landed wrong, but the sentinel was caught by a gate that exists for a different reason, which is luck rather than design. Counter-measure, applied from the next session on: every reviewer block's gate list keeps a `git status --porcelain` gate, and the reviewer re-reads `.agent/STOP` from disk before authoring each round rather than trusting the Phase 0 result; any handoff that names the next session's first action names Phase 1 rule 1 before rule 2. OPEN.

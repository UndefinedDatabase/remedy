## Gaps

1. Goal & Done's DONE sentence says the second gate test drives, through `apps.cli.grouped.main`, "an order that runs in the repository of the project it names wherever the client stands" (row 3) and "a result that is declined" (row 7). The second gate test (`tests/cli/test_machine_client_paths.py`, three tests) and F295's gate test contain no `project:` header and no `job decline`: measured by reading both files and by grep (the only matches of "project" are the `digest["projects"]` reads). Both behaviours are fully proved through the command line by other tests (rows 2, 6, 16 to 20, 24 to 26, all red under their mutations), but not by the gate test the sentence names, so the DONE sentence as written is not met. What is missing: an order file with a `project:` header started from another place, and a `job decline` followed by a read of `status`, inside `test_machine_client_paths.py`.
2. Observations that are not gaps. (a) With the last operation dropped from the interface (P28), `test_the_text_output_names_every_operation` stayed green; only the page test went red, so the "names every operation" claim rests on the page test and on the hand-written `CLIENT_OPERATION_IDS`. (b) Row 23's proof is a unit proof; the only other caller of `apply_job` is the `remedy do --apply` step (`do_sequence.do_apply_one_job`), which reports a not-applied job as a failed step and was not mutated in this audit. (c) Row 39's mutation is on a test file because the claim is about that file.

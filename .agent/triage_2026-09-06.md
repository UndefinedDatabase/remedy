## How the open set was built (A.1)

The canonical count function is `scripts/rotate_live_review.py::count_open_findings`
(line 120), whose docstring names the formula: lines matching `^- R-\d{4} — ` minus
lines matching `^Done: R-\d{4} — `. Measured over `.agent/live_review.md` and
`.agent/live_review_archive.md` at the branch point, that function returns **296**
(296 on the ledger, 0 on the archive, which is balanced by construction because
`rotate_live_review.py` moves only complete pairs).

The TABLE below has **298** rows, and the two-row difference is not a second
definition. The ids are derived from the same two regexes the canonical function
uses, with the id captured: an id is open when it has a registration record and no
`Done:` record. `R-0721` and `R-0725` each carry TWO `Done:` lines, so the LINE
formula subtracts them twice while the SET difference subtracts them once. The
script's own docstring anticipates this state ("any id with two `Done:` records
stay"), and finding R-0778 registers it. A finding is a thing, not a line, so the
triage is performed over the 298 distinct ids; the canonical 296 is reported
beside it wherever a count is stated.

## Bucket rules as applied (A.2)

Buckets are first-match-wins in the operator's order, and each was decided by
reading the finding's own text. Two readings had to be fixed before the sweep and
are recorded here so a later reader can audit them rather than re-derive them:

1. **`fixed` is scoped to DURABLE artifacts.** `.agent/plan.md`, `.agent/context.md`,
   `.agent/handoff.md` and a round's block are rewritten every round, so a defect
   described in one of them is trivially "no longer on main" and every such
   finding would fall into `fixed`, which would empty the bucket of meaning. A
   finding is `fixed` only when it names code, a test, a doc, a script or an
   append-only record and that defect is verifiably gone; a round-local reviewer
   artifact routes to `process-only`, which is what it is.
2. **The process-only line is the review process's OWN artifacts.** The operator's
   test names reviewer prose, block gate arithmetic, `.agent/` bookkeeping,
   checklist wording, handoff counts and a comment or docstring with no
   behavioural effect. `docs/agents/planner_reviewer_prompt.md`,
   `docs/roadmap/STATUS_closure_protocol.md` and `docs/agents/handback_template.md`
   are checklist wording and route there. A roadmap feature file, a design
   reference and `docs/agents/integration_gate.md` are NOT: builders and gates
   execute against them, so a defect in one is `product` — for the integration
   gate, additionally under amend0827 rule 2's own clause for "a gate over
   production code shown to be blind or unmeetable".

The ambiguity rule was applied as written: could-be-either is `product`, and a
finding naming a deleted module beside a surviving behaviour is `product`
(R-0796 and R-0809 are the two instances).

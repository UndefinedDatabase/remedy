WHAT THE PARITY MEASUREMENT DOES NOT COVER, STATED PLAINLY
------------------------------------------------------------------------------

A4 answers 'was dist rewritten during the run?' — no, in both runs. It does
NOT answer 'was dist USABLE by the run?', and in base run 1 it was not: the
copied dist was byte-correct but mtime-older than the freshly checked-out
source, so `_frontend_is_stale()` returned True and the server refused to
start. A3's 'restore parity by COPY' is incomplete on its own, because
shutil.copytree preserves mtimes while `git worktree add` stamps the source
with the checkout time. Base run 2 completed the restoration by bumping the
copied dist's mtimes past the checkout time; nothing in the repository was
edited to achieve it, only files inside the throwaway worktree.
